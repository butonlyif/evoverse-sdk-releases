Efinity Adapter Guide

Efinity Adapter Guide

Version: v1.0　Applies to SDK version: v1.0.0 Updated: 2026-09-30

The Efinity Adapter provides the Workbench and the full set of vendor capabilities for the Efinix Titanium FPGA: compilation, timing, on-chip debug, programming, RISC-V software, IP management, and interface design. For installation instructions, see the SDK Overview.

1. Requirements

Item Requirement
Core extension evoverse-sdk at the same version (required; install it before this Adapter)
Efinity 2026.1+; path configured in the core setting evoverse.efinityPath
Debug No extra requirements — since v0.9.0, on-chip debug runs through a pure CLI and never launches the Efinity GUI

2. The Six Workbench Tabs

Open it with EvoVerse: Open Efinity Workspace, or find it in the sidebar after installation.

Tab Function
Home Project dashboard: Build button, board information, toolchain actions
Build Build configuration (Map/PNR/PT/PGM options, parallel threads), unified flow, live output, cancel
Timing Timing reports, 12-rule diagnostics, data path and pipeline analysis, Tcl console
Debug Pure-CLI debug loop (see §4)
SW RISC-V software app list, BSP regeneration, new RISC-V project creation
IP Browse/add IP, configure complex IP in the Efinity IP Manager, sync back into the project

3. Build Flow

  1. Configure options in the Build tab (or keep the defaults)
  2. Click Build — the Adapter invokes efx_run.bat --flow compile (the native Efinity unified flow: PT → map → pnr → pgm)
  3. Live output streams in; when the build finishes, the Build tab shows resources, clock domains, and a timing summary
  4. The status bar indicates Ready / Running / Failed

To cancel: EvoVerse: Cancel Efinity Build.

4. On-Chip Debug (redone in v0.9.0, pure CLI)

The entire debug flow goes through evoverse_dbg.py, which bridges the Efinity efx_dbg API without opening the Efinity GUI. The top of the Debug page provides a seven-step flow guide (mark signals → first build → enable debug → second build → program & scan → trigger capture → wrap up). The page sections are:

Section Content
Debug flow guide Seven-step overview + AI-assist notes
1 · Debug configuration Profile status, auto-instantiation, sample clock / sample depth (a rebuild is required after changes)
2 · Program Download the bitstream
3 · Scan device FTDI/JTAG scan; confirm the hardware debug cores
4 · Debug probes LA / VIO probe table + trigger conditions (comparison mode / match value / mask)
5 · Capture Conditional-trigger capture / immediate capture; the VCD waveform opens automatically when done
6 · Virtual IO (VIO) Read all probe values; safe writes to output probes (direction and width validation + confirmation receipt)
Capture results Sample count, status, timestamp, VCD path
Debug version management Clean debug traces (one click back to a clean baseline) / branch a clean baseline (keep the debug version as a separate copy)

For full steps, trigger-condition semantics, artifact files, and troubleshooting, see the On-Chip Debug Guide.

AI assist: Editing RTL, changing the sample configuration, and running builds and programming can all be driven from the Trae chat in natural language (for example, "add a debug marker to pattern with a sample depth of 4096, then build and program"); the Debug page handles status viewing, trigger configuration, and capture.

Programming (Toolchain: Program FPGA) is implemented by the Efinity Adapter; generic capabilities such as simulation and code checks remain in the core extension and are not duplicated in the Adapter.

6. RISC-V Software Development

The SW tab manages Sapphire SoC software applications:

  • The application list refreshes live (it depends on the project soc/ directory)
  • Regen BSP: regenerate the BSP headers after hardware changes
  • New RiscV Project: create a software project from a template

For the build, programming, and GDB debug procedures, see Chapters 16–17 of the User Manual.

7. IP Management

Two configuration paths:

  • Simple IP: browse and add directly in the IP tab; parameters are configured through VS Code forms
  • Complex IP (DDR/MIPI, etc.): Open in Efinity IP Manager configures them in the native wizard of the Efinity GUI; Sync from Efinity pulls the result back into the project when done

8. Known Boundaries

  • Debugging requires the Efinity-generated debug profile (debug_profile.json); if the profile has not been generated, step 1 of the Debug tab reports it
  • VIO writes and debug-configuration application both require explicit confirmation; there is no path that silently writes to hardware
  • The Workbench UI is owned by the Adapter; upgrading the Adapter may adjust the tab layout, while the functional commands remain stable
Advanced references are for on-demand lookup; design records, release procedures, audit reports and future plans are not customer entry points.
