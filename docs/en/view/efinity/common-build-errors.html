Efinity Common Build Errors

Efinity Common Build Errors

Version: v1.0 | Based on Efinity 2026.1 (efx_map / efx_pnr / IP Manager / Design Check)

1. Error taxonomy overview

Compile errors in the Efinity toolchain fall into six categories by origin:

Category Source Typical stage
Synthesis errors efx_map map
XML configuration errors efx_map / efx_pnr map / pnr
Interface design check errors Interface Designer (Design Check) pnr
IP Manager errors IP Manager (efxIP.log) project initialization
P&R errors efx_pnr pnr
Programmer errors efx_pgm pgm

Source: efx_map --help error codes; C:\Efinity\2026.1\ipm\log\efxIP.log; Design Check rules

2. Synthesis errors

2.1 EFX-0002: Illegal command line

EFX-0002 (ERROR): Illegal command line

Meaning: A command-line argument passed to efx_map is malformed or unrecognized.

Troubleshooting: - Check the command-line help efx_map --help - Confirm parameter names are spelled correctly and follow the name=value convention

Source: efx_map --help — EFX-0002

2.2 EFX-0003: Source file analysis failed

EFX-0003 (ERROR): Analysis of source file '<file>' failed

Meaning: Syntax analysis or semantic elaboration of a Verilog/VHDL source file failed.

Troubleshooting: - Look at the error messages that precede this one to pinpoint the specific syntax/semantic problem - Check the file for undeclared signals, missing module definitions, and syntax errors

Source: efx_map --help — EFX-0003

2.3 Undefined black-box modules

When the design references an undefined module, the default behavior is an error.

Control parameter:

Parameter Default Description
--blackbox-error arg 1 Set to 0 to downgrade black boxes from ERROR to WARNING

Source: efx_map --help — --blackbox-error

2.4 Raising log verbosity

When an error message is not specific enough, increase the output verbosity:

Parameter Default Description
--message-verbosity arg 0 Increase this value for more detailed error context
--suppress_warning_msgs arg 0 Set to 1 to suppress warnings (not recommended while troubleshooting)
--msg_config_file arg — Specify a custom message-filter configuration file 
# Pass verbosity options through efx_run
efx_run.bat my_design --map_opts message-verbosity=1

Source: efx_map --help — --message-verbosity, --suppress_warning_msgs, --msg_config_file

3. XML project file configuration errors

3.1 Element ordering breaking efx_map

In --un_flow (Unified Netlist Flow) mode, an incorrect XML element order breaks synthesis:

  • Symptom: efx_map refuses to process the file and may report a parse error
  • Root cause: the XML schema enforces element order strictly; some elements placed in the wrong position cause a flow-sequence mismatch
  • Troubleshooting: check element order against the project XML schema (xml-project-schema.md)

Source: EvoVerse SDK engineering practice (project_memory.md)

3.2 peri_file in the wrong place

The <efx:peri_file> element must sit inside <efx:constraint_info>, not <efx:interface_info>:

<!-- Correct -->
<efx:constraint_info>
    <efx:peri_file name="output/design.peri.xml" />
</efx:constraint_info>

<!-- Wrong: peri_file must not be inside interface_info -->
<efx:interface_info>
    <efx:peri_file name="output/design.peri.xml" />
</efx:interface_info>
  • <efx:interface_info> should contain only <efx:default_peri_file> (usually with an empty name)
  • <efx:constraint_info> holds the SDC, ISF, and peri files

Source: EvoVerse SDK engineering practice (project_memory.md); Efinity XML Project File Schema Reference §4, §5

3.3 Illegal ooc_info element

The <efx:ooc_info /> element is not accepted in some flows (for example the Unified Netlist Flow):

  • Symptom: a project XML containing this element produces an illegal-configuration error in specific flows
  • Troubleshooting: if the project does not use OOC (Out-of-Context) synthesis, remove the <efx:ooc_info /> element
  • Note: even an empty element (such as <efx:ooc_info />) can trigger the problem

Source: EvoVerse SDK engineering practice (project_memory.md)

3.4 Empty inter_file element

If the name of <efx:inter_file name="" /> is empty and not needed, delete the line outright instead of keeping an empty element:

<!-- Wrong: empty inter_file element -->
<efx:inter_file name="" />

<!-- Correct: omit the element entirely -->

Source: EvoVerse SDK engineering practice (project_memory.md); Efinity XML Project File Schema Reference §5

4. Interface design check errors (Design Check)

The Interface Designer's Design Check runs before the P&R stage and validates rules for clocks and clock multiplexers.

Source: Titanium Design Check Error Messages

4.1 Clock rules (clock_rule)

Error Description
clock_rule_capacity More than N distinct clocks cannot be connected within one region
clock_rule_max_count The number of core clocks used exceeds the maximum limit (32)
clock_rule_lvds_rx_clock_source A PLL output clock drives LVDS Rx on a different edge
clock_rule_pll_ref_clock_lvds_rx The edge of the PLL reference clock does not match the edge where the LVDS Rx sits
clock_rule_undefined_name Undefined clock source

Source: Design Check clock_rule_* error messages

4.2 Clock multiplexer rules (clkmux_rule)

Error Description
clkmux_rule_clocks_routed An unrouted pin drives a clock-mux input
clkmux_rule_core_clock_pin A core clock pin can only be used when the dynamic mux is enabled
clkmux_rule_core_clock_static_mux A core clock pin cannot be connected through a static mux
clkmux_rule_dynamic_clock_pin The dynamic clock pin name is empty
clkmux_rule_dynamic_clock_select_pin The dynamic clock select pin name is empty
clkmux_rule_global_regional_pin The global pin name for a regional connection is missing
clkmux_rule_global_regional_resource A regional buffer does not support a global connection
clkmux_rule_pll_output_clock A PLL output clock is routed more than once
clkmux_rule_regional_conn_type A regional buffer requires the rclk or rctrl connection type
clkmux_rule_type_config MIPI/GPIO/LVDS resources may not connect to the dynamic mux

Source: Design Check clkmux_rule_* error messages

4.3 SDC constraint errors

Poorly configured SDC constraints cause errors in the timing analysis stage:

  • unconstrained endpoints: missing SDC constraints leave many endpoints unconstrained
  • Troubleshooting: confirm that the <efx:sdc_file name="..." /> path in the project XML is correct and the file exists
  • Make sure every clock domain has a create_clock or create_generated_clock definition

Source: EvoVerse SDK engineering practice (project_memory.md)

4.4 GPIO assignment conflicts

When the board image and the ISF file conflict, Interface Designer GPIO assignment fails:

  • Symptom: pin assignment fails with an already-assigned or conflict message
  • Troubleshooting: check whether pins assigned manually in the ISF file overlap pins auto-assigned by the board image

Source: EvoVerse SDK engineering practice (project_memory.md)

5. IP Manager errors

The IP Manager log lives at C:\Efinity\2026.1\ipm\log\efxIP.log.

Error pattern Description
PICKLE_LOAD-ERROR IP parameter deserialization failed — the IP configuration file is corrupt or in an incompatible format
VALIDATE_PARAM-ERROR IP parameter validation failed — a parameter value is out of range or has the wrong type

Source: C:\Efinity\2026.1\ipm\log\efxIP.log

6. P&R errors

6.1 Routing congestion

Routing congestion is a common P&R-stage problem:

  • Symptom: efx_pnr reports that routing cannot complete or some nets are unrouted
  • Troubleshooting:
  • Raise the congestion optimization level with --optimization_level CONGESTION_1/2/3
  • Consider spreading out the placement of critical modules

Source: efx_pnr --help-verbose — --optimization_level

6.2 Timing violations

  • Symptom: WNS (Worst Negative Slack) is negative; critical path timing is not met
  • Related parameter: --print_critical_path N (default 10)
  • Troubleshooting: inspect the critical path report and look for unnecessarily long combinational paths

Source: efx_pnr --help — --print_critical_path

7. Programmer errors

Programmer errors usually occur during bitstream generation (pgm) or programming:

Problem Possible cause What to check
Flash not detected The model is not in the database Check pgm/bin/flash_db/
Bitstream too large Compression not enabled Confirm --bitstream_compression on (on by default)
SPI Active configuration fails Clock divider too high Increase --oscillator_clock_divider
Multi-image not working CBSEL pins not configured correctly Confirm --enable_cbsel on and legal addresses

Source: efx_pgm --help

8. Troubleshooting workflow

8.1 Standard troubleshooting steps

1. Identify the error source (map / pnr / pgm / PT)
      │
2. Check the preceding error message (the error before EFX-0003)
      │
3. Enable verbose logging: --map_opts message-verbosity=1
      │
4. Check the XML project file: element order, peri_file placement
      │
5. Check SDC constraints: clock definitions, unconstrained endpoints
      │
6. Check the Design Check report: clock/clkmux rules
      │
7. Check the IP Manager log: efxIP.log

Source: compiled from efx_map --help, Design Check rules, and EvoVerse SDK engineering practice

8.2 Common diagnostic commands

# Raise synthesis log verbosity
efx_run.bat my_design --map_opts message-verbosity=1

# Synthesis only (skip later steps for fast iteration)
efx_run.bat my_design --flow map --map_opts message-verbosity=1

# P&R only, print more critical paths
efx_run.bat my_design --flow pnr --pnr_opts print_critical_path=50

# Suppress black-box errors (temporary triage; not recommended for release)
efx_run.bat my_design --map_opts blackbox-error=0

# Custom message filtering
efx_run.bat my_design --map_opts msg_config_file=my_filter.cfg

Source: efx_map --help; efx_pnr --help; efx_run --help

9. Integration with the EvoVerse SDK

9.1 Error handling in the SDK

Both the EvoVerse SDK CLI and the IDE Build hand the raw project XML to Efinity's official runner:

call <Efinity>/bin/setup.bat
<Efinity>/bin/efx_run.bat <project.xml> --flow compile
  • The directory holding the XML serves as the working directory; the SDK does not split the flow, pre-run PT, or generate a substitute XML
  • By default it injects no thread counts, timeout, --un_flow, or MAP/PNR parameters; they are appended only when the user overrides them explicitly
  • SDK health checks are advisory only and cannot override Efinity's own judgment of whether the project is legal
  • stdout, stderr, and the exit code are returned verbatim by the vendor runner
  • The SDK's Build Report panel shows the parsed, structured error information
  • Efinity 2026.1 is the verified baseline; other versions stay native pass-through and are flagged as unverified

Note: Efinity 2026.1 itself may update the project XML's version, sync state, or format. The SDK must not additionally rewrite or restore these vendor behaviors around a build.

Source: EvoVerse SDK buildRunner.ts

9.2 Report enrichment

  • The efinity-adapter's src/capabilities/report.ts parses the map/P&R/timing reports and extracts resource usage and timing summaries
  • timingDiagnoser.ts performs root-cause classification using six categories of error fingerprints
  • LLM context injection (copilotContext.ts) can send RTL + SDC + diagnosis results to AI-assisted analysis

Source: EvoVerse SDK toolchain/ module
