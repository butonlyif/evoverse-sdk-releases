Efinity Design Rules

Efinity Design Rules

Summarized from the Efinity 2026.1 toolchain and the actual RTL code of EvoVerse projects. Data sources: efx_map --help, efx_run.py, project snapshot RTL, and the Golden Top reference design.

1. RTL coding rules

1.1 File structure

`default_nettype none
`timescale 1ns / 1ps

//============================================================================
// Module: <module_name>
// Description: <description>
// Interface: <port description>
//============================================================================
module module_name (
    input  wire clk_i,
    input  wire rst_n_i,
    output wire sig_o
);

    // ---- Internal signals ----
    reg [WIDTH-1:0] reg_name_r;

    // ---- Combinational / sequential logic ----
    // ...

endmodule

`default_nettype wire

Key points: - The file header must be `default_nettype none; restore `default_nettype wire at the end - Implicit net types are forbidden; every wire must be declared explicitly - The timescale is uniformly 1ns / 1ps

1.2 Naming conventions

Type Suffix Example
Input port _i clk_i, rst_n_i, enable_i
Output port _o count_o, pwm_o, led_o
Internal register _r count_r, state_r
Active-low signal _n rst_n, btn_n
Clock signal clk_ clk_50m, sys_clk
Parameter constant UPPER_CASE WIDTH, DEPTH

1.3 Port declarations

All ports must declare both direction AND type explicitly:

// Correct
module top (
    input  wire       clk50_in,
    input  wire       rst_n_i,
    output wire       led_user,
    output reg  [7:0] count_o
);

// Wrong — implicit net type
module top (input clk50_in, output led_user);

1.4 Parameterization

module counter #(
    parameter WIDTH = 8
) (
    input  wire              clk_i,
    input  wire              rst_n_i,
    output wire [WIDTH-1:0]  count_o
);
    reg [WIDTH-1:0] count_r;
    // ...
endmodule

1.5 Instantiation

// Correct — named port connections
counter_top #(
    .WIDTH(16)
) u_counter (
    .clk_i   (sys_clk),
    .rst_n_i (rst_n),
    .count_o (led_count)
);

// Forbidden — .* implicit connection

1.6 Section comments

// ---- Async-reset synchronous-release ----
reg [2:0] rst_sync;
always @(posedge sys_clk or negedge rst_n_i) begin
    // ...
end

// ---- 26-bit counter ----
reg [25:0] blink_cnt;
always @(posedge sys_clk or negedge rst_n) begin
    // ...
end

// ---- LED drive ----
assign led_user = blink_cnt[25];

2. Reset design

2.1 Async-reset synchronous-release (mandatory pattern)

// 3-stage synchronizer: asynchronous assert, synchronous release
reg [2:0] rst_sync;
always @(posedge sys_clk or negedge rst_n_i) begin
    if (!rst_n_i)
        rst_sync <= 3'b000;
    else
        rst_sync <= {rst_sync[1:0], 1'b1};
end
wire rst_n = rst_sync[2];

2.2 Merging with PLL lock

// Hold the system in reset while the PLL is unlocked
wire async_rst_n = rst_n_i & pll_locked;

2.3 Submodule reset

always @(posedge clk_i or negedge rst_n_i) begin
    if (!rst_n_i)
        count_r <= '0;
    else
        count_r <= count_r + 1'b1;
end

2.4 Reset coverage principles

  • All sequential logic (registers) must have a reset
  • assign statements in combinational logic are not reset directly; they are reset indirectly through the registers that drive them
  • Reset polarity is uniformly active-low (_n suffix)

3. CDC (clock-domain crossing) handling

3.1 Single-bit control signal synchronization

// 2-3 stage shift-register synchronizer
reg [2:0] sync;
always @(posedge dst_clk) begin
    sync <= {sync[1:0], src_signal};
end
wire dst_signal = sync[2];

3.2 Multi-bit data buses

  • Cross clock domains with an asynchronous FIFO (Gray-coded pointers)
  • Never synchronize a multi-bit bus through a shift-register synchronizer

3.3 CDC declarations in SDC

# Declared between all asynchronous clock domains
set_clock_groups -asynchronous \
    -group {clk_50m} \
    -group {clk_33_ddr} \
    -group {clk_27_mipi_a clk_27_mipi_b}

# False path on the first stage of the CDC synchronizer chain
set_false_path -from [get_cells {u_rst_sys/sync_r[0]}]

3.4 Simplification for single-clock-domain projects

Teaching projects (single clock domain) do not need set_clock_groups. However, every clock port on the board must still be declared in the SDC (even if unused in RTL), otherwise STA analysis will be incomplete.

4. SDC constraint rules

4.1 Minimal constraint template (Stage 0/1)

# Primary clock
create_clock -name clk50_in -period 20.000 [get_ports clk50_in]

# False path for asynchronous inputs
set_false_path -from [get_ports rst_n_i]
set_false_path -from [get_ports {btn_n[*]}]

# False path for slow outputs
set_false_path -to [get_ports led_user]

4.2 Complete constraint template

# 1. Declare every on-board clock
create_clock -name clk50_in     -period 20.000 [get_ports clk50_in]
create_clock -name clk33_ddr    -period 30.000 [get_ports clk33_ddr]

# 2. Clock uncertainty (jitter budget)
set_clock_uncertainty 0.200 [get_clocks clk50_in]

# 3. Asynchronous clock groups
set_clock_groups -asynchronous \
    -group {clk50_in} \
    -group {clk33_ddr}

# 4. I/O delay constraints
set_input_delay  -max 5.0 -clock clk50_in [get_ports uart_rxd]
set_output_delay -max 5.0 -clock clk50_in [get_ports uart_txd]

# 5. False path for asynchronous inputs
set_false_path -from [get_ports rst_n_i]
set_false_path -from [get_ports {btn_n[*]}]

# 6. False path for slow / debug outputs
set_false_path -to [get_ports led_user]

4.3 Constraint principles

Principle Description
Declare conservatively Declare clock ports in the SDC even when the RTL does not use them
Asynchronous = false path Add a false path to every asynchronous external input
First-stage CDC exemption Apply an explicit false path to the first register of each CDC synchronizer chain
Constrain I/O as needed Use set_input/output_delay for high-speed interfaces and false paths for slow signals

4.4 Common mistakes

Mistake Consequence Fix
SDC omits declarations for unused clock ports STA does not analyze the clock network attached to that port Always declare all on-board clocks
No clock groups declared Cross-domain paths produce bogus setup violations set_clock_groups -asynchronous
No false path on the synchronizer first stage Metastability paths are reported as timing violations Point the false path precisely at the synchronizer first stage
create_clock period unit error 20 ns written as 20 (ps) Always use ns units

5. Golden Top reference constraint system

The Golden Top is the complete WS-E1 hardware reference design; its constraint files can serve as constraint templates for complex multi-peripheral designs.

5.1 Clock domain declarations

# 8 independent on-board clock domains
create_clock -name clk_50m      -period 20.000 [get_ports clk_50m]
create_clock -name ddr_clk_ref  -period 30.000 [get_ports ddr_clk_ref]
create_clock -name clk_27_mipi_a -period 37.037 [get_ports clk_27_mipi_a]
create_clock -name clk_27_mipi_b -period 37.037 [get_ports clk_27_mipi_b]
create_clock -name pll_ethernet_refclk -period 40.000 [get_ports pll_ethernet_refclk]
create_clock -name rgmii_rxc    -period 8.000  [get_ports rgmii_rxc]

5.2 Peripheral I/O constraints

# UART (115200 bps)
set_input_delay  -max 10.0 -clock clk_50m [get_ports system_uart_0_io_rxd]
set_output_delay -max 10.0 -clock clk_50m [get_ports system_uart_0_io_txd]

# SPI (10MHz)
set_output_delay -max 20.0 -clock clk_50m [get_ports {system_spi_0_io_*}] -add

# GPIO
set_false_path -from [get_ports {system_gpio_0_io_*}]
set_false_path -to   [get_ports {system_gpio_0_io_*}]

5.3 CDC synchronizer chain exemptions

# Reset synchronizer first stage
set_false_path -from [get_cells {u_rst_sys/sync_r[0]}]
set_false_path -from [get_cells {u_rst_spi/sync_r[0]}]

# First stage of the cross-domain signal synchronizers
set_false_path -from [get_cells {u_sync_btn/sync_r[0]}]

6. Simulation rules

6.1 Testbench template

`timescale 1ns / 1ps

module tb_module_name;

    reg        clk;
    reg        rst_n;
    wire [7:0] count;

    // DUT instantiation
    module_name u_dut (
        .clk_i  (clk),
        .rst_n_i(rst_n),
        .count_o(count)
    );

    // Clock generation
    always #5 clk = ~clk;  // 100MHz

    // VCD dump
    initial begin
        $dumpfile("dump.vcd");
        $dumpvars(0, tb_module_name);
    end

    // Test stimulus
    initial begin
        clk   = 0;
        rst_n = 0;
        #20 rst_n = 1;  // release reset after 2 cycles
        // ... stimulus ...
        #1000 $finish;
    end

endmodule

6.2 Simulation verification points

  • Reset release: hold reset for at least 2 clock cycles
  • Waveform dump: use $dumpfile + $dumpvars
  • Test coverage: normal operation, boundary conditions, reset recovery

7. Synthesis coding considerations

7.1 Avoid latches

// Wrong — infers a latch
always @(*) begin
    if (enable) out = data;
end

// Correct — complete if-else
always @(*) begin
    if (enable) out = data;
    else        out = '0;
end

7.2 Avoid combinational loops

// Wrong — combinational loop
assign a = b | c;
assign b = a & d;

// Correct — break the loop through a register
always @(posedge clk) a_r <= b_r | c;
assign a = a_r;

7.3 Prefer registered outputs

// Avoid — long combinational logic driving a port directly
assign led = (complex_combinational_expression);

// Recommended — registered output
always @(posedge clk) led_r <= complex_combinational_expression;
assign led = led_r;

7.4 Efinity synthesis inference notes

  • Efinity efx_map can infer BRAM, DSP, and IO registers from RTL
  • Steer inference with attributes such as (* ram_style = "block" *)
  • In the unified flow, synthesis infers GPIO automatically; do not re-create in the ISF any GPIO that synthesis has already inferred
  • peri-syn-instantiation / peri-syn-inference control how peripheral primitives are inferred
Advanced references are for on-demand lookup; design records, release procedures, audit reports and future plans are not customer entry points.
