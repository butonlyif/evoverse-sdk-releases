1. create_clock — primary clock constraint

Purpose: defines a primary clock (fed into the FPGA from outside, or generated internally).

1.1 Basic syntax

create_clock -period <period_ns> -name <clk_name> [get_ports <port_name>]

1.2 Complete Efinity example

# Primary clock: 50 MHz, port clk_50m
create_clock -period 20.0 -name sys_clk [get_ports clk_50m]

# Video clock: 148.5 MHz
create_clock -period 6.734 -name video_clk [get_ports video_clk_i]

# SPI clock: 10 MHz (note: -waveform controls the duty cycle)
create_clock -period 100.0 -name spi_clk [get_ports spi_clk_i]

1.3 -waveform controls the clock edges

# DDR rising-edge sampling: first edge at 0, second edge at period/2
create_clock -period 10.0 -name ddr_clk \
    -waveform {0.0 5.0} \
    [get_ports ddr_clk_p]

"Using the create_clock Constraint ... Provides the period and (optionally) duty cycle / waveform of the primary clock." —— Source: C:\Efinity\2026.1\doc\pdf\efinity-timing-closure.pdf §5 "Using the create_clock Constraint" ([A1])

1.4 The -add option

# One port driven by multiple clocks (rare, but worth noting)
create_clock -period 10.0 -name clk_a -add [get_ports clk_pad]
create_clock -period 20.0 -name clk_b -add [get_ports clk_pad]

See C:\Efinity\2026.1\doc\topics\tim-add-clock-create.html.

2. create_generated_clock — derived clocks

Purpose: defines the derived clock at the output of a PLL / clock divider / clock mux. The STA tool automatically traces the relationship between the derived clock and the primary clock.

2.1 PLL output (basic)

# PLL output 100 MHz (from primary clock sys_clk via a 4x PLL)
create_generated_clock -name pll_out \
    -source [get_ports sys_clk] \
    -multiply_by 4 -divide_by 1 \
    [get_pins {pll_inst/clk_out}]

2.2 Clock divider

# Clock divider: sys_clk 100 MHz → div_clk 25 MHz (÷4)
create_generated_clock -name div_clk \
    -source [get_ports sys_clk] \
    -divide_by 4 \
    [get_pins {clk_div_inst/Q}]

2.3 -edges / -edge_shift fine-grained control

# Based on the PLL output but phase-shifted by 90°
create_generated_clock -name pll_out_90 \
    -source [get_pins {pll_inst/clk_out}] \
    -edges {1 2 3} -edge_shift {0.0 2.5 5.0}

"Using the create_generated_clock Constraint ... Defines a derived clock from a PLL, divider, or clock mux. STA traces back to source clock for relationship analysis." —— Source: C:\Efinity\2026.1\doc\pdf\efinity-timing-closure.pdf §5 "Using the create_generated_clock Constraint" ([A1])

See C:\Efinity\2026.1\doc\topics\tim-add-clock-creategen.html.

3. Virtual Clocks

When to use: the external clock source is not visible on any FPGA pin (e.g., the board clock enters through a dedicated clock buffer and the FPGA receives only data, not the clock).

3.1 Typical scenarios

  • Source-synchronous DDR interfaces (external clock and data arrive at the FPGA simultaneously; the FPGA has a dedicated internal PLL)
  • An external PHY chip provides the reference clock to the MAC, and the MAC data enters the FPGA through ordinary I/O

3.2 Syntax

create_clock -period 10.0 -name virtual_ddr_clk
# Reference the virtual clock in set_input_delay
set_input_delay -clock virtual_ddr_clk -max 2.0 [get_ports ddr_data*]

"Virtual Clocks ... Used when the clock source is external and not present on an FPGA pin (e.g., source-synchronous interfaces)." —— Source: C:\Efinity\2026.1\doc\pdf\efinity-timing-closure.pdf §5 "Virtual Clocks" ([A1])

See C:\Efinity\2026.1\doc\topics\tim-clock-virtual.html.

4. PLL Clock Latency — 4 modes

Efinity PLLs have 4 feedback modes; each mode has a different clock insertion delay and PLL compensation delay.

"Trion and Titanium FPGAs have PLLs that you can use to generate clock signals in your design. The PLLs are located in the corners of the FPGA. You can use the PLL to compensate for clock skew/delay via external or internal feedback to meet timing requirements in advanced applications." "Global clock signals incur delays as they traverse the FPGA." "The clock insertion delay is the time it takes for a clock signal to travel from the pad of a GPIO configured as a global clock (GCLK) through the global clock network to the destination register. This document calls it the 'base' clock insertion delay." "The PLL compensation delay is the delay that is removed from the base clock insertion delay to create the actual insertion delay. It is always an amount you subtract from the clock insertion delay. Some PLL modes have a PLL compensation delay and some do not." —— Source: AN 042 v1.0 §A4.3 ([A4.3])

PLL mode Feedback path Compensation delay Use case Efinity doc
Local Feedback internal feedback to the PLL's local input yes single clock domain with the lowest skew requirement tim-clock-latency-pll-local.html
Core Feedback internal feedback into the core clock network yes spans multiple registers, core clock balancing tim-clock-latency-pll-core.html
External Feedback external board-level feedback (dedicated PLL feedback pin) no (board delay counted) source-synchronous interfaces (DDR/RGMII) tim-clock-latency-pll-external.html
Cascading PLL cascade (PLL1 output → PLL2 reference) accumulated across PLLs multiple frequency domains, ultra-low jitter tim-clock-latency-pll-cascading.html

Source: C:\Efinity\2026.1\doc\pdf\efinity-timing-closure.pdf §5 "Clock Latency" sub-sections ([A1])

Complete PLL ISF configuration example: pll-and-clock-design.md §"PLL ISF".

5. set_clock_latency — source/network latency

Purpose: models the board-level delay from the clock source to the FPGA pin (source latency) + the clock tree delay (network latency).

"The source clock latency represents the time it takes to get from the clock source on the board to the global clock tree on the FPGA. This delay includes the board delay, buffer delay, and any PLL delay (including PLL compensation delay, which is negative, see AN 042: Working with PLLs)." "Most of the time you do not need to use set_clock_latency. However, it is required when you want to constrain external signals to core registers to capture the latency effect of the clock signal transferring onto the FPGA." "The Efinity software v2023.2 and higher creates a template for the set_clock_latency constraint in the <project>.pt.sdc file." —— Source: C:\Efinity\2026.1\doc\topics\tim-clock-latency.html ([A3.2])

5.1 Basic syntax

# Source latency: board-level delay
set_clock_latency -source -early 2.0 [get_clocks sys_clk]
set_clock_latency -source -late  4.0 [get_clocks sys_clk]

# Network latency: clock tree delay (usually inferred by the tool)
set_clock_latency -early 0.5 [get_clocks sys_clk]
set_clock_latency -late  1.0 [get_clocks sys_clk]

5.2 GPIO clock latency details

Source: C:\Efinity\2026.1\doc\topics\tim-clock-latency-gpio.html ([A3])

6. set_clock_uncertainty — Jitter + Margin

Purpose: adds jitter and margin to the setup/hold checks.

# Setup: 60 ps (jitter + margin)
set_clock_uncertainty -to clk -setup 0.06

# Hold: 20 ps (OCV/jitter)
set_clock_uncertainty -to clk -hold 0.02

"How to Set Clock Uncertainty ... set_clock_uncertainty -to clk -setup 0.06" —— Source: C:\Efinity\2026.1\doc\pdf\efinity-timing-closure.pdf §5 "How to Set Clock Uncertainty" ([A1])

Typical values (100 MHz system): - Setup uncertainty: 60–100 ps - Hold uncertainty: 5–20 ps

See fpga-sta-basics.md §9.

7. set_clock_groups — asynchronous/exclusive grouping

Purpose: tells the STA tool which pairs of clock domains do not need timing checks.

7.1 Exclusive clocks (only 1 active at a time)

set_clock_groups -exclusive -group {clk1 clk2} -group {clk3} -group {clk4}

Typical scenario: a multi-way clock mux, with a sel register choosing the currently active clock.

7.2 Asynchronous clocks (independent sources)

set_clock_groups -asynchronous -group {clk_a} -group {clk_b}

Typical scenario: USB PHY clock vs. CPU clock (completely different clock sources).

7.3 Multiple-group forms

# Multiple groups in one command (recommended)
set_clock_groups -exclusive -group {clk1 clk2} -group {clk3} -group {clk4}

# Or multiple commands
set_clock_groups -exclusive -group {clk1 clk2}
set_clock_groups -exclusive -group {clk3}
set_clock_groups -exclusive -group {clk4}

Source: C:\Efinity\2026.1\doc\topics\tim-add-clock-set-clock-groups.html ([A3.8])

"Compares exclusive vs. asynchronous clock groups and provides constraint examples." —— Source: C:\Efinity\2026.1\doc\topics\tim-unrelated-clk.html ([A3.7])

See fpga-cdc-patterns.md §6 and fpga-timing-exceptions-cookbook.md §2-3.

8. Object Specifiers — get_* commands

Purpose: selects the object collection (ports, pins, cells, nets) for SDC commands.

8.1 Main object selectors

# Get ports by name
[get_ports clk_50m]
[get_ports {data_in[*]}]              # all bits of the bus
[get_ports "data_in[0..7]"]           # bit 0-7
[get_ports {data_in[*] input_valid}]  # multiple objects

# By clock object
[get_clocks sys_clk]
[get_clocks {clk_a clk_b}]

# By pin (a specific pin of a cell)
[get_pins {u_fft/clk}]
[get_pins {u_fft/Q_reg[*]/D}]

# By cell
[get_cells u_fft]
[get_cells {u_cpu u_dsp*}]

# By net
[get_nets {n_reset n_data*}]

8.2 Wildcards

# * matches any characters
[get_ports {*_clk}]           # all *_clk ports

# Multi-level wildcard
[get_cells {u_core/*}]        # all cells under u_core

"Object Specifiers ... get_clocks, get_ports, get_pins, get_cells, get_nets." —— Source: C:\Efinity\2026.1\doc\pdf\efinity-timing-closure.pdf §12 "Object Specifiers" ([A1])

8.3 Filtering

# Filter only leaf ports (excluding the bus)
[get_ports -filter {is_hierarchical==false} {data*}]

# Filter by direction
[get_ports -filter {direction==in} {*_i}]

See C:\Efinity\2026.1\doc\topics\constraint-object-specifiers.html.

9. Complete Efinity SDC example

9.1 Basic system + asynchronous FIFO interface

# ============================================
# Clock definitions
# ============================================
# Main system clock 100 MHz, driven directly by the external crystal
create_clock -period 10.0 -name sys_clk [get_ports clk_100m]

# Video processing clock 148.5 MHz, independent PLL output (PLL configuration: see pll-and-clock-design.md)
create_generated_clock -name vid_clk \
    -source [get_pins {pll_video/clkin}] \
    -multiply_by 37 -divide_by 25 \
    [get_pins {pll_video/clkout}]
    # Actual frequency = 100 MHz * 37/25 = 148 MHz

# DDR controller clock 400 MHz (from the DDR PHY hard block)
create_generated_clock -name ddr_ck \
    -source [get_pins {ddr_phy_inst/clk}] \
    -multiply_by 4 -divide_by 1 \
    [get_pins {ddr_phy_inst/ck_out}]

# Asynchronous FIFO write clock 50 MHz (external ADC)
create_clock -period 20.0 -name adc_clk [get_ports adc_clk_i]

# ============================================
# Clock Uncertainty
# ============================================
set_clock_uncertainty -to sys_clk -setup 0.100
set_clock_uncertainty -to sys_clk -hold  0.020
set_clock_uncertainty -to vid_clk -setup 0.150
set_clock_uncertainty -to vid_clk -hold  0.030

# ============================================
# Asynchronous clock grouping (mutually unchecked)
# ============================================
set_clock_groups -asynchronous \
    -group {sys_clk vid_clk ddr_ck} \
    -group {adc_clk}

# ============================================
# False paths (special paths)
# ============================================
# Reset signal path (asynchronous reset, unchecked)
set_false_path -from [get_ports arst_n]

# JTAG / debug interface (functional, excluded from STA)
set_false_path -from [get_ports {tck tms tdi}]
set_false_path -to   [get_ports tdo]

# ============================================
# IO constraints (see fpga-io-timing-constraints.md)
# ============================================
# DDR-controller-specific constraints (auto-generated by the Efinity hard block)
# ...

# ADC input: sys_clk domain, 2 ns data delay (PCB trace)
set_input_delay -clock sys_clk -max 4.0 [get_ports adc_data_i*]
set_input_delay -clock sys_clk -min 1.0 [get_ports adc_data_i*]

# LED output: sys_clk domain
set_output_delay -clock sys_clk -max 2.0 [get_ports led_user_o]

# ============================================
# Multicycle / max delay (see fpga-timing-exceptions-cookbook.md)
# ============================================
# CPU ↔ peripherals: the processor bus can span multiple cycles
set_multicycle_path -setup -from [get_clocks cpu_clk] -to [get_clocks peri_clk] 2
set_multicycle_path -hold  -from [get_clocks cpu_clk] -to [get_clocks peri_clk] 1

9.2 RGMII interface (source-synchronous) — real AN 043 example

# RGMII TX clock: 125 MHz (PLL output)
create_generated_clock -name rgmii_tx_clk \
    -source [get_pins {pll_rgmii/clkin}] \
    -multiply_by 5 -divide_by 4 \
    [get_pins {pll_rgmii/clkout}]

# RGMII RX clock: 125 MHz (input from the PHY)
create_clock -period 8.0 -name rgmii_rx_clk [get_ports rgmii_rx_clk_i]

# RGMII dynamic clock switching (2.5 / 25 / 125 MHz) — Titanium only
create_generated_clock -name rgmii_tx_clk_2p5 \
    -source [get_pins {pll_rgmii/clkin}] \
    -multiply_by 1 -divide_by 40 \
    -add [get_pins {pll_rgmii/clkout}]
create_generated_clock -name rgmii_tx_clk_25 \
    -source [get_pins {pll_rgmii/clkin}] \
    -multiply_by 1 -divide_by 4 \
    -add [get_pins {pll_rgmii/clkout}]

# Exclusive group (pick one of the three RGMII clocks)
set_clock_groups -exclusive \
    -group {rgmii_tx_clk} \
    -group {rgmii_tx_clk_25} \
    -group {rgmii_tx_clk_2p5}

Source: AN 043 v1.3 §"RGMII Dynamic Clock Switch" ([A4.2])

10. Efinity-specific notes

10.1 The auto-generated pt.sdc template

Efinity 2023.2+ generates <project>.pt.sdc in the project directory with a built-in set_clock_latency template—users should not delete it manually, or the PLL compensation delay is lost.

"The Efinity software v2023.2 and higher creates a template for the set_clock_latency constraint in the <project>.pt.sdc file." —— Source: C:\Efinity\2026.1\doc\topics\tim-clock-latency.html ([A3.2])

See toolchain-reference.md §"pt.sdc".

10.2 Exclusive vs asynchronous

Option Meaning When to use
-exclusive only one active at a time clock mux with multiple selectable clocks
-asynchronous completely independent clock sources (never active at the same time) cross-domain CDC

Source: C:\Efinity\2026.1\doc\topics\tim-unrelated-clk.html ([A3.7])

10.3 SDC file management

Efinity supports multiple SDC files (divided by hierarchy): - <project>.sdc — the user's main constraints - <project>_dc.sdc — generated by PnR after the first run (original constraints preserved) - <project>.pt.sdc — auto-generated PT timing constraints - <design_module>.sdc — module-level constraints (OOC synthesis)

See C:\Efinity\2026.1\doc\topics\tim-sdc-overview.html and C:\Efinity\2026.1\doc\topics\tim-sdc-multiple.html.

10.4 SDC warnings (tim-sdc-warnings)

After parsing the SDC, the Efinity STA tool emits diagnostic messages (see C:\Efinity\2026.1\doc\topics\efn-sdc-warnings.html). Common warnings:

Warning Cause Fix
Unreferenced clock create_clock present but never referenced Delete it, or add set_input_delay
Multiple drivers on clock multiple sources drive the same net Use set_clock_groups -exclusive
No path found between ... different clock domains not grouped Add set_clock_groups or set_false_path

See toolchain-reference.md §"STA Warnings".
