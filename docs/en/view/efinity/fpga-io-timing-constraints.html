1. Why IO timing constraints matter

The core problem: when the FPGA talks to external chips (DDR / PHY / ADC / DAC), the arrival time of external signals depends on the PCB trace length + the external device's Tco/Tsu/Th—information only the designer knows; the STA tool does not infer it automatically.

"Static timing analysis is 'static' because it doesn't depend on specific input stimulus vectors — instead, it analyzes all possible paths in worst case. But there's a key premise: the tool needs to know what 'qualified' means. That standard is what we give via timing constraints." —— Source: [B7] CSDN timing analysis

Consequences of leaving paths unconstrained: - The STA tool assumes 0 ns external delay → paths too tight → too many reported violations - Or it assumes infinite delay → paths too loose → the actual hardware does not work

"If you don't add constraints, the tool uses a very permissive default that only guarantees basic connectivity. The tool may route critical signals on slow channels, or use non-optimized placement, ultimately causing the design to fail to work." —— Source: [B7] CSDN timing analysis

Two typical problem classes:

Type Start End
In-Reg (input) external chip → PCB trace → FPGA input pin internal FPGA register D
Reg-Out (output) internal FPGA register Q PCB trace → external chip input pin

See fpga-sta-basics.md §2.

2. set_input_delay — input delay

Purpose: tells the STA tool how long an external signal still needs, after arriving at the FPGA input pin, to reach an internal register's D pin.

2.1 Synchronous input (same source as the FPGA clock)

# Input delay: external device Tco_max + PCB trace max delay
set_input_delay -clock sys_clk -max 4.0 [get_ports adc_data_i*]

# min delay: external device Tco_min + PCB trace min delay
set_input_delay -clock sys_clk -min 1.0 [get_ports adc_data_i*]

Meaning: - -max 4.0 (ns): worst-case data delay of 4 ns - The STA tool computes: Required time = sys_clk period − max delay − Tsu − uncertainty - That is: setup slack = (Period − 4 − Tsu − uncertainty) − (Tco + Tlogic + Tnet)

2.2 Asynchronous input (independent clock domain)

# The external device has its own clock, asynchronous to sys_clk
set_input_delay -clock virtual_ext_clk -max 5.0 [get_ports async_in_i]
set_input_delay -clock virtual_ext_clk -min 2.0 [get_ports async_in_i]

# Pair with a CDC synchronizer
set_clock_groups -asynchronous -group {sys_clk} -group {virtual_ext_clk}

See the CDC synchronizer template in fpga-cdc-patterns.md §3.

2.3 The -clock_fall option (DDR)

# DDR interface: the falling edge also samples
set_input_delay -clock ddr_clk -clock_fall -max 2.0 [get_ports ddr_dq[*]]

See §8.

2.4 -add_delay multi-clock stacking

# The same input port is sampled by two clocks (rare, but worth noting)
set_input_delay -clock clk_a -max 3.0 [get_ports data_in] -add
set_input_delay -clock clk_b -max 4.0 [get_ports data_in] -add

3. set_output_delay — output delay

Purpose: tells the STA tool the arrival time of the FPGA output-pin data relative to the downstream device's clock edge.

3.1 Basic syntax

# Max delay: external device Tsu
set_output_delay -clock sys_clk -max 2.0 [get_ports led_user_o]

# Min delay: external device Th (-min must not be negative)
set_output_delay -clock sys_clk -min -0.5 [get_ports led_user_o]

Meaning: - -max 2.0 (ns): the downstream device needs the data to arrive within 2 ns after the clock edge (to satisfy its Tsu) - The STA tool computes: Required time = sys_clk period + Tco + output max delay - That is: setup slack = (Period + 2 − Tco − output_delay) − (Tco + Tlogic + Tnet + T_output_buf)

3.2 -add_delay and -reference_pin

# Specify a reference pin (a reference that is not a clock port)
set_output_delay -reference_pin [get_ports clk_o] -max 1.5 [get_ports data_o*]

4. Source-synchronous interfaces

Definition: clock and data are emitted by the external chip at the same time (typical: DDR, RGMII, high-speed SPI modes)

4.1 DDR3 interface (AN 042 + DDR3 controller)

The DDR3 controller is an Efinity hard IP and its constraints are usually auto-generated. Manual case:

# DDR3 clock: 400 MHz (DDR CK 800 MHz data rate)
create_clock -period 2.5 -name ddr_ck [get_ports ddr_ck_t]

# DDR DQ input delay (DDR mode: rising + falling edges)
set_input_delay -clock ddr_ck -max 0.4 [get_ports ddr_dq[*]]
set_input_delay -clock ddr_ck -min -0.4 [get_ports ddr_dq[*]]
set_input_delay -clock ddr_ck -clock_fall -max 0.4 [get_ports ddr_dq[*]]
set_input_delay -clock ddr_ck -clock_fall -min -0.4 [get_ports ddr_dq[*]]

# DDR DQ output delay
set_output_delay -clock ddr_ck -max 0.4 [get_ports ddr_dq[*]]
set_output_delay -clock ddr_ck -min -0.4 [get_ports ddr_dq[*]]

Source: AN 042 + DDR3 Soft Controller Core User Guide v1.6 §A4.5

DDR PHY hard block (Titanium):

# Titanium DDR PHY: max 3,300 Mbps
# CLKOUT4 drives controller at 1/4 PHY data rate
create_generated_clock -name ddr_ckout4 \
    -source [get_pins {ddr_phy/clk}] \
    -divide_by 4 \
    [get_pins {ddr_phy/clkout4}]

Source: Titanium DDR DRAM Block User Guide v2.6 §A4.6

4.2 RGMII interface (AN 043)

RGMII is a source-synchronous DDR interface whose clock and data are center-aligned—the clock edge sits in the middle of the data eye.

# RGMII TX clock 125 MHz (PLL output)
create_generated_clock -name rgmii_tx_clk \
    -source [get_pins {pll_rgmii/clkin}] \
    -multiply_by 5 -divide_by 4 \
    [get_pins {pll_rgmii/clkout}]

# TX data: DDR mode, use -clock_fall
set_output_delay -clock rgmii_tx_clk -max 0.5 [get_ports rgmii_txd[*]]
set_output_delay -clock rgmii_tx_clk -min 1.0 [get_ports rgmii_txd[*]]
set_output_delay -clock rgmii_tx_clk -max 0.5 -clock_fall [get_ports rgmii_txd[*]]
set_output_delay -clock rgmii_tx_clk -min 1.0 -clock_fall [get_ports rgmii_txd[*]]

# RX data: input from the PHY
create_clock -period 8.0 -name rgmii_rx_clk [get_ports rgmii_rx_clk_i]
set_input_delay -clock rgmii_rx_clk -max 0.5 [get_ports rgmii_rxd[*]]
set_input_delay -clock rgmii_rx_clk -min 1.0 [get_ports rgmii_rxd[*]]
set_input_delay -clock rgmii_rx_clk -clock_fall -max 0.5 [get_ports rgmii_rxd[*]]
set_input_delay -clock rgmii_rx_clk -clock_fall -min 1.0 [get_ports rgmii_rxd[*]]

Source: AN 043 v1.3 §"RGMII Dynamic Clock Switch" ([A4.2])

4.3 SPI interface (simple source-synchronous)

# SPI clock 50 MHz
create_clock -period 20.0 -name spi_clk [get_ports spi_sck_i]

# SPI MOSI/MISO synchronous constraints
set_input_delay -clock spi_clk -max 5.0 [get_ports spi_miso_i]
set_input_delay -clock spi_clk -min 2.0 [get_ports spi_miso_i]
set_output_delay -clock spi_clk -max 4.0 [get_ports spi_mosi_o]
set_output_delay -clock spi_clk -min 0.0 [get_ports spi_mosi_o]

5. System-synchronous interfaces

Definition: the FPGA and the external device share the same clock bus (typical: asynchronous SRAM, parallel DAC, bus interfaces)

5.1 Asynchronous SRAM interface

# System clock 100 MHz
create_clock -period 10.0 -name sys_clk [get_ports clk_100m]

# SRAM input (address + data + control)
set_input_delay -clock sys_clk -max 6.0 [get_ports sram_data_io*]
set_input_delay -clock sys_clk -min 1.0 [get_ports sram_data_io*]

# SRAM output
set_output_delay -clock sys_clk -max 5.0 [get_ports sram_data_io*]
set_output_delay -clock sys_clk -min 0.0 [get_ports sram_data_io*]
set_output_delay -clock sys_clk -max 5.0 [get_ports {sram_addr[*] sram_oe_n sram_we_n sram_cs_n}]

5.2 Bus interfaces (wishbone / AXI / APB)

# Common-source clock
create_clock -period 10.0 -name sys_clk [get_ports clk_i]

# Input
set_input_delay -clock sys_clk -max 4.0 [get_ports {bus_data_i[*] bus_ack_i bus_err_i bus_rty_i}]
set_input_delay -clock sys_clk -min 1.0 [get_ports {bus_data_i[*] bus_ack_i bus_err_i bus_rty_i}]

# Output
set_output_delay -clock sys_clk -max 3.0 [get_ports {bus_data_o[*] bus_adr_o[*] bus_we_o bus_sel_o[*] bus_cyc_o bus_stb_o}]
set_output_delay -clock sys_clk -min 0.0 [get_ports {bus_data_o[*] bus_adr_o[*] bus_we_o bus_sel_o[*] bus_cyc_o bus_stb_o}]

6. FPGA pin Tsu / Th

FPGA pin Tsu/Th: the intrinsic setup/hold requirements of the FPGA's internal IO cell (independent of the PCB). Provided in the FPGA datasheet.

"The Setup time (t_su) is the time required for the input to be stable before a clock edge." "The Hold time (t_h) is the minimum amount of time required for the input to be stable after the clock edge." —— Source: [B4] MPI Lesson 11

Typical FPGA Tsu/Th:

Process Tsu Th
7nm ASIC 45 ps 35 ps
Modern FPGA (typical) 180 ps 120 ps

Source: [B5] arXiv 2510.26985

Efinity Trion/Titanium: see the specific device datasheet (TJ180A484S etc.):

Tsu (input setup to global clock) = ~0.6 ns (typical)
Th  (input hold from global clock) = ~0.1 ns (typical)

The PnR tool uses the concrete values automatically during STA. See the corresponding device datasheet.

7. Efinity GPIO Clock Latency

Efinity GPIO as a clock input: the clock latency needs dedicated constraints.

Source: C:\Efinity\2026.1\doc\topics\tim-clock-latency-gpio.html ([A3])

7.1 The three segments of clock latency

Segment Start End Source
Board-level delay external clock source FPGA pin set_clock_latency -source
GCLK network delay FPGA pin (as GCLK) global clock tree inferred automatically by the tool
PLL compensation delay PLL input PLL output applied automatically by Efinity

7.2 Complete example

# Board-level clock latency: crystal → FPGA pin
set_clock_latency -source -early 1.0 [get_clocks sys_clk]
set_clock_latency -source -late  3.0 [get_clocks sys_clk]

# GCLK network latency (usually inferred by the tool; no manual setting needed)
# set_clock_latency -early 0.5 [get_clocks sys_clk]
# set_clock_latency -late  1.0 [get_clocks sys_clk]

See fpga-clock-constraints-cookbook.md §5 and AN 042.

8. SDR vs DDR timing

8.1 SDR (Single Data Rate)

Characteristic: 1 bit of data per clock cycle.

# Rising-edge sampling: the default
set_input_delay -clock sys_clk -max 4.0 [get_ports sdr_data_i*]
set_input_delay -clock sys_clk -min 1.0 [get_ports sdr_data_i*]

8.2 DDR (Double Data Rate)

Characteristic: 2 bits of data per clock cycle (sampled on both the rising and falling edges).

# DDR input: sampled on both rising and falling edges
set_input_delay -clock ddr_clk -max 1.5 [get_ports ddr_dq[*]]
set_input_delay -clock ddr_clk -min 0.0 [get_ports ddr_dq[*]]
set_input_delay -clock ddr_clk -clock_fall -max 1.5 [get_ports ddr_dq[*]]
set_input_delay -clock ddr_clk -clock_fall -min 0.0 [get_ports ddr_dq[*]]

8.3 Center-aligned vs edge-aligned

Alignment Typical interfaces set_input_delay meaning
Edge-aligned SPI, async SRAM data and clock arrive at the same time
Center-aligned DDR, RGMII the clock sits in the middle of the data eye

Edge-aligned: set_input_delay -max ≈ the data valid window Center-aligned: set_input_delay -max ≈ (period/2 − setup margin)

8.4 Edge-aligned compensation example (DDR write leveling)

# The DDR PHY handles write leveling automatically; users need no manual compensation
# Adjust manually only if PHY calibration fails:
set_output_delay -clock ddr_ck -max 0.5 [get_ports ddr_dq[*]]
set_output_delay -clock ddr_ck -min 0.0 [get_ports ddr_dq[*]]

9. Complete Efinity IO SDC example

9.1 Integrated system: DDR3 + RGMII + SPI + GPIO

# ============================================
# Clock definitions
# ============================================
create_clock -period 10.0 -name sys_clk [get_ports clk_100m]      # 100 MHz main clock
create_generated_clock -name vid_clk -multiply_by 37 -divide_by 25 \
    -source [get_pins {pll_video/clkin}] [get_pins {pll_video/clkout}]   # 148.5 MHz
create_generated_clock -name ddr_ck -multiply_by 4 -divide_by 1 \
    -source [get_pins {pll_ddr/clkin}] [get_pins {pll_ddr/clkout}]       # 400 MHz DDR
create_clock -period 8.0 -name rgmii_rx_clk [get_ports rgmii_rx_clk_i]   # 125 MHz
create_clock -period 20.0 -name spi_sck_i [get_ports spi_sck_i]          # 50 MHz SPI

# ============================================
# Uncertainty
# ============================================
set_clock_uncertainty -to sys_clk -setup 0.100
set_clock_uncertainty -to sys_clk -hold  0.020

# ============================================
# Asynchronous grouping (video + DDR isolated from the main system)
# ============================================
set_clock_groups -asynchronous \
    -group {sys_clk spi_sck_i rgmii_rx_clk} \
    -group {vid_clk ddr_ck}

# ============================================
# DDR3 controller (hard block auto-constrained; a few manual entries)
# ============================================
# The hard-block PHY usually auto-generates set_input_delay
set_input_delay -clock ddr_ck -max 0.4 [get_ports ddr_dq[*]]
set_input_delay -clock ddr_ck -min -0.4 [get_ports ddr_dq[*]]
set_input_delay -clock ddr_ck -clock_fall -max 0.4 [get_ports ddr_dq[*]]
set_input_delay -clock ddr_ck -clock_fall -min -0.4 [get_ports ddr_dq[*]]

# ============================================
# RGMII TX (center-aligned DDR output)
# ============================================
create_generated_clock -name rgmii_tx_clk -multiply_by 5 -divide_by 4 \
    -source [get_pins {pll_rgmii/clkin}] [get_pins {pll_rgmii/clkout}]
set_output_delay -clock rgmii_tx_clk -max 0.5 [get_ports rgmii_txd[*]]
set_output_delay -clock rgmii_tx_clk -min 1.0 [get_ports rgmii_txd[*]]
set_output_delay -clock rgmii_tx_clk -clock_fall -max 0.5 [get_ports rgmii_txd[*]]
set_output_delay -clock rgmii_tx_clk -clock_fall -min 1.0 [get_ports rgmii_txd[*]]

# RGMII RX (center-aligned DDR input)
set_input_delay -clock rgmii_rx_clk -max 0.5 [get_ports rgmii_rxd[*]]
set_input_delay -clock rgmii_rx_clk -min 1.0 [get_ports rgmii_rxd[*]]
set_input_delay -clock rgmii_rx_clk -clock_fall -max 0.5 [get_ports rgmii_rxd[*]]
set_input_delay -clock rgmii_rx_clk -clock_fall -min 1.0 [get_ports rgmii_rxd[*]]

# ============================================
# SPI input (external SPI Flash)
# ============================================
set_input_delay -clock spi_sck_i -max 5.0 [get_ports spi_miso_i]
set_input_delay -clock spi_sck_i -min 1.0 [get_ports spi_miso_i]
set_output_delay -clock spi_sck_i -max 4.0 [get_ports spi_mosi_o]
set_output_delay -clock spi_sck_i -min 0.0 [get_ports spi_mosi_o]
set_output_delay -clock spi_sck_i -max 4.0 [get_ports spi_csn_o]

# ============================================
# GPIO (buttons + LEDs)
# ============================================
# Button input (asynchronous, synchronized in the sys_clk domain)
set_input_delay -clock sys_clk -max 8.0 [get_ports btn_i*]
set_input_delay -clock sys_clk -min 2.0 [get_ports btn_i*]

# LED output
set_output_delay -clock sys_clk -max 4.0 [get_ports led_o*]
set_output_delay -clock sys_clk -min 0.0 [get_ports led_o*]

# ============================================
# Asynchronous reset / JTAG / test
# ============================================
set_false_path -from [get_ports arst_n]
set_false_path -from [get_ports {tck tms tdi}]
set_false_path -to   [get_ports tdo]

9.2 AN 043 real-world RGMII PHY mode

# RGMII 2.5 / 25 / 125 MHz dynamic switching (Titanium only)
create_generated_clock -name rgmii_tx_125 -multiply_by 5 -divide_by 4 \
    -source [get_pins {pll_rgmii/clkin}] [get_pins {pll_rgmii/clkout}]
create_generated_clock -name rgmii_tx_25 -multiply_by 1 -divide_by 4 \
    -source [get_pins {pll_rgmii/clkin}] [get_pins {pll_rgmii/clkout}] -add
create_generated_clock -name rgmii_tx_2p5 -multiply_by 1 -divide_by 40 \
    -source [get_pins {pll_rgmii/clkin}] [get_pins {pll_rgmii/clkout}] -add

# Pick one of the three
set_clock_groups -exclusive \
    -group {rgmii_tx_125} \
    -group {rgmii_tx_25} \
    -group {rgmii_tx_2p5}

Source: AN 043 v1.3 ([A4.2])
