Efinity Generic Simulation Flow

Efinity Generic Simulation Flow

Version: v1.0 | Based on Efinity 2026.1 (sim_models / efx_run / efx_map / efx_pnr)

1. Simulation flow overview

The Efinity toolchain provides simulation flows at four levels, from pure RTL to the final timing-annotated gate-level netlist:

Flow efx_run --flow Simulation level Timing annotation Applicable stage
RTL simulation rtlsim Behavioral None Functional verification
Post-synthesis simulation mapsim Gate-level (post-synthesis) None Synthesis correctness verification
Post-P&R simulation pnrsim Gate-level (post-place-and-route) SDF Timing verification
PT-level RTL simulation ptsimrtl Behavioral (PT timing) efx_sta Interface timing verification
PT-level full-chip simulation ptsimfc Full-chip (PT timing) efx_sta System-level timing verification

Relationship between the full compile flow and simulation:

map → PT(interface) → pnr → pgm
                   ↑ pnrsim becomes available after this point
       ↑ mapsim becomes available after this point
 ↑ rtlsim runs without any compile

Source: efx_run --help — --flow option; C:\Efinity\2026.1\scripts\efx_run.py

2. Simulation libraries

2.1 Library directory layout

The Efinity simulation models live under C:\Efinity\2026.1\sim_models\:

C:\Efinity\2026.1\sim_models\
├── maplib/                              — synthesis libraries (pure Verilog, general simulation)
│   ├── efinix_maplib.v                  — primitive mapping library
│   ├── efinix_peri_lib.v                — peripheral library
│   ├── efxlib_maplib.vdb                — Aldec compiled library
│   └── *.vdb                            — other compiled VDB files
├── verilog/                             — gate-level primitive Verilog models
│   ├── efx_add.v, efx_comb4.v           — arithmetic/combinational primitives
│   ├── efx_dpram10.v, efx_dpram_5k.v    — dual-port Block RAM primitives
│   ├── efx_dsp12.v, efx_dsp24.v, efx_dsp48.v — DSP primitives
│   ├── efx_ff.v, efx_gbufce.v, efx_lut4.v, efx_mult.v
│   ├── efx_ram10.v, efx_ram_10k.v, efx_ram_5k.v, efx_srl8.v
└── vhdl/packages/                       — VHDL simulation packages

Source: C:\Efinity\2026.1\sim_models\ directory structure

2.2 Library initialization (setup_efxlib)

efx_run --flow setup_efxlib compiles the Efinity simulation libraries for third-party simulators:

  • Compiles both the Verilog and VHDL libraries
  • The target simulator is selected via --modelsim (ModelSim/QuestaSim), --aldec (Active-HDL/Riviera-PRO), or --ncsim (Cadence)
# Compile libraries for ModelSim
efx_run.bat --flow setup_efxlib --modelsim

# Compile libraries for Aldec
efx_run.bat --flow setup_efxlib --aldec

Source: efx_run --help — --flow setup_efxlib; efx_run.py lines 178–233

2.3 Open-source simulator (iverilog)

iverilog can use the maplib/*.v files directly, with no VDB compilation required:

  • Add efinix_maplib.v and efinix_peri_lib.v to the source file list
  • Suitable for RTL simulation (rtlsim) and basic gate-level simulation

Source: C:\Efinity\2026.1\sim_models\maplib\ contains pure-Verilog libraries (.v files) — directly usable by iverilog

2.4 Aldec compiled libraries (VDB)

The .vdb files in maplib/ are precompiled binary libraries dedicated to the Aldec Riviera-PRO / Active-HDL simulators:

  • efxlib_maplib.vdb — the main mapping library
  • Other *.vdb — auxiliary libraries

Source: C:\Efinity\2026.1\sim_models\maplib\ contains .vdb files

3. RTL simulation (rtlsim)

RTL simulation verifies design functionality at the behavioral level, with no synthesis or place-and-route required.

# Basic RTL simulation
efx_run.bat my_design --flow rtlsim --tb <testbench_top.v> --tb_top <tb_module_name>

# Select the simulator
efx_run.bat my_design --flow rtlsim --tb tb_top.v --tb_top tb_top --modelsim
efx_run.bat my_design --flow rtlsim --tb tb_top.v --tb_top tb_top --aldec
efx_run.bat my_design --flow rtlsim --tb tb_top.v --tb_top tb_top --ncsim

Key parameters:

Parameter Description
--tb arg Path to the simulation-only testbench file
--tb_top arg Top-level testbench module name
--modelsim Use ModelSim / QuestaSim
--aldec Use Aldec Active-HDL / Riviera-PRO
--ncsim Use Cadence
--sim_opts arg Extra options passed straight to the simulator

Source: efx_run --help — simulation-related parameters

4. Post-synthesis simulation (mapsim)

mapsim runs simulation on the post-synthesis gate-level netlist, verifying that the logic produced by the synthesis tool is correct.

4.1 Generating the post-synthesis netlist

Output options provided by efx_map:

Parameter Description
--write-efx-verilog arg Write the post-synthesis Verilog netlist (used by mapsim)
--binary-db arg Write the mapped netlist as a Verific binary DB

Source: efx_map --help

4.2 Running mapsim

# First synthesize and write the netlist
efx_run.bat my_design --flow map --map_opts write-efx-verilog=post_synth.v

# Then run mapsim
efx_run.bat my_design --flow mapsim --tb tb_top.v --tb_top tb_top

mapsim uses the gate-level primitive models (the efx_*.v files in sim_models/verilog/) as the simulation backend.

Source: efx_run --help — --flow mapsim; efx_map --help — --write-efx-verilog; C:\Efinity\2026.1\sim_models\verilog\

5. Post-P&R simulation (pnrsim)

pnrsim runs simulation on the post-place-and-route netlist with SDF timing annotation (Standard Delay Format annotation) — the simulation level closest to real hardware.

5.1 The role of SDC constraints

The SDC constraint file used by efx_pnr determines the precision of timing analysis:

Parameter Description
--sdc_file SDC constraint file (SDF annotation in pnrsim is based on it)
--sdc_filelist Multi-file SDC list
--unified_sdc_file Unified timing-analysis SDC
--unified_sdc_filelist Unified SDC file list
--print_critical_path N Print the N most critical paths (default 10)

Source: efx_pnr --help and --help-verbose

5.2 Running pnrsim

# compile or pnr must be completed first
efx_run.bat my_design --flow compile

# Then run pnrsim
efx_run.bat my_design --flow pnrsim --tb tb_top.v --tb_top tb_top
  • pnrsim uses the netlist output by P&R plus the SDF delay file
  • The simulation models are the gate-level primitives in sim_models/verilog/
  • It reflects real place-and-route delays, clock skew, and setup/hold times

Source: efx_run --help — --flow pnrsim

6. PT-level simulation (ptsimrtl / ptsimfc)

PT-level simulation uses the Interface Designer's timing models (efx_sta) to add interface-level timing annotation to simulation; it is suited to verifying inter-module interface timing.

6.1 ptsimrtl (PT-level RTL simulation)

Uses efx_sta timing data + RTL behavioral models:

efx_run.bat my_design --flow ptsimrtl --tb tb_top.v --tb_top tb_top

6.2 ptsimfc (PT-level full-chip simulation)

Full-chip gate-level simulation + efx_sta timing:

efx_run.bat my_design --flow ptsimfc --tb tb_top.v --tb_top tb_top

Source: efx_run --help — --flow ptsimrtl and --flow ptsimfc

# Pass extra options to the simulator

            │  Write RTL    │
            └──────┬───────┘
                   │
                   ▼
         ┌─────────────────┐

         └────────┬─────────┘

         │  map (synthesis) │
         └────────┬─────────┘
                  │

         ┌─────────────────┐

         └─────────────────┘

Quick decision table:

Need Recommended flow
Fast functional verification rtlsim
Verify synthesis did not break the logic mapsim
Suspected timing problems pnrsim
Multi-module interface timing verification ptsimrtl / ptsimfc

9. Integration with the EvoVerse SDK

9.1 Simulation support in the SDK

The EvoVerse SDK selects the simulation flow through efx_run's --flow parameter:

# The SDK forwards simulation commands through buildRunner.ts
efx_run.bat <project> --flow rtlsim --tb <tb_file> --tb_top <tb_module> --aldec

The SDK does not implement a simulation engine itself; it schedules third-party simulators through efx_run.

Source: EvoVerse SDK buildRunner.ts — efx_run invocation pattern

9.2 Recommended workflow

  1. Development stage: iterate quickly with rtlsim for functional verification
  2. After synthesis: verify primitive-mapping correctness with mapsim
  3. After place-and-route: verify timing closure with pnrsim
  4. Before board bring-up: confirm pnrsim passes, then run pgm to program the board
