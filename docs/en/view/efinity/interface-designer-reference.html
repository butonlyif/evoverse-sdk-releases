Interface Designer Reference

Efinity Interface Designer Reference

Version: v1.0 | Based on Efinity 2026.1 (UG-TiINTF-v1.0)

1. Overview

Efinity Interface Designer is the GUI tool inside the Efinity software for building the FPGA periphery. It is independent of the core logic design and focuses on configuring GPIO, LVDS, PLL, MIPI, DDR, and other hardware blocks.

Positioning: - Efinity main window → design the core logic - Interface Designer → design the peripheral interfaces

How to launch:

efinity_pt.bat        # Windows
efinity_pt.sh         # Linux

Source: C:\Efinity\2026.1\pt\doc\topics\hlp-id-intro.html

2. Architecture

Interface Designer is built on a Python plugin architecture:

pt/
├── bin/
│   ├── api_service/      # API service layer (design, device, resources)
│   ├── common_device/     # Common device logic (GPIO, Quad, properties, rules)
│   ├── common_gui/        # Common GUI components (builder, validator, viewer)
│   ├── design/            # Design database (db.py, db_item.py, service.py)
│   ├── device/            # Device database (clocks, io_info, package, service.py)
│   ├── main_gui/          # Main window GUI
│   ├── res_asg/           # Resource assigner
│   ├── pin_browser/       # Pin browser
│   ├── pkg_gui/           # Package planner
│   ├── schema/            # XML Schema definitions (40+ XSD files)
│   ├── writer/            # Output file generators (pinout, timing, periphery)
│   ├── efx_run_pt_*.py    # CLI entry scripts
│   └── engine.py          # Core engine
├── db/
│   ├── die/               # Die definitions (block_models/*.xml)
│   └── resource/          # Device resource database (.db files)
└── config.ini             # Configuration file

4. GUI Workflow

4.1 Designing an interface

  1. Select the device and package
  2. Create interface blocks (Create Block → choose the type)
  3. Configure block parameters (PLL frequency, GPIO direction, etc.)
  4. Assign pins (Resource Assigner or Package Planner)
  5. Run the design check (Design Check)
  6. Generate constraint files (Generate Constraint Files)

4.2 Resource Assigner

  • Resource View: inspect all assigned resources
  • Import/Export: import and export GPIO assignments (CSV format or ISF format)
  • GPIO CSV: bulk GPIO configuration

4.3 Package Planner

  • Visual chip package pin map
  • Drag-and-drop pin assignment
  • Filter by bank
  • Exclude specific pins/banks
  • Light/dark themes supported

6. ISF (Interface Scripting File) vs GUI

6.1 The GUI way (Interface Designer)

  • Graphical operation, suited to interactive design
  • What you see is what you get
  • Suited to designs with small to medium pin counts
  • Drag-and-drop pin assignment supported

6.2 The ISF scripting way

  • A Python script describes the interface configuration
  • Suited to bulk operations (large numbers of GPIOs)
  • Suited to design reuse and porting across boards
  • Version-control friendly (text files)
  • Can be exported → modified → re-imported

ISF format example:

# Efinity Interface Configuration
# Version: 2020.M.138

# Create GPIO instances
design.create_output_gpio("Fled", 3, 0)
design.create_inout_gpio("Sled", 3, 0)
design.create_clockout_gpio("Oclk_out")
design.create_pll_input_clock_gpio("pll_clkin")
design.create_global_control_gpio("resetn")

# Set properties
design.set_property("Fled", "OUT_REG", "REG")
design.set_property("Fled", "OUT_CLK_PIN", "Fclk")

# Resource assignment
design.assign_pkg_pin("Fled[0]", "J2")
design.assign_pkg_pin("pll_clkin", "C3")
design.assign_pkg_pin("resetn", "F1")

How ISF relates to the unified flow: - The ISF file is executed in the PT (Interface Designer) step of the unified compile flow - The Python code is executed line by line via exec(), with the design object injected by the framework - See Efinity ISF Syntax Reference for details

11. Relationship to the Unified Compile Flow

In the Efinity unified compile flow (efx_run --flow compile):

RTL Design → Interface Designer (PT) → Synthesis → P&R → Bitstream

During the Interface Designer stage: 1. Read the device/package information from the project XML 2. Load the ISF file (if specified) 3. Validate the interface configuration 4. Generate constraint files (.sdc, .csv, _template.v) 5. Generate the I/O configuration file
