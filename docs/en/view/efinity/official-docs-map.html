5. EFX_FF single-SR-pin evidence chain

Conclusion first: the Efinix flip-flop (EFX_FF) has only one SR (set/reset) pin; there is no independently encodable separate set and reset. This corroborates the hard constraint in the workspace RTL rules that "a register must not encode both set and reset". The four independent pieces of evidence below agree completely.

5.1 Evidence 1: the maplib source (the synthesis backend truth)

Evidence: C:\Efinity\2026.1\sim_models\maplib\efinix_maplib.v

module EFX_FF(Q, D, CE, CLK, SR);   // line 21: the port list has a single SR
Line Content Meaning
16-18 SR_SYNC_PRIORITY macro defaults to 1 SR wins when SR and CE conflict in the same cycle
21 module EFX_FF(Q, D, CE, CLK, SR); A single SR port, no independent SET/RST
27 comment // 0 CE, 1 SR priority arbitration table: CE=0, SR=1

5.2 Evidence 2: the official synthesis document's port table

Evidence: C:\Efinity\2026.1\doc\topics\syn-ff.html (UG-EFN-SOFTWARE-v14.0)

Line Content

5.5 Evidence chain summary and engineering implications

# Evidence Layer Key point
1 efinix_maplib.v line 21 Backend maplib source The port list physically has a single SR
2 syn-ff.html lines 213-215 Official synthesis document SR = asynchronous/synchronous set/reset (either-or configuration)
3 efx_ff.v line 31 Simulation behavioral model The behavioral model matches the port list
4 efn-simulating-models.html lines 243-249 Official model master table Original description uses the singular "Set/Reset Pin"

Engineering implications:

  1. RTL that encodes both set and reset forces the synthesizer to emulate the second control signal with extra LUTs → area bloat + timing degradation (the counter-example in the workspace RTL rules stems from this hardware fact);
  2. SR polarity/synchronicity is configured via ISF/synthesis attributes (SR_SYNC, SR_VALUE), not by adding another pin;
  3. When writing RTL, each register should have only a single reset (or single set) path; see Efinity Design Rules and the repository RTL coding rules.
