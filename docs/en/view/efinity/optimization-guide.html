Efinity Optimization Strategies

Efinity Optimization Strategies Reference

Compiled from Efinity 2026.1 native tool parameters and official documentation. Sources: efx_map --help, efx_pnr --help/--help-verbose, efx_pgm --help, and the official PDF documentation.

1. Synthesis optimization (efx_map)

1.1 Optimization modes (--mode)

Mode Description Applicable scenario
speed (default) fMAX priority Timing-critical designs
speed2 Enhanced speed mode More aggressive speed optimization than speed
area Area optimization Designs close to resource limits
area2 Enhanced area mode (large MUX/selector-tree optimization) Designs dense with large multiplexers
cong Congestion relief Designs with severe routing congestion
power Power priority Low-power scenarios

1.2 Retiming (--retiming)

Value Effect
0 Disabled
1 Enabled — moves registers across combinational logic to balance path delays
2 (default) Advanced mode — more aggressive than mode 1; recommended for Titanium

Limitation: it can only redistribute existing registers; it cannot create new ones. Applicable to combinational paths whose pipelining is not deep enough.

1.3 Sequential optimization (--seq_opt)

Value Effect
0 Disabled
1 (default) Enabled — optimizes the synthesis result of sequential logic
--seq-opt-sync-only Optimizes only synchronous set/reset logic

1.4 DSP optimization

Parameter Default Description
--dsp-input-regs-packing 1 (on) DSP input register packing (Titanium)
--dsp-output-regs-packing 1 (on) DSP output register packing (Titanium)
--dsp-mac-packing 1 (on) DSP multiply-accumulate (MAC) packing (Titanium)
--mult-decomp-retime 1 (on) Wide-multiplier decomposition followed by retiming
--mult-auto-pipeline 0 (off) Automatic pipelining of wide multipliers (sets the stage count, 0-36)
--max_mult -1 (unlimited) Limits the number of DSPs/multipliers

1.5 BRAM optimization

Parameter Default Description
--bram_output_regs_packing 1 (on) BRAM output register packing
--bram-push-tco-outreg 0 (off) Pushes out the BRAM Tco output register
--max_ram -1 (unlimited) Limits the number of Block RAMs
--ram-decomp-mode 0 RAM decomposition mode (0=speed, 1=area, 2=power)
--use-logic-for-small-mem 64 Memories smaller than this number of bits are implemented in LEs
--use-logic-for-small-rom 64 ROMs smaller than this number of bits are implemented in LEs
--max-bit-blast-mem-size 10240 Maximum memory bits to be blown out into logic

1.6 Logic optimization

Parameter Default Description
--infer-clk-enable 3 Clock-enable inference effort level (0=disabled, 1-4 increasing effort)
--infer-sync-set-reset 1 (on) Infers synchronous set/reset signals onto FFs
--fanout-limit 0 (unlimited) Fanout cap (0=unlimited, 1-2000)
--min-ce-fanout 0 Minimum fanout for FF CE inference
--min-sr-fanout 0 Minimum fanout for SR inference
--operator-sharing 0 (off) Resource sharing of arithmetic operators and MUXes
--optimize-adder-tree 0 (off) Optimizes skewed adder trees
--insert-carry-skip 0 (off) Carry-skip chain optimization (Titanium)
--blast_const_operand_adders 1 (on) Blows apart constant-operand adders
--pack-luts-to-comb4 0 (off) Packs LUTs into COMB4 primitives (Titanium, effort levels 0/1/2)
--create-onehot-fsms 0 (off) Creates one-hot encoded finite state machines

1.7 Compilation control

Parameter Default Description
--hdl-compile-unit 1 (single file) SystemVerilog compilation-unit mode (0=multiple files, 1=single file)
--hdl-loop-limit 20000 HDL loop unrolling limit
--max_threads -1 (automatic) Number of parallel threads

2. P&R optimization (efx_pnr)

2.1 Optimization levels (--optimization_level)

Level Direction Description
TIMING_1 Timing Basic timing optimization
TIMING_2 Timing Medium timing optimization
TIMING_3 Timing Aggressive timing optimization
CONGESTION_1 Congestion Light congestion relief
CONGESTION_2 Congestion Medium congestion relief
CONGESTION_3 Congestion Aggressive congestion relief
POWER_1 Power Basic power optimization
POWER_2 Power Aggressive power optimization

Tip: an empty string "" means the tool's default strategy is used.

2.2 Placement options

Parameter Default Description
--placer_effort_level 2 Placement effort level (1=fastest, 5=highest quality)
--seed 1 Placement random seed

Placer effort level impact: - 1-2: fast placement, suitable for iterative development - 3-4: medium quality, suitable for timing closure - 5: highest quality, with a significant (2-3×) compile-time increase

2.3 Seed sweep

Different --seed values produce different placement results and have a significant impact on timing.

# Automatic seed sweep (iterates over 10 seeds)
efx_run_pnr_sweep.bat <prj_xml> sweep_seeds --num_seeds 10

# Iterate over optimization-level combinations
efx_run_pnr_sweep.bat <prj_xml> sweep_opt_levels

2.4 Beneficial skew (--beneficial_skew)

Value Effect
on (default, Titanium) Uses clock skew to improve setup timing
off Disabled

Cautions: - May introduce hold violations that require extra hold fixing - Applicable to the Titanium device family - If you hit hold problems, consider turning this option off

2.5 Packing options

Parameter Description
--packing_level Packing degree: NONE, MINIMAL, BASIC, L1 (default), L2, L3
--physical_packing DSP physical packing (based on early placement results, on/off)

2.6 Routing options

Parameter Description
--max_router_iterations Maximum number of routing iterations
--load_route Load an existing routing file (incremental routing)

3. Bitstream optimization (efx_pgm)

3.1 Configuration performance

Parameter Default Description
--oscillator_clock_divider DIV8 SPI programming clock divider (DIV8→DIV4→DIV2→DIV1 for speedup)
--width 1 Configuration width (x1/x2/x4/x8/x16/x32; higher is faster)
--bitstream_compression on Bitstream compression (smaller storage, but may increase configuration time)
--spi_low_power_mode on Flash low-power mode after programming

3.2 Reliability

Parameter Description
--enable_crc_check CRC verification during programming
--enable_seu_crc_check SEU (single-event upset) detection in user mode
--seu_mode automatic or manual
--seu_enable_correction Enables automatic SEU correction (requires SEU CRC to be enabled first)
--seu_correction_mode Correction mode: manual, timer, monitor, autofix
--io_weak_pullup Weak IO pull-ups during configuration

4. Progressive timing-closure strategy

Level 1: no code changes (tool level)

  1. Turn on retiming (--retiming 2, on by default)
  2. Raise the placer effort level (--placer_effort_level 3-5)
  3. Run a seed sweep (try different random seeds)
  4. Try different optimization levels (--optimization_level TIMING_2/3)
  5. Try a different synthesis mode (--mode speed2)
  6. Use AOE to explore option combinations automatically:
efx_run_aoe.bat run -x <project.xml> -r regular.recipe

Level 2: constraint level (SDC changes)

  1. Add I/O delay constraints (set_input_delay / set_output_delay)
  2. Set multicycle paths (loosen unnecessarily strict constraints)
  3. Set clock groups (set_clock_groups -asynchronous)
  4. Set false paths (asynchronous resets, slow signals)
  5. Add max_delay / min_delay point-to-point constraints

Level 3: RTL level (code changes)

  1. Insert pipeline registers into long combinational paths
  2. Optimize the CDC (clock domain crossing) structure — use standard synchronizers
  3. Reduce fanout: duplicate drivers or use the max_fanout constraint
  4. Optimize state-machine encoding (one-hot vs. binary)
  5. Manually add pipelines to wide multipliers
  6. Use (* keep *) or (* dont_touch *) to protect critical registers

5. Titanium device optimization essentials

5.1 Architectural characteristics

  • LUT4 basic element: chains of ≥3 consecutive LUT combinational levels easily produce setup violations
  • DSP blocks: support MAC (multiply-accumulate) packing; input/output register packing is on by default
  • Clock network: beneficial_skew defaults to on

5.3 Titanium checklist when timing fails to close

  1. Check whether beneficial_skew introduced hold violations (try turning it off)
  2. Check for combinational paths of ≥3 consecutive LUT levels (insert a pipeline)
  3. Confirm active_capture_clk_edge is set to negedge (the Titanium-specific default)
  4. Confirm the Ti35/Ti60 devices are not using the deprecated I4/I4L timing models
  5. Check whether DSP packing was accidentally turned off (dsp-*-packing should be 1)
