PLL and Clock Design

Efinity PLL and Clock Design

Version: v1.0 Date updated: 2026-07-30 Applicable tools: Efinity 2026.1 (Titanium / Trion / Topaz families) Sources: Efinity ISF Syntax Reference (ISF Importer/Exporter source code), efx_pll_cfg IP documentation, efx_pll_autoreset IP source code, Efinity design rules, Efinity RTL coding style guide

Related documents: - isf-syntax-reference.md — ISF PLL creation and property-setting commands - design-rules.md — §2 PLL-lock merge rules in reset design - rtl-coding-style.md — §3 clock naming and clock-enable rules - ip-manager-guide.md — using PLL-related IPs in IP Manager

1. PLL architecture overview

The Efinity FPGA PLL (Phase-Locked Loop) is an analog hard macro built around a VCO (voltage-controlled oscillator); it generates the required frequencies from the reference clock through a feedback divider and output dividers.

Core parameter relationships: - FVCO = FIN × (Feedback Divider) — VCO frequency - FCLKOUTx = FVCO / CLKOUTx_DIV — frequency of each output channel

In Efinity the PLL is configured as a hard macro through the Interface Designer (ISF); it is not instantiated directly in RTL.

Source: ISF Syntax Reference §3.1 (BLOCK_TYPE list), where PLL is listed as a block type supported by all devices [isf-syntax-reference.md §3.1]

2. Configuring the PLL via ISF

2.1 Creating a PLL instance with create_block

Create the PLL block in the ISF with design.create_block():

design.create_block("my_pll", "PLL")

Source: ISF Syntax Reference §3 (block creation), C:\Efinity\2026.1\pt\bin\api_service\design.py (DesignAPI.create_block, line 192) [isf-syntax-reference.md §3]

2.2 PLL property settings

PLL properties are set through design.set_property("inst", "PROP_NAME", "value", "PLL"):

Property Description Example value
FIN Input reference clock frequency (MHz) "50"
CLKOUT0_EN Enable output channel 0 "TRUE" / "FALSE"
CLKOUT0_DIV Output channel 0 divide ratio "2" (VCO/2)
CLKOUT1_EN ~ CLKOUTx_EN Enable output channels 1..N "TRUE" / "FALSE"
CLKOUT1_DIV ~ CLKOUTx_DIV Output channels 1..N divide ratios "4", "8", etc.
CLKOUTx_PHASE Output channel phase shift (degrees) "90", "180"
BANDWIDTH PLL loop bandwidth "LOW", "MEDIUM", "HIGH"

Source: ISF Syntax Reference §4.2 (PLL property examples) [isf-syntax-reference.md §4.2]

2.3 Binding the PLL resource

design.assign_resource("my_pll", "PLL_R0", "PLL")

Source: ISF Syntax Reference §5.2 (assign_resource), C:\Efinity\2026.1\pt\bin\api_service\design.py (DesignAPI.assign_resource, line 790) [isf-syntax-reference.md §5.2]

2.4 Complete ISF PLL example

# === PLL: 50MHz → 100MHz (CLKOUT0) + 200MHz (CLKOUT1) ===
design.create_block("sys_pll", "PLL")
design.set_property("sys_pll", "FIN", "50", "PLL")
design.set_property("sys_pll", "CLKOUT0_EN", "TRUE", "PLL")
design.set_property("sys_pll", "CLKOUT0_DIV", "10", "PLL")     # 1000MHz/10 = 100MHz
design.set_property("sys_pll", "CLKOUT1_EN", "TRUE", "PLL")
design.set_property("sys_pll", "CLKOUT1_DIV", "5", "PLL")      # 1000MHz/5 = 200MHz
design.assign_resource("sys_pll", "PLL_R0", "PLL")

The PLL reference clock uses a dedicated GPIO created by create_pll_input_clock_gpio as the PLL clock source.

Source: ISF Syntax Reference §2.1 (create_pll_input_clock_gpio) [isf-syntax-reference.md §2.1]

3. Configuring the PLL via the Interface Designer GUI

In the Efinity GUI, the PLL can be configured graphically through the Interface Designer:

  1. Open the project, then go to Tools → Interface Designer
  2. In the left panel, right-click → Create Block → PLL
  3. Set FIN, per-channel divide ratios, phase, and other parameters in the property panel
  4. The GUI calculates and displays each channel's output frequency in real time
  5. Click Generate to generate the ISF and peri.xml

The Interface Designer-generated configuration is equivalent to a hand-written ISF. The generated ISF file lives under constraints/.

Source: ISF Syntax Reference §1 (ISF overview — the ISF lives in the PT step of the unified compile flow) [isf-syntax-reference.md §1]

4. PLL dynamic reconfiguration (efx_pll_cfg IP)

4.1 Feature overview

The efx_pll_cfg IP core switches PLL configurations dynamically while the FPGA is running, without recompiling the bitstream. Core features:

  • Stores and switches between up to 85 PLL configurations
  • Can restore the original PLL settings from the bitstream (PCR, Peripheral Configuration Register)
  • Two modes: Single Configuration and Multi Configuration

Source: C:\Efinity\2026.1\ipm\ip\efx_pll_cfg\ipm\doc\topics\pll-dyn-recfg-core-features.html (Features page)

5. PLL Autoreset (efx_pll_autoreset IP)

5.1 Feature overview

efx_pll_autoreset is the Trion PLL Auto-Reset IP core (Trion families only); it automatically fires a reset pulse when the PLL loses lock. Core features:

  • Checks the PLL lock status after a reset is triggered
  • Automatically issues a reset pulse on timeout
  • Supports 1–8 independent FSMs; each FSM can monitor one or more PLLs

Source: C:\Efinity\2026.1\ipm\ip\efx_pll_autoreset\ipm\doc\topics\pll-autoreset-core-features.html (Features page)

5.2 RTL parameters and ports

Parameters: | Parameter | Description | Range | |------|------|------| | N_FSM | Number of FSMs | 1–8, default 8 |

Ports: | Port | Direction | Width | Description | |------|------|------|------| | i_pll_rstn | input | N_FSM | External reset input per PLL (active low) | | i_pll_locked | input | N_FSM | Lock status input per PLL | | o_pll_rstn | output | N_FSM | Reset output per PLL (external reset merged with the internal auto reset) | | ro_clk | output | 1 | Internal oscillator clock output (used as the FSM clock) |

Source: C:\Efinity\2026.1\ipm\ip\efx_pll_autoreset\source\efx_pll_autoreset.v (module port and parameter declarations)

5.3 Internal architecture

The IP consists of the following submodules: - clk_gen — internal oscillator clock generation - EFX_GBUFCE — global clock buffer (with clock enable) - checker — lock checking and reset-pulse generation for each FSM - Synchronizers — the lock_filt / lock_sync two-stage filtering prevents metastability

Source: C:\Efinity\2026.1\ipm\ip\efx_pll_autoreset\source\efx_pll_autoreset.v (module implementation)

5.4 Parameter configuration

Parameter Options Default Description
FSM Count 1 ~ 8 2 Number of FSMs. Multiple PLLs can share one FSM (provided you do not care about the individual PLLs' start/stop ordering)

6. Clock tree planning

6.1 Global vs. regional clocks

The Efinity FPGA clock network divides into:

Type ISF GPIO type Description
Global Clock (GCLK) create_input_clock_gpio Global clock network, reaches the entire die
Regional Clock (RCLK) create_regional_input_clock_gpio Regional clock; supported only on Trion and above
PLL Clock Input create_pll_input_clock_gpio Dedicated PLL reference clock input
Clock Output create_clockout_gpio Clock output to a pin

Source: ISF Syntax Reference §2.1 (GPIO command table), C:\Efinity\2026.1\pt\bin\api_service\design.py [isf-syntax-reference.md §2.1]

6.2 Clock spines

Clocks in Efinity devices are distributed through clock spines. Each clock spine can drive the logic of one region. PLL outputs reach the target logic region through the global or regional clock network.

6.3 PLL connection in RTL

In RTL, the PLL output clocks are declared as top-level input ports:

// The PLL is configured as a hard macro through the Interface Designer and is not instantiated in RTL
// RTL declares only the clock ports output by the PLL and the lock signal
input  wire pll_clk_out,   // working clock output by the PLL
input  wire pll_locked,    // PLL lock indication

Source: Efinity RTL coding style guide §7.3 (PLL configuration) [rtl-coding-style.md §7.3]

7. Clock domain strategy

7.1 Synchronous clock domains

Different output channels of the same PLL (CLKOUT0, CLKOUT1, ...) are synchronous (same VCO source) and need no CDC handling.

7.2 Asynchronous clock domains (CDC)

The following are asynchronous clock domains and require CDC handling:

  • Between outputs of different PLL instances
  • Between an external standalone crystal clock and PLL outputs
  • Between multiple independent clock ports on the board

For CDC handling rules see Efinity design rules §3 [design-rules.md §3] and the Efinity RTL coding style guide §6 [rtl-coding-style.md §6].

7.3 SDC clock group declarations

# Asynchronous clock domains
set_clock_groups -asynchronous \
    -group [get_clocks clk_50m] \
    -group [get_clocks sys_clk] \
    -group [get_clocks video_clk]

Source: Efinity RTL coding style guide §9.2 (clock grouping) [rtl-coding-style.md §9.2]

8. Design Check clock rules

The Design Check of the Efinity PT (Interface Designer) stage includes the following clock-related rules. Violations abort the compile.

Rule Meaning Common cause and fix
clock_rule_capacity More clocks connected to one region than allowed Reduce the number of clock domains in that region, or spread the logic across more regions
clock_rule_max_count Core clock count exceeds the maximum (32) Merge unnecessary clock domains; use clock enables instead of divided clocks
clock_rule_lvds_rx_clock_source A PLL output clock drives LVDS Rx on a different side Ensure LVDS Rx on the same side uses the output clock of a PLL on that side
clock_rule_pll_ref_clock_lvds_rx The PLL reference clock and LVDS Rx are not on the same side Move the PLL reference clock source to the same side as the LVDS Rx
clock_rule_undefined_name A signal has no clock source defined Declare create_clock for every clock port in the SDC

Source: the Design Check clock rule table (clock_rule_*) provided with the task requirements

9. SSC (Spread-Spectrum Clocking) PLL

The spread-spectrum PLL (PLL_SSC) reduces EMI (electromagnetic interference). Create it in the ISF with create_block:

design.create_block("ssc_pll", "PLL_SSC")

PLL_SSC is an independent type in the BLOCK_TYPE list [isf-syntax-reference.md §3.1]. The specific SSC parameters (modulation frequency, spread range) are set with set_property; efinity-python-api.pdf is authoritative.

Source: ISF Syntax Reference §3.1 (BLOCK_TYPE list includes PLL_SSC), Efinity Design API Integration (designapi-integration.md) §version compatibility (properties follow efinity-python-api.pdf) [isf-syntax-reference.md §3.1]

10. Using the internal oscillator (OSC)

Efinity devices have a built-in internal oscillator (OSC) that can be created through the ISF:

design.create_block("my_osc", "OSC")

OSC is listed in the BLOCK_TYPE list as supported by all devices [isf-syntax-reference.md §3.1]. Typical OSC uses: - Power-on initial clock (transitional clock before the PLL locks) - Low-power standby clock - FSM clock source for efx_pll_autoreset (see §5)

Source: ISF Syntax Reference §3.1 (BLOCK_TYPE list includes OSC) [isf-syntax-reference.md §3.1]

11. Clock uncertainty budget

Use set_clock_uncertainty in the SDC to reserve jitter/skew margin for STA:

# Jitter budget for PLL output clocks (typically 0.150–0.300 ns)
set_clock_uncertainty 0.200 [get_clocks sys_clk]

# External crystal clock
set_clock_uncertainty 0.100 [get_clocks clk_50m]

Source: Efinity design rules §4.2 (set_clock_uncertainty 0.200 in the complete constraint template) [design-rules.md §4.2]

12. Integrating PLL lock with system reset

12.1 Merging PLL lock into reset

The PLL lock signal pll_locked must be merged with the external reset:

// Hold system reset while the PLL is unlocked
wire async_rst_n = rst_n_i & pll_locked;

Source: Efinity design rules §2.2 (merge with PLL lock) [design-rules.md §2.2]

12.2 Asynchronous reset, synchronous release

The merged reset must pass through a synchronized release chain:

// 3-stage synchronizer: asynchronous assertion, synchronous release
reg [2:0] rst_sync;
always @(posedge sys_clk or negedge async_rst_n) begin
    if (!async_rst_n)
        rst_sync <= 3'b000;
    else
        rst_sync <= {rst_sync[1:0], 1'b1};
end
wire rst_n = rst_sync[2];

Source: Efinity design rules §2.1 (asynchronous reset, synchronous release) [design-rules.md §2.1]

13. Clock naming and coding rules

13.1 Clock naming

Signal Naming Example
Input reference clock clk_<freq>m_i clk_50m_i, clk_100m_i
System working clock sys_clk sys_clk
Video/pixel clock <domain>_clk video_clk, pixel_clk
PLL output pll_<freq>m pll_200m

Source: Efinity RTL coding style guide §3.2 (clock naming) [rtl-coding-style.md §3.2]

13.2 Clock enables instead of divided clocks

Never drive logic with a divided clock. Use a clock enable instead:

// ❌ Forbidden
always @(posedge clk_div2) begin
    cnt <= cnt + 1;
end

// ✅ Correct
reg clk_en;
always @(posedge sys_clk) begin
    clk_en <= ~clk_en;  // divide-by-2 enable
end
always @(posedge sys_clk) begin
    if (clk_en)
        cnt <= cnt + 1;
end

Source: Efinity RTL coding style guide §3.3 (clock enables) [rtl-coding-style.md §3.3]

14. Complete design examples

14.1 ISF example: multi-clock-domain system

# === Clock input ===
design.create_input_clock_gpio("clk_50m")

# === PLL: 50MHz → 100MHz + 200MHz + 25MHz ===
design.create_block("sys_pll", "PLL")
design.set_property("sys_pll", "FIN", "50", "PLL")
design.set_property("sys_pll", "CLKOUT0_EN", "TRUE", "PLL")
design.set_property("sys_pll", "CLKOUT0_DIV", "10", "PLL")     # 100MHz
design.set_property("sys_pll", "CLKOUT1_EN", "TRUE", "PLL")
design.set_property("sys_pll", "CLKOUT1_DIV", "5", "PLL")      # 200MHz
design.set_property("sys_pll", "CLKOUT2_EN", "TRUE", "PLL")
design.set_property("sys_pll", "CLKOUT2_DIV", "40", "PLL")     # 25MHz
design.assign_resource("sys_pll", "PLL_R0", "PLL")

14.2 SDC example: complete clock constraints

# Board clock declaration
create_clock -name clk_50m  -period 20.000 [get_ports clk_50m]

# PLL output clocks (referenced via get_pins on the PLL output pins)
create_clock -name sys_clk   -period 10.000 [get_pins {sys_pll/CLKOUT0}]
create_clock -name clk_200m  -period  5.000 [get_pins {sys_pll/CLKOUT1}]
create_clock -name clk_25m   -period 40.000 [get_pins {sys_pll/CLKOUT2}]

# Clock uncertainty (jitter budget)
set_clock_uncertainty 0.200 [get_clocks sys_clk]
set_clock_uncertainty 0.200 [get_clocks clk_200m]

# Asynchronous clock groups (external crystal vs. PLL outputs)
set_clock_groups -asynchronous \
    -group {clk_50m} \
    -group {sys_clk clk_200m clk_25m}

Source: synthesized from the ISF Syntax Reference [isf-syntax-reference.md] and Efinity design rules §4 [design-rules.md §4]

14.3 RTL example: PLL and reset integration

module top (
    input  wire clk_50m_i,
    input  wire rst_n_i,
    output wire led_o
);
    // PLL outputs (generated by the Interface Designer, connected to top-level ports)
    // At compile time, Efinity automatically connects the PLL clock to the signal used in RTL

    // ---- Merge PLL lock into reset ----
    wire async_rst_n = rst_n_i & pll_locked;  // pll_locked comes from the PLL

    // ---- 3-stage synchronized release ----
    reg [2:0] rst_sync;
    always @(posedge sys_clk or negedge async_rst_n) begin
        if (!async_rst_n)
            rst_sync <= 3'b000;
        else
            rst_sync <= {rst_sync[1:0], 1'b1};
    end
    wire rst_n = rst_sync[2];

    // ---- User logic ----
    // ...
endmodule
