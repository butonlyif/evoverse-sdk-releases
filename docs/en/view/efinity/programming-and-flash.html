Efinity Programming and Flash Reference

Efinity Programming and Flashing Guide

Version: v1.0 | Based on Efinity 2026.1 (AN033 v1.3 / AN061 / efx_pgm --help)

1. Overview

Efinity supports multiple FPGA configuration modes. This volume covers configuration principles, the command-line tools, hardware connections, SEU protection, the FlashShell script API, and integration with the EvoVerse SDK.

Key terms: - Active mode: the FPGA is the master, actively reading the bitstream from external SPI Flash - Passive mode: the FPGA is the slave, with the bitstream supplied by an external master (MCU/CPU/JTAG debugger) - JTAG: always available, unaffected by other pin configurations

Source: AN033 v1.3 "Titanium Configuration"

Dedicated configuration pins (Titanium): | Pin | Direction | Description | |-----|-----------|-------------| | CDONE | Output (open-drain, internal pull-up) | Configuration-done indicator | | CRESET_N | Input (active low, internal pull-up) | Configuration reset | | TCK, TMS, TDI, TDO | JTAG (internal pull-up) | JTAG interface | | SSL_N, CDI[0:7], CCK, SSU_N | Multi-function (reused as User IO after configuration) | SPI Active/Passive interface |

Source: AN033 v1.3 — Dedicated Config Pins

3. Configuration Modes in Detail

3.1 Mode comparison

Mode Master/Slave Interface Typical use case
SPI Active (serial) FPGA master SSL_N, CCK, CDI[0], SSU_N Standalone power-on self-start (most common)
SPI Active (parallel) FPGA master SSL_N, CCK, CDI[0:7], SSU_N Ultra-fast startup
SPI Passive (serial) External master Same as Active but FPGA slave External MCU supplies the bitstream
SPI Passive (parallel) External master Same as Active parallel External high-speed configuration
JTAG External debugger TCK, TMS, TDI, TDO Debugging (always available)

Source: AN033 v1.3 — Configuration Modes

3.2 SPI Active instruction set

The standard SPI read instructions the FPGA issues to the Flash in SPI Active mode:

Instruction code Mode Description
0BH x1 Fast Read Single-lane fast read
3BH x2 Fast Read Dual-lane fast read
6BH x4/x8 (dual Flash) Quad/octal fast read

Source: AN033 v1.3 — SPI Active Instructions

3.3 Configuration time estimation

Configuration time formula (AN061):

Configuration Time = Bitstream Size ÷ (Config Clock × Data Bus Width)
  • The larger the divisor, the faster the configuration: lower --oscillator_clock_divider (DIV8→DIV1) or increase --width
  • Compression shrinks the bitstream (about 50% on Titanium)

Source: AN061 — Topaz Configuration

5. Multi-Image and Remote Update

5.1 Multi-image selection (CBSEL)

Select different images to load from different Flash addresses via the CBSEL[1:0] hardware pins:

  • Requires --enable_cbsel on
  • Use --flash_addr_2, --flash_addr_3, --flash_addr_4 to specify each image's starting byte address in Flash
  • Typical use: a Golden Image + Update Image dual-image scheme

Source: efx_pgm --help; AN033 — Multi-Image

5.2 Remote Update

The FPGA triggers reconfiguration from internal logic in user mode:

  • --enable_remote_update on
  • --remote_update_retries N sets the retry count
  • Usually combined with CBSEL for safe firmware updates (a failed update automatically falls back to the Golden Image)

Source: efx_pgm --help; AN033 — Remote Update

6. SEU Detection and Correction

Single-event upsets (SEU) are the key reliability concern for SRAM FPGAs in radiation environments. Efinity supports SEU protection at two levels.

6.1 SEU CRC detection

Parameter Valid values Description
--enable_seu_crc_check on / off Enable user-mode SEU CRC checking
--seu_mode automatic / manual Automatic scanning (periodically triggered) or manually triggered
--seu_wait_interval unsigned integer Wait interval between two CRC checks in automatic mode

Source: efx_pgm --help; AN061 — SEU

6.2 SEU Correction

--enable_seu_crc_check must be on first. Correction parameters:

Parameter Valid values Description
--seu_enable_correction on / off Enable SEU correction
--seu_correction_mode manual, timer, monitor, autofix Correction mode
--seu_correction_timer unsigned integer Maximum wait time in Timer mode
--seu_correction_clearable on / off UNFIXABLE state clearable
--seu_correction_err_inject on / off Error injection (for debugging)
  • manual: correction triggered by user logic
  • timer: correction triggered on a timer
  • monitor: continuous monitoring; correct as soon as an error is detected
  • autofix: detect and fix automatically

Source: efx_pgm --help; AN061 — SEU Correction

7. Hardware Connection Reference

7.1 Dedicated configuration pins

Pin Type Description
CDONE Output, open-drain, pull-up Pulled high after configuration completes; can reset external devices or trigger the next action
CRESET_N Input, active low, pull-up Pull low to re-trigger the configuration flow
TCK / TMS / TDI / TDO JTAG, pull-up Always available, independent of GPIO functions
SSL_N Multi-function SPI chip select (during configuration); reused as User IO after configuration
CDI[0:7] Multi-function SPI data input (during configuration); reused as User IO after configuration
CCK Multi-function SPI clock (during configuration); reused as User IO after configuration
SSU_N Multi-function SPI slave select (during configuration); reused as User IO after configuration

Source: AN033 v1.3 — Dedicated Config Pins

7.2 Topaz specifics

  • The JTAG_VCCIO_SEL pin selects the JTAG voltage for the BR4 bank
  • Supports both 3-byte and 4-byte SPI Flash addressing (Titanium Ti35/Ti60: 3-byte only)

Source: AN061 — Topaz Dedicated Pins; AN033 — Ti35/Ti60 3-byte only

  • Suited to production-line batch programming, CI/CD pipelines, and similar scenarios

9. EvoVerse SDK Integration

9.1 The programming step inside the compile flow

The EvoVerse SDK compile flow efx_run --flow compile already includes the pgm step:

map → PT(interface) → pnr → pgm

Users do not need to invoke efx_pgm separately.

Source: EvoVerse SDK buildRunner.ts (toolchain/buildRunner.ts)

9.2 Standalone programming scenarios

When an already-generated bitstream must be programmed to the FPGA, the SDK invokes efx_pgm with the project XML and configuration mode:

efx_pgm --project-xml <project.xml> --mode active

Source: EvoVerse SDK buildRunner.ts — standalone programming invocation

9.3 Programmer Web UI

The SDK extension can invoke the programmer Web UI in C:\Efinity\2026.1\pgm\bin\webui\ to give users a graphical programming interface.

Source: C:\Efinity\2026.1\pgm\bin\webui\ directory structure

10. Troubleshooting

Problem Possible cause What to check
Programming fails, Flash not detected Flash model not in the database Check pgm/bin/flash_db/
Bitstream too large Compression not enabled Confirm --bitstream_compression on (on by default)
SPI Active startup fails Clock divider too high Increase --oscillator_clock_divider (DIV1→DIV8)
Multi-image not working CBSEL pins not configured correctly Confirm --enable_cbsel on and valid addresses
SEU correction not taking effect CRC check not enabled Confirm --enable_seu_crc_check on
