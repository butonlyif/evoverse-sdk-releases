A.7 Dedicated conclusion: the official examples do not cover DDR / LVDS / standalone PLL

Conclusions after enumerating all 10 examples one by one:

  1. None of the official examples contains a complete project with a DDR controller or LVDS transceivers;
  2. PLLs appear only in helloworld-unified's _kit_manual.isf (a one-time bootstrap script); there is no "standalone PLL example project";
  3. Efinix places the complete DDR/LVDS/MIPI references in the official website support/ed/ (§C) and in each IP's Example Design in the IP Catalog (§B, generated by IP Manager), not in the examples directory.

A.9 Deep-dive guide to the helloworld-unified golden template

Location: C:\Efinity\2026.1\examples\helloworld-unified\ Status: the default-parameter alignment baseline for the EvoVerse project generator (awesomsdk\sdk\cli\evoverse _build_native_project_xml); the official proof of the ISF bootstrap/replay contract (AGENTS.md §15).

A.9.1 Roles and relationships of the three file types

helloworld.xml (project XML, enf_proj namespace)
   │  design_info → design_file (user RTL)
   │  constraint_info → <efx:isf_file name="Ti60F225_kit_pins.isf"/>   ← references only the pins ISF
   │            └──────→ <efx:inter_file name=""/>                     ← empty entry (see the A.9.4 pitfall)
   ▼
Ti60F225_kit_pins.isf (replay-safe: set_property / assign_pkg_pin only)
   │  replayed on every unified build ──┐
   ▼                               ▼
Ti60F225_kit_manual.isf      helloworld.peri.xml (efxpt:design_db namespace)
(one-time bootstrap: create_*)   (design source produced by the PT tool; must survive the build)

The three-way relationship in one sentence: the project XML declares "which pins ISF I use"; the manual ISF is the bootstrap tool that runs only once; peri.xml is the persisted result after bootstrap, incrementally replayed by the pins ISF on every build.

A.9.2 The dual-ISF split (9 boards × 2 = 18 ISFs, audited)

File Command style When executed Replayable
<kit>_pins.isf Only design.set_property (PULL_OPTION etc.) + design.assign_pkg_pin (e.g., ("led[0]","K14")) Every build (the project XML's efx:isf_file references it) Idempotent; can be replayed indefinitely
<kit>_manual.isf design.create_pll_input_clock_gpio + design.create_block("pll_inst1","PLL") + PLL-parameter set_property (M/N/O, REFCLK_FREQ=25.0, CLKOUT0_DIV=110) + assign_pkg_pin("pll_refclk","B2") + assign_resource("pll_inst1","PLL_TL0","PLL") A one-time bootstrap only when peri.xml does not exist Not replayable (re-running create_* raises an exists error)

The project XML references only _kit_pins.isf — _kit_manual.isf is referenced by no XML and is executed manually during the bootstrap phase. This corresponds exactly to the AGENTS.md §15 acceptance rule of "bootstrap compile + replay compile, two consecutive PASSes".

A.9.3 What is inside peri.xml (audited highlights)

helloworld.peri.xml (namespace efxpt:design_db):

Content Audited value
device_def Ti60F225
iobank definitions 12 banks: 1A~4B are 1.8V LVCMOS; BL/BR/TL/TR are 3.3V
ctrl_info cfg_CBSEL / cfg_ENA / cfg_ERROR / cfg_USR_STATUS (the Remote Update control plane)
clkmux_info CLKMUX_B / CLKMUX_L / CLKMUX_R
seu_info SEU-related configuration

peri.xml is a design source file: put it under version control, keep it alive after builds, and never let any build path delete it — deleting and regenerating it is a workaround, not a fix (AGENTS.md §15).

A.9.4 A real, observed pitfall: the empty <efx:inter_file name=""/>

The audited helloworld.xml contains an empty <efx:inter_file name=""/> entry in its constraint_info. The official example compiles with it, but in EvoVerse practice this entry breaks the build — rules-efinity-hard.md §2 states explicitly that "the name of <efx:inter_file> must not be an empty string". This repository's generator (_build_native_project_xml) handles it as follows: it does not emit the inter_file line; likewise, an empty isf_file omits the whole line (an empty <efx:isf_file name=""/> makes PT reject a project that carries a peri.xml).

Mandatory when copying and adapting: delete the empty <efx:inter_file/>; confirm that efx:isf_file points to a pins ISF that actually exists.

A.9.5 The bootstrap ritual (aligned with AGENTS.md §15)

  1. Write the pins-style ISF (set/assign only) and temporarily enable the manual ISF's create_* lines;
  2. Compile once to generate peri.xml → immediately comment out the create_* lines, adding a one-line note (when to enable them);
  3. The replay compile must PASS again in full — only bootstrap + replay, two consecutive PASSes, counts as ISF acceptance;
  4. Put peri.xml under version control together with the ISFs.

Source: full read of C:\Efinity\2026.1\examples\helloworld-unified\ (helloworld.xml, 18 ISFs, helloworld.peri.xml, 2026-09-25); AGENTS.md §15

M.2 Points to watch when porting into this repository

  1. XML element order: the <efx:project> order of every reference design must follow xml-project-schema.md: device_info → design_info → interface_info → constraint_info → sim_info → misc_info → ooc_info → ip_info. peri.xml belongs to interface_info and must not be placed in constraint_info. An IP's design_file registration entry must come before <efx:top_vhdl_arch>.
  2. ISF references: the *_kit.isf in reference designs are the board vendor's original ISFs; when this repository uses its own ISFs, replace them with evoverse-sdk/catalog/boards/<board>/<board>.isf.
  3. syn_peri_port: the classic flow requires (* syn_peri_port = 0 *) on the RTL top-level external ports (see helloworld/helloworld.v); it can be omitted under the unified flow (unified_flow="true").
  4. Empty inter_file / empty isf_file: helloworld-unified ships an empty <efx:inter_file name=""/> that must be deleted when copying and adapting; when efx:isf_file has no value, omit the whole line (A.9.4).
  5. Timing constraints: the sdc in reference designs contains only a baseline; production projects must add PLL/clock-group/IO-delay constraints.
  6. Licenses: all official Efinix source follows either Efinix's own license or MIT; redistribution must keep the original LICENSE file.

N. Fetch flow (memo)

The standard fetch flow for any of the GitHub repositories:

# 1. Create a separate directory in a suitable location (not inside this repository)
mkdir -p d:/work/efinix-refs && cd d:/work/efinix-refs

# 2. Shallow-clone as needed
git clone --depth 1 https://github.com/Efinix-Inc/<repo>.git

# 3. Enter the project
cd <repo>
git log -1   # confirm the commit

This repository does not host any of this code — only GitHub links are kept, to avoid repository bloat and license contamination; fetch it with the commands above when needed.
