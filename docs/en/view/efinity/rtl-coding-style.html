Efinity RTL Coding Style

Efinix FPGA Verilog/SystemVerilog Coding Style Guide

Version: v1.0 Updated: 2026-09-30 Applies to SDK version: v1.0.0 Tools: Efinity IDE (Titanium / Trion / Quantum families) Scope: All RTL development in EvoVerse SDK projects, including vibe-coding-generated code Sources: Efinity Synthesis Coding Style / Coding Reliability PPTX, Intel AN-1016, AMD UG949, existing EvoVerse RTL practice

1. File organization and naming

1.1 File naming

Rule Description
One module per file File name = module name, e.g. ws_clock_mgr.v
Extension .v (Verilog) or .sv (SystemVerilog) .sv recommended for new code
Lowercase + underscores mipi_csi_rx.sv, ddr3_controller.sv
No hyphens mipi-csi-rx.sv ❌ → mipi_csi_rx.sv ✅
Top-level names end with _top ws_golden_top.v

1.2 Directory layout (within a module)

rtl/
├── top/            # top-level integration
├── clk_rst/        # clock and reset management
├── data_path/      # data path (subdirectories per function)
├── ctrl/           # control logic / FSMs
├── cdc/            # cross-clock-domain modules
└── ip_wrappers/    # third-party IP wrappers

2. Module authoring rules

2.1 Module header template

`default_nettype none
`timescale 1ns / 1ps

//============================================================================
// Module: <module_name>
// Description: <one sentence on what it does>
// Interface: <key interface protocols, e.g. AXI-Stream / Avalon-MM / custom handshake>
// Constraints: <clock frequency, latency requirements, throughput, etc.>
// References: <design documents and IP datasheets cited>
//============================================================================
module module_name #(
    parameter DATA_WIDTH = 16,
    parameter ADDR_WIDTH = 10
)(
    input  wire                    clk_i,
    input  wire                    rst_n_i,
    // Data input
    input  wire [DATA_WIDTH-1:0]   data_i,
    input  wire                    valid_i,
    output wire                    ready_o,
    // Data output
    output wire [DATA_WIDTH-1:0]   data_o,
    output wire                    valid_o,
    input  wire                    ready_i
);

    //----------------------------------------------------------
    // Internal signal declarations
    //----------------------------------------------------------
    // ...

    //----------------------------------------------------------
    // Logic implementation
    //----------------------------------------------------------
    // ...

endmodule

`default_nettype wire

2.2 Port naming

Direction Suffix Example
Input _i clk_i, data_i, valid_i
Output _o data_o, valid_o, led_o
Bidirectional _io sda_io
Active-low _n prefix or suffix rst_n_i, cs_n_o

2.3 Internal signal naming

Type Convention Example
Register descriptive name + _r, or no suffix cnt_r, state, data_reg
Wire descriptive name fifo_full, buf_sel
FSM state uppercase ST_ prefix ST_IDLE, ST_READ, ST_WRITE
Parameter/constant uppercase + underscores DATA_WIDTH, MAX_BURST

2.4 Forbidden practices

  • ❌ Do not use inout bidirectional ports except for top-level IO (clearly marked with the _io suffix)
  • ❌ Do not put complex logic inside the top-level module (instantiation + simple wiring only)
  • ❌ Do not use * wildcard port connections (.data_i(data_i) instead of .*)

3. Clocks and reset

3.1 Reset strategy

Uniformly use async-reset synchronous-release:

// Standard 3-stage synchronized reset release
reg [2:0] rst_sync;
always @(posedge clk or negedge rst_n_i) begin
    if (!rst_n_i)
        rst_sync <= 3'b000;
    else
        rst_sync <= {rst_sync[1:0], 1'b1};
end
wire rst_n = rst_sync[2];

Rules: - The top level exposes a single rst_n_i (asynchronous, active-low) - Each clock domain independently generates its synchronously released rst_n - The release chain has at least 2 stages (3 recommended) - ❌ Do not use a purely asynchronous reset (code of the form always @(posedge clk or negedge rst_n_i) must not contain asynchronous release logic without a synchronizer) - ❌ Do not use a global reset on the data path (reset control logic only; drive data registers with valid)

3.2 Clock naming

Signal Naming Example
Input reference clock clk_<freq>m_i clk_50m_i, clk_100m_i
System working clock sys_clk sys_clk
Video/pixel clock <domain>_clk video_clk, pixel_clk
PLL output pll_<freq>m pll_200m

3.3 Clock enables (instead of divided clocks)

Never drive logic with a divided clock:

// ❌ Do not do this
always @(posedge clk_div2) begin
    cnt <= cnt + 1;
end

Use a clock enable instead:

// ✅ Do this
reg clk_en;
always @(posedge sys_clk) begin
    clk_en <= ~clk_en;  // divide-by-2 enable
end

always @(posedge sys_clk) begin
    if (clk_en)
        cnt <= cnt + 1;
end

4. Timing-friendly coding

4.1 Registered outputs

Register every module output before it leaves the module whenever possible:

// ✅ Recommended: registered outputs
always @(posedge clk) begin
    data_o  <= data_next;
    valid_o <= valid_next;
end

Rules: - Module outputs should normally pass through a register - If a timing violation crosses modules, add the output register at the sending side first - Data and its sideband control signals (valid/last/user) must be registered in the same cycle

4.2 Pipeline insertion principles

When a combinational path has ≥ 3 consecutive LUT levels and logic delay > 60% of the period, consider inserting pipeline registers:

// ❌ Long combinational chain
assign result = stage3(stage2(stage1(data)));

// ✅ Pipelined
reg [W-1:0] pipe1, pipe2;
always @(posedge clk) begin
    pipe1 <= stage1(data);
    pipe2 <= stage2(pipe1);
end
assign result = stage3(pipe2);

4.3 High-fanout control

Constrain control signals with fanout greater than 200 using the (* max_fanout *) attribute:

(* max_fanout = 100 *) reg shared_enable;

Or replicate the driver manually:

// Replicate one enable signal 4 times, each copy driving 1/4 of the load
reg [3:0] en_replica;
always @(posedge clk) en_replica <= {4{en_src}};

5. Synthesis-friendly coding

5.1 FSM encoding

One-hot encoding recommended (an Efinix recommendation, friendly to the LUT structure):

(* fsm_encoding = "one-hot" *)
reg [3:0] state, state_next;

localparam ST_IDLE  = 4'b0001;
localparam ST_READ  = 4'b0010;
localparam ST_PROC  = 4'b0100;
localparam ST_WRITE = 4'b1000;

5.2 Case statements

// ✅ Complete case
always @(*) begin
    case (state)
        ST_IDLE:  next = ST_READ;
        ST_READ:  next = data_valid ? ST_PROC : ST_READ;
        default:  next = ST_IDLE;  // default is mandatory
    endcase
end
  • Every case must have a default
  • Every if-else chain must end with an else
  • Avoid inferring latches inside combinational always @(*) blocks

5.3 Avoiding accidental latches

Common latch-producing situations and fixes:

Situation Bad example Fix
A signal in a combinational always block is not assigned in every branch if (en) y = a; Add else y = 0; or assign a default value at the top
case missing default case (sel) 2'b00: y=a; ... Add default: y = 0;
Non-blocking assignment inside a combinational block always @(*) y <= a; Switch to =, or to always @(posedge clk)

6. Cross-clock domains (CDC)

6.1 Synchronizer templates

Single-bit control signal — 2/3-stage synchronizer:

(* ASYNC_REG = "TRUE" *) reg [2:0] sync_ff;

always @(posedge clk_dst) begin
    sync_ff <= {sync_ff[1:0], src_signal};
end
wire signal_synced = sync_ff[2];

Multi-bit bus — MUX synchronization (sample after synchronizing valid):

// Sending side (clk_src domain)
reg        valid_toggle;
reg [31:0] data_bus;

always @(posedge clk_src) begin
    if (send) begin
        data_bus      <= new_data;
        valid_toggle  <= ~valid_toggle;
    end
end

// Receiving side (clk_dst domain)
(* ASYNC_REG = "TRUE" *) reg [2:0] toggle_sync;
reg toggle_prev;

always @(posedge clk_dst) begin
    toggle_sync <= {toggle_sync[1:0], valid_toggle};
    toggle_prev <= toggle_sync[2];
    if (toggle_sync[2] != toggle_prev)
        captured_data <= data_bus;  // data_bus is stable by now
end

6.2 CDC rules

  • Every signal crossing clock domains must pass through a synchronizer
  • ❌ Do not simply set_false_path CDC paths in the SDC
  • First confirm set_clock_groups -asynchronous, then apply set_false_path -from sync_ff_0 -to sync_ff_2 to the synchronizer itself
  • Tag synchronizer chains with (* ASYNC_REG = "TRUE" *) so the synthesizer cannot move or optimize them away
  • Stretch a single-cycle pulse from a fast to a slow domain before synchronizing it

7. Resource utilization

7.1 BRAM inference

// ✅ BRAM-inference-friendly style
(* ram_style = "block" *)
reg [DATA_W-1:0] mem [0:DEPTH-1];
reg [DATA_W-1:0] mem_rd;

always @(posedge clk) begin
    if (wr_en)
        mem[wr_addr] <= wr_data;
    mem_rd <= mem[rd_addr];  // register the read too (output register)
end
  • Tell the synthesizer explicitly with (* ram_style = "block" *)
  • Register the read data (BRAM has a built-in output register — free)
  • Prefer BRAM over distributed RAM at depth ≥ 128

7.2 DSP inference

// ✅ DSP-inference-friendly style
(* use_dsp = "yes" *)
reg [17:0] mult_result;

always @(posedge clk) begin
    mult_result <= $signed(a) * $signed(b);
end
  • Register both multiplier inputs and outputs (exploit the DSP's built-in pipeline registers)
  • Use $signed() to state clearly that the multiplication is signed

7.3 PLL configuration

PLLs should be configured as hard macros through the Efinity Interface Designer, not instantiated in RTL:

// ✅ PLL configured via Interface Designer
// In RTL, only declare the PLL output clock ports and the lock signal
input  wire pll_clk_out,   // working clock produced by the PLL
input  wire pll_locked,    // PLL lock indicator

9. SDC constraints companion

9.1 Clock names matched to RTL

Clock names in the SDC must match the RTL port names or PLL output names:

# RTL:    input wire clk_50m_i
# or PLL: output named sys_clk
create_clock -period 20.0 -name clk_50m [get_ports clk_50m_i]
create_clock -period 5.0  -name sys_clk [get_pins {u_pll/sys_clk}]

9.2 Clock grouping

# Asynchronous clock domains
set_clock_groups -asynchronous \
    -group [get_clocks clk_50m] \
    -group [get_clocks sys_clk] \
    -group [get_clocks video_clk]

9.3 IO delays

set_input_delay  -clock sys_clk -max 2.0 [get_ports {data_in[*]}]
set_output_delay -clock sys_clk -max 1.5 [get_ports {led_o[*]}]

10. Anti-pattern list (forbidden practices)

# Anti-pattern Effect Correct practice
1 A combinational always @(*) block that assigns no defaults to all outputs Accidental latch Assign defaults to all outputs at the top of the block
2 case without default / if-else without else Accidental latch Add the missing default branch
3 Driving logic with a divided clock More clock domains, more complex constraints Replace with a clock enable
4 Crossing clock domains without a synchronizer Metastability-induced functional errors Add synchronizers per §6
5 Asynchronous reset without synchronized release Metastability at reset release The synchronized release chain of §3.1
6 Registering data and control signals in different cycles Downstream sees misaligned valid/data Register them together in the same always block
7 Not replicating high-fanout signals Routing congestion causes violations max_fanout or manual replication
8 BRAM read without an output register Wastes the BRAM's built-in register Register both the read address and the read data
9 Multiplier without registered inputs/outputs Longer critical path Register both sides of the DSP
10 Mixing = and <= in one always block Simulation/synthesis behavior mismatch Use = for combinational, <= for sequential
11 inout ports not at the top level Internal inout logic is unconventional Split into _i/_o/_oe signals
12 Signal names colliding with Verilog keywords Compile errors Choose a different name

11. Checklist

After writing or modifying RTL, confirm each item:

Structure: - [ ] File name = module name, lowercase + underscores - [ ] Module header has a description comment - [ ] Starts with default_nettype none / ends with default_nettype wire - [ ] Ports carry _i / _o direction suffixes

Timing: - [ ] Module outputs are registered - [ ] Data and control signals are registered in the same always block - [ ] High-fanout signals carry max_fanout or manual replication - [ ] Cross-domain signals have synchronizers + the ASYNC_REG attribute

Synthesis: - [ ] Every case has a default - [ ] Every output of a combinational always @(*) has a default value before the branches - [ ] BRAM reads use an output register - [ ] Multiplier inputs/outputs are registered - [ ] FSM uses fsm_encoding = "one-hot"

Constraint companion: - [ ] The SDC has clock definitions (matching RTL port names) - [ ] Asynchronous clock domains have set_clock_groups - [ ] IOs have set_input_delay / set_output_delay
