Sapphire SoC Configuration

Sapphire SoC Configuration Guide

Version: v1.0 | Based on Efinity 2026.1 | Last updated: 2026-07-30

This document describes in detail the configuration parameters, usage, memory map, BSP structure, and typical application scenarios of the three Efinix Sapphire RISC-V SoC IP cores.

1. Sapphire SoC family overview

Efinix offers three Sapphire RISC-V SoC IPs covering the full spectrum from low-cost soft cores to high-performance hardened SoCs:

Feature efx_soc (Sapphire RV32) efx_soc_rv64 (Sapphire RV64) efx_hard_soc (HP SoC)
IP version (2026.1) 3.4.0 1.0.0 1.23.0
ISA RV32IMAC RV64IMAC RV64IMAC (hardened)
Core count 1–4 1–4 (SMP) 4 (hardened)
Implementation Soft core (VexRiscv) Soft core (VexRiscv) Hardened (ASIC-like)
Applicable device families Trion / Titanium Titanium / Topaz Titanium (Ti375)
L1 Cache Configurable I$/D$ (1–4 way) Configurable I$/D$ (1–4 way) Hardened
L2 Cache None Optional shared L2 Hardened
FPU Optional (F/D) Optional (F/D) Hardened
MMU Optional Optional (Sv39) Hardened
External memory AXI3 (optional DDR3/LPDDR3) AXI4 (DDR3/DDR4/LPDDR4) LPDDR4 (hardened controller)
Logic resource cost ~5K–15K LUTs ~15K–30K LUTs ~0 LUTs (CPU portion)

2. SoC selection guide

Application scenario Recommended SoC Rationale
Simple GPIO/peripheral control efx_soc (1 core) Smallest resource cost
Sensor fusion, low-speed networking efx_soc (1 core + DDR3) Works on both Trion/Titanium
Linux systems, high bandwidth efx_soc_rv64 (1–4 cores) RV64 + MMU required
High-bandwidth video processing efx_soc_rv64 + EVSoC See the EVSoC reference design
Highest performance, lowest power efx_hard_soc (Ti375C529 only) The hardened CPU consumes no FPGA resources
Getting started / learning efx_soc (T8/T20/Xyloni) Lowest cost and complexity

Sources: device applicability comes from the IP directory's fpga subdirectories (e.g. efx_soc_rv64/fpga/fpga_ti180/soc.xml) and Efinity Reference Design Index (reference-design-index.md) §D–E.

5. efx_hard_soc (High-Performance SoC) configuration in detail

5.1 Core characteristics

efx_hard_soc is a hardened 4-core RISC-V SoC dedicated to the Ti375 family; its CPU cores consume no FPGA logic resources:

  • Module name: Axi4Peripheral_wrapper
  • Implementation: ASIC-hardened on the Ti375 die
  • LPDDR4 memory controller: Hardened (built in)
  • AXI4 Slave interface: For user logic to hook into
  • Co-Debug: Supported
  • Performance: Far above the soft cores, with lower power

Source: C:\Efinity\2026.1\ipm\ip\efx_hard_soc\ipm\component.pickle (displayName = "Sapphire High Performance SoC", isHardIP = 1).

  • Ti375C529 only: only the Ti375C529 device is supported (see the Ti375 branch of EmbeddedSystem-Solution)

9. Interrupt controllers

9.1 CLINT (Core Local Interruptor)

  • Provides software interrupts + timer interrupts
  • Per-core mtime / mtimecmp registers
  • Replaced the old Machine Timer in v2.0

9.2 PLIC (Platform-Level Interrupt Controller)

  • Manages all peripheral interrupts
  • Supports interrupt priorities
  • Up to 24 user interrupt sources (PLIC IDs are configurable)

Peripheral interrupt ID assignments:

10. Bootloader design

10.1 Bootloader functions

  • Initializes the DDR controller (if present)
  • Loads the application from SPI Flash into RAM
  • Jumps to the application entry point

11.2 Co-Debug configuration

Co-Debug lets a single FTDI cable debug both the RTL and the RISC-V core at the same time. Set CO_DEBUG to ENABLE in the IP configuration wizard.

12. SoC + DDR calibration flow

  1. Enable DDR in the IP configuration wizard
  2. Use the efx_socddr_calrst IP to handle the DDR calibration and reset sequence
  3. Compile the RTL + generate the .hex
  4. After programming, the bootloader runs DDR calibration
  5. The application runs from DDR

Source: official AN043 (TSE MAC + Sapphire SoC lwIP example, DDR calibration flow).
