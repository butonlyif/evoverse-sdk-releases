Trae Installation and First-Time Setup

EvoVerse SDK: Trae Installation Guide

Applies to: v1.0.0　Updated: 2026-10-16　Recommended hosts: Trae CN / Trae International

Getting-started path at a glance

From receiving the release package to starting your first design, the main line is 6 steps:

flowchart LR
    A[Get the release package] --> B[Install the 3 VSIXes]
    B --> C[Restart Trae]
    C --> D[First-launch bootstrap<br>confirm the workspace]
    D --> E[Welcome opens automatically]
    E --> F[Sync Catalog]
    F --> G["@evoverse and start working"]

Verification for each step is described in the corresponding section. Prepare the base software (Trae, Python, Git, Efinity, drivers, simulator) before installing the VSIXes.

1. Prerequisites

Item Requirement Notes
Operating system Windows 10/11 64-bit (preferred); macOS 12+; Ubuntu 20.04+ macOS cannot serve as a complete Efinity build/programming workstation
Python 64-bit 3.11+ The CLI and MCP Server use only the standard library; no pip packages needed
Git On PATH EvoVerse: Sync Catalog pulls the board catalog over Git
Efinity 2026.1+ Required for real builds and programming
Simulator Icarus Verilog RTL functional simulation; QuestaSim also works
Hardware FPGA core board + USB data cable Checklist in §2

Recommended machine: 8-core CPU, 16 GB RAM (32 GB for larger designs), 30 GB or more of free SSD space, and at least 2 USB ports.

2. Hardware preparation

  1. An EvoVerse/Efinix FPGA core board (for example ws-e1 in the Catalog);
  2. A matching carrier board / carrier / customer-built board;
  3. A power supply that matches the board specification — never guess voltage and polarity from connector shape;
  4. A USB cable that carries data — charge-only cables cannot be used for JTAG/serial;
  5. An on-board FTDI debug interface, or an FT2232H/FT4232H JTAG module;
  6. For serial logs, an on-board USB-UART or a standalone 3.3 V USB-UART adapter;
  7. Sensors / MIPI / display / networking peripherals as needed.

Before connecting anything, read the board specification in the Catalog (available after the Catalog is installed and synced):

~/evoverse-sdk/catalog/boards/<board-id>/<board-id>.md
~/evoverse-sdk/catalog/boards/<board-id>/docs/

3. Install the base software

3.1 Install Trae

  1. Install Trae CN or Trae International from the official Trae download page;
  2. Launch it and complete account sign-in.

Verify: running Trae: Show Version from the command palette returns the version number.

3.2 Install Python 3.11+

  1. Install 64-bit Python 3.11 or newer from the Python website;
  2. Check Add Python to PATH.

Verify:

py -3 --version     # Windows
python3 --version   # macOS / Linux

The output must show 3.11 or newer. With an insufficient version, the first-launch bootstrap reports SYSTEM_PYTHON_MISSING and Python-related capabilities are disabled. The customer VSIX does not need Node.js / npm.

3.3 Install Git

  1. Install from the Git website; on Windows keep the default options (Git Credential Manager is included);
  2. If the GitHub CLI is already installed, its authentication also works.

Verify:

git --version

3.4 Install Efinity 2026.1+

  1. Get the installer from the Efinix Support Center and complete installation and license configuration following the official guide for that version;
  2. Note the Efinity root directory (for example C:\Efinity\2026.1).

Verify: bin/setup.bat (Windows) or bin/setup.sh and bin/efx_run.bat exist under the root directory. Each time EvoVerse runs a tool it invokes Efinity's setup script to establish the child-process environment, so no permanent PATH changes are needed.

3.5 Install the FPGA USB/JTAG drivers

  • Windows: use Zadig or the designated driver per the board user manual and the Efinity installation guide; do not blindly replace every interface of a composite FTDI device — first confirm the interface required by the board documentation;
  • macOS: the Efinity installer bundles the drivers;
  • Linux: disconnect the board, run sudo <EFINITY_HOME>/bin/install_usb_driver.sh, reload the udev rules, then reconnect the board.

3.6 Install Icarus Verilog

  • macOS: brew install icarus-verilog;
  • Linux: sudo apt install iverilog;
  • Windows: install a prebuilt distribution and add it to PATH.

Verify: both iverilog -V and vvp -V print a version number.

3.7 Optional: the RISC-V software toolchain

Only needed when you use the Sapphire/RISC-V SoC. After installation you can run EvoVerse: Download & Install RISC-V Toolchain in Trae to install it automatically, or install it manually and then set evoverse.riscvToolchainPath.

4. Get the release package

  1. Obtain the customer delivery package EvoVerse-SDK-v1.0.0.tar.gz;
  2. Fully extract it in the directory containing the package (Windows 10 1803+ ships with tar, so the long-path errors of zip extraction do not occur):
tar -xzf EvoVerse-SDK-v*.tar.gz

Verify: the extracted directory contains deploy.ps1 / deploy.sh and the 3 .vsix files. START-HERE.md and docs/site/customer-portal.html are the entry documents.

5. Install the 3 VSIXes

v1.0.0 ships 3 extensions of the same version:

VSIX Purpose Required?
evoverse-sdk-1.0.0.vsix SDK core: Welcome, Catalog, Workbench shell, CLI / MCP Required
evoverse-efinity-adapter-1.0.0.vsix Efinity build / timing / debug / programming / IP Required for FPGA development
evoverse-rk3588-adapter-1.0.0.vsix RK3588 software verification loop Install when doing RISC-V software

All three VSIX versions must match; mixing different versions is unsupported.

5.1 Option A: one-shot deployment (recommended)

Open PowerShell in the extracted package directory:

.\deploy.ps1 -Target trae

macOS / Linux:

./deploy.sh --target trae

The script installs Core, the two Adapters, and Skills in dependency order; optional Adapters missing from the package are skipped with a notice. Video Sim is embedded in the Core VSIX and needs no separate installation.

Verify: all installed EvoVerse extensions show as Enabled in the Extensions panel.

5.2 Option B: manual installation from the Extensions panel

  1. Press Ctrl+Shift+X (macOS: Cmd+Shift+X) to open the Extensions panel;
  2. Click ... in the top-right corner → Install from VSIX...;
  3. Select the VSIXes one by one in the order of the table above.

Or from the command line:

trae --install-extension D:\packages\evoverse-sdk-1.0.0.vsix
trae --install-extension D:\packages\evoverse-efinity-adapter-1.0.0.vsix
trae --install-extension D:\packages\evoverse-rk3588-adapter-1.0.0.vsix

6. Restart Trae and complete the first-launch bootstrap

  1. Fully quit and restart Trae so the extensions activate;
  2. On first activation a dialog asks "Set up EvoVerse SDK?" — choose Yes, set up. The bootstrap creates the Catalog, project, and runtime directories under the default workspace ~/evoverse-sdk (change the path with evoverse.home) and does not modify system files;
  3. Watch Output → EvoVerse SDK; the bootstrap prints each item, and once all show ✓ you see === EvoVerse SDK ready ===:
  4. EVOVERSE_HOME ready at … — workspace ready;
  5. Deployed Efinity knowledge base — knowledge base deployed;
  6. MCP integration: … — writes mcpServers.evoverse into ~/.trae/mcp.json (merge-only, other entries untouched; a *.evoverse.bak backup is made before overwriting);
  7. Agent rule: … — writes evoverse.md and evoverse-rtl-style.md under ~/.trae/user_rules/;
  8. CLI works: … — CLI smoke test;
  9. If Git is not on PATH you get a ! git not found warning; Sync Catalog only works after Git is installed;
  10. If Python is missing or too old the bootstrap reports SYSTEM_PYTHON_MISSING; re-run it after installing Python 3.11+;
  11. When finished you are prompted "Restart the host to load the MCP server." — choose Restart now to restart again.

Verify: after the restart the Welcome page opens automatically. If it does not, run EvoVerse: Show Welcome (evoverse.welcome) from the command palette.

If you chose Later in the dialog, or need to re-run the bootstrap, run EvoVerse: Set Up (re-run bootstrap) (evoverse.setup). Standard VS Code never writes ~/.trae; for host differences see HOST-DIFFERENCES.md.

7. Sync the Catalog

On a fresh install the Catalog is empty and the UI and MCP report CATALOG_NOT_INSTALLED. This is the expected state, not a failure.

  1. Run EvoVerse: Sync Catalog (evoverse.syncCatalog). The sync pulls from the official public release repository (evoverse-catalog-release) by default—no GitHub account is required; when GitHub is unreachable (network errors), the sync automatically retries from the Gitee domestic mirror carrying the identical release, and the receipt records which repository actually served it—and writes the receipt catalog-sync-receipt.json when it finishes;
  2. Run EvoVerse: Catalog Status (evoverse.catalogStatus), or run evoverse catalog status --json in a terminal, and record the state, location, and the receipt's catalog_version and commit.

To use a self-hosted mirror or a private repository instead, override the repository URL with evoverse sync --repository <URL> or the EVOVERSE_CATALOG_REPOSITORY environment variable.

Verify: the Welcome page Board Catalog panel lists boards (such as ws-e1). A failed sync does not affect existing local content; fix the network and sync again.

8. Verify the installation

  1. The EvoVerse view opens from the left activity bar;
  2. The Workbench shows the installed Adapters (if the Efinity Adapter is installed, its entry should appear);
  3. Run EvoVerse: Health Check (evoverse.sdkHealthCheck) and confirm Python / Efinity / MCP / simulator / CLI / Adapter all pass (the Welcome page also has an SDK health panel);
  4. In Settings, confirm evoverse.efinityPath points to the real Efinity installation directory.

9. Start using

  1. Start with natural language: type @evoverse in the Chat panel and describe your requirement:

text @evoverse I want to implement MIPI to USB on ws-e1, with DDR buffering in between

The SDK first confirms the working mode with you: the reliable design flow or free-form development. Ordinary conversations without @evoverse stay in free-form development; the reliable flow is never enabled automatically and no dedicated rule files are generated into customer projects.

  1. Pick the flow in the Workbench: you can also choose the design flow in the Workbench Project Control dropdown, command EvoVerse: Select Design Flow (evoverse.selectDesignFlow);
  2. The six Workbench tabs: Home / Build / Timing / Debug / SW / IP;
  3. Build: the Build tab or the command palette Toolchain: Build (evoverse.build). The build is executed by the Efinity Adapter with efx_run --flow compile, and the status bar shows Build: Ready / Running / Failed;
  4. Timing diagnosis: Toolchain: Diagnose Timing Violations (evoverse.diagnoseTiming);
  5. Program the board: Toolchain: Program FPGA (evoverse.program).

For the full daily development workflow, see the User Manual.

10. Troubleshooting

10.1 @evoverse is missing from the Chat panel

  1. Confirm that ~/.trae/mcp.json contains mcpServers.evoverse;
  2. Confirm that you completed the restart after the "Restart the host to load the MCP server." prompt;
  3. Trae → Settings → MCP: confirm the evoverse server shows running;
  4. Type @ in the Chat panel; evoverse should appear in the dropdown.

10.2 ~/.trae/mcp.json is corrupted

The SDK backs the file up as ~/.trae/mcp.json.evoverse.bak before writing. Restore from the backup and re-run EvoVerse: Set Up (re-run bootstrap):

cp ~/.trae/mcp.json.evoverse.bak ~/.trae/mcp.json

10.3 Agent rules conflict with team rules

  • The rule sources live in ~/evoverse-sdk/agent-rules/; do not edit ~/.trae/user_rules/*.md directly;
  • Write project-level rules to .github/copilot-instructions.md;
  • If you must change user rules, back them up first and merge manually after each SDK upgrade.

10.4 The bootstrap reports SYSTEM_PYTHON_MISSING

Install or fix Python 3.11+ (see §3.2), or point evoverse.pythonPath at the real interpreter and re-run EvoVerse: Set Up (re-run bootstrap).

10.5 Other

For installation issues (Sync Catalog failures, Health Check failures, Efinity not found), follow the "Troubleshooting" table in the Deployment Guide.
