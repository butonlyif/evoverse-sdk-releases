Trae Installation and First-Time Setup

EvoVerse SDK: Trae — From a Bare Machine to Full-Feature Use

Updated: 2026-08-15 Goal: starting from a computer with no development environment installed, get to RTL editing, rules and constraints, simulation, Efinity builds, timing diagnosis, programming, the MCP Agent, and native Chat integration in Trae (Trae CN / Trae International).

0. Relationship to the VS Code installation

The EvoVerse SDK supports Trae, standard Visual Studio Code, and other VS Code forks with the same VSIX. The vast majority of installation steps are identical to VSCODE-INSTALLATION.md; this document covers only the differences under Trae plus installation and initialization behavior unique to Trae.

Intended audience: - Customers who have chosen Trae as their daily development editor; - Customers who need @evoverse and MCP tools in the Trae Chat panel; - Operations staff who need to understand which files under the Trae-specific path ~/.trae/ are managed automatically by the SDK.

0.1 Agent and the reliable-flow entry point

  • When you need a specification, RTL Design Assurance, and stage-by-stage simulation confirmation, start the requirement with @evoverse, for example: @evoverse I want to implement MIPI to USB on ws-e1, with DDR buffering in between. The SDK first confirms the working mode with you: the reliable design flow or free-form development.
  • When starting a new, independent design iteration in an existing project, raise the requirement with @evoverse again; the SDK updates the existing specification, or creates one if none exists.
  • Ordinary Agent conversations without @evoverse remain free-form development: the reliable flow is not enabled automatically, and no dedicated rule files are generated into customer projects.
  • Build, Timing, and Debug are standalone tool entry points; they do not require selecting the reliable flow first.

1. First pin down the scope of "full functionality"

In this guide, full functionality covers:

  • The EvoVerse Workbench, Catalog, project creation, and health checks;
  • Verilog/SystemVerilog editing, RTL coding rules, and Agent workflows;
  • Icarus Verilog functional simulation and VCD waveform viewing;
  • Efinity synthesis, place-and-route (PNR), bitstream generation, resource reports, and timing reports;
  • Timing Diagnosis, Build AI, and the multi-turn Conversation Runtime;
  • Programming Efinix FPGAs over USB/JTAG;
  • Invoking SDK tools through @evoverse in the Trae Chat panel;
  • Optional Sapphire/RISC-V software compilation, flashing, and GDB debugging.

1.1 Recommended operating systems

As with the VS Code installation, use one of the following:

  • Windows 10/11, 64-bit: the first choice for customer desktop environments;
  • macOS 12 or later: an officially supported platform for the Trae desktop app;
  • Ubuntu 20.04 or later.

macOS can run Trae, EvoVerse, MCP, AI, and Icarus simulation, but it cannot serve as a complete Efinity build/programming workstation as defined in this guide. For Efinity's current official installation requirements and USB driver steps, see the Efinity Software Installation User Guide.

1.2 Recommended hardware configuration

Item Bare minimum to launch Recommended full-feature customer workstation
CPU 64-bit dual-core 8 cores or more
Memory ~1 GB for Trae + EvoVerse; ~8 GB for the Efinity design flow 16 GB; 32 GB recommended for larger designs
Disk 10 GB of free space 30 GB or more of free SSD space
USB 1 free USB port 2 or more; avoid unpowered hubs
Network Optional for offline installation Required for the first download of Trae, Efinity, extensions, models, and toolchains

For Trae's own minimum system requirements, see the official Trae download page; for Efinity memory and system requirements, defer to the official documentation of the version you install.

2. Hardware preparation

This is exactly the same as the VS Code installation: read VSCODE-INSTALLATION.md §2 for the hardware checklist and pre-connection checks. At minimum, prepare:

  1. An EvoVerse/Efinix FPGA core module — for example ws-e1 in the Catalog;
  2. A carrier board matching the core module, or a customer-built board;
  3. A power supply that matches the board specification; never guess voltage and polarity from connector shape alone;
  4. A USB cable that carries data; charge-only cables cannot be used for JTAG/serial;
  5. An on-board FTDI debug interface, or a compatible FT2232H/FT4232H JTAG module;
  6. For serial logs, an on-board USB-UART or a standalone 3.3 V USB-UART adapter;
  7. For sensors, MIPI, display, or networking, the corresponding Jackets, cables, and peripherals.

Before connecting anything, read the board specification in the Catalog (available after installation):

${EVOVERSE_HOME}/catalog/boards/<board-id>/<board-id>.md
${EVOVERSE_HOME}/catalog/boards/<board-id>/docs/
${EVOVERSE_HOME}/catalog/boards/<board-id>/carriers/

3. Install the base software

3.1 Install Trae

  1. Download the build for your platform from the official Trae download page:
  2. Trae CN: for users in mainland China; connects to domestic model providers by default;
  3. Trae International: for users outside mainland China; connects to international model providers by default.
  4. Launch Trae after installation and complete account registration and sign-in as the wizard guides you.
  5. Verify:
# Run from the command palette
Trae: Show Version

Or from a terminal:

where trae     # Windows
which trae     # macOS / Linux

3.2 Install Python 3.11+

The EvoVerse CLI and MCP Server use only the Python standard library; no pip install of other packages is required.

Windows:

  1. Install 64-bit Python 3.11 or newer from python.org;
  2. Check Add Python to PATH;
  3. Verify:
py -3 --version
python --version

macOS / Linux:

python3 --version

The output must show 3.10 or newer. Customers installing from the VSIX do not need Node.js or npm; those are only used to build the extension from source.

3.3 Install Efinity

This is exactly the same as the VS Code installation: follow VSCODE-INSTALLATION.md §3.3 to install Efinity and configure the license. When finished, note the Efinity root directory:

Windows:  C:\Efinity\2026.1
macOS:    /Applications/efinity.app/Contents/Resources/2026.1
Linux:    /opt/efinity/2026.1

Every time EvoVerse runs a tool it sets up the child-process environment using Efinity's setup script, so permanent changes to the system PATH are normally not required.

3.4 Install the FPGA USB/JTAG drivers

Identical to the VS Code installation:

  • Windows: use Zadig or the designated driver per the target board's user manual and the Efinity installation guide. Do not blindly replace every interface of a composite FTDI device; first confirm which interface the board documentation requires.
  • macOS: the official Efinity installer bundles the drivers; if a device is not recognized, follow the Efinity documentation to load them.
  • Linux: disconnect the board, then run:
sudo <EFINITY_HOME>/bin/install_usb_driver.sh
sudo udevadm control --reload-rules
sudo udevadm trigger

Reconnect the board.

3.5 Install Icarus Verilog

Full simulation functionality requires iverilog and vvp.

  • macOS: brew install icarus-verilog
  • Linux:
sudo apt update
sudo apt install iverilog

Verify:

iverilog -V
vvp -V

3.6 Optional: the RISC-V software toolchain

Only needed when you use the Sapphire/RISC-V SoC; identical to the VS Code installation. See VSCODE-INSTALLATION.md §3.6.

4. Install the EvoVerse SDK VSIX

Trae and VS Code share the same evoverse-sdk-0.9.0.vsix for EvoVerse.

4.1 Installation steps

  1. In Trae, press Ctrl+Shift+X (macOS: Cmd+Shift+X) to open the Extensions panel;
  2. Click ... in the top-right corner → Install from VSIX...;
  3. Select evoverse-sdk-0.9.0.vsix from the delivery package.

Or use the command line:

# Windows (PowerShell)
trae --install-extension D:\packages\evoverse-sdk-0.9.0.vsix

# macOS / Linux
trae --install-extension ~/packages/evoverse-sdk-0.9.0.vsix

4.2 Recommended companion extensions

Extension Purpose Declared as an EvoVerse dependency
VaporView Opens VCD waveforms produced by simulation Yes
Cortex-Debug RISC-V/MCU GDB debugging Yes
Verilog/SystemVerilog language plugin Syntax highlighting, navigation, and lint No; choose per your license and team standards

Trae ships with a built-in Chat Agent; you do not need to install GitHub Copilot separately to use @evoverse in the Chat panel. To use the OpenAI-compatible Provider of the EvoVerse built-in Runtime, see §7.

5. First launch: Trae-specific Set Up behavior

If the EvoVerse extension detects that ~/evoverse-sdk is not ready when it activates, it prompts you to Set Up. Under Trae, Set Up additionally performs the following operations (not performed under VS Code):

5.1 Writing ~/.trae/mcp.json

The SDK automatically writes the EvoVerse MCP Server into the mcpServers.evoverse field of ~/.trae/mcp.json:

  • It merges only and never overwrites other entries under mcpServers;
  • It creates ~/.trae/mcp.json if the file does not exist;
  • If mcpServers.evoverse already exists, it compares byte-for-byte: equal means skip; otherwise it backs the file up as ~/.trae/mcp.json.evoverse.bak and then overwrites.

Example (for reference only; generated by the SDK):

{
  "mcpServers": {
    "evoverse": {
      "command": "python",
      "args": ["-m", "mcp_server.server"],
      "env": {}
    }
  }
}

5.2 Writing ~/.trae/user_rules/

The SDK automatically installs two Agent Rules files:

  • ~/.trae/user_rules/evoverse.md — general EvoVerse rules;
  • ~/.trae/user_rules/evoverse-rtl-style.md — dedicated RTL coding-style rules.

The rule sources live in ~/evoverse-sdk/agent-rules/; the SDK compares byte-for-byte before writing:

  • Equal → skip (unchanged);
  • Different → back up as *.evoverse.bak, then overwrite;
  • Corrupted or unexpected format → back up and report an error; never silently wipe.

5.3 The "Restart now" prompt

Only under Trae will you see the "Restart Trae now to load MCP" prompt. Trae loads MCP from a host-fixed directory, so MCP tools appear in the Chat panel only after Trae restarts.

Standard VS Code and unknown hosts never show this prompt; if you see it under VS Code, host detection is off — first check whether vscode.env.appName starts with trae.

5.4 Handling corrupted host configuration

If ~/.trae/mcp.json or ~/.trae/user_rules/*.md is already corrupted, the SDK will:

  1. Back up the original file as *.evoverse.bak;
  2. Surface an error message in the UI;
  3. Not silently overwrite (so customer-defined rules are never wiped unintentionally).

7. Using an OpenAI-compatible Provider (optional)

If you prefer not to use Trae's built-in models, configure an OpenAI-compatible Provider in the EvoVerse Conversation Runtime:

  1. Run EvoVerse: Set OpenAI-compatible API Key to store the API key in SecretStorage;
  2. Fill in the model ID from your provider under evoverse.model.modelId;
  3. Restart Trae to make sure the configuration takes effect.

Never write a model API key into the env field of ~/.trae/mcp.json; the SDK rejects such configurations.

8. Troubleshooting

8.1 @evoverse is missing from the Trae Chat panel

Work through the following in order:

  1. Confirm that ~/.trae/mcp.json contains mcpServers.evoverse;
  2. Confirm that the SDK showed the Restart now prompt and that the restart has completed;
  3. Open Trae → Settings → MCP and confirm the evoverse server shows as running;
  4. Type @ in the Chat panel and confirm evoverse appears in the dropdown.

8.2 ~/.trae/mcp.json is corrupted

  1. Before writing, the SDK backs the file up as ~/.trae/mcp.json.evoverse.bak; restore from that backup: bash cp ~/.trae/mcp.json.evoverse.bak ~/.trae/mcp.json
  2. Run EvoVerse: Set Up again.

8.3 ~/.trae/user_rules/*.md conflicts with team rules

  • The rule sources EvoVerse installs live in ~/evoverse-sdk/agent-rules/; do not edit ~/.trae/user_rules/*.md directly;
  • To add rules for a project, edit the project-level .github/copilot-instructions.md;
  • If you must change user rules, back them up first and re-merge manually after every SDK upgrade.

8.4 Host detection is wrong

Open the Trae command palette and run:

# Inspect via Developer Tools
Developer: Toggle Developer Tools

In the Console, run:

JSON.stringify({ appName: require('vscode').env.appName })

It should return one of "Trae", "Trae CN", or "Trae - ide". If it returns something else, see HOST-DIFFERENCES.md §1 for the detectHostId() decision logic.

8.5 Model unavailability breaks build/report generation

EvoVerse's deterministic capabilities (build, reporting, rule diagnostics, timing analysis) must work independently on every host. If builds or reports are also blocked while the model is unavailable, the model provider configuration under Trae has leaked into the child-process environment; re-check the Efinity setup script invocation per VSCODE-INSTALLATION.md §3.3.
