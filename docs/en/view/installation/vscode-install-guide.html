VS Code Installation Differences

EvoVerse SDK: VS Code Installation Guide

Applicable version: v1.0.0　Updated: 2026-10-16　Host: Visual Studio Code Stable

Getting-started path at a glance

From receiving the release package to starting your first design, the main line is 6 steps:

flowchart LR
    A[Get the release package] --> B[Install the 3 VSIXes]
    B --> C[Restart VS Code]
    C --> D[First-run bootstrap<br>confirm the workspace]
    D --> E[Welcome opens automatically]
    E --> F[Sync Catalog]
    F --> G[Start working with MCP / Workbench]

How to verify each step is described in the corresponding section. The difference under VS Code is the Agent ecosystem: Trae uses the built-in Chat's @evoverse, while VS Code uses the native Chat Agent + EvoVerse MCP (see §10).

1. Prerequisites

Item Requirement Notes
Operating system Windows 10/11 64-bit (preferred); Ubuntu 20.04+; RHEL 8.8+ macOS cannot serve as a complete Efinity build/programming workstation
Python 64-bit 3.11+ The CLI and MCP Server use only the standard library; no pip packages needed
Git On PATH EvoVerse: Sync Catalog pulls the board catalog through Git
Efinity 2026.1+ Required for real builds and programming
Simulator Icarus Verilog RTL functional simulation; QuestaSim also works
Hardware FPGA core board + USB data cable See §2 for the checklist

Recommended machine specs: 8-core CPU, 16 GB RAM (32 GB for larger designs), 30 GB or more of free SSD space, and at least 2 USB ports.

2. Hardware preparation

  1. An EvoVerse/Efinix FPGA core board (for example ws-e1 in the Catalog);
  2. A matching carrier board / Carrier / customer-built board;
  3. A power supply that matches the board specification — never guess voltage and polarity from connector shape;
  4. A USB cable that carries data — charge-only cables cannot be used for JTAG/serial;
  5. An on-board FTDI debug interface, or an FT2232H/FT4232H JTAG module;
  6. For serial logs, an on-board USB-UART or a standalone 3.3 V USB-UART adapter;
  7. Sensors / MIPI / display / networking peripherals as needed.

Do not connect a custom board while its I/O voltage, JTAG levels, or power direction are unknown; before connecting, read the board specification in the Catalog:

~/evoverse-sdk/catalog/boards/<board-id>/<board-id>.md
~/evoverse-sdk/catalog/boards/<board-id>/docs/

3. Install the base software

3.1 Install Visual Studio Code

  1. Install the Stable 64-bit build from the official VS Code download page;
  2. On Windows, the User Installer is recommended; check "Add to PATH" and the Explorer "Open with Code" option.

Verify: running code --version in a terminal returns a version number; if code is not found, reopen the terminal or reinstall with PATH enabled.

3.2 Install Python 3.11+

  1. Install 64-bit Python 3.11 or newer from python.org;
  2. Check Add Python to PATH.

Verify:

py -3 --version     # Windows
python3 --version   # Linux

The output must show 3.11 or higher. When the version is insufficient, the first-run bootstrap reports SYSTEM_PYTHON_MISSING and Python-related capabilities are disabled. The customer VSIX does not need Node.js / npm.

3.3 Install Git

Install from the Git website (Windows default options include Git Credential Manager). Verify: git --version returns a version number.

3.4 Install Efinity 2026.1+

  1. Get the installer that matches your target device and license from the Efinix Support Center, and complete the installation and license configuration per the official guide;
  2. On Windows, install the Microsoft Visual C++ 2022 x64 Runtime; some IP Managers (for example Sapphire SoC) additionally require 64-bit Java 8 or 11;
  3. On Linux, install the GUI libraries and Java per the official requirements and make sure Java is on the PATH;
  4. Note the Efinity root directory (for example C:\Efinity\2026.1).

Verify that the root directory contains:

bin/setup.bat             # Windows
bin/setup.sh              # Linux
bin/efx_run.bat or efx_run.py
bin/efinity.exe or bin/efinity

Every time EvoVerse runs a tool it invokes Efinity's setup script to build the child-process environment, so permanent PATH changes are not needed.

3.5 Install the FPGA USB/JTAG drivers

  • Windows: use Zadig or the designated driver per the board's user manual and the Efinity installation guide; do not blindly replace every interface of a composite FTDI device — first confirm which interface the board documentation requires;
  • Linux: disconnect the board, run sudo <EFINITY_HOME>/bin/install_usb_driver.sh, reload the udev rules, then reconnect the board.

3.6 Install Icarus Verilog

  • Windows: install a prebuilt build and add it to PATH;
  • Linux: sudo apt install iverilog.

Verify: both iverilog -V and vvp -V print a version number.

3.7 Optional: the RISC-V software toolchain

Only needed when you use the Sapphire/RISC-V SoC: xPack GNU RISC-V Embedded GCC, GDB, the BSP generated by Efinity, the Cortex-Debug extension, and the board's debugger configuration. You can run EvoVerse: Download & Install RISC-V Toolchain in VS Code to install automatically, or install manually and then set evoverse.riscvToolchainPath.

4. Obtain the release package

  1. Get the customer delivery package EvoVerse-SDK-v1.0.0.tar.gz;
  2. Extract it fully in the directory that contains the package (Windows 10 1803+ ships with tar, avoiding the path-too-long errors of zip extraction):
tar -xzf EvoVerse-SDK-v*.tar.gz

Verify: the extracted directory contains deploy.ps1 / deploy.sh and the 3 .vsix files. START-HERE.md and docs/site-en/customer-portal.html are the entry documents.

5. Install the 3 VSIXes

v1.0.0 delivers 3 extensions of the same version:

VSIX Purpose Required?
evoverse-sdk-1.0.0.vsix SDK core: Welcome, Catalog, the Workbench shell, CLI / MCP Required
evoverse-efinity-adapter-1.0.0.vsix Efinity build / timing / debug / programming / IP Required for FPGA development
evoverse-rk3588-adapter-1.0.0.vsix RK3588 software verification loop Install when doing RISC-V software

The three VSIXes must be the same version; mixing versions is unsupported.

5.1 Method A: one-shot deploy (recommended)

Open PowerShell in the extracted package directory:

.\deploy.ps1 -Target vscode

macOS / Linux:

./deploy.sh --target vscode

The script installs Core, the two Adapters, and Skills in dependency order; an optional Adapter missing from the package is skipped with a notice. Video Sim is embedded in the Core VSIX and needs no separate install.

5.2 Method B: manual install via CLI / the Extensions panel

code --install-extension D:\packages\evoverse-sdk-1.0.0.vsix
code --install-extension D:\packages\evoverse-efinity-adapter-1.0.0.vsix
code --install-extension D:\packages\evoverse-rk3588-adapter-1.0.0.vsix

Or, in the Extensions panel, click the ... at the top right → Install from VSIX... and pick each file.

5.3 Recommended companion extensions

Extension Purpose Declared as an EvoVerse dependency
GitHub Copilot VS Code native Chat Agent, VS Code MCP, and vscode-lm No; install and sign in when using the native Chat Agent
VaporView Opens VCD waveforms produced by simulation Yes
Cortex-Debug RISC-V/MCU GDB debugging Yes
Verilog/SystemVerilog language plugin Syntax highlighting, navigation, and lint No; choose per your license and team standards

Offline environments require an administrator to prepare the dependency-extension VSIX files in advance; when the Marketplace is unreachable, the main EvoVerse VSIX will not download dependency extensions on the customer's behalf.

6. Restart VS Code and complete the first-run bootstrap

  1. Reload VS Code (Developer: Reload Window or restart) so the extensions activate;
  2. On first activation a dialog asks "Set up EvoVerse SDK?" — choose Yes, set up. The bootstrap creates the Catalog, project, and runtime directories under the default workspace ~/evoverse-sdk (the path can be changed with evoverse.home) and does not modify system files;
  3. Watch Output → EvoVerse SDK: the bootstrap prints one item at a time, and after all items show ✓ you see === EvoVerse SDK ready ===:
  4. EVOVERSE_HOME ready at … — the workspace is ready;
  5. Deployed Efinity knowledge base — the knowledge base is deployed;
  6. MCP integration: … — merges servers.evoverse into the VS Code user-level mcp.json (on Windows %APPDATA%\Code\User\mcp.json; existing entries for other servers are untouched, and a backup mcp.json.evoverse.bak is written before any overwrite);
  7. CLI works: … — the CLI smoke test;
  8. If Git is not on PATH you get a ! git not found warning; Sync Catalog becomes usable only after Git is installed;
  9. If Python is missing or too old, SYSTEM_PYTHON_MISSING is reported; install Python 3.11+ and rerun the bootstrap;
  10. When the completion notice appears, choose Restart now to reload the window.

Verify: after the restart the Welcome page opens automatically. If it does not, run EvoVerse: Show Welcome (evoverse.welcome) from the command palette.

If you chose Later in the dialog, or you need to rerun the bootstrap, run EvoVerse: Set Up (re-run bootstrap) (evoverse.setup). Standard VS Code never creates or writes ~/.trae; if an enterprise policy locks the configuration directory and MCP auto-registration fails, merge manually per §10.2.

7. Sync the Catalog

On a fresh install the Catalog is empty and the UI and MCP report CATALOG_NOT_INSTALLED — this is the expected state, not a failure.

  1. Run EvoVerse: Sync Catalog (evoverse.syncCatalog). The sync pulls from the official public release repository (evoverse-catalog-release) by default—no GitHub account is required; when GitHub is unreachable (network errors), the sync automatically retries from the Gitee domestic mirror carrying the identical release, and the receipt records which repository actually served it; it verifies integrity via treeDigest and then switches the local version transactionally;
  2. Run EvoVerse: Catalog Status (evoverse.catalogStatus), or run evoverse catalog status --json in a terminal, and record catalogVersion, commit, and treeDigest.

To use a self-hosted mirror or a private repository instead, override the repository URL with evoverse sync --repository <URL> or the EVOVERSE_CATALOG_REPOSITORY environment variable.

Verify: the Welcome page's Board Catalog panel lists boards (for example ws-e1). A failed sync does not affect existing local content; fix the network and sync again.

8. Verify the installation

  1. The EvoVerse entry in the left activity bar opens;
  2. The Workbench shows the installed Adapters;
  3. Run EvoVerse: Health Check (evoverse.sdkHealthCheck) and confirm that Python / Efinity / MCP / simulator / CLI / Adapter all pass (the Welcome page also has an SDK health panel);
  4. Complete Settings, MCP, project rules, and model configuration per §10.

9. Configure Settings and environment variables

9.1 Settings

Open Settings and search for evoverse, or fill in the user settings.json (replace the paths with the real ones on the customer machine):

{
  "evoverse.home": "D:\\EvoVerse",
  "evoverse.pythonPath": "C:\\Users\\<user>\\AppData\\Local\\Programs\\Python\\Python312\\python.exe",
  "evoverse.efinityPath": "C:\\Efinity\\2026.1",
  "evoverse.simulator": "iverilog",
  "evoverse.iverilogPath": "C:\\iverilog\\bin",
  "evoverse.build.parallelJobs": 4,
  "evoverse.build.autoOpenReport": true,
  "evoverse.program.defaultMode": "jtag"
}

Linux example:

{
  "evoverse.home": "/home/<user>/evoverse-sdk",
  "evoverse.pythonPath": "/usr/bin/python3",
  "evoverse.efinityPath": "/opt/efinity/2026.1",
  "evoverse.simulator": "iverilog",
  "evoverse.iverilogPath": "/usr/bin"
}

evoverse.iverilogPath points directly at the directory containing iverilog and vvp. When using QuestaSim:

{
  "evoverse.simulator": "questa",
  "evoverse.questaPath": "C:\\questasim64_2024.1\\win64"
}

evoverse.questaPath must directly contain vlib, vlog, and vsim.

9.2 Environment variables

Prefer evoverse.* Settings; set system environment variables only when the CLI, MCP, or an enterprise deployment needs paths shared across processes.

Variable Required? Purpose
EVOVERSE_HOME Recommended for MCP Root of the Catalog and projects
EVOVERSE_CLI Recommended for MCP Absolute path of the EvoVerse CLI
PYTHONUTF8=1 Recommended for Windows MCP Keeps JSON/logs UTF-8 for both Chinese and English
EFINITY_HOME Usually no need to set permanently Efinity root; the extension builds the child-process environment from the setting
PATH As needed Lets terminals find Python, Git, Icarus, Java, and the RISC-V GCC

Example for the current user in Windows PowerShell:

[Environment]::SetEnvironmentVariable('EVOVERSE_HOME', "$HOME\evoverse-sdk", 'User')
[Environment]::SetEnvironmentVariable('PYTHONUTF8', '1', 'User')

After writing to a shell profile you must reopen VS Code so the MCP child process inherits the new environment.

10. Configure how the Agent works

10.1 Two Q&A entry points

The VS Code native Chat Agent and the EvoVerse built-in Conversation Runtime are two independent sessions:

Entry point Model configuration Source of EvoVerse tools Shared session history?
VS Code native Chat Agent VS Code Chat model picker The EvoVerse MCP configured in VS Code No
EvoVerse Timing Diagnosis / Build AI evoverse.model.* Extension-internal context and toolchain No

Prefer the native Chat Agent for writing files and running terminal commands, so multiple agents never auto-modify the same workspace concurrently. The native Chat Agent cannot act directly as evoverse.model.provider; to have both entry points use the same host model, select the model in native Chat and configure the built-in Runtime as vscode-lm.

10.2 EvoVerse MCP

The first-run bootstrap in §6 has already registered the MCP; this section is the verification method and the manual fallback.

Verify: after reloading, run MCP: List Servers:

  1. evoverse shows as Running;
  2. The tools list shows list_boards, validate_manifest, check_rtl_code_style, and so on;
  3. In Chat Agent mode, ask "Use the EvoVerse tools to list the available boards" — the result must come from the actual Catalog, not from model memory;
  4. If MCP reports errors, inspect the logs via MCP: List Servers → evoverse → Show Output.

Manual fallback (when auto-registration did not take effect): first confirm the paths —

py -3 --version
Test-Path "$HOME\evoverse-sdk\mcp-server\server.py"
Test-Path "$HOME\evoverse-sdk\cli\evoverse"

Merge the following into the mcp.json opened by MCP: Open User Configuration:

{
  "servers": {
    "evoverse": {
      "command": "py",
      "args": [
        "-3",
        "C:\\Users\\<user>\\evoverse-sdk\\mcp-server\\server.py"
      ],
      "env": {
        "EVOVERSE_HOME": "C:\\Users\\<user>\\evoverse-sdk",
        "EVOVERSE_CLI": "C:\\Users\\<user>\\evoverse-sdk\\cli\\evoverse",
        "PYTHONUTF8": "1"
      }
    }
  }
}

If the machine has no py launcher, set command to the absolute path of python.exe and remove -3 from args. Linux example:

{
  "servers": {
    "evoverse": {
      "command": "/usr/bin/python3",
      "args": [
        "/home/<user>/evoverse-sdk/mcp-server/server.py"
      ],
      "env": {
        "EVOVERSE_HOME": "/home/<user>/evoverse-sdk",
        "EVOVERSE_CLI": "/home/<user>/evoverse-sdk/cli/evoverse",
        "PYTHONUTF8": "1"
      }
    }
  }
}

Scope choice: user-level (available in every workspace — a good fit for a dedicated workstation) or workspace-level (<project>/.vscode/mcp.json — good for team sharing, but never commit usernames or absolute paths). Under Remote/SSH/WSL the MCP runs in the environment where the configuration lives; use remote paths and the remote Python. Never write a model API key into mcp.json. The customer confirms authorization on first tool use; do not enable unrestricted auto-approval.

10.3 Project rules and engineering instructions

Describe the new or take-over project in natural language in Chat; the Agent shows the current action via the project_next envelope of Workbench Control and executes after you confirm. When the project is created, VS Code instructions are generated from the official rule assets:

~/evoverse-sdk/agent-rules/rules.md
~/evoverse-sdk/agent-rules/rules-rtl-style.md

It generates .github/copilot-instructions.md and .github/instructions/rtl.instructions.md. VS Code officially supports these three file kinds (copilot-instructions.md, a root AGENTS.md, and instructions/*.instructions.md); see Use custom instructions in VS Code.

Existing projects (not going through the new-project flow) can generate them manually:

New-Item -ItemType Directory -Force ".github\instructions" | Out-Null
Copy-Item "$HOME\evoverse-sdk\agent-rules\rules.md" ".github\copilot-instructions.md"
$header = "---`nname: EvoVerse RTL rules`ndescription: Mandatory RTL, CDC, reset and verification rules`napplyTo: `"**/*.{v,sv,vh,sdc}`"`n---`n`n"
$header + (Get-Content "$HOME\evoverse-sdk\agent-rules\rules-rtl-style.md" -Raw) | Set-Content ".github\instructions\rtl.instructions.md" -Encoding utf8

Linux:

mkdir -p .github/instructions
cp "$HOME/evoverse-sdk/agent-rules/rules.md" .github/copilot-instructions.md
printf '%s\n' '---' 'name: EvoVerse RTL rules' 'description: Mandatory RTL, CDC, reset and verification rules' 'applyTo: "**/*.{v,sv,vh,sdc}"' '---' '' > .github/instructions/rtl.instructions.md
cat "$HOME/evoverse-sdk/agent-rules/rules-rtl-style.md" >> .github/instructions/rtl.instructions.md

The key approval boundaries after generation include: inspect evoverse-project.md, the constraints, and the board/IP manifests before changing RTL; never claim timing closure before the build and simulation pass; never program the board or apply an optimization candidate without explicit approval. Model output cannot serve as proof of functional or timing correctness.

Confirm in Settings:

{
  "chat.useAgentsMdFile": true,
  "chat.instructionsFilesLocations": {
    ".github/instructions": true
  }
}

In Chat's Customizations/Diagnostics, confirm that both instruction files are loaded. Custom instructions influence Chat/Agent behavior but are not guaranteed to influence verbatim inline completion; the final authority remains EvoVerse's deterministic checks.

10.4 Model configuration (Timing Diagnosis / Build AI)

Host model (vscode-lm): install and sign in to GitHub Copilot → confirm in VS Code Chat that the target model is available → set "evoverse.model.provider": "vscode-lm" in Settings → run EvoVerse: Select AI Model and pick from the list the host actually returns (the exact Model ID is saved) → reload the window. EvoVerse never silently picks the first model; if you do not know the exact ID, confirm it with the picker first, or switch to OpenAI-compatible.

Bring your own API key (openai-compatible): fits OpenAI, DeepSeek, Zhipu, MiniMax, or corporate gateways. The service must support the OpenAI Chat Completions format:

{
  "evoverse.model.provider": "openai-compatible",
  "evoverse.model.modelId": "<endpoint-model-id>",
  "evoverse.model.baseUrl": "https://<provider-host>/v1/",
  "evoverse.model.allowLocalHttp": false
}

Configuration steps:

  1. Obtain the API key, Base URL, and exact Model ID from your provider;
  2. Fill in the three values above;
  3. Run EvoVerse: Set OpenAI-compatible API Key — the key is stored in VS Code SecretStorage;
  4. Run Developer: Reload Window;
  5. On the first question, review the outgoing-size prompt and choose Send.

baseUrl takes only the API root path; EvoVerse appends chat/completions itself. Never put the key into settings, MCP, or the project repository. Local endpoints are limited to localhost/loopback addresses with allowLocalHttp explicitly enabled. Common services:

Service evoverse.model.baseUrl Example modelId
OpenAI API https://api.openai.com/v1/ An OpenAI model ID actually available to the account
DeepSeek https://api.deepseek.com/v1/ deepseek-chat
Zhipu BigModel https://open.bigmodel.cn/api/paas/v4/ A GLM model ID actually available to the account
MiniMax https://api.minimaxi.com/v1/ A MiniMax model ID actually available to the account
Corporate aggregation gateway The HTTPS /v1/-compatible root URL provided by the company The model ID published by the gateway

The built-in Runtime currently has no native Anthropic Messages API Provider. To use Claude: select a Claude model actually exposed by VS Code under vscode-lm, or go through a gateway that offers OpenAI-compatible Chat Completions; do not paste an Anthropic-native Base URL into this section's configuration.

Verify: open a project that has built successfully and contains a timing report → Toolchain: Diagnose Timing Violations → click Ask AI and confirm the streaming reply → ask a follow-up question to confirm multi-turn context → in the Build Report click Ask AI Agent and confirm you receive an answer with a build summary. The answer should cite the current report's WNS/TNS, clock domains, or critical paths; model suggestions are for analysis only and cannot replace simulation, CDC checks, and the Efinity timing report.

11. Start using

  1. Start in natural language: describe the requirement in the VS Code native Chat (Agent mode); the Agent proceeds step by step through the project_next envelope with confirmation. Without a native Chat Agent, use the Workbench's Project Control dropdown to pick the design flow (EvoVerse: Select Design Flow, evoverse.selectDesignFlow);
  2. The Workbench's six tabs: Home / Build / Timing / Debug / SW / IP;
  3. Build: the Build tab or Toolchain: Build (evoverse.build). The build is executed by the Efinity Adapter via efx_run --flow compile, and the status bar shows Build: Ready / Running / Failed;
  4. Simulate: Toolchain: Simulate (evoverse.sim); open VCDs with VaporView;
  5. Timing diagnosis: Toolchain: Diagnose Timing Violations (evoverse.diagnoseTiming);
  6. Program: Toolchain: Program FPGA (evoverse.program).

For the full daily development workflow, see the User Manual.

12. Step-by-step acceptance

Do not jump straight to programming; pass each step in order before continuing.

12.1 Basics and the Catalog

  1. Open the EvoVerse Activity Bar and confirm that ws-e1 exists in the Board Catalog;
  2. Run EvoVerse: Show Knowledge Base and confirm the knowledge base opens;
  3. Describe a minimal project goal in Chat, confirm the project_next envelope, and create the project;
  4. Confirm the project contains evoverse-project.md, .github/copilot-instructions.md, and .github/instructions/rtl.instructions.md.

12.2 Rules and MCP

  1. Open an RTL file and run Toolchain: Check This File's Code Style;
  2. In Chat's Customizations/Diagnostics, confirm the rule files are loaded;
  3. Run MCP: List Servers, confirm evoverse is Running, and that list_boards results come from the actual Catalog.

12.3 Simulation

  1. The project contains a testbench;
  2. Run Toolchain: Simulate; iverilog and vvp report success in Output;
  3. When a VCD is produced, open it with VaporView and confirm the clock, reset, and output behavior.

12.4 Efinity build and timing

  1. Run Toolchain: Project Health Check and fix missing SDC, device, or source-file issues;
  2. Run Toolchain: Build (Full Flow);
  3. In the Build Report, confirm that Resources, I/O/Clock, Timing, and Critical Paths are readable;
  4. Run Toolchain: Diagnose Timing Violations; treat AI suggestions as inference only — WNS/TNS, CDC, simulation, and build results are the verification evidence.

12.5 Programming

  1. With the board powered off, confirm jumpers, voltages, JTAG, and boot mode;
  2. Connect power and the USB data cable;
  3. In the Efinity Programmer, first confirm the target device enumerates;
  4. Return to VS Code and run Toolchain: Program FPGA;
  5. If you see "no FTDI device", check the data cable, drivers, permissions, hubs, and board power.

12.6 Optional RISC-V

  1. Configure the Sapphire SoC IP and sync it from Efinity;
  2. Run Software: Sync BSP from SoC IP;
  3. Run Software: Build App…;
  4. Run Software: Program FPGA…;
  5. After confirming Cortex-Debug, GDB, and the debugger paths, run Software: Debug App….

13. Troubleshooting

Symptom Check
Set Up reports SYSTEM_PYTHON_MISSING Install Python 3.11+, or point evoverse.pythonPath at the interpreter's absolute path, reload, and rerun Set Up
MCP exits immediately on start Check command, server.py, EVOVERSE_HOME, and JSON escaping; open the MCP Output
MCP has a server but no tools Restart the server, confirm the running server.py is the one extracted from the VSIX, and check Python stderr
Chat ignores the RTL rules Check .github/copilot-instructions.md, the RTL instruction, Customizations/Diagnostics, and the applyTo glob
Sync Catalog fails Confirm Git is on PATH and the network is reachable; the default public repository needs no GitHub account; see the Deployment Guide
Build cannot find Efinity Check that evoverse.efinityPath points at the installation root rather than bin, and that the setup script exists
IP Manager fails to start Check the 64-bit Java version, PATH, and the Efinity version requirements
Simulation cannot find executables Check evoverse.simulator; point the path directly at the directory containing iverilog/vvp or vlib/vlog/vsim
FPGA/FTDI not found Check the USB data cable, drivers, udev/Zadig, board power, and JTAG mode
AI shows model unavailable Set the exact evoverse.model.modelId explicitly; check authorization or the endpoint's model names
MCP paths invalid under Remote/WSL The MCP runs in the environment where the configuration lives; use the remote Python and remote file paths

14. Delivery acceptance checklist

  • [ ] VS Code Stable 64-bit launches;
  • [ ] The 3 EvoVerse VSIXes (same version 1.0.0) and the required dependency extensions are installed and Enabled;
  • [ ] Python 3.11+ and Git are executable;
  • [ ] The first-run bootstrap completed, === EvoVerse SDK ready ===, and the CLI smoke test passed;
  • [ ] The Welcome page opened automatically and the Board Catalog lists boards after Sync Catalog;
  • [ ] Efinity, the license, Java, and the USB drivers are done;
  • [ ] Icarus iverilog/vvp are executable;
  • [ ] The EvoVerse MCP is Running and its tools are callable;
  • [ ] Both the general and RTL custom instructions are loaded;
  • [ ] The minimal simulation passes and waveforms can be viewed;
  • [ ] The Full Build succeeds and produces resource/timing reports;
  • [ ] Timing Diagnosis opens;
  • [ ] Efinity enumerates the FPGA and programming succeeds;
  • [ ] If RISC-V is needed, the full BSP, GCC, GDB, and Cortex-Debug chain passes;
  • [ ] The team understands that model inference cannot replace simulation, STA, CDC, and hardware verification.
Advanced references are for on-demand lookup; design records, release procedures, audit reports and future plans are not customer entry points.
