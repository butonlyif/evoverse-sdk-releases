Project-Aware Efinity AI Build Review

Project-Aware Efinity AI Build Review

The efinity-build-review skill explains an existing Efinity project and its native build evidence. It supports EvoVerse projects and customer-native projects without .evoverse, including arbitrary source layouts and flist/include references.

Use it

Open the project folder in Trae and enter:

/efinity-build-review
Review this Efinity project. Let me select the project XML, then explain the design structure, build stages, resources, timing, constraint coverage, artifacts, critical-path source correlation, and next actions.

When multiple Efinity XML files exist, the skill requires an explicit selection. It analyzes existing reports by default and asks before starting a new native build.

Read the result

The report keeps Flow, Artifact, Timing, Resource, Constraint, and Freshness separate:

  • BLOCKED: the build failed or evidence is insufficient.
  • BUILT_NOT_READY: build output exists, but timing, freshness, or another condition blocks readiness.
  • READY_WITH_RISK: proceed to verification only with the stated risks.
  • READY_FOR_VERIFICATION: build evidence supports the next verification step; this is not a simulation, programming, or hardware pass.

An mtime-only check can produce POSSIBLY_STALE, never strong CURRENT. Missing facts remain NOT_AVAILABLE or UNKNOWN, not zero.

Source correlation and advice safety

Path locations are labeled EXACT, SYMBOL_MATCH, SEMANTIC_CANDIDATE, HEURISTIC, or UNRESOLVED. Only an authorized native-report file:line annotation is EXACT. Ambiguous candidates remain visible. Verilog/SystemVerilog uses a structured tokenizer/parser to model modules, instances, ports, parameters, processes, assignments, functions, generate blocks, arrays, source ranges, and driver-consumer edges, then uses data cones to support correlation. Incomplete macro/parameter elaboration, VHDL, generated units, and encrypted units degrade explicitly instead of pretending to be fully elaborated.

Pipeline advice checks feedback, FSM state, valid/ready, packet boundaries, reset/clock enable, fixed latency, RAM/DSP behavior, CDC, multiple consumers, and verification assets. The path drawer presents the data cone, candidate locations, pipeline suitability, strategy matrix, functional impact, and verification checklist together. Missing semantic evidence yields UNKNOWN. I/O delays require external-device and PCB timing parameters. Timing exceptions require structural evidence, design-intent evidence, and user confirmation. The skill does not invent values or silently edit RTL, SDC, ISF, or XML.

Reports and export

Each local review is atomically promoted from a temporary directory into a new non-overwriting directory containing review.json, evidence.json, report.html, and report.md; failure or cancellation cannot leave a partial review that looks complete. Exported HTML remains script-free under a strict CSP. The IDE Webview injects only a nonce-bound local bridge and revalidates evidence ID, file existence, and line number before opening source, so customer content cannot invoke commands directly. The HTML has a print stylesheet; PDF support currently means IDE/browser “Print to PDF”, not a built-in deterministic PDF engine.

Customer export removes local paths and source bodies, then scans for absolute paths, credential-like text, and environment values. Findings fail closed. Comparison first checks project, device, and top-module compatibility, then reports changes in WNS/TNS, resources, duration, paths, constraints, and issue clusters. Without fresh native after-build evidence, a strategy cannot become IMPROVED, NO_CHANGE, or REGRESSED.

Verification boundary

Compile, Timing, Simulation, Programming, and Hardware are independent results. A native map/interface/PNR/PGM pass and bitstream do not prove simulation, download, or board behavior. Resources, WNS/TNS, stages, and the top-level verdict come from deterministic parsing; AI provides only explanation, risk analysis, and verifiable recommendations.

Advanced references are for on-demand lookup; design records, release procedures, audit reports and future plans are not customer entry points.
