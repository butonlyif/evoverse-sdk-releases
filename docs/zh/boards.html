Catalog 物料与获取

适用版本：v1.0.0　适用对象：拿到客户交付包的全部用户

这页讲什么

EvoVerse SDK 的板卡、参考设计与 IP 物料不随安装包分发。它们集中存放在唯一的私有 Catalog 仓库中，安装扩展后按授权同步到本地。本页说明 Catalog 里有什么、如何获得访问权限、如何同步；具体板卡的规格与 datasheet 不在本页展开，同步后随物料一起提供。

Catalog 里有什么

物料类别 说明
板卡定义 核心板的板卡数据（供自然语言工程创建、pinout 与约束生成使用）
底板与扩展 底板（carrier）定义与扩展接口信息
参考设计 Jacket 可一键创建的完整参考工程（含规格与实施说明）
Demo 工程 面向各板卡的示例工程
IP 物料 随 Catalog 分发的 IP 核与配套文档
板卡文档 各板卡的规格书、datasheet 与参考设计说明（随同步落地到本地）

当前提供哪些板卡、Jacket 与 IP，以同步后的 Catalog 实际内容为准，不在交付包中静态罗列。

获取流程

  1. 把自己的 GitHub 用户名（不是邮箱）告知 EvoVerse 运营人员，等待 evoverse-catalog 私有仓库的只读邀请。
  2. 在邮箱中接受邀请。仓库地址对扩展可见，但没有 GitHub 授权仍无法读取内容。
  3. 用 Git Credential Manager 或 GitHub CLI 在本机完成该账户认证。不要索取或使用团队共享 PAT。
  4. 在 Trae / VS Code 左侧打开「Board Catalog」视图点刷新，或运行命令 EvoVerse: Sync Catalog。
  5. 同步完成后，Welcome 与 Trae 自然语言工程流程即可看到全部板卡、Demo 与 IP。

同步后物料在哪里

物料安装到 evoverse.home（默认 ~/evoverse-sdk）下的 catalog/ 目录：

  • catalog/boards/<板卡>/ — 板卡数据与随板维护的文档（规格、datasheet、参考设计说明）
  • 上一版本会保留为 catalog.previous/，供离线回退

可用 evoverse catalog status --json 查看当前 catalogVersion、commit 与 treeDigest。

常见状态与问题

现象 说明与处理
CATALOG_NOT_INSTALLED 尚未同步，属预期状态；完成上述获取流程后 Sync 即可
同步失败（网络/鉴权） 修复网络或 GitHub 认证后重试；已有版本不受影响
新版本同步失败但本地版本健康 可运行 EvoVerse: Roll Back Catalog 离线回退到 catalog.previous
物料更新 运营发布新版 Catalog 后重新 Sync 即可，无需重装扩展

设计说明

物料不打进安装包是刻意的访问控制设计：Catalog 通过 GitHub 只读授权按客户发放，扩展安装时会主动校验 VSIX 内不含 Catalog 物料。板卡文档与板卡数据在同一仓库中同版本演进，因此文档也随物料同步，而不是随安装包静态分发。

高级参考用于按需查询；设计记录、发布流程、审计报告和未来规划不属于客户操作入口。
