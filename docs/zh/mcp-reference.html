可靠设计与证据 · 11

efinity_debug_intent_create

以自然语言观察目标创建权威 Debug Intent（DRAFT）。多 XML 工程必须显式给 project_xml；信号由 Adapter 权威发现，调用方不可提供候选。

必填：projectproject_xmlgoals

efinity_debug_intent_read

读取当前权威 Intent 状态（revision/status/候选/回执），供刷新与并发读取。

必填：projectproject_xmlintent_id

efinity_debug_intent_revise

修订观察目标：作废候选与回执并回到 DRAFT，服务端重绑当前输入摘要。

必填：projectproject_xmlintent_idexpected_revisiongoals

evoverse_health

检查 EvoVerse MCP 与已加载控制引擎是否可用或需要重连；不读取或修改工程。

必填：无

project_execute

以 expectedRevision + actionId + inputs 执行服务端下发的 ActionDescriptor。expectedRevision 只是提示值，服务始终按最新 revision 追加；requestId 用于幂等重放，未提供时服务端自动生成。spec.draft 的 inputs.packagePath 必须指向密封的可执行 2.0 包目录（JSON 为权威，specification.md 只是生成的评审视图），Markdown 文件会被拒绝。失败时读取 error.recovery 中的恢复/对账动作，禁止改用 CLI 代跑。

必填：projectexpectedRevisionactionIdinputs

可选：requestId

project_next

返回当前 revision 下服务端允许的动作列表（ActionDescriptor：actionId、inputSchema、preconditions、blockedReasons、effect、requiredCapability、executionPolicy）。只读；不得自行计算下一步动作。

必填：project

project_status

读取 Project Control Plane 的当前权威投影：revision、baseline、intents、assets、evidence、materials、specs、candidates、compositions。只读；UI/CLI/MCP/Skill 都必须以它为准。每个控制面响应（含错误）都带 envelope 层 runtime 块：stale=true 表示服务进程加载的引擎模块与磁盘部署不一致，recovery=reload-mcp-session 时应重连 MCP 再重试；响应缺 runtime 块说明服务进程早于该自报能力，同样应重连。

必填：project

rk3588_project_build

按固定 U-Boot、kernel/DTB、rootfs、package 四阶段构建当前工程。

必填：projectstages

rk3588_project_generate

从已验证 WS-E2 Catalog 物料和已部署 BSP 生成绑定的 RK3588 minimal Linux 工程。

必填：projectboardcarrierreferenceProject

rk3588_project_preflight

复验当前 RK3588 工程的 BSP、Profile、DTS 和构建输入。

必填：project

rk3588_project_status

读取并复验当前 RK3588 工程的 readiness、阶段与产物证据。

必填：project

构建、软件与 IP · 1

efinity_debug_build

PROFILE_READY 后执行统一 Debug Build（efx_run --flow compile + 自动实例化），要求全阶段 PASS 与新鲜比特流/调试工件，进入 READY_TO_PROGRAM。需要独立铸造的一次性 BUILD 确认（已确认的 Apply 不授权 Build）；编译产物 jtag_user 与确认 USER TAP 漂移时拒绝（DEBUG_BUILD_REJECTED）。

必填：projectproject_xmlintent_idexpected_revision

调试、烧录与时序 · 3

efinity_debug_selection_apply

消费一次性预览回执：厂商原生生成 profile/debug core RTL 并原子发布，进入 PROFILE_READY。需要 Workbench 可信 host 铸造的一次性 APPLY 确认；无确认的调用一律拒绝。

必填：projectproject_xmlintent_idexpected_revisionreceipt_id

efinity_debug_selection_preview

对结构化选择（标量 ID/探针类型/采样时钟/深度/USER TAP 闭合枚举 USER1|USER2）生成原生 profile 预览与一次性回执；时钟域未证明或漂移时失败关闭。对话流程到 discovery 为止：确认、应用与编译由用户在 Workbench Debug 页驱动。

必填：projectproject_xmlintent_idexpected_revisionselection

efinity_debug_signals_discover

用原生 sta_tclsh 从当前编译数据库发现真实网表候选；无当前基线返回 BASELINE_BUILD_REQUIRED，绝不隐式触发构建。

必填：projectproject_xmlintent_idexpected_revision

其他 SDK 能力 · 6

efinity_review_collect

为用户明确选择的原生 Efinity XML 收集确定性 Build Review 证据。这是正式评审的第一步；不得用自由文本分析替代。

必填：projectprojectXml

efinity_review_render

最终校验并原子生成 review.json、evidence.json、report.html/report.md（中文为主）和report-en.html/report-en.md（纯英文镜像）。传 review 生成完整 AI 评审；AI 不可用时传mode=deterministic 生成合法的确定性降级报告。已存在的 reviewId 不会被覆盖。

必填：projectprojectXml

可选：review、mode

efinity_review_validate

诊断 closed AIReviewDocument 的 schema 和证据引用错误。正常流程可直接调用 efinity_review_render，因为 render 会执行同一校验并仅在 valid=true 时写产物。

必填：projectprojectXmlreview

rk3588_environment_deploy

在用户明确接受许可证后，用一次性 token 部署已检查的 RK3588 离线环境。

必填：inspectionTokenacceptedLicenses

rk3588_environment_prepare

检查固定离线包收件箱并在可部署时返回一次性 inspection token。

必填：无

rk3588_environment_status

只读检查 RK3588 宿主、Docker、工具链、BSP 与安装收据状态。

必填：无
