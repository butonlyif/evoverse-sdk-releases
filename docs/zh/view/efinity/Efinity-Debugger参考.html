Efinity Debugger 参考

Efinity Debugger 参考

版本: v1.0 | 基于 Efinity 2026.1 (HLP-EFN-DBG-v2.0)

1. Debugger 概述

Efinity Debugger 是基于 JTAG 接口的 FPGA 硬件调试工具，提供两个透视图（Perspective）：

  • Profile Editor Perspective：手动配置调试核心（Debug Core）的界面
  • Debug Perspective：运行时观察探针信号值的界面

Debugger 包含两种调试核心： - Virtual I/O (VIO)：支持探针输入和输出，模拟虚拟 IO - Logic Analyzer (LA)：采样和捕获内部信号波形

最低频率要求： 调试核心的最低工作频率为 2 倍的 JTAG TCK 频率。

来源: C:\Efinity\2026.1\debugger\doc\topics\hlp-dbg-intro.html

2. 调试工作流程

  1. 创建 debug profile（VIO 和/或 LA 核心）
  2. 生成 debug design file 并添加到项目
  3. 编译
  4. 烧录 FPGA
  5. 运行 Debugger GUI 观察探针值

3. Debug Profile JSON 格式

Debug Profile 是一个 JSON 文件，定义调试核心的配置。关键结构：

{
    "debug_cores": [
        {
            "name": "vio0",
            "type": "vio",
            "uuid": "b60ce617846c46eb85bdb96be34cc1b0",
            "probes": [
                {"name": "counter", "width": 29, "init": null},
                {"name": "vio_reverse", "width": 1, "init": "0x0"}
            ]
        },
        {
            "name": "la0",
            "type": "la",
            "uuid": "55ccee6a763c4221a397cfa01e4fa0b2",
            "probes": [
                {"name": "counter", "width": 29, "probe_type": 1}
            ],
            "data_depth": 1024,
            "trigin_en": false,
            "trigout_en": false,
            "capture_control": false,
            "input_pipeline": 1,
            "auto_inserted": false
        }
    ],
    "session": {"debug_widget": [], "wizard": {}},
    "jtag_user": "USER1"
}

关键字段： | 字段 | 说明 | |------|------| | debug_cores | 调试核心数组，可包含多个 VIO 和 LA | | type | 核心类型："vio" 或 "la" | | uuid | 128 位唯一标识符，用于 JTAG 路由 | | probes[].probe_type | LA 探针类型：1=Data and Trigger | | data_depth | LA 缓冲区深度（使用片上 RAM）| | trigin_en / trigout_en | 触发输入/输出使能 | | capture_control | 捕获控制使能（消耗更多资源）| | auto_inserted | 是否由 Debug Wizard 自动生成 | | jtag_user | JTAG USER TAP："USER1" 或 "USER2" |

来源: C:\Efinity\2026.1\examples\helloworld-dbg_GOLDEN\dbg_manual.json

4. VIO Debug Core

用途： 在调试过程中驱动内部信号（输出探针）和观察内部信号（输入探针）。

参数： | 参数 | 说明 | |------|------| | NUM_PROBE_IN | 输入探针数量（从 FPGA 读取的信号）| | NUM_PROBE_OUT | 输出探针数量（驱动 FPGA 的信号）| | PROBE_INn_WIDTH | 第 n 个输入探针的位宽 | | PROBE_OUTn_WIDTH | 第 n 个输出探针的位宽 | | UUID | 128 位唯一标识 | | 数据深度 | 4096 |

探针类型： - Probe Inputs (probe_in): 从设计读取信号值 - Probe Outputs (probe_out): 向设计写入信号值（可设置初始值 init）

来源: C:\Efinity\2026.1\debugger\doc\topics\dbg-vio.html

5. LA Debug Core

用途： 捕获内部信号的时序波形，类似逻辑分析仪。

参数： | 参数 | 说明 | |------|------| | Buffer Depth | 缓冲区深度（4K、8K、16K 等），使用片上 RAM | | input_pipeline | 输入流水线级数（0-2）| | Capture Control | 启用后可在 Debug Perspective 的 Capture Setup 中切换捕获模式 | | Trigger Enable | 支持 triggers 来启动/停止捕获 |

探针类型 (probe_type)： | 值 | 类型 | 说明 | |----|------|------| | 1 | Data and Trigger | 数据 + 触发 | | 2 | Data Only | 仅数据 | | 3 | Trigger Only | 仅触发 |

捕获模式（Capture Mode）： - Immediately: 下载 bitstream 后立即开始捕获 - Wait for Trigger: 等待触发条件满足后开始捕获

来源: C:\Efinity\2026.1\debugger\doc\topics\dbg-la.html

6. Debug Wizard（调试向导）

用途： 为 Logic Analyzer 提供自动化的添加流程。适用于多层级复杂设计。

工作流程： 1. 启动 Debug Wizard 2. 选择 buffer depth（影响 RAM 使用量） 3. 可选启用 Capture Control 4. 选择 JTAG User TAP（USER1/USER2） 5. 选择信号源：Elaborated Netlist 或 Post-Map 网表 6. 选择信号并通过箭头添加（支持正则过滤） 7. 指定每个信号的探针类型（Data+Trigger / Data Only / Trigger Only） 8. 点击 Next，向导自动生成核心并连接 9. 开启 Enable Auto Instantiation 10. 点击 Finish

生成文件： | 文件 | 说明 | |------|------| | debug_profile.wizard.json | 向导创建的 debug profile | | debug_TEMPLATE.v | 调试模板（含模块实例化）| | debug_top.v | 调试核心的 RTL 逻辑 |

注意： - 需要 JTAG_USER1 或 JTAG_USER2 资源，如果该资源被 Debugger 占用，其他 JTAG 功能将无法使用 - 时钟域为 "Undefined" 的信号在 post-map 网表中无时钟驱动，需手动添加 LA 核心

来源: C:\Efinity\2026.1\debugger\doc\topics\dbg-wizard.html

7. mark_debug 综合属性

用途： 在 RTL 中标记需要调试的信号，综合工具自动生成包含这些信号的 debug profile。

Verilog 用法：

(* mark_debug = "true" *) wire [7:0] debug_signal;
// 或
(* mark_debug = "1" *) reg debug_reg;

VHDL 用法：

attribute mark_debug : string;
attribute mark_debug of debug_signal : signal is "true";

综合选项： - 启用：efx_map --enable-mark-debug（或 GUI 中开启 synthesis option） - 综合完成后生成 debug_profile.mark_debug.json - 可在 Debug Wizard 中导入该 profile

来源: C:\Efinity\2026.1\debugger\doc\topics\dbg-mark-debug.html

8. Debugger Auto Instantiation

项目 XML 配置 (<efx:debugger> 段)：

<efx:debugger>
    <efx:profile name="profile_path"/>
    <efx:auto_instantiation name=""/>
    <efx:work_dir name="work_directory"/>
</efx:debugger>

参数： | 参数 | 说明 | |------|------| | profile | debug profile JSON 文件路径 | | auto_instantiation | 是否启用自动实例化 | | work_dir | 调试核心工作目录 |

在 GUI 中： Project Editor → Debugger tab → Debugger Auto Instantiation 开关

CLI 触发条件（efx_run.py 源码验证，2026.1）： efx_run --flow compile 调度 run_debugger_auto_instantation 前有两道静默检查（check_and_set_auto_dbg_mark_dbg）：

  1. XML profile 参数指向的文件必须真实存在（os.path.isfile，相对 CWD=工程根）——不存在时 debug 流程整个静默跳过，日志无任何警告，编译照常"成功"
  2. mark_debug 自动生成流程（--mark_debug 模式）仅当 profile 值精确等于 outflow/debug_profile.mark_debug.json（args.output_dir + "/debug_profile.mark_debug.json" 字符串匹配，须写相对路径）时激活；此时 efx_run_dbg.py 用 DbgWizard.gen_debug_v_from_profile 从综合生成的 mark_debug profile 自动生成 debug core RTL

正确的最小 XML 配置（mark_debug 流程）：

<efx:debugger>
    <efx:param name="profile" value="outflow/debug_profile.mark_debug.json" value_type="e_string"/>
    <efx:param name="auto_instantiation" value="on" value_type="e_bool"/>
    <efx:param name="work_dir" value="work_dbg" value_type="e_string"/>
</efx:debugger>

验证日期: 2026-08-16（ws-e1-sys：profile 误指不存在路径 → 编译静默跳过 debug、work_dbg/ 不生成；改指 outflow 路径后修复）

首次编译的坑（2026-08-16 debug_flow_test 实测）： profile 文件尚不存在时就以 auto=on + profile=outflow/debug_profile.mark_debug.json 启动 compile，整个编译以 exit 1 崩溃（不是静默跳过）——An exception occurred: No such file: outflow\<design>.elab.vdb。机制： - efx_run.py:1249-1251：map 步骤仅在 flow 启动时 args.debug_profile 已设置（即 profile 文件当时已存在）才追加 --opt write-premap-module=<design>.elab.vdb 写出 elab 库 - efx_run_dbg.py:291-292：mark_debug（pre-map）profile 必须读 outflow/<design>.elab.vdb 做 VDB 合并 - 而同一轮 map 又会因 enable-mark-debug 把 mark_debug profile 生成出来并触发 debug 步骤 → 步骤找不到 elab.vdb 崩溃

正确的两次编译顺序（必须遵守）： build #1 用 auto=off（此时 enable-mark-debug 收集信号生成 profile JSON，无 debug 步骤）→ build #2 才 auto=on（flow 启动时 profile 已存在 → map 写 elab.vdb → efx_run_dbg 合并成功）。工具侧（SDK adapter preview 校验 + SDK saveBuildOptions）已按此收紧：auto=on 前置要求 profile 文件存在。

来源: C:\Efinity\2026.1\scripts\efx_run.py:129-145（check_and_set_auto_dbg_mark_dbg）、efx_run.py:1650-1702（run_debugger_auto_instantation）、efx_run.py:1249-1251（write-premap-module 条件）、efx_run_dbg.py:291-292（elab.vdb 依赖）

9. 命令行脚本

efx_run_dbg.py —— Debugger 自动实例化流程： - compile_dbg_core() — 编译调试核心 - merge_vdb() — 合并 VDB 文件 - insert_jtag() — 插入 JTAG user tap

使用方式：

efx_run.bat --flow compile  # 自动在编译中包含 debug 核心

来源: C:\Efinity\2026.1\scripts\efx_run_dbg.py

11. 并发调试 (Concurrent Debugging)

  • 可以打开多个 debug 窗口，同时连接到不同的 JTAG USER TAP 接口
  • 需要使用 Hardware Server 连接
  • 通过 Tools → Open Debugger 或多次点击 Debugger 图标打开多个窗口

来源: C:\Efinity\2026.1\debugger\doc\topics\dbg-concurrent.html

12. Debug Core 自动生成的 RTL 结构

以 helloworld-dbg_GOLDEN\dbg_manual_top.v 为例：

module dbg_manual_edb_top (
    // JTAG boundary scan 端口
    input  bscan_CAPTURE, bscan_DRCK, bscan_RESET, bscan_RUNTEST,
    input  bscan_SEL, bscan_SHIFT, bscan_TCK, bscan_TDI, bscan_TMS,
    input  bscan_UPDATE, output bscan_TDO,
    // VIO 时钟和探针
    input  vio0_clk, input [28:0] vio0_counter,
    input [3:0] vio0_raddr, input [5:0] vio0_led,
    output vio0_vio_reverse, output vio0_vio_mux_sel,
    output [3:0] vio0_vio_maddr,
    // LA 时钟和探针
    input  la0_clk, input [28:0] la0_counter,
    input [3:0] la0_raddr, input [5:0] la0_led
);
    // Debug Hub（JTAG 总线转换器）
    // edb_vio_top 实例化
    // edb_la_top 实例化
endmodule

结构层次：

debug_top.v
├── Debug Hub (JTAG → 内部总线)
├── VIO Core (edb_vio_top)
└── LA Core (edb_la_top)

来源: C:\Efinity\2026.1\examples\helloworld-dbg_GOLDEN\dbg_manual_top.v

14. 禁用 Debug Core

通过 GUI 操作： 1. 打开 Project Editor 2. 点击 Debugger tab 3. 关闭 Debugger Auto Instantiation 选项 4. 点击 OK 5. 重新编译

注意：禁用不会删除磁盘上的 debug profile，可以随时重新启用。

来源: C:\Efinity\2026.1\debugger\doc\topics\dbg-disable.html
