Efinity DesignAPI 方法参考

适用版本：Efinity 2026.1（PT / Periphery Toolchain） 调查日期：2026-09-25 调查方式：逐行实读 Efinity 2026.1 安装目录下的官方 Python 源码，全部结论附源码行号证据。 核心证据源： - C:\Efinity\2026.1\pt\bin\api_service\design.py（2810 行，DesignAPI 门面类真身） - C:\Efinity\2026.1\pt\bin\efx_run_pt_unified.py（393 行，unified flow 编排器） - C:\Efinity\2026.1\pt\bin\api_service\exim\isf_importer.py（435 行，ISF 导入器） - C:\Efinity\2026.1\pt\bin\design\service.py（DesignWriterXml，peri.xml 写出器）

0. 位置勘误与阅读指引

0.1 三条重要勘误（先读）

在查阅 Efinity DesignAPI 相关资料时，以下三个位置很容易搞错，本文以实读源码为准予以勘误：

勘误 1：DesignAPI 真身在 pt\bin\api_service\design.py，不是 design\db.py。

  • api_service\design.py L71 定义 class DesignAPI，是用户直接调用的门面类（Facade），约 2810 行，包含全部 create_*_gpio / set_property / assign_pkg_pin / import_design 等公开方法。
  • design\db.py（pt\bin\design\db.py）L64 定义的是 class PeriDesign(db_item.PeriDesignItem)——这是内部数据容器，保存 GPIO/PLL/IOBank 等对象的内存数据库，不对外提供操作语义。DesignAPI 通过 from design.db import PeriDesign（design.py L31）持有它。
  • 另有中间编排层 api_service\internal\int_design.py 的 IntDesignAPI（load L140 / create L316 / save L391 / create_block L758 / check_design L978 等），DesignAPI 的大部分生命周期方法都是对它的一层薄封装。

勘误 2：peri.xml 写出器 DesignWriterXml 在 pt\bin\design\service.py（L3476），不在 api_service\design\service.py（该路径不存在），也不在 writer 目录。

  • pt\bin\api_service\ 目录下没有 design 子包——api_service\design.py 是单文件模块，不是包。
  • pt\bin\design\service.py 顶层定义 class DesignService（L540）与 class DesignWriterXml（L3476），前者负责 peri.xml 的加载/保存编排，后者是真正的 XML 写出器。

勘误 3：peri.xml 的写出器只有一个，peri.xml 本身是"工程源文件"而非"构建生成物"。

  • 每次 unified build（efx_run --flow compile）都会加载已持久化的 <design>.peri.xml，并把工程 XML 引用的 ISF 重放上去（见第 3 节）。因此 peri.xml 必须随工程纳入版本管理，任何构建路径都不得在构建前删除它。
  • 它的根元素与命名空间是 efxpt:design_db / http://www.efinixinc.com/peri_design_db（service.py L3506、L3521-3526），与工程 XML 的 enf_proj 命名空间（http://www.efinixinc.com/enf_proj）是两个不同的 schema，详见《Efinity-XML工程文件Schema参考.md》。

0.3 与 ISF / peri.xml 的关系

  • ISF 是 Python API 源码：.isf 文件内容就是一行行 design.xxx(...) 调用，由 isf_importer.py 以 exec() 逐行执行（L236、L289）。这就是"ISF 语法错误 → 整个 import 立即终止"的根源（Python 的 SyntaxError 无法按行恢复，见 4.3 节异常矩阵）。
  • peri.xml 是对象数据库的 XML 序列化：ISF 执行产生的全部对象/属性/引脚分配最终写入 PeriDesign 容器，再由 DesignWriterXml 序列化为 <design>.peri.xml。
  • 重放安全：每次 build 都会重新执行 ISF 到已存在的 peri.xml 上，所以工程 XML 引用的 ISF 只能包含幂等命令（set_property / assign_pkg_pin / assign_resource / set_device_property / set_iobank_voltage）；create_* 是一次性 bootstrap，只能在 peri.xml 不存在时执行一次——ISF 命令集没有 delete/clear，重复 create_* 会报 "already exists" 类错误。此契约的完整表述见《Efinity-ISF语法参考.md》与硬约束规则 §15。

1.2 对象句柄模型

DesignAPI 的绝大多数方法第一个参数是 inst，类型为 BlockInstanceType = Union[str, int]（L68）：

  • 传 str：按实例名查找（如 "ddr0"、"my_pll"）。
  • 传 int：按内部 object_id 查找。
  • IOBank / SEU / RU / EXT_FLASH / CLKMUX 特殊：这些不是普通块，而是器件设置单例。__get_object_id（L2681）会把这类名字映射到器件设置对象（L2695-2713），所以 set_device_property("TL", "VOLTAGE", "3.3", "IOBANK") 可以直接用 bank 名作 inst。

1.3 block_type 体系

create_block(name, block_type, ...) 与属性方法的 block_type 参数使用如下块类型（在 design.py 各方法签名与 docstring 中出现）：

block_type 用途 关联硬 IP
GPIO 普通 GPIO / 总线 GPIO（禁用 create_block 创建，L196-197） —
PLL 锁相环 PLL
OSC 片上振荡器 OSC
LVDS_TX / LVDS_RX / LVDS_BIDIR LVDS 差分 LVDS
MIPI_TX_LANE / MIPI_RX_LANE MIPI Lane MIPI
JTAG JTAG JTAG
DDR DDR 控制器 DDR
PMA_DIRECT PMA 直通（PCIe/高速串行） PMA
QUAD_PCIE PCIe Quad PCIe
CM Clock Morphing / 时钟管理 CM

GPIO 连接类型（conn_type，由 14 个 create_*_gpio 固定注入）：GCLK（全局时钟）、RCLK（区域时钟）、PLL_CLKIN（PLL 参考时钟输入）、PLL_EXTFB（PLL 外部反馈）、MIPI_CLKIN（MIPI 时钟输入）、PCIE_PERSTN（PCIe 复位）、GCTRL（全局控制）、clkout（时钟输出）。

1.4 devset_type 体系

set_device_property / get_device_property / reset_device_settings 使用的器件设置类型（L576 docstring）：

devset_type 含义
IOBANK IO Bank（电压、mode_sel 等）
SEU SEU（软错误纠察）设置
RU 冗余/备用设置
EXT_FLASH 外部 SPI Flash 设置
CLKMUX 全局时钟复用（经 get/set_mode_sel_name、global mux 方法族操作）

3. efx_run_pt_unified.py 九步流程详解

3.1 流程定位与退出码

pt\bin\efx_run_pt_unified.py（393 行）是 unified flow 中 PT 阶段的编排器：定位/引导 peri.xml → 重放 ISF → 设计检查 → 生成约束报告 → 导出仿真/时序网表。退出码定义（L52-57）：

OK = 0
ERROR = 1
WARNING_SKIP = 0   # skip 时返回 0，避免中断 GUI 流程

注意 WARNING_SKIP 与 OK 同为 0：可跳过的情况（非支持 family、内部测试器件等）不算失败，这是为了让 efx_run --flow compile 的 GUI 流程不被 PT 侧的可跳过情形打断。

辅助函数： - check_bitstream_enabled(device, family)（L60-74）：调用 efx_pgm --query_bitstreams（L66-67）查询器件是否启用 bitstream。 - sync_design_file_efxproject(design_file, project_file)（L77-107）：工程改名后同步 peri.xml 文件名（写新文件、删旧文件；源码自带 tech debt 注释 L79-80）。

证据：pt\bin\api_service\exim\isf_importer.py（435 行）。

4.1 两条导入入口

4.2 exec + design 绑定：ISF 之所以是 Python

逐行模式核心 __import_line_code（L197）：

  • 以 UTF-8 读入文件（L202）；
  • design = self.design_api——源码注释原文 "Set design context for import, used by exec()"（L217）；
  • 跳过空行与 # 注释行（L227-228）；is_skip_resasg=True 时跳过 design.assign 前缀的行（L231-233）；
  • 逐行 exec(code)（L236）。

整文件模式核心 __import_code（L272-304）：

# L282
module = types.ModuleType(name)
# L287
setattr(module, "design", self.design_api)
# L289
exec(code, module.__dict__)

即：ISF 文件被当作 Python 模块体在临时模块命名空间中执行，且该命名空间里预置了名字 design → DesignAPI 实例。这就是 ISF 必须写成 design.xxx(...)、且本质是 Python 源码的直接证据——任何"自创 XML 约束格式"在 Efinity 的导入器眼里都是 Python 语法错误，必然被拒（历史教训见《Efinity-ISF语法参考.md》卷首）。

4.3 异常处理矩阵（L240-267）

逐行 exec 的异常分流决定了"ISF 错误是立即终止还是记账继续"：

异常 处理 后果
PTException 记账（__register_command_issue L351，severity=warning） 继续下一行
AttributeError 记账 + 打印 traceback 继续下一行
SyntaxError 记账（__register_syntax_issue L370，severity=error）+ break 整个导入立即终止
TypeError break 立即终止
UnicodeError break 立即终止
其他 Exception __register_general_issue（L389）+ break 立即终止

解读： - 属性级错误可恢复（unknown property、already exists 等 PTException）——按 warning 记账后继续，因此一条错误 ISF 可能产生多条 issue； - 语法级错误不可恢复（SyntaxError 是 Python 解析层的，无法定位到"下一行"语义）——立即终止。这从实现层面印证硬约束"ISF 语法错误 → 整个 import 立即终止，不部分处理"。

4.4 后处理与设计检查

  • __do_post_processing（L414-421）：导入完成后重算所有 PLL 频率（L417-420），保证计数器与频率属性一致。
  • __do_design_check（L424-431）：调用 APIPropertyChecker 做轻量检查。

5.3 块写出顺序（L3596-3697）

源码注释原文 "Blocks must be written in correct order"（L3596）。固定顺序：

GPIO → PLL → OSC → LVDS → MIPI → JTAG → DDR → H264 → MIPI lane
→ SPI flash → HyperRAM → PLL SSC → common quad → QUAD PCIe
→ Lane10G → Lane1G → RawSerdes → SOC → CM

该顺序由工具保证；手工编辑 peri.xml 打乱顺序/手工造假peri.xml 均不受支持——peri.xml 只能由 PT 工具产出（硬约束 §1）。
