1. IP Manager 概述

Efinity IP Manager 是 Efinity IDE 内置的交互式向导工具，用于自定义、验证和生成 Efinix 软 IP 核。

核心功能：

功能 入口 说明
IP Catalog 工具栏按钮 / Tools → Open IP Catalog 浏览全部 47 个 IP 组件（见 §3）
IP Configuration Catalog 中选中 IP → Next 向导式配置参数、选择交付物、审查并生成
IP Editor / IP Manager 主窗口 Tools → IP Manager 管理已生成 IP、导入第三方 IP、打包 IP

IP Manager 对参数做合法性验证（VALIDATE_PARAMS），生成时可附带面向 Efinix 开发板的 Example Design 和/或 Testbench。

来源: C:\Efinity\2026.1\ipm\ip\efx_pll_cfg\ipm\doc\topics\ipm-main-pll-dyn-recfg.html、C:\Efinity\2026.1\ipm\ip\efx_pll_autoreset\ipm\doc\topics\ipm-main-pll-autoreset.html

4. 双 IP 体系：软 IP（ipm）与硬 IP（pt）走完全不同的通道

Efinity 2026.1 中"IP"一词覆盖两类东西，配置通道完全不同，混用是常见错误来源。

4.1 对照表

维度 软 IP（IP Manager 体系） 硬 IP（PT / Interface Designer 体系）
代表 efx_soc、efx_dma、efx_tsemac、efx_fifo_2、efx_bram、efx_uart、efx_csi2 协议层等 §3 全部 47 个 PLL、DDR（ddr-memtest 类）、LVDS、MIPI D-PHY 引脚层、JTAG 硬核、OSC
描述格式 IPXACT 1685-2014（ipm/ip_component.xml） PT 工具内部数据 + ISF Python API
配置入口 IP Manager GUI / IPMDesignAPI Interface Designer（GUI）或手写 ISF
参数存储 工程 ip/<module>/settings.json <design>.peri.xml（efxpt:design_db 命名空间）
注册位置 工程 XML <efx:ip_info>（原生 GUI flow）或 <efx:design_file>（EvoVerse flow，见 §7.3） 工程 XML <efx:isf_file> 引用 ISF；ISF 重放到 peri.xml
产物 变体 RTL（.v/.sv）+ 例化模板 peri.xml 中的硬块定义，综合时自动例化网表
create 语义 create_ip 可重复执行（生成新实例目录） ISF design.create_* 是一次性 bootstrap（见 §4.3）

4.2 判断规则

拿到一个需求，先问"它是不是硬化宏单元"：

  1. 硬化宏单元（硅片上物理存在的块：PLL、DDR hard controller、LVDS、MIPI D-PHY、JTAG、OSC、PCIe 硬核）→ 走 ISF/peri.xml 通道，不要也不可能在 IP Manager 里创建。注意 MIPI 的分层：D-PHY 引脚/寄存器层是硬 IP（ISF），而 CSI-2/DSI 协议层是软 IP（§3 mipi 组 12 个组件）。
  2. 纯 RTL 软 IP（§3 清单内）→ 走 IP Manager 通道（GUI 或 IPMDesignAPI）。
  3. 边界情况：JTAG 硬核本身在 PT 通道；efx_jtag（JTAG 用户接口）与 efx_jtag2spi_flash（spiOverJtag）是挂在 JTAG 硬核上的软 IP，走 IP Manager。
  4. 两类 IP 最终在同一次编译中合流：软 IP 变体 RTL 进 efx_map 源扫描，硬块定义经 peri.xml 进 PT/布局布线。

来源: C:\Efinity\2026.1\ipm\ip\ 组件清单 vs $EFINITY_HOME PT 工具文档； EvoVerse 双通道实践见 awesomsdk\products\efinity-adapter\extension\src\capabilities\ip.ts

4.3 与 ISF 引导契约的关系

ISF 的 create_* 命令一次性语义（引导后注释、只留 set/assign 重放安全命令）由 rules-efinity-hard.md §15 契约约束；peri.xml 是工程源文件、构建后必须存活。IP Manager 通道不触碰 peri.xml——IPMDesignAPI.generate_ip 虽然会自动定位 peri.xml，但那只是为了让生成器感知工程上下文，不会向其写入内容。

来源: C:\Efinity\2026.1\ipm\bin\ipm_api_service\design.py（generate_ip 实现）；AGENTS.md §15

7. IP 实例化数据流（从配置到综合）

7.1 全链路总览

[配置]  GUI 向导 ──或── IPMDesignAPI.create_ip/config_ip
              │
              ▼
工程 ip/<module>/settings.json          ← 参数快照（可版本管理）
              │
              ▼ generate_ip
工程 ip/<module>/ 变体 RTL + _tmpl 例化模板 + _define 参数头
              │
              ▼ 注册
工程 XML：<efx:ip_info>（原生 GUI flow）或 <efx:design_file>（EvoVerse flow）
              │
              ▼ efx_map
变体 RTL 与用户 RTL 一起进入综合源扫描

7.2 原生 Efinity GUI flow 的注册方式

原生 flow 由 Efinity 自动在工程 XML 写入：

<efx:ip_info>
    <efx:ip path="ip/<module_name>/settings.json"/>
</efx:ip_info>

efx_run/efx_map 解析该条目时，将其转换为对 ip/<module_name>/ 目录的源扫描（--dir 语义），从而把生成的变体 RTL 纳入编译。

7.3 EvoVerse flow 的实证决策：不写 <efx:ip>，改注册 design_file

EvoVerse 生成工程时刻意不写 <efx:ip> 条目，而是把生成的 IP RTL 以 <efx:design_file> 形式注册。实证原因（awesomsdk\products\efinity-adapter\extension\src\capabilities\ip.ts publishGeneratedIp L73-108 注释）：

  1. <efx:ip path="ip/<m>/settings.json"> 会被 efx_run 转成 --dir ip/<m> 整目录源扫描，与已注册的 design_file 条目重复编译，报 VERI-1206（重复模块定义）；
  2. 走 ip_src_file 语义时，解析会定位到 IP 根目录而找不到 SoC 网表类产物。

因此 EvoVerse 只注册 design_file。实现要点（publishGeneratedIp）：

  • 新 design_file 条目必须插在 <efx:top_vhdl_arch> 之前（enf_proj.xsd 的元素顺序约束）；
  • ip.ts 内置 vlnv 校验正则：^[A-Za-z0-9_.-]+(?:[:/][A-Za-z0-9_.-]+){2,3}$（validateIpIdentity）。

环节 文件 关键函数/位置

14.3 IP 添加时的 peri.xml 保护

evoverse ip add 流程（adapter 侧）：

  1. beginIpTransaction 备份当前 peri.xml 与工程 ip/ 目录；
  2. 调用 IPMDesignAPI 生成 IP；
  3. 生成后运行 DesignAPI DRC；
  4. 若 IPM、结果解析或后置 DRC 任一失败 → rollbackIpTransaction 恢复原库，避免半完成状态进入编译。

这与 AGENTS.md §15 的 peri.xml 存活契约一致：peri.xml 是工程源文件，任何失败路径都不得留下被破坏的版本。

14.4 不写 <efx:ip> 的决策记录

见 §7.3。要点：避免 --dir 目录扫描与 design_file 重复编译（VERI-1206）；避免 ip_src_file 解析错位。此决策为 EvoVerse 实证，写工程 XML 时必须遵守。

来源: ip.ts L100-106 注释原文；sdk\cli\evoverse _build_native_project_xml 实读（2026-09-25）

15. 故障排查

15.1 IP 生成失败

现象 原因 修复
Module Name 为空 未输入模块名 IP Configuration 的 Module Name 框输入名称
Pickle 缓存损坏 pickle 文件损坏 删除该 IP 的 component.pickle/graph.pickle，重开 IP Manager 自动重建
PermissionError pickle 被其他 Efinity 进程占用 关闭其他 Efinity 实例后重试（efxIP.log 有实例记录）
器件/系列不匹配 工程器件与 IP 缓存目标不符 PICKLE_LOAD-ERROR 日志显示详情；属正常回退，等待全量加载完成即可
重复模块定义（VERI-1206） EvoVerse 工程误写 <efx:ip> 或手动重复注册 按 §7.3 只用 design_file 注册；删除多余 <efx:ip> 条目
手动添加 <module_name>.sv 报重复 IP 文件已由工具自动管理 删除手动添加条目（§6.3）

  3. 名称类问题先对照 §3.3 陷阱表核对 IPXACT name 与 moduleName。
