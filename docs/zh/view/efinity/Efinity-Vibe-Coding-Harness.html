Efinity Vibe Coding Harness

Efinity Vibe Coding Harness

EvoVerse Harness 把 Agent 的“完成”声明绑定到真实工程 diff 和确定性工具证据。MCP、CLI、Trae 与 VS Code 共用 sdk/cli/harness_engine.py，MCP 不复制工程规则。

5 分钟导读

如果这是你第一次用 vibe coding 生成 RTL，按顺序看这5 件事：

  1. 在 Trae Chat 里以 @evoverse 开头描述需求。Agent 会先与你确认工作方式：可靠设计流程（推荐，逐阶段确认）或自由开发。第一次接触建议选可靠设计流程。
  2. 每次"完成"必须带回执：L1–L4 风险等级、每个门禁的 evidenceId、spec freeze 状态。没有回执不算 PASS；blocked 不等于通过。
  3. 受保护资产（XML / SDC / ISF / YAML / IP 配置 / 寄存器映射）永远不要直接编辑——它们走 apply-controlled-change 的 Broker 通道；普通 RTL 可以直接编辑。
  4. catalog 物料是只读基线：Agent 用 asset.observe 观察工作树、用 asset.adopt 把自由代码纳入受管候选，不需要运行任何 bootstrap 脚本；不要直接改写 catalog 物料。详见 工作树资产与 RTL 基线。
  5. 完整 efx_run --flow compile 通过不等于板级硬件验证通过——后者需要真板卡烧录 +接收端证据。

基本工作流

evoverse harness inspect-project-contract <project-root>
evoverse harness classify-change <project-root>
evoverse harness verify-task <project-root> --completion-kind task
evoverse harness get-verification-evidence <project-root> <evidence-id>

IDE 中执行 EvoVerse: Verify Current Change with FPGA Harness。结果在 EvoVerse Output 中显示风险等级、每个门禁和 evidenceId。

风险等级

等级 典型变更 强制门禁
L1 局部 RTL/testbench/软件 Design Assurance、iverilog -g2012、定向 testbench
L2 时钟、复位、CDC、寄存器契约 L1 + CDC/复位与契约检查
L3 XML、SDC、ISF、IP、manifest L2 + Efinity 原生 DesignAPI DRC
L4 三个以上受保护域或明确完整验证 L3 + efx_run --flow compile

风险等级取实际 Git 工作区 diff 与用户请求等级中的较高者。Agent 自报低风险不会降低等级。

受保护资产

工程 XML、SDC、ISF、YAML manifest、IP 配置和寄存器映射必须通过 Broker：

evoverse harness apply-controlled-change <project-root> `
  --patch-file protected-change.json `
  --intent "add PLL interface"

Patch 文件是“工程内相对路径 → 完整 UTF-8 文件内容”的 JSON 对象。Broker 在隔离副本中验证，全部通过后才原子发布并写入回执。回执与当前内容不匹配时失效。

普通 RTL 可以直接编辑，但功能性 RTL 没有同名定向 testbench 时，targeted-sim 必须失败。

RTL 规则只由版本化 Design Assurance rule pack 判定；Harness 不再维护独立的正则风格规则。Assurance 回执为 fail 时门禁失败，为 incomplete 时保持 blocked，直到规格驱动仿真产生合格的动态属性证据。客户意图存在歧义时必须先形成 DecisionRequest，不能由 Agent 猜测。

证据与 CI

证据保存在项目 .evoverse/harness/evidence/，包含 contract/diff hash、风险等级、工具版本、门禁结果与时间。CI 应在待验证 diff 位于工作区时执行 verify-task，并只接受退出码 0 且 status=passed。

blocked 表示许可证、Efinity、Icarus 或其他必需工具不可用，不等同于通过。完整 compile 通过也不代表板级硬件验证完成。

Efinity 原生边界

  • Harness 不生成替代约束格式，也不模拟 DesignAPI、Pre-PT、map、P&R 或 pgm。
  • peri.xml 是 Efinity 生成资产，不作为 legacy inter_file。
  • L3/L4 通过现有 EvoVerse CLI 调用 Efinity 原生 DesignAPI/统一 build 流程。
  • Efinity 报告和退出码决定结果；知识库与 LLM 只能解释失败，不能覆盖结果。
