Efinity 片上调试指南

Efinity 片上调试指南

版本：v1.0　适用 SDK：v1.0.0（Efinity Adapter） 更新日期：2026-09-30

Efinity Adapter 的 Debug 页提供不打开 Efinity GUI 的片上调试闭环：标记信号 → 两次编译 → 烧录 → 扫描设备 → 配置触发条件 → 采集波形。全程通过 evoverse_dbg.py 桥接 Efinity 官方调试 API，结果以 VCD 波形文件交付。

1. 两个核心概念

概念 全称 作用
LA（逻辑分析仪） Logic Analyzer 像 FPGA 内部的示波器：按采样时钟连续记录信号值，触发条件满足时把整段历史波形导出为 VCD。用于"信号在时间轴上怎么变化"。
VIO（虚拟输入输出） Virtual I/O 不占板卡引脚的虚拟开关/指示灯：输出探针可以在运行中写入值驱动 FPGA 内部信号，输入探针可以实时读取当前值。用于"手动拨一下看反应"。

mark_debug 调试流程默认使用 LA（每信号采样记录）；VIO 核心需要在调试配置文件中手动定义，或在 AI 辅助下生成。

2. 准备条件

项目 要求
扩展 evoverse-sdk 与 evoverse-efinity-adapter 已安装
Efinity 2026.1+，路径已配置在核心设置 evoverse.efinityPath
硬件 板卡 JTAG 已连接，下载线驱动正常
工程 已打开一个 Efinity FPGA 工程（有可编译的 RTL）

3. 完整流程（七步）

Debug 页顶部有同样的流程指南。每一步也可以直接交给 AI（见 §5）。

第 1 步 · 标记信号

在 RTL 编辑器中选中信号名（pattern、data_valid 等），右键 → Add Signal to Efinity Debug。命令会在声明前写入综合属性：

(* mark_debug = "true" *) wire [7:0] pattern;
  • 同一信号再次执行会提示已存在；Remove Signal from Efinity Debug 撤销标记（保留其他综合属性如 keep）。
  • 手写 (* mark_debug = "true" *) 效果相同——右键命令只是自动化的编辑。
  • 右键菜单要求：有选中文本 + 文件扩展名为 .v/.sv/.vh/.svh。
  • Prepare Selection for Efinity Debug = 标记后直接跳到 Debug 页。

第 2 步 · 第一次编译（生成调试配置文件）

点击 Build。综合器（enable-mark-debug 选项）收集所有标记信号，在 outflow/debug_profile.mark_debug.json 生成调试配置：包含探针列表、位宽、采样时钟和默认采样深度。

为什么必须先编译一次：调试核的自动实例化要求配置文件在编译开始前已存在（Efinity 机制，见 Efinity Debugger 参考 §8）。首次就开启自动实例化会导致编译崩溃（elab.vdb 缺失）。Adapter 已做前置校验拦截这种用法。

第 3 步 · 启用调试（Debug 页 · 1 · 调试配置）

  • 勾选自动实例化，配置文件路径自动填为 outflow/debug_profile.mark_debug.json。可先"预览配置变更"再"应用"。
  • 采样深度（默认 1024）：LA 缓冲一次采集记录的采样点数，越大越占 BRAM。修改后需重新编译生效。
  • 采样时钟：从综合结果自动识别（探针所属时钟域），只读展示。

第 4 步 · 第二次编译（把调试核编进硬件）

再点一次 Build。编译完成后 Debug 页 profile 状态应显示 ✓ debug cores compiled，work_dbg/ 目录出现调试核 RTL。

第 5 步 · 烧录并扫描设备

Debug 页 2 · 烧录 下载位流，3 · 扫描设备 扫描 FTDI/JTAG 链，确认硬件里的调试核数量。探针表此时显示已标记信号。

第 6 步 · 配置触发条件并采集

4 · 调试探针 每行一个信号：

列 含义
比较条件 等于 / 不等于 / < / <= / > / >=；1 位信号另有 不触发（该信号不参与）
匹配值 比较目标，如 0xA5
掩码 默认全 1（所有位参与）；置 0 的位被忽略

5 · 采集： - 条件触发采集：点击时收集表中条件下发给硬件，条件同时满足才开始记录，完成后自动导出 VCD 并打开。 - 立即采集：不等条件，立刻记录当前状态——排查"信号是否有变化"先用它。

多信号条件之间是与关系：所有信号条件同时满足才触发。

第 7 步 · 收尾（调试版本管理）

  • 清除调试痕迹：一键回到未开启调试的基线——移除全部 (* mark_debug *) 标记、重置调试配置（自动实例化=关、profile=NONE）、删除调试配置文件和 work_dbg/ 目录。会弹确认框；已烧录位流中的调试核要重新编译后才消失。
  • 分支出干净基线：把工程复制到一个新文件夹并清除副本的调试痕迹，原调试版工程原样保留——适合"保留一个带调试的版本，另起炉灶测其他内容"。

4. Debug 页区块速查

区块 内容
调试流程指南 七步流程 + AI 辅助说明
1 · 调试配置 profile 状态、自动实例化、采样时钟/采样深度、预览/应用
2 · 烧录 下载位流到 FPGA
3 · 扫描设备 FTDI/JTAG 扫描，读取硬件调试核
4 · 调试探针 LA/VIO 探针表 + 触发条件（比较/匹配值/掩码）

调试版本管理 清除调试痕迹 / 分支出干净基线

5. AI 辅助路径

Debug 页只做状态查看、触发配置和采集；改 RTL、改配置、跑编译都可以直接在 Trae 对话里用自然语言驱动，例如：

"给 pattern 和 data_valid 加调试标记，采样深度改成 4096，编译并烧录。"

"帮我清除这个工程的所有调试痕迹，再分支出一个干净副本叫 blink_test。"

AI 会直接编辑 RTL/工程 XML 并调用 SDK 编译命令；危险操作（写 VIO、应用配置）仍走带确认的命令通道。

7. 产物文件

路径 生成时机 说明

8. 常见问题

现象 原因与处理
编译崩溃，日志含 No such file: ...elab.vdb 首次编译就开了自动实例化。按正确顺序：先无自动实例化编译一次生成配置文件，再开启并二次编译。Adapter 已拦截，遇到时按提示顺序重做。
右键没有 Add Signal 菜单 未选中文本，或文件不是 .v/.sv/.vh/.svh。先在编辑器里选中信号名。
Debug 页状态陈旧 编译/应用完成后会自动刷新；若打开时工程未就绪，重开一次 Debug 页。
探针表为空 还没扫描设备，或位流里没有调试核（检查 profile 状态是否 ✓、是否已完成第二次编译）。
改了采样深度没生效 深度在编译时固化进硬件，改后需重新编译并重新烧录。
触发后一直等待 条件永不满足。先用"立即采集"确认信号在变化，再放宽条件或改掩码。
想恢复成干净工程 用"清除调试痕迹"；想同时保留调试版，用"分支出干净基线"。

底层机制（两次编译的 elab.vdb 依赖、XML debugger 块字段、profile JSON 格式）见 Efinity Debugger 参考。
