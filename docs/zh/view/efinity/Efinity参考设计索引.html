A.7 结论专节：官方示例不覆盖 DDR / LVDS / 独立 PLL

10 个示例逐一枚举后的结论：

  1. 没有任何一个官方示例包含 DDR 控制器或 LVDS 收发器的完整工程；
  2. PLL 只在 helloworld-unified 的 _kit_manual.isf（一次性引导脚本）中出现，不存在"独立 PLL 示例工程"；

A.9 helloworld-unified 黄金样板深读指南

位置: C:\Efinity\2026.1\examples\helloworld-unified\ 地位: EvoVerse 工程生成器（awesomsdk\sdk\cli\evoverse _build_native_project_xml）的默认参数对齐基准；ISF 引导/重放契约（AGENTS.md §15）的官方实证。

A.9.1 三类文件的角色与关系

helloworld.xml（工程 XML，enf_proj 命名空间）
   │  design_info → design_file（用户 RTL）
   │  constraint_info → <efx:isf_file name="Ti60F225_kit_pins.isf"/>   ← 只引用 pins ISF
   │            └──────→ <efx:inter_file name=""/>                     ← 空条目（见 A.9.4 陷阱）
   ▼
Ti60F225_kit_pins.isf（重放安全：仅 set_property / assign_pkg_pin）
   │  每次 unified build 被重放到 ──┐
   ▼                               ▼
Ti60F225_kit_manual.isf      helloworld.peri.xml（efxpt:design_db 命名空间）
（一次性引导：create_*）      （PT 工具产出的工程源文件，构建后必须存活）

三者关系一句话：工程 XML 声明"我要用哪个 pins ISF"；manual ISF 是开荒工具只跑一次；peri.xml 是开荒后的持久化结果，每次构建被 pins ISF 增量重放。

A.9.2 双 ISF 分工（9 块板 × 2 = 18 个 ISF，实测）

文件 命令风格 执行时机 可否重放
<kit>_pins.isf 仅 design.set_property（PULL_OPTION 等）+ design.assign_pkg_pin（如 ("led[0]","K14")） 每次 build（工程 XML efx:isf_file 引用它） 幂等，可无限重放
<kit>_manual.isf design.create_pll_input_clock_gpio + design.create_block("pll_inst1","PLL") + PLL 参数 set_property（M/N/O、REFCLK_FREQ=25.0、CLKOUT0_DIV=110）+ assign_pkg_pin("pll_refclk","B2") + assign_resource("pll_inst1","PLL_TL0","PLL") 仅 peri.xml 不存在时的一次性 bootstrap 不可重放（create_* 重复执行报 exists 错误）

工程 XML 只引用 _kit_pins.isf——_kit_manual.isf 不被任何 XML 引用，靠人工在引导阶段执行。这与 AGENTS.md §15「引导编译 + 重放编译两连 PASS」验收完全对应。

A.9.3 peri.xml 里有什么（实测要点）

helloworld.peri.xml（命名空间 efxpt:design_db）：

内容 实测值
device_def Ti60F225
iobank 定义 12 个 bank：1A~4B 为 1.8V LVCMOS；BL/BR/TL/TR 为 3.3V
ctrl_info cfg_CBSEL / cfg_ENA / cfg_ERROR / cfg_USR_STATUS（Remote Update 控制面）
clkmux_info CLKMUX_B / CLKMUX_L / CLKMUX_R
seu_info SEU 相关配置

peri.xml 是工程源文件：纳入版本管理、构建后存活、任何构建路径不得删除——删除重生成是 workaround 不是修复（AGENTS.md §15）。

A.9.4 已知陷阱实物：空的 <efx:inter_file name=""/>

helloworld.xml 的 constraint_info 中实测存在 <efx:inter_file name=""/> 空条目。官方示例带着它能编过，但 EvoVerse 实践中该条目会导致 build 失败——rules-efinity-hard.md §2 明确"<efx:inter_file> 的 name 不能为空字符串"。本仓生成器（_build_native_project_xml）的处理：不输出 inter_file 行；同理 isf_file 为空时整行省略（空 <efx:isf_file name=""/> 会让 PT 拒绝携带 peri.xml 的工程）。

拷贝改时必须做：删掉空的 <efx:inter_file/>；确认 efx:isf_file 指向真实存在的 pins ISF。

A.9.5 引导 ritual（对齐 AGENTS.md §15）

  1. 写好 pins 风格 ISF（只 set/assign），manual ISF 的 create_* 临时启用；
  2. 编译一次生成 peri.xml → 立即注释 create_* 行，附一行说明（何时启用）；
  3. 重放编译必须再次全 PASS——引导 + 重放两连 PASS 才算 ISF 验收通过；
  4. peri.xml 与 ISF 一起纳入版本管理。

来源: C:\Efinity\2026.1\examples\helloworld-unified\ 全目录实读（helloworld.xml、18 个 ISF、helloworld.peri.xml，2026-09-25）；AGENTS.md §15

M.2 移植到本仓库的注意事项

  1. XML 元素顺序：所有参考 design 的 <efx:project> 顺序必须遵守 Efinity-XML工程文件Schema参考.md： device_info → design_info → interface_info → constraint_info → sim_info → misc_info → ooc_info → ip_info。 peri.xml 属于 interface_info，不能放进 constraint_info。IP 的 design_file 注册条目必须位于 <efx:top_vhdl_arch> 之前。
  2. ISF 引用：参考 design 里的 *_kit.isf 是板卡原厂 ISF；本仓库使用自建 ISF 时要替换为 evoverse-sdk/catalog/boards/<board>/<board>.isf。
  3. syn_peri_port：经典 flow 需在 RTL 顶层外部端口加 (* syn_peri_port = 0 *)（见 helloworld/helloworld.v）；unified flow（unified_flow="true"）下可省略。
  4. 空 inter_file / 空 isf_file：helloworld-unified 自带空的 <efx:inter_file name=""/>，拷贝改时必须删除；efx:isf_file 无值时整行省略（A.9.4）。
  5. 时序约束：参考 design 里的 sdc 仅含基线；正式工程需补 PLL/clock group/IO delay。
  6. 许可证：所有 Efinix 官方源码遵循 Efinix 自有许可证或 MIT；二次发布需保留原 LICENSE 文件。

N. 获取流程（备忘）

任何 GitHub 仓库的标准获取流程：

# 1. 在合适位置（不要放在本仓库内）建立单独目录
mkdir -p d:/work/efinix-refs && cd d:/work/efinix-refs

# 2. 按需浅克隆
git clone --depth 1 https://github.com/Efinix-Inc/<repo>.git

# 3. 进入工程
cd <repo>
git log -1   # 确认 commit

本仓库不存放这些代码——只留 GitHub 链接，避免仓库体积膨胀与许可证污染；需要时按上面命令去取。
