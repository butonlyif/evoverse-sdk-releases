1. 工具链总览与统一流程管线

1.0 EvoVerse 双 Python 运行域

EvoVerse 不要求客户把系统 Python 改成 Efinity 随附版本，也不会自动安装 Python：

  • SDK 的规格、Design Assurance、分层仿真编排、CLI 和 MCP 使用客户系统 Python 3.11+。启动前实际导入 encodings、json、hashlib 和验证引擎；只看版本号不算可用。
  • Efinity Build、DesignAPI、IPM 和 Debug 只由 Efinity Adapter 管理。Adapter 对选中的安装先运行其 bin/setup.bat，再使用该环境选择的厂商解释器；SDK 不拼接 python311 等版本目录。
  • 两个子进程都会移除对方遗留的 PYTHONHOME、PYTHONPATH 和 Python PATH 项。一个运行域失效不会被另一个 Python 顶替。
  • Build、DesignAPI、IPM、Debug 分别报告能力。例如原生 efx_run.bat --flow compile 可用时，DesignAPI 不兼容不会阻断 Build。

Workbench 的 Runtime domains 只说明解释器及 API 探测结果。它不等于仿真、Questa license、原生编译、时序或硬件验证通过。

1.2 统一流程管线（compile flow 的七个 do_ 步骤）

efx_run.py 把每个 flow 展开为一组布尔开关（build_cmdline_options，L265-298 逐个置 False 后按 flow 分支置位）。compile（默认 flow）展开为七个步骤（L332-340）：

elif re.match('^nosim$|^compile$', args.flow):     # efx_run.py L332
    args.use_prj_name = True
    args.do_map = True              # 1. 综合
    args.do_pt_generation = True    # 2. Interface Designer（PT）
    args.do_pnr = True              # 3. 布局布线 + STA
    args.do_pgm = True              # 4. 比特流生成
    args.do_security = True         # 5. 安全层（仅 --prj 模式存活，见下）
    args.do_security_sc = True      # 6. 安全层 SC（同上）
    args.do_export_bitstream = True # 7. 导出位流产物

run_flow() 的实际执行顺序（L1991-2014，取 compile 相关主线）：

run_synthesis(map)                          # L1991
run_debugger_auto_instantation (可选)        # L1995，debug_profile 时
run_pt('default')                           # L1996  ← map 之后、pnr 之前
run_pnr (可先 run_early_phys_syn)           # L2000-2003
run_pgm                                     # L2005
run_security / run_security_sc              # L2006-2007
run_export_bitstream                        # L2008

即 map → PT(interface) → pnr → pgm → security → export_bitstream。两个关键编排规则：

  • security 两步只在 --prj（工程 XML 模式）下存活：build_cmdline_options 末尾，非 prj 模式强制 args.do_security = False; args.do_security_sc = False（L553-555）。
  • debug_profile 劫持 PT 步骤：compile/full flow 下若给定 --flow 之外的 debug profile，do_auto_instantiate_dbg=True、do_dbg_pt_generation=True、普通 do_pt_generation=False（L140-145），即用"自动插核 + dbg PT"替换标准 PT。

来源：C:\Efinity\2026.1\scripts\efx_run.py。PT 步骤内部（efx_run_pt_unified.py 的九步 DesignAPI 编排）不在本卷展开，见《Efinity-DesignAPI方法参考》。

1.3 退出码语义

efx_run.py：二值退出码（__main__，L2130-2151）：

退出码 条件
0 run_flow 返回 True（且 --prj 模式下已回写工程 XML，update_project_file L2141-2142）
1 任何一步失败：子进程非零退出（CalledProcessError，L2015-2021）、--timeout 超时（TimeoutExpired，L2022-2028）、或其它 Python 异常（L2029-2032、L2144-2146）

注意两点：(1) run_flow 内部 success = e（L2032）把异常对象赋给 success，__main__ 再 raise 出来统一兜底——所以任何异常最终都收敛为 exit 1；(2) update_project_file（L2046 起）在成功后把本次命令行 opts 合并回工程 XML，工程文件是"被编排器更新的活文档"。

efx_run_pt_unified.py：三态状态码，但 WARNING_SKIP 与 OK 同为 0（sys.exit(ret)，L393）：

PTFlowRunnerStatusCode exit code 触发
OK 0 PT 正常完成
WARNING_SKIP 0 EFX_SKIP_PT 非 '0'（L127-129）或 family 不属于 trion/titanium/topaz（L138-140）
ERROR 1 设备/族缺失（L133-135、L142-145）或任何异常（L390-392）

因此对上层而言 PT 直调只有 0/1 两态；"跳过"被视为成功——这正是 AGENTS.md §7 反对用 EFX_SKIP_PT 拼流程的原因之一：它让"该跑没跑"静默变成绿色。三态枚举的完整语义与九步流程见《Efinity-DesignAPI方法参考》。

1.4 PT 直调与 ISF 自检（efx_run_pt_unified.py / import_gpio）

1.4.1 空白 PT 基线（不带 --peri_scripts 直调）

efx_run_pt_unified.py 不带 --peri_scripts 时，脚本导入循环为空、不执行任何 ISF，直接生成只含器件默认外设数据库的空白 <工程名>.peri.xml：

# 在工程根目录执行（design_dir 默认为当前目录）
python efx_run_pt_unified.py <design> <family> <device> --project_xml <工程>.xml
# 产出：<工程根目录>\<工程名>.peri.xml（空白基线）

关键行为（来源：C:\Efinity\2026.1\scripts\efx_run_pt_unified.py）：

行为 出处
peri_scripts 缺省为空列表，导入循环不执行 L377-378（if args.peri_scripts is None: d['peri_scripts'] = []）、导入循环消费该列表
空脚本列表下仍调用 design_api.generate() 产出外设设计 PTFlowRunner 主体
project_xml 模式下 peri.xml 固定写入工程根目录（与工程 XML 同目录），不是 outflow proj_path / f"{proj_db.project_name}.peri.xml"
--output_dir 默认 <design_dir>/outflow，--work_dir 默认 work_pt L365 附近 argparse 定义

1.4.2 ISF dry-run 自检的"首次导入"语义

SDK 随附的 sdk/cli/import_gpio.bat（→ import_gpio_cli.py）只是薄封装：加载 peri.xml → 调用 Efinity 官方 DesignAPI.import_design()（ISF 路径）/ ImportGPIODesign（CSV 路径）→ 报告 issue；--dry-run 只解析+报告、不写回 peri.xml。

必须理解：import 的作用对象是 --peri 传入的 peri.xml 设计库。 assign_pkg_pin 只能给 peri.xml 中已存在的 GPIO 实例赋引脚；实例不存在时导入直接失败（实测错误签名 Unknown instance）。ISF 的 create_*_gpio 负责先创建实例——因此：

自检基线必须是空白 PT 首次导入（1.4.1 的空白 peri.xml），不能用已导入过 GPIO 的 peri.xml。 对已含 GPIO 的库做 dry-run 会因实例已存在而得到与真实编译流程（PT 在 synthesis 之后消费持久化 peri.xml 并重放 ISF）完全不同的结果。

1.4.3 CI 固定基线标准流程

# 1. 空白 PT 产出首次导入基线（见 1.4.1）
# 2. 对待检 ISF 做 dry-run，exit 0 才有效
import_gpio.bat --peri <工程>.peri.xml --input constraints\xxx.isf --dry-run

每次 constraints/*.isf 变更都应重复"空白 PT → dry-run"两步；基线必须由当次工具链现场产出，不得复用手工留存或历史编译遗留的 peri.xml。

1.4.4 调查性运行的输出隔离

PT 直调会在工程目录产生 outflow/ 与 work_pt/。排查问题、验证 ISF 等调查性运行应显式指定独立输出目录：

python efx_run_pt_unified.py ... --output_dir <独立目录>\outflow --work_dir <独立目录>\work_pt

注意 --output_dir 只隔离中间产物；peri.xml 始终写工程根目录（1.4.1），不会被该参数重定向。

2.3 直传选项机制（--opt name=value）

四个 *_opts 参数都是 append nargs='+' 的字符串列表，元素必须是 name=value 形式。编排器把它们逐组展开为目标工具的 --opt 前缀参数：

目标 拼接代码（efx_run.py） 目标工具收到的形式
efx_map L1245 [sys.argv.extend(['--opt'] + x) for x in args.map_opts] efx_map ... --opt mode=area --opt retiming=1
efx_pnr L1317 argv.extend(['--opt'] + x) efx_pnr ... --opt seed=42
efx_pgm L1370 [sys.argv.extend(['--opt'] + x) for x in args.pgm_opts] efx_pgm ... --opt bitstream_compression=off
PT L1448 for x in chain(*args.pt_opts) DesignAPI 参数字典

三个防错机制：

  1. option_exists() 去重（L2037-2043）：用 ^option= 正则检查直传列表中是否已有同名选项，编排器注入的自动选项（如 root=、arch=、sdc_file=）不会覆盖用户显式直传的值（L693-701、L726-733）。
  2. name=value 的 name 必须用选项 XML 里的注册名（§8），不接受 CLI 拼横线风格的变体（例如 efx_map 直传写 retiming=2，不是 --retiming 2）。
  3. 成功后回写工程 XML：update_project_file（L2046 起）在 --prj 模式编译成功后把 opts 合并回工程 XML 对应 section（<synthesis> / <place_and_route> / <bitstream_generation> 的 <param>），GUI 与 CLI 由此共享同一份参数真值。

<constraint_info>/<sdc_file>（多个） vpr_opts += [sdc_file=a,b,c]（逗号 join，空名被过滤） L729-733
<constraint_info>/<unified_sdc_file> vpr_opts += [unified_sdc_file=...] L720、L729-733
<constraint_info>/<inter_file> vpr_opts += [sync_file=<name>]——name 为空字符串时静默跳过（elem.get('name') 假值），空 <efx:inter_file name=""/> 因此直接丢失接口文件，build 必失败 L720（映射表）、L726-727

7.2 EFX_SKIP_PT

只出现在 efx_run_pt_unified.py（L127-129）：

if os.getenv('EFX_SKIP_PT', '0') != '0':
    print("Skipping Interface Designer flow due to EFX_SKIP_PT environment variable")
    return PTFlowRunnerStatusCode.WARNING_SKIP
  • 语义：设为任意非 '0' 值（1、true、yes 均可）即跳过整个 PT 步骤，exit code 仍为 0（§1.3 WARNING_SKIP=0）。
  • EvoVerse 立场：禁止在生产构建路径使用（AGENTS.md §7 No Workaround Tools）。它是官方留给"接口已固化、只想重跑后端"的调试后门，但静默成功特性会让"该跑 PT 而没跑"的配置错误（如 peri.xml 缺失、<inter_file name=""/>）逃过编译检查，直到板级验证才爆。根因修复永远是修工程配置，不是设这个变量。
  • 正常构建中它应处于未设置状态；CI 可加断言 EFX_SKIP_PT 未定义。

8. 选项 XML 真值对照与 XML-only 判定方法

8.1 三个选项 XML 的架构差异

文件 namespace schema 条目数（all/族专属） 与工程 XML 的关系
bin\efx_map_options.xml enf_topt enf_topt.xsd 32 / Trion 2 + Titanium 5 值经编排器写入 <synthesis>/<param> 并回读
bin\efx_pnr_options.xml enf_topt enf_topt.xsd 5 / Titanium 1 + TitaniumX 1 值写入 <place_and_route>/<param>（qp_options= 合并机制，efx_run.py L813-840）
bin\efx_pgm_options.xml enf_proj（例外） enf_proj.xsd 15 / Titanium 3 与 <bitstream_generation>/<param> 同构，直接透传

option 元素统一结构（三个文件一致）：

<efx:option name="--mode" value="speed,area,cong,power,speed2,area2" default="speed" value_type="e_option"/>
  • value_type 四种：e_option（枚举，value=逗号分隔合法值）、e_integer（value=min,max 是闭区间，如 --fanout-limit value="0,2000" = 0..2000；特例 --seed value="1" 单值）、e_bool（value=on,off）、e_string（仅 --jtag_usercode）。
  • options_group 按 family_name + device_name 分组；子组同名选项覆盖 all 组默认值（唯一实例：--active_capture_clk_edge all=posedge → Titanium=negedge）。
  • 族专属选项只对该族合法：Titanium 组选项给 Trion 工程传会被工具拒绝。

8.2 XML-only 选项的判定方法（不运行 --help）

本文「仅XML?」列的判定步骤，供后续版本升级复用：

  1. 读 bin\efx_*_options.xml 拿全部注册选项（真值源：名称/默认/合法值）。
  2. 对应官方 CLI 文档页（DITA 生成，正文约从 L168 起、此前为导航样板）：
  3. doc\topics\cli-map-opts.html（Table 1 Synthesis Options，L178 起）
  4. doc\topics\cli-pnr-opts.html（Table 1-5，L178-365）
  5. doc\topics\cli-pgm-opts.html（Table 1-3，L178-425）
  6. XML 有而 HTML 表无 → XML-only：不出现在 --help，只能经 --opt name=value 直传或工程 XML param 设置。
  7. HTML 有而 XML 无 → CLI 固有参数（§3.3 / §4.2 / §5.2），由编排器自动生成或不入工程 XML。

8.3 efx_run.py 与选项 XML 的两层校验分工

  • 编排层（efx_run.py parse_project_file）：只做存在性与去重（option_exists），不消费 value_type（L802-803 读后即弃）——类型合法性由工具二进制自行校验。此结论与《Efinity-XML工程文件Schema参考》一致。
  • 工具层（efx_map/efx_pnr/efx_pgm）：按选项 XML 校验枚举/范围，非法值直接报错退出（exit ≠ 0 → efx_run 收敛为 exit 1）。
  • 空名真值检查：elem.get('name') 假值时编排器跳过选项生成（L726）——<efx:inter_file name=""/> 不会生成 sync_file=，也不会报"空名错误"，错误被推迟到 pnr 找不到接口文件时。这是 AGENTS.md §7 "空的 <efx:inter_file> 是配置 bug" 的源码级证据。
