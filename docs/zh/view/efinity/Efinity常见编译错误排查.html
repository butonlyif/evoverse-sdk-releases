Efinity 常见编译错误

Efinity 常见编译错误排查

版本: v1.0 | 基于 Efinity 2026.1 (efx_map / efx_pnr / IP Manager / Design Check)

1. 错误体系概述

Efinity 工具链的编译错误按来源分为六大类：

类别 来源 典型阶段
综合错误 efx_map map
XML 配置错误 efx_map / efx_pnr map / pnr
接口设计检查错误 Interface Designer (Design Check) pnr
IP 管理器错误 IP Manager (efxIP.log) 工程初始化
P&R 错误 efx_pnr pnr
编程器错误 efx_pgm pgm

来源：efx_map --help 错误码；C:\Efinity\2026.1\ipm\log\efxIP.log；Design Check 规则

2. 综合错误

2.1 EFX-0002：命令行非法

EFX-0002 (ERROR): Illegal command line

含义：传递给 efx_map 的命令行参数格式错误或不被识别。

排查： - 检查命令行帮助 efx_map --help - 确认参数名拼写正确、格式符合 name=value 规范

来源：efx_map --help — EFX-0002

2.2 EFX-0003：源文件分析失败

EFX-0003 (ERROR): Analysis of source file '<file>' failed

含义：Verilog/VHDL 源文件的语法分析或语义解析（elaboration）失败。

排查： - 查看该错误之前的其他错误消息，定位具体的语法/语义问题 - 检查文件中是否存在未声明的信号、缺失的模块定义、语法错误

来源：efx_map --help — EFX-0003

2.3 黑盒模块未定义

当设计中引用了未定义的模块时，默认会报错。

控制参数：

参数 默认值 说明
--blackbox-error arg 1 设为 0 可将黑盒从 ERROR 降级为 WARNING

来源：efx_map --help — --blackbox-error

2.4 调高日志详细程度

当错误信息不够明确时，可增加详细输出：

参数 默认值 说明
--message-verbosity arg 0 增大该值以获取更详细的错误上下文
--suppress_warning_msgs arg 0 设为 1 可抑制警告（但不推荐在排查时使用）
--msg_config_file arg — 指定自定义消息过滤配置文件 
# 通过 efx_run 传递详细日志选项
efx_run.bat my_design --map_opts message-verbosity=1

来源：efx_map --help — --message-verbosity、--suppress_warning_msgs、--msg_config_file

3. XML 工程文件配置错误

3.1 元素顺序导致 efx_map 失败

在 --un_flow（Unified Netlist Flow）模式下，XML 元素出现顺序不正确会导致综合失败：

  • 现象：efx_map 拒绝处理，可能报解析错误
  • 根因：XML schema 对元素顺序有严格要求，某些元素前后位置错误会导致流程序列不匹配
  • 排查：参考工程 XML Schema（Efinity-XML工程文件Schema参考.md）检查元素顺序

来源：EvoVerse SDK 工程实践（project_memory.md）

3.2 peri_file 位置错误

<efx:peri_file> 元素必须放在 <efx:constraint_info> 中，而非 <efx:interface_info>：

<!-- 正确 -->
<efx:constraint_info>
    <efx:peri_file name="output/design.peri.xml" />
</efx:constraint_info>

<!-- 错误：peri_file 不应在 interface_info 中 -->
<efx:interface_info>
    <efx:peri_file name="output/design.peri.xml" />
</efx:interface_info>
  • <efx:interface_info> 只应包含 <efx:default_peri_file>（通常 name 为空）
  • <efx:constraint_info> 包含 SDC、ISF、peri 文件

来源：EvoVerse SDK 工程实践（project_memory.md）；Efinity-XML工程文件Schema参考 §4、§5

3.3 ooc_info 元素非法

<efx:ooc_info /> 元素在某些流程中不可用（例如 Unified Netlist Flow）：

  • 现象：包含此元素的工程 XML 在特定流程中产生配置非法错误
  • 排查：如果工程不涉及 OOC（Out-of-Context）综合，移除 <efx:ooc_info /> 元素
  • 注意：空元素（如 <efx:ooc_info />）也可能触发该问题

来源：EvoVerse SDK 工程实践（project_memory.md）

3.4 inter_file 空元素

<efx:inter_file name="" /> 如 name 为空且不需要，应直接移除该行，而非保留空元素：

<!-- 错误：空的 inter_file 元素 -->
<efx:inter_file name="" />

<!-- 正确：不写该元素 -->

来源：EvoVerse SDK 工程实践（project_memory.md）；Efinity-XML工程文件Schema参考 §5

4. 接口设计检查错误（Design Check）

Interface Designer 的 Design Check 在 P&R 阶段之前执行，对时钟和时钟复用器进行规则校验。

来源：Titanium Design Check Error Messages

4.1 时钟规则（clock_rule）

错误 说明
clock_rule_capacity 不能在一个区域内连接超过 N 个不同时钟
clock_rule_max_count 使用的核心时钟数量超过最大限制（32 个）
clock_rule_lvds_rx_clock_source PLL 输出的时钟驱动了不同边的 LVDS Rx
clock_rule_pll_ref_clock_lvds_rx PLL 参考时钟的边与 LVDS Rx 所在的边不匹配
clock_rule_undefined_name 未定义时钟源

来源：Design Check clock_rule_* 错误消息

4.2 时钟复用器规则（clkmux_rule）

错误 说明
clkmux_rule_clocks_routed 未布线的引脚驱动了时钟复用器的输入端
clkmux_rule_core_clock_pin 核心时钟引脚只能在启用动态复用器时使用
clkmux_rule_core_clock_static_mux 核心时钟引脚不能通过静态复用器连接
clkmux_rule_dynamic_clock_pin 动态时钟引脚名称为空
clkmux_rule_dynamic_clock_select_pin 动态时钟选择引脚名称为空
clkmux_rule_global_regional_pin 缺少用于区域连接的全局引脚名称
clkmux_rule_global_regional_resource 区域缓冲器不支持全局连接
clkmux_rule_pll_output_clock PLL 输出时钟被重复布线
clkmux_rule_regional_conn_type 区域缓冲器需要 rclk 或 rctrl 连接类型
clkmux_rule_type_config MIPI/GPIO/LVDS 资源不允许连接到动态复用器

来源：Design Check clkmux_rule_* 错误消息

4.3 SDC 约束错误

SDC 约束配置不当会导致时序分析阶段出错：

  • unconstrained endpoints：缺失 SDC 约束导致大量端点未被约束
  • 排查：确认工程 XML 中 <efx:sdc_file name="..." /> 路径正确且文件存在
  • 确保所有时钟域都有 create_clock 或 create_generated_clock 定义

来源：EvoVerse SDK 工程实践（project_memory.md）

4.4 GPIO 分配冲突

Board image（板卡镜像）与 ISF 文件冲突时，Interface Designer 的 GPIO 分配出错：

  • 现象：引脚分配失败，提示已分配或冲突
  • 排查：检查 ISF 文件中手动分配的引脚是否与 board image 自动分配的引脚重叠

来源：EvoVerse SDK 工程实践（project_memory.md）

5. IP 管理器错误

IP Manager 日志位于 C:\Efinity\2026.1\ipm\log\efxIP.log。

错误模式 说明
PICKLE_LOAD-ERROR IP 参数反序列化失败——IP 配置文件损坏或格式不兼容
VALIDATE_PARAM-ERROR IP 参数校验失败——参数值超出允许范围或类型不匹配

来源：C:\Efinity\2026.1\ipm\log\efxIP.log

6. P&R 错误

6.1 布线拥塞（Routing Congestion）

布线拥塞是 P&R 阶段常见问题：

  • 现象：efx_pnr 报告无法完成布线或部分 net 未布线
  • 排查：
  • 使用 --optimization_level CONGESTION_1/2/3 提高拥塞优化级别
  • 考虑分散关键模块布局

来源：efx_pnr --help-verbose — --optimization_level

6.2 时序违规（Timing Violations）

  • 现象：WNS（Worst Negative Slack）为负值，关键路径时序不满足
  • 相关参数：--print_critical_path N（默认 10）
  • 排查：检查关键路径报告，分析是否有不必要的长组合逻辑路径

来源：efx_pnr --help — --print_critical_path

7. 编程器错误

编程器错误通常发生在比特流生成（pgm）或烧录阶段：

问题 可能原因 检查项
Flash 未检测到 型号不在数据库中 检查 pgm/bin/flash_db/
比特流过大 未启用压缩 确认 --bitstream_compression on（默认开启）
SPI Active 配置失败 时钟分频过高 增大 --oscillator_clock_divider
多镜像不工作 CBSEL 引脚未正确配置 确认 --enable_cbsel on 且地址合法

来源：efx_pgm --help

8. 排查工作流

8.1 标准排查步骤

1. 确认错误来源（map / pnr / pgm / PT）
      │
2. 检查上一条错误消息（EFX-0003 的前置错误）
      │
3. 启用详细日志：--map_opts message-verbosity=1
      │
4. 检查 XML 工程文件：元素顺序、peri_file 位置
      │
5. 检查 SDC 约束：时钟定义、unconstrained endpoints
      │
6. 检查 Design Check 报告：clock/clkmux 规则
      │
7. 检查 IP Manager 日志：efxIP.log

来源：综合 efx_map --help、Design Check 规则、EvoVerse SDK 工程实践

8.2 常用诊断命令

# 提高综合日志详细度
efx_run.bat my_design --map_opts message-verbosity=1

# 仅运行综合（跳过后续步骤，快速迭代）
efx_run.bat my_design --flow map --map_opts message-verbosity=1

# 仅运行 P&R，打印更多关键路径
efx_run.bat my_design --flow pnr --pnr_opts print_critical_path=50

# 抑制黑盒错误（临时排查用，不推荐发布）
efx_run.bat my_design --map_opts blackbox-error=0

# 自定义消息过滤
efx_run.bat my_design --map_opts msg_config_file=my_filter.cfg

来源：efx_map --help；efx_pnr --help；efx_run --help

9. 与 EvoVerse SDK 集成

9.1 SDK 中的错误处理

EvoVerse SDK 的 CLI 与 IDE Build 都把原始工程 XML 交给 Efinity 官方 runner：

call <Efinity>/bin/setup.bat
<Efinity>/bin/efx_run.bat <project.xml> --flow compile
  • XML 所在目录作为工作目录；SDK 不拆分 flow、不预运行 PT、不生成替代 XML
  • 默认不注入线程数、超时、--un_flow 或 MAP/PNR 参数；只有用户显式覆盖才追加
  • SDK 健康检查只提供提示，不能阻止 Efinity 判断工程是否合法
  • stdout、stderr 和退出码由厂商 runner 原样返回
  • SDK 的 Build Report 面板展示解析后的结构化错误信息
  • Efinity 2026.1 是已验证基线；其他版本保持原生直通并标记为未验证

注意：Efinity 2026.1 自身可能更新工程 XML 的版本、同步状态或格式。SDK 不应在构建前后另外改写或恢复这些厂商行为。

来源：EvoVerse SDK buildRunner.ts

9.2 报告增强

  • efinity-adapter 的 src/capabilities/report.ts 解析 map/P&R/timing 报告，提取资源使用和时序摘要
  • timingDiagnoser.ts 基于六类错误指纹做根因分类诊断
  • LLM 上下文注入（copilotContext.ts）可将 RTL + SDC + 诊断结果发送给 AI 辅助分析
