Efinity 版本迁移

Efinity 版本迁移指南

版本: v1.0 | 基于 Efinity 2026.1 | 最后更新: 2026-07-30

本文档汇总从旧版 Efinity 迁移到 v2026.1 时需要注意的所有变更点，涵盖工具链、工程 XML、Sapphire SoC、RTL 编码、时序约束等方面的不兼容变化。

1. 版本概述

1.1 如何查看当前版本

方法 命令/路径 说明
Efinity 启动画面 GUI 启动时显示 显示版本号和构建日期
命令行 efx_run.bat --version 显示 efx_run 版本
工程 XML 工程 .xml 中 <project sw_version="..."> 记录创建工程的 Efinity 版本
版本文件 C:\Efinity\<version>\version.txt 包含完整版本信息

来源：Efinity UG v16.0/v16.2 及工程 XML 实践。

1.2 版本兼容性警告

重要： 用新版 Efinity 打开旧工程后，工程文件会被更新为版本特定的建模信息，不可向后兼容。如果旧版编译产物（综合/布局布线输出）不兼容，软件会提示重新编译。

来源：Efinity Software User Guide v16.0/v16.2，"Using an Existing Project with a New Software Version" 节。

来源：「Efinity工具链参考.md」§5.4：C:\Efinity\2026.1\scripts\efx_run.py 第 556–567 行（时序模型废弃检查逻辑）。

3. 工具链迁移（GCC 8.3 → 13.4）

3.1 变更概览

版本 GCC 版本 目标架构
Efinity ≤ v2025.2 GCC 8.3.0（riscv64-unknown-elf-gcc） RV32IMAC / RV64IMAC
Efinity v2026.1 GCC 13.4.0（riscv64-unknown-elf-gcc） RV32IMAC / RV64IMAC

3.2 升级收益

  • 改进的 C23 支持
  • 更好的 C++20/C++23 支持
  • 更多 RISC-V ISA 扩展支持

3.3 不兼容风险

  • BSP/firmware 代码：用 GCC 8.3 编译通过的代码在 GCC 13.4 下可能需要修改
  • 链接脚本：可能需要适配新版本链接器行为
  • 编译选项：某些旧版编译器标志可能已废弃
  • Sapphire SoC：v2026.1 生成的 SoC 必须搭配 Efinity RISC-V Embedded Software IDE v2026.1 使用

3.4 回退策略

如果不希望升级工具链，可以继续使用： - Efinity v2025.2 + Efinity RISC-V Embedded Software IDE v2025.2

来源：Efinix 官方文档（https://www.efinixinc.com/docs-html/riscv-embedded-ide-ug/topics/riscv-embedded-software-ide-toolchain.html）。

4. Sapphire SoC 迁移（v1 → v2）

4.1 迁移前提

Sapphire SoC v2.0 自 Efinity v2021.2 引入，不能自动迁移 v1.x 工程。Efinix 官方建议所有新设计使用 v2.0。

来源：Efinix 官方 Sapphire RISC-V SoC User Guide v5.4，"Migrating to the Sapphire RV32 SoC v2.0" 节（https://www.efinixinc.com/docs-html/rv32-sapphire-ug/topics/riscv-sapphire-migrate-to-2.0.html）。

4.2 v1 → v2 关键变更

类别 v1.x v2.0
Timer 外设 Machine Timer CLINT Timer（原生 CPU 定时器）
设备名称定义 旧命名（soc.h） 新命名 + compatibility.h 桥接层
参数名称 部分不同 更新后的参数名
IP 配置向导 无 FPU/MMU/Peripheral Clock 选项 新增：可配置 Cache、FPU、MMU、Peripheral Clock
Debug 配置 仅支持 default_softTap 支持 Co-Debug、多种 JTAG 配置
AXI 接口 仅 AXI3 支持 AXI3 和 AXI4（v2.0+）

4.3 手动迁移步骤

  1. 新建 v2.0 工程：使用 IP Manager 创建 Sapphire SoC v2.0，选择对应器件型号
  2. 重新配置外设：在 IP 配置向导中逐一启用所需外设（UART/SPI/I2C/GPIO 等）
  3. 重新挂接 APB/AXI 从设备：在 RTL 顶层中重新连接自定义外设
  4. 固件代码适配：
  5. 在应用代码顶部添加 #include "compatibility.h" 和 #include "bsp.h"
  6. 将 Machine Timer 调用替换为 CLINT Timer 驱动调用
  7. 重新编译所有 firmware（使用 GCC 13.4）
  8. 替换 Debug 配置：删除旧的 debug 配置，使用 v2.0 版本

4.4 v2.0 IP 配置参考（兼容 v1.x 行为）

Tab 选项 推荐设置 说明
SOC Peripheral Clock DISABLE v1.x 中外设使用系统时钟
SOC FPU DISABLE v1.x 不支持
SOC MMU DISABLE v1.x 不支持
SOC Atomic Extension DISABLE v1.x 不支持
Cache/Memory Data Cache Way 1 v1.0 固定为 1 way
Cache/Memory Data Cache Size 4 KB（v1.0）/ 1–32 KB（v1.1） 匹配原设计
Cache/Memory I-Cache Way 1 同上
Cache/Memory I-Cache Size 4 KB（v1.0）/ 1–32 KB（v1.1） 同上

来源：Efinix 官方文档（https://www.efinixinc.com/docs-html/rv32-sapphire-ug/topics/riscv-sapphire-migrate-to-2.0.html）。

5. 工程 XML 迁移

5.1 元素顺序强制要求

Efinity 2026.1 对工程 XML 的 <efx:project> 子元素顺序有严格要求：

device_info → design_info → interface_info → constraint_info → sim_info → misc_info → ooc_info → ip_info

关键点： - peri_file 必须放在 <interface_info> 中，不能放在 <constraint_info> 中 - ooc_info 在部分 flow 模式下会导致失败（如果包含内容） - 顺序错误可能导致解析失败或行为异常

来源：「Efinity参考设计索引.md」§M.2 及 C:\Efinity\2026.1\bin\enf_proj.xsd。

5.2 XML 自动升级行为

  • 用 v2026.1 打开旧版工程 XML 时，Efinity 自动升级 XML schema
  • 升级后的 XML 不可在旧版 Efinity 中打开
  • 建议在升级前备份原工程目录

来源：Efinity UG v16.0/v16.2。

5.3 Unified Flow 注意事项

  • Unified Flow（unified_flow="true"）在 2026.1 中继续支持
  • 旧版非 Unified Flow 工程需要 (* syn_peri_port = 0 *) 标记，可逐步迁移到 Unified Flow

来源：「Efinity参考设计索引.md」§M.2。

6. peri.xml 重新生成

6.1 版本不兼容

peri.xml（Interface Designer 设计数据库）在不同 Efinity 版本之间可能不兼容。Block type、property、preset 和 resource 名称与器件及 Efinity 版本相关。

来源：「Efinity设计API集成.md」§「版本兼容」。

6.2 重新生成策略

当升级 Efinity 版本后 peri.xml 不兼容时：

  1. 删除旧的 peri.xml（备份后）
  2. 确认工程 XML 正确引用对应的 .peri.isf：
  3. 运行 Efinity 原生 efx_run --flow compile，让原生 PT 阶段重新生成
  4. 或在 Interface Designer 中打开并验证后保存
  5. 验证 DRC：运行 evoverse design validate
  6. 确认编译通过：运行完整 compile flow

不要在 SDK 中维护 XML schema 迁移器——ISF 是规范来源。

来源：「Efinity设计API集成.md」§「版本兼容」及 §「TJ180 实测基线」。

6.3 TJ180 实测案例

已验证的迁移路径（Efinity 2026.1）： 1. 删除旧 peri.xml 2. 从 constraints/base.peri.isf 重建 3. DesignAPI DRC 通过（0 error） 4. Synthesis → Interface → PNR → PGM 全流程 PASS

来源：「Efinity设计API集成.md」§「TJ180 实测基线」。

8. RTL/综合迁移

8.1 时序模型废弃

Ti35/Ti60 器件上 I4 / I4L 时序模型在 Efinity 2026.1 中已废弃。运行时会产生警告。应切换到当前支持的时序模型。

来源：「Efinity工具链参考.md」§5.4。

8.2 Periphery 推断 vs 实例化

模式 参数 说明
推断模式 --peri-syn-inference 由综合工具自动推断外设原语
实例化模式 --peri-syn-instantiation 手动实例化外设原语
Unified Flow unified_flow="true" 推荐模式，统一管理

来源：「Efinity工具链参考.md」§2.1 第 107–108 行。

8.3 新增综合选项

Efinity 2026.1 新增/更新的综合选项（与旧版对比需实测确认），核心参数参见「Efinity工具链参考.md」§2。

9. SDC/约束迁移

9.1 时序模型变更

  • Ti35/Ti60 的 I4/I4L 时序模型废弃后，关联的 SDC 约束可能需要调整
  • 新器件（Ti125/Ti95）需要新的 --operating_conditions 设置

9.2 Unified SDC

  • 2026.1 继续支持 unified SDC 文件（--unified_sdc_file）
  • Interface Designer 生成的 PT SDC 自动包含在编译流程中

来源：「Efinity工具链参考.md」§3.2。

10. 构建脚本迁移（efx_run 变更）

10.1 核心变更

项目 旧行为 新行为（2026.1）
默认器件族 Titanium Titanium
默认器件 Ti60F225 Ti60F225
编译流程 map → PT → pnr → pgm 不变
Python API 无 efx_py 支持

10.2 AOE 脚本

新增 efx_run_aoe.py 自动探索综合和布局选项，替代手动参数试验。

10.3 构建命令示例

# 标准编译（与旧版兼容）
efx_run.bat my_design

# 使用新器件（需指定）
efx_run.bat my_design --family Titanium -d Ti125F225

# 使用 AOE 探索
efx_run_aoe.py my_design

来源：「Efinity工具链参考.md」§1.1–1.2 及 Efinity v2026.1 发布说明。

11. 完整升级检查清单

升级前

  • [ ] 备份整个工程目录（含 .xml、peri.xml、*.peri.isf、sdc 文件）
  • [ ] 记录当前 Efinity 版本号
  • [ ] 检查是否使用已废弃的 Ruby/Jade/Opal SoC
  • [ ] 检查是否使用 I4/I4L 时序模型
  • [ ] 确认 IP 依赖版本

升级中

  • [ ] 安装 Efinity 2026.1 及 RISC-V Embedded Software IDE 2026.1
  • [ ] 用 v2026.1 打开工程 → 自动升级 XML schema
  • [ ] 删除旧 peri.xml → 从 ISF 重新生成
  • [ ] 检查 <efx:project> 子元素顺序（参见 §5.1）
  • [ ] 如果是 Sapphire v1 → 按 §4.3 手动迁移到 v2
  • [ ] 更新 GCC 工具链（8.3 → 13.4），重新编译 firmware

升级后

  • [ ] 运行 Interface Designer DRC（evoverse design validate）
  • [ ] 运行 Synthesis，检查编译警告
  • [ ] 运行完整 compile flow（Map → PT → PNR → PGM）
  • [ ] 检查时序报告（确认无新增 violation）
  • [ ] 重新烧录验证硬件功能
  • [ ] 更新 DAYLOG.md

12. 回滚策略

如果需要回到旧版 Efinity：

  1. 保留旧版安装：Efinity 支持多版本并存（安装到不同目录）
  2. 使用备份工程：不要用新版工程 XML 回到旧版——已被自动升级
  3. 恢复 peri.xml：从 ISF 重建（而非恢复旧版二进制）
  4. 回退工具链：使用旧版 Efinity + 旧版 RISC-V IDE（GCC 8.3）

推荐的多版本管理方法：

C:\Efinity\
├── 2025.2\   （保留旧版，用于现有稳定工程）
└── 2026.1\   （新版，用于新工程和迁移验证）

文件位置：docs/efinity/Efinity版本迁移指南.md
