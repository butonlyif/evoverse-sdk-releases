Efinity 硬 IP：PLL 与 OSC 参考

Efinity 硬 IP 参考 — PLL 与 OSC

适用版本：Efinity 2026.1（实测安装目录 C:\Efinity\2026.1） 调查日期：2026-09-25 证据来源：本文全部属性名、合法值、默认行为均逐行实测自 Efinity 2026.1 安装目录内 Python 源码，每条标注 文件:行号。除特别注明外，源码根目录为 C:\Efinity\2026.1\pt\bin\（下文简写为 pt\bin\）。 同系列文档：《Efinity-ISF语法参考.md》《Efinity文件格式-peri.xml.md》《Efinity-DesignAPI方法参考.md》《Efinity硬IP-DDR参考.md》《Efinity硬IP-接口与JTAG参考.md》

1. 概述与定位

PLL 与 OSC 是 Efinity 器件中的两个片上时钟源硬 IP：

硬 IP 作用 创建方式 API block_type 字符串
PLL 锁相环：将参考时钟倍频/分频/移相为多路输出时钟 create_block("名", "PLL") "PLL"
OSC 片上振荡器：无需外部时钟即可产生低频时钟 create_block("名", "OSC") "OSC"

硬约束（与 rules-efinity-hard.md §4 一致）：PLL 必须在 ISF 中创建（design.create_block("name", "PLL")），不能在 RTL 中例化；RTL 只声明 pll_clk_out / pll_locked 端口。注意 create_* 是一次性 bootstrap（见 §7 与 AGENTS.md §15）。

1.1 PLL 的六代变体（重要）

2026.1 源码中 PLL 不是单一类，而是六代变体的继承链。design.create_block("x", "PLL") 时，工具按器件型号自动选择对应代的 Prop 类；写属性时用的是统一的大写属性名，但不同代可用的属性与合法值不同：

代 Prop 类（属性权威） DB block_type（ISF 导出层） 典型器件家族
v1 简单 PLL PLLProp（pt\bin\api_service\property\pll_prop.py:49） pll Trion（T4/T8/T13/T20 系列）
v2 高级 PLL PLLAdvProp（pll_prop.py:599，继承 PLLProp） adv_pll Titanium（TiTi60/Ti375、Tz170 等）
v3 五输出 PLL PLLCompProp（pll_prop.py:1152，继承 PLLAdvProp） comp_pll Titanium 新版
v4 PLLV4Prop（pll_prop.py:1674，继承 PLLCompProp） （沿用 v3 路径） —
EfxFpll V1 EfxFpllV1Prop（pll_prop.py:1786，继承 PLLV4Prop） efx_fpll_v1 —
EfxFpll V2 EfxFpllV2Prop（pll_prop.py:1990，继承 EfxFpllV1Prop） efx_fpll_v2 Ti125 等最新器件

继承链证据：pll_prop.py:599 class PLLAdvProp(PLLProp)、:1152 class PLLCompProp(PLLAdvProp)、:1674 class PLLV4Prop(PLLCompProp)、:1786 class EfxFpllV1Prop(PLLV4Prop)、:1990 class EfxFpllV2Prop(EfxFpllV1Prop)。

每代有独立的合法值表（api_options）与独立的 ISF 导出器（isf_exporter.py）：

  • 合法值 import 证据（pll_prop.py:40-45）：pll_api_options → v1_api_ops_map、pll_adv_api_options → v2_api_ops_map、pll_comp_api_options → v3_api_ops_map、pll_v4_api_options → v4_api_ops_map、fpll_v1_api_options、fpll_v2_api_options。
  • ISF 导出器链（pt\bin\api_service\exim\isf_exporter.py）：PLLISFBuilder（:1476，db_block_type pll）→ PLLAdvISFBuilder（:1495，adv_pll）→ PLLCompISFBuilder（:1507，comp_pll）→ PLLV3ComplexISFBuilder（:1518，efx_pll_v3_comp）→ EfxFpllV1ISFBuilder（:1529，efx_fpll_v1）→ EfxFpllV2ISFBuilder（:1540，efx_fpll_v2）。
  • 另有独立的 PLL_SSC 扩频时钟块（block_type "PLL_SSC"，PLLSSCISFBuilder 于 isf_exporter.py:1953，属性类 pll_ssc_prop.py）与 CM 时钟块（CMISFBuilder :1452，db_block_type cm_v1），本文不展开，见 §6.4。

写作纪律：本文所有"合法值"均标注适用代际。跨代混用合法值是 PLL 配置出错的第一大来源。

2. 创建三件套

硬 IP 没有专用创建方法，统一走泛型三件套（DesignAPI 真身 pt\bin\api_service\design.py，create_block 签名 :192）：

design.create_block("pll_inst1", "PLL")                      # 1. 创建块（block_type 必须是 "PLL"）
design.set_property("pll_inst1", "REFCLK_FREQ", "25.0", "PLL")  # 2. 逐条设置属性（第 4 参必须传 "PLL"）
design.assign_resource("pll_inst1", "PLL_TL0", "PLL")        # 3. 分配 PLL 硬资源（第 3 参是资源名，第 4 参 "PLL"）

要点（均实测）：

  1. block_type 字符串：PLL 用 "PLL"、OSC 用 "OSC"。合法值清单见 pt\bin\api_service\common\object_db.py:35-59（API_BLOCK_TYPE Literal 列表：GPIO, JTAG, PLL, OSC, MIPI_TX, MIPI_RX, ..., DDR, PLL_SSC, ...）；枚举→字符串映射 otype2str_map 在 object_db.py:109-140。传入不支持的字符串会抛 PTBlkCreateException（design.py:229-231，校验 is_block_supported）。
  2. 参考时钟引脚 GPIO 单独创建：外部参考时钟需要一条 design.create_pll_input_clock_gpio("pll_refclk")（官方 ISF 实例：C:\Efinity\2026.1\examples\helloworld-unified\Ti60F225_kit_manual.isf:15），再用 design.assign_pkg_pin("pll_refclk", "B2") 绑定封装引脚（同文件 :45）。
  3. set_property 的第 4 参（block_type）不能省：JTAG/PLL/OSC 等非 GPIO 块都必须显式传 "PLL"/"OSC"。
  4. create_* 是一次性 bootstrap：create_block / create_pll_input_clock_gpio 只能在该工程 peri.xml 尚不存在时执行一次；unified build 每次都会把工程 XML 引用的 ISF 重放到已持久化的 peri.xml 上，重放的 ISF 里若还有 create_* 会报 ... exists。引导编译完成后必须把 create_* 行注释掉（AGENTS.md §15、rules-efinity-hard.md §15）。

3.3 输出时钟（CLKOUT0–CLKOUT4）

每路输出有三个开关型属性加两个频率属性：

属性模式 类型 合法值 说明 证据
CLKOUTn_EN（n=0–4） BOOL "0"/"1" 使能第 n 路输出。未使能的输出路不要设其它 CLKOUTn_* 属性 pll_prop.py:76-80（EN）、:81-85（PIN）、:86-90（DIV）
CLKOUTn_PIN 引脚名（STR） 默认 "" 该路输出时钟在 RTL 侧的信号名 pll_prop.py:81-85
CLKOUTn_DIV INT v1：只能是 2 的幂次 [2,4,8,16,32,64,128,256]；v2：1–256 任意整数；v3/f1：1–128 输出分频器 pll_api_options.py:4-6（v1 OptionValidator）；pll_adv_api_options.py:5,7,9（v2 RangeValidator(1,256)）；pll_comp_api_options.py（v3 1–128）
CLKOUTn_FREQ 只读 —（由工具计算回填） 输出频率（MHz），由 calc_pll_clock 计算 pll_prop.py:91-95

重要澄清（工具侧实证）：「PLL 输出分频只能是 2 的幂次」这条经验只对 v1 简单 PLL 成立（api_options\pll_api_options.py:4-6 的 OptionValidator([2,4,...,256])）。v2 高级 PLL（Titanium 等）的 clkout0/1/2_div 是 RangeValidator(1,256)（api_options\pll_adv_api_options.py:5-9），任意整数均合法。官方示例 C:\Efinity\2026.1\examples\helloworld-unified\Ti60F225_kit_manual.isf:26 中 Ti60 配置 CLKOUT0_DIV="110"、Ti60F225_kit.isf:101 中 CLKOUT0_DIV="27"，均非 2 的幂次，可直接编译。请在工程中按实际器件代际对待此约束。

v3 起支持第 4/5 路输出：CLKOUT3_EN/PIN/DIV/FREQ/PHASE、CLKOUT4_*（pll_prop.py PropId 定义 :92-98 区段）；v4 起 CLKOUT3/4 连接类型支持 GCLK/RCLK（PLLV4Presenter，pll_prop.py:1773-1783）。

6. 专用 API（时钟计算族）

全部位于 DesignAPI（pt\bin\api_service\design.py，class DesignAPI :71 起）。

6.1 calc_pll_clock — 手动配置后回算频率

design.calc_pll_clock(inst) -> Dict[str, str]   # design.py:1989
  • 前提：先自行配好 M/N/O 与各路 CLKOUTn_DIV。
  • 返回：VCO 频率、PLL 频率、各使能输出频率的属性映射（内部经 PLLProp.get_frequency_property，design.py:2019）。
  • 实例不存在抛 PTBlkEditException（design.py:2003-2004）。

6.2 auto_calc_pll_clock — 目标频率自动求解（推荐）

design.auto_calc_pll_clock(inst,
                           target_freq: Dict[str, str],   # 目标频率（MHz）与相位（度）
                           apply_optimal: bool = True,    # True=把最优解写回 PLL 计数器
                           result_len: Optional[int] = None  # 返回方案数，默认 5；0=全部
                          ) -> List[Dict]                  # design.py:2219
  • target_freq 的键名取决于 PLL 代际，由计算器参数映射决定（pt\bin\api_service\property\pll_cal_prop.py）：
  • 简单 PLL（PLLCalcPresenter）：输入 M/N/O/REFCLK_FREQ/CLKOUTn_FREQ/CLKOUTn_PHASE/CLKOUTn_EN/CLKOUTn_DIV 等，结果含 VCO_FREQ/CLKOUTn_DIV/...；
  • 五输出 PLL（PLLCompCalcPresenter）：增加 PHASE_SETTING（psv0–4）参数；
  • EfxFpllV2（EfxFpllV2CalcPresenter）：增加 FEEDBACK_CM_CLKOUT/FEEDBACK_CM_PHASE/FEEDBACK_CM_FREQ 输入与 FEEDBACK_CM_DIV/PHASE_SETTING 结果。
  • target_freq=None 直接抛异常（design.py:2242-2244）。
  • 典型用法：
results = design.auto_calc_pll_clock("pll_inst1", {"CLKOUT0_FREQ": "100"})
best = results[0]                      # 按精度排序的候选方案列表
design.set_property("pll_inst1", "M", str(best["M"]), "PLL")
design.set_property("pll_inst1", "N", str(best["N"]), "PLL")
design.set_property("pll_inst1", "O", str(best["O"]), "PLL")
design.set_property("pll_inst1", "CLKOUT0_DIV", str(best["CLKOUT0_DIV"]), "PLL")

8. 常见错误与排查

症状 根因 处置
PTBlkCreateException: block type ... is not supported block_type 拼错（如 pll/PLLV2） 只能用 API_BLOCK_TYPE 清单中的字符串（object_db.py:35-59）；PLL 固定 "PLL"
第二次编译报 PLL pll_inst1 ... exists 重放的 ISF 里残留 create_block/create_pll_input_clock_gpio 引导编译后立即注释 create_*（AGENTS.md §15；ISF 无 delete 命令，不可试图"幂等删除"）
set_property 报非法值 跨代混用合法值（最常见：给 v1 填 CLKOUT0_DIV=110，或给 v2 填 PHASE=315） 对照 §4 速查表确认器件代际；v1 div 只能 2 的幂次，v2 phase 无 315
计算出的频率全错 REFCLK_FREQ 与实际输入不符；或先算后改计数器 修改 M/N/O/DIV 后重新 calc_pll_clock；或改用 auto_calc_pll_clock
Unknown instance 异常 实例名未创建/拼错；或对非 PLL 实例调 PLL 计算器 design.py:2001-2004、:2237-2240 均先校验对象类型
BYPASS/PWDN 属性报错 2026.1 DesignAPI 无此属性（证伪，见 §3.9） 删除该行；相应功能在 GUI 中配置
ISF 中 CLKOUT0_CONN_TYPE 大小写纠结 API 大写（GCLK）/DB 小写（gclk）双轨 抄官方 ISF 用 DB 值；脚本经 DesignAPI 写时两者皆可
bank 资源冲突（PLL_TL0 已占用） PLL 资源槽位唯一 assign_resource 换空闲资源名；每个 bank 的 PLL 资源数量见器件手册
OSC 输出无时钟 用了简单 OSC 却设 FREQ（该属性仅 adv/hposc 存在） 简单 OSC 只有 CLKOUT_PIN（osc_prop.py:34-40）；频率由器件固定
