Efinity 硬 IP：接口与 JTAG 参考

Efinity 硬 IP —— LVDS / MIPI / JTAG 接口参考

适用版本：Efinity 2026.1 调查日期：2026-09-25 调查方式：实读 2026.1\pt\bin\api_service\ Python 源码、2026.1\examples\ 官方工程样本，逐条提取属性名 / 合法值 / 默认值 / builder 行为；每个属性标注源文件与行号。 核心证据源（下文简写均省略前缀 C:\Efinity\2026.1\）： - pt\bin\api_service\property\jtag_prop.py —— JTAG 属性权威 - pt\bin\api_service\property\lvds_prop.py —— LVDS（legacy / Adv / V3）属性权威 - pt\bin\api_service\property\mipi_prop.py —— MIPI 像素级 TX/RX 属性权威 - pt\bin\api_service\property\mipi_dphy_prop.py —— MIPI DPHY lane 级 TX/RX 属性权威 - pt\bin\api_service\property\mipi_hard_dphy_prop.py + mipi_hard_dphy_prop_id.py —— 硬 DPHY 属性权威 - pt\bin\api_service\exim\isf_exporter.py —— ISF builder（命令产出机制） - pt\bin\api_service\common\object_db.py —— block_type 字符串注册表 - pt\bin\common_device\iobank\iobank_rule.py —— bank 电压 / LVDS bank 规则 - pt\bin\api_service\api_options\*.py —— 静态合法值 - examples\helloworld-dbg_MULTI_USERS\Ti375C529_kit.isf —— JTAG 官方 ISF 样本（helloworld-unified 系列不含 JTAG 实例）

1. 概述与定位

本卷覆盖三类接口型硬 IP，与《Efinity硬IP-PLL与OSC参考.md》《Efinity硬IP-DDR参考.md》构成硬 IP 系列：

关键结论：

  1. 三族硬 IP 都没有专用公开创建方法（对比 PLL 的 create_block/DDR 亦然）——公开面只有泛型三件套 create_block + set_property + assign_resource。
  2. JTAG 是唯一有官方 ISF 样本的接口硬 IP（helloworld-dbg_MULTI_USERS）；LVDS 与 MIPI 在全部 examples\*.isf 中无任何样本 → 本卷的 LVDS/MIPI ISF 模板按属性表构造，使用前必须过 cli/import_gpio.bat --dry-run 自检（同《Efinity硬IP-DDR参考.md》的处理）。
  3. 三族全部受 §9 bank 电压规则约束：LVDS bank 强制 3.3 V，MIPI DPHY 要求 1.2 V bank，二者不能共存同一 bank。

1.1 block_type 命名反转陷阱（重要）

object_db.py 中两个 MIPI DPHY 相关字符串命名方向相反，极易写错：

你想要的东西 正确 block_type 字符串 证据
lane 级软 DPHY（分立 lane，替代像素级 MIPI） "MIPI_TX_LANE" / "MIPI_RX_LANE" object_db.py:121-122（内部名 mipi_dphy_tx/rx → MIPI_TX_LANE/MIPI_RX_LANE）
硬 DPHY 整块 IP（含 PLL/SSC 等完整 PHY） "MIPI_DPHY_TX" / "MIPI_DPHY_RX" object_db.py:126-127（内部名 mipi_hard_dphy_tx/rx → MIPI_DPHY_TX/MIPI_DPHY_RX）

记忆法：字符串里带 LANE 的是 lane 级软 DPHY；字符串里带 DPHY 的才是硬 DPHY。写错时 PT 会按另一套属性集解析，表现为属性被拒或行为不符。

1.2 ISF 支持白名单

isf_exporter.py 的 supp_block 列出可进 ISF 的 block 类型（:149-173）：

  • 基础：GPIO、PLL、IOBANK、JTAG（:149）
  • 像素级 MIPI：MIPI_TX、MIPI_RX（:156-157）
  • 硬 DPHY：MIPI_DPHY_TX、MIPI_DPHY_RX（:160-161）
  • lane 级 DPHY + LVDS：MIPI_RX_LANE、MIPI_TX_LANE、LVDS_RX、LVDS_TX、LVDS_BIDIR（:164-168）

2. 创建三件套

所有接口硬 IP 的 ISF 配置都由三种命令构成（BlockISFBuilder CommandType，isf_exporter.py:1252-1258；字符串映射 cmd2str_map :1260-1264）：

# 1) 创建实例 —— 一次性 bootstrap（peri.xml 不存在时才允许执行）
design.create_block("<实例名>", "<BLOCK_TYPE>", [create 额外参数])

# 2) 设置属性 —— 幂等，可重放
design.set_property("<实例名>", "<PROP_NAME>", "<值>", "<BLOCK_TYPE>")

# 3) 分配硬件资源 —— 幂等，可重放
design.assign_resource("<实例名>", "<RESOURCE>", "<BLOCK_TYPE>")

要点：

  • set_property 第 4 参必须传精确 block_type 字符串（通用实现 isf_exporter.py:1379-1425）。
  • assign_resource 只有在实例的 device（RESOURCE）非空时才会由 builder 输出（build_resasg_command，isf_exporter.py:1427-1449）——JTAG 的 RESOURCE 即 JTAG_USER1/JTAG_USER2。
  • 重放安全契约（《Efinity-ISF语法参考.md》与硬约束 §15）：create_* 是一次性 bootstrap；进入工程引用的常驻 ISF 只允许 set_property / assign_resource / set_iobank_voltage 等幂等命令。引导编译生成 <design>.peri.xml 后立即注释掉 create_* 行。详见《Efinity文件格式-peri.xml.md》。
  • LVDS create 命令携带额外关键字参数（builder 依代际输出）：legacy TX 输出 tx_mode="<api_mode>"（gen_extra_create_parameter，isf_exporter.py:2225-2235）、legacy RX 输出 rx_conn_type="<api_mode>"（:2334-2344）；lane 级 DPHY TX 按 mode 输出 mode="CLOCK_LANE" 或 mode="DATA_LANE"（MIPIDPhyTxISFBuilder :1764-1767）。

3. JTAG 硬 IP

JTAG 用于 FPGA 配置后的边界扫描 / 用户调试通道。它是接口三族中唯一有官方 ISF 样本的硬 IP，本节属性表与模板可直接照抄。

3.1 属性全表

jtag_prop.py 的 jtag_prop_map（:67-79）中全部条目均无默认值（PropData(..., None)）——所有属性都必须显式设置。合法值方面 get_valid_option 返回空集（:230-233），即 ISF 层面对值不做静态枚举校验，值由 PT 内部使用方式决定（引脚名约定见下）。

8. 常见错误与排查

现象 根因 修复
二次编译报 GPIO/PLL/JTAG ... exists create_* 留在常驻 ISF 被重放 引导编译生成 peri.xml 后立即注释 create_* 行（硬约束 §15）

9. Bank 电压共存规则专节（LVDS / MIPI 关键约束）

规则引擎：pt\bin\common_device\iobank\iobank_rule.py 的 IOBankChecker 在 Design Check 阶段挂两条规则（_build_rules :108-113）：

  1. io_bank_rule_voltage_assignment（IOBankStandard，:126-151）：逐 bank 校验每个 IO 的 voltage standard 是否在该 bank 的器件库支持表内——checker.reg.is_io_standard_valid(device_db, bank, standard)（:148-149），失败报 "I/O Voltage ... is not supported for the bank"（:150-151）。bank 能用什么电压由 device db 定义，规则只做机制校验。
  2. io_bank_rule_lvds（IOBankLVDS，:155-195）：bank 内只要存在 LVDS 实例，该 bank 的 IO standard 必须等于 LVDS_IO_STANDARD = "3.3 V LVTTL / LVCMOS"（:36），否则报 "I/O Voltage has to be set to ... when LVDS is used"（:193-194）。LVDS bank 集合由 set_lvds_bank_map 维护（:61-106）。

由此得出的共存结论（实操约束，与既有硬约束一致）：

  • MIPI DPHY bank 必须 1.2 V——具体数值由 device db 支持表定义（iobank_rule.py 只做机制校验，:48 注释提及 mipi dphy 走同一电压规则）。
  • LVDS bank 强制 3.3 V（上条规则 2，源码硬编码 :36）。
  • 一个 bank 无法同时满足「仅 1.2 V」与「必须 3.3 V」→ MIPI 与 LVDS 不能共存同一 bank。违规的第一表现形通常是 io_bank_rule_voltage_assignment 报错。
  • ISF 中用 design.set_iobank_voltage("<bank>", "<voltage>") 声明 bank 电压（幂等，重放安全）；同一 bank 所有 IO 必须使用兼容该电压的 IO standard。

排查动作：报 io_bank_rule_voltage_assignment 时，按「检查该 bank 电压声明 → 列出 bank 内全部实例的 IO standard → 对照 device db 支持表 → 把 MIPI 与 LVDS 拆到不同 bank」四步处理。
