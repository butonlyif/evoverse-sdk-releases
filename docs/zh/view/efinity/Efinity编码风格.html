Efinity RTL 编码风格

Efinix FPGA Verilog/SystemVerilog 编码风格指南

版本: v1.0 更新日期: 2026-07-30 适用工具: Efinity IDE (Titanium / Trion / Quantum 系列) 适用场景: EvoVerse SDK 项目中的所有 RTL 开发，包括 Vibe Coding 生成的代码 来源: Efinity Synthesis Coding Style / Coding Reliability PPTX、Intel AN-1016、AMD UG949、现有 EvoVerse RTL 实践

关联文档: - EVOVERSE-SDK-完整设计说明书.md（主设计文档） - efinity-optimization-design.md（优化设计——方向一：代码风格指导系统的权威来源） - 用户使用手册.md（§10 代码风格检查——基于本指南的 25 条自动检查规则）

1. 文件组织与命名

1.1 文件命名

规则 说明
一个模块一个文件 文件名 = 模块名，如 ws_clock_mgr.v
扩展名 .v（Verilog）或 .sv（SystemVerilog） 推荐 .sv 用于新代码
小写 + 下划线 mipi_csi_rx.sv、ddr3_controller.sv
不要用连字符 mipi-csi-rx.sv ❌ → mipi_csi_rx.sv ✅
Top-level 命名以 _top 结尾 ws_golden_top.v

1.2 目录结构（模块内）

rtl/
├── top/            # 顶层集成
├── clk_rst/        # 时钟与复位管理
├── data_path/      # 数据通路（按功能分子目录）
├── ctrl/           # 控制逻辑 / 状态机
├── cdc/            # 跨时钟域模块
└── ip_wrappers/    # 第三方 IP 封装

2. 模块编写规范

2.1 模块头部模板

`default_nettype none
`timescale 1ns / 1ps

//============================================================================
// 模块名称: <module_name>
// 功能描述: <一句话说明做什么>
// 接口说明: <关键接口协议，如 AXI-Stream / Avalon-MM / 自定义握手>
// 设计约束: <时钟频率、延迟要求、吞吐率等>
// 关联文档: <引用的设计文档、IP datasheet>
//============================================================================
module module_name #(
    parameter DATA_WIDTH = 16,
    parameter ADDR_WIDTH = 10
)(
    input  wire                    clk_i,
    input  wire                    rst_n_i,
    // 数据输入
    input  wire [DATA_WIDTH-1:0]   data_i,
    input  wire                    valid_i,
    output wire                    ready_o,
    // 数据输出
    output wire [DATA_WIDTH-1:0]   data_o,
    output wire                    valid_o,
    input  wire                    ready_i
);

    //----------------------------------------------------------
    // 内部信号声明
    //----------------------------------------------------------
    // ...

    //----------------------------------------------------------
    // 逻辑实现
    //----------------------------------------------------------
    // ...

endmodule

`default_nettype wire

2.2 端口命名

方向 后缀 示例
输入 _i clk_i, data_i, valid_i
输出 _o data_o, valid_o, led_o
双向 _io sda_io
低有效 _n 前缀或后缀 rst_n_i, cs_n_o

2.3 内部信号命名

类型 命名方式 示例
寄存器 描述性名称 + _r 或不加后缀 cnt_r, state, data_reg
连线 描述性名称 fifo_full, buf_sel
状态机状态 ST_ 大写前缀 ST_IDLE, ST_READ, ST_WRITE
参数/常量 大写 + 下划线 DATA_WIDTH, MAX_BURST

2.4 禁止事项

  • ❌ 不要使用 inout 双向口，除非顶层 IO（用 _io 后缀标记清楚）
  • ❌ 不要在顶层模块内部写复杂逻辑（仅做实例化 + 简单连线）
  • ❌ 不要用 * 通配端口连接（.data_i(data_i) 而不是 .*）

3. 时钟与复位

3.1 复位策略

统一使用异步复位、同步释放：

// 标准 3 级同步释放复位
reg [2:0] rst_sync;
always @(posedge clk or negedge rst_n_i) begin
    if (!rst_n_i)
        rst_sync <= 3'b000;
    else
        rst_sync <= {rst_sync[1:0], 1'b1};
end
wire rst_n = rst_sync[2];

规则： - 顶层对外提供一个 rst_n_i（异步低有效） - 每个时钟域独立生成同步释放后的 rst_n - 复位释放链至少 2 级（推荐 3 级） - ❌ 不要用纯异步复位（always @(posedge clk or negedge rst_n_i) 的代码里不能只有异步释放逻辑而没有同步器） - ❌ 不要在数据通路上用全局复位（只复位控制逻辑，数据寄存器用 valid 控制）

3.2 时钟命名

信号 命名 示例
输入参考时钟 clk_<freq>m_i clk_50m_i, clk_100m_i
系统工作时钟 sys_clk sys_clk
视频/像素时钟 <domain>_clk video_clk, pixel_clk
PLL 输出 pll_<freq>m pll_200m

3.3 时钟使能（替代分频时钟）

不要用分频后的时钟去驱动逻辑：

// ❌ 不要这样
always @(posedge clk_div2) begin
    cnt <= cnt + 1;
end

用时钟使能替代：

// ✅ 应该这样
reg clk_en;
always @(posedge sys_clk) begin
    clk_en <= ~clk_en;  // 2 分频使能
end

always @(posedge sys_clk) begin
    if (clk_en)
        cnt <= cnt + 1;
end

4. 时序友好编码

4.1 寄存器输出

每个模块的输出尽量打一拍再出去：

// ✅ 推荐：输出寄存器化
always @(posedge clk) begin
    data_o  <= data_next;
    valid_o <= valid_next;
end

规则： - 模块输出通常应经过寄存器 - 如果有跨模块的时序违例，优先在发送端加输出寄存器 - 数据与伴生控制信号（valid/last/user）必须在同一拍寄存

4.2 流水线插入原则

当一条组合路径上连续 LUT 级数 ≥ 3 且逻辑延迟 > 周期的 60% 时，考虑插入流水线寄存器：

// ❌ 长组合链
assign result = stage3(stage2(stage1(data)));

// ✅ 流水线化
reg [W-1:0] pipe1, pipe2;
always @(posedge clk) begin
    pipe1 <= stage1(data);
    pipe2 <= stage2(pipe1);
end
assign result = stage3(pipe2);

4.3 高扇出控制

大于 200 扇出的控制信号，用 (* max_fanout *) 属性约束：

(* max_fanout = 100 *) reg shared_enable;

或手动复制驱动：

// 把一个使能信号复制 4 份，每份驱动 1/4 的负载
reg [3:0] en_replica;
always @(posedge clk) en_replica <= {4{en_src}};

5. 综合友好编码

5.1 FSM 编码

推荐 one-hot 编码（Efinix 推荐，LUT 结构友好）：

(* fsm_encoding = "one-hot" *)
reg [3:0] state, state_next;

localparam ST_IDLE  = 4'b0001;
localparam ST_READ  = 4'b0010;
localparam ST_PROC  = 4'b0100;
localparam ST_WRITE = 4'b1000;

5.2 Case 语句

// ✅ 完整 case
always @(*) begin
    case (state)
        ST_IDLE:  next = ST_READ;
        ST_READ:  next = data_valid ? ST_PROC : ST_READ;
        default:  next = ST_IDLE;  // 必须有 default
    endcase
end
  • 所有 case 必须有 default
  • if-else 链必须有最后的 else
  • 避免在组合逻辑 always @(*) 块中产生 latch

5.3 避免意外 Latch

产生 latch 的常见情况和修复：

情况 错误示例 修复
组合 always 块中信号未在所有分支赋值 if (en) y = a; 加 else y = 0; 或在开头赋默认值
case 缺少 default case (sel) 2'b00: y=a; ... 加 default: y = 0;
非阻塞赋值在组合逻辑块 always @(*) y <= a; 改 = 或改 always @(posedge clk)

6. 跨时钟域（CDC）

6.1 同步器模板

单比特控制信号 — 2/3 级同步器：

(* ASYNC_REG = "TRUE" *) reg [2:0] sync_ff;

always @(posedge clk_dst) begin
    sync_ff <= {sync_ff[1:0], src_signal};
end
wire signal_synced = sync_ff[2];

多比特总线 — MUX 同步（valid 同步后采样）：

// 发送侧（clk_src 域）
reg        valid_toggle;
reg [31:0] data_bus;

always @(posedge clk_src) begin
    if (send) begin
        data_bus      <= new_data;
        valid_toggle  <= ~valid_toggle;
    end
end

// 接收侧（clk_dst 域）
(* ASYNC_REG = "TRUE" *) reg [2:0] toggle_sync;
reg toggle_prev;

always @(posedge clk_dst) begin
    toggle_sync <= {toggle_sync[1:0], valid_toggle};
    toggle_prev <= toggle_sync[2];
    if (toggle_sync[2] != toggle_prev)
        captured_data <= data_bus;  // data_bus 此时已经稳定
end

6.2 CDC 规则

  • 任何跨时钟域的信号必须经过同步器
  • ❌ 不要在 SDC 里对 CDC 路径简单地设 set_false_path
  • 先确认 set_clock_groups -asynchronous，再对同步器本身 set_false_path -from sync_ff_0 -to sync_ff_2
  • 同步链加 (* ASYNC_REG = "TRUE" *) 防止被综合器挪动或优化掉
  • 快域→慢域单周期脉冲要先拉伸再同步

7. 资源利用

7.1 BRAM 推断

// ✅ BRAM 推断友好写法
(* ram_style = "block" *)
reg [DATA_W-1:0] mem [0:DEPTH-1];
reg [DATA_W-1:0] mem_rd;

always @(posedge clk) begin
    if (wr_en)
        mem[wr_addr] <= wr_data;
    mem_rd <= mem[rd_addr];  // 读也打一拍（output register）
end
  • 用 (* ram_style = "block" *) 显式告知综合器
  • 读数据用寄存器输出（BRAM 有内置 output register，免费）
  • 深度 ≥ 128 时优先用 BRAM 而非分布式 RAM

7.2 DSP 推断

// ✅ DSP 推断友好写法
(* use_dsp = "yes" *)
reg [17:0] mult_result;

always @(posedge clk) begin
    mult_result <= $signed(a) * $signed(b);
end
  • 乘法器输入/输出都加寄存器（利用 DSP 内置 pipeline register）
  • 使用 $signed() 明确告知是有符号乘法

7.3 PLL 配置

PLL 应通过 Efinity Interface Designer 配置为硬核，不在 RTL 中例化：

// ✅ PLL 通过 Interface Designer 配置
// 在 RTL 中只声明 PLL 输出的时钟端口和锁定信号
input  wire pll_clk_out,   // PLL 输出的工作时钟
input  wire pll_locked,    // PLL 锁定指示

8. Efinix 特有属性

属性 用途 示例
(* ASYNC_REG = "TRUE" *) CDC 同步链标记 (* ASYNC_REG = "TRUE" *) reg [2:0] sync;
(* max_fanout = N *) 扇出控制 (* max_fanout = 100 *) reg en;
(* ram_style = "block" *) BRAM 推断 (* ram_style = "block" *) reg [15:0] mem [0:511];
(* use_dsp = "yes" *) DSP 推断 (* use_dsp = "yes" *) reg [35:0] p;
(* syn_keep = "true" *) 防止优化 (* syn_keep = "true" *) wire debug_sig;
(* fsm_encoding = "one-hot" *) 状态机编码 (* fsm_encoding = "one-hot" *) reg [3:0] state;

9. SDC 约束配套

9.1 时钟命名与 RTL 对应

SDC 中的时钟名必须与 RTL 中的端口名或 PLL 输出名匹配：

# RTL:    input wire clk_50m_i
# 或 PLL: 输出名为 sys_clk
create_clock -period 20.0 -name clk_50m [get_ports clk_50m_i]
create_clock -period 5.0  -name sys_clk [get_pins {u_pll/sys_clk}]

9.2 时钟分组

# 异步时钟域
set_clock_groups -asynchronous \
    -group [get_clocks clk_50m] \
    -group [get_clocks sys_clk] \
    -group [get_clocks video_clk]

9.3 IO 延迟

set_input_delay  -clock sys_clk -max 2.0 [get_ports {data_in[*]}]
set_output_delay -clock sys_clk -max 1.5 [get_ports {led_o[*]}]

10. 反模式清单（禁止事项）

# 反模式 说明 正确做法
1 纯组合逻辑 always @(*) 块中没有给所有输出赋默认值 产生意外 latch 在块开头给所有输出赋默认值
2 case 没有 default / if-else 没有 else 产生意外 latch 补齐缺省分支
3 用分频时钟驱动逻辑 时钟域变多，约束变复杂 用时钟使能替代
4 跨时钟域不加同步器 亚稳态导致功能错误 按 §6 加同步器
5 异步复位没有同步释放 复位释放时产生亚稳态 §3.1 的同步释放链
6 数据和控制信号不同拍寄存 下游收到错位的 valid/data 同 always 块内统一寄存
7 对大扇出信号不加复制 布线拥塞导致违例 max_fanout 或手动复制
8 BRAM 读不用 output register 浪费 BRAM 内置寄存器 读地址和数据都打一拍
9 乘法器输入/输出不加寄存器 关键路径变长 DSP 前后都打拍
10 在一个 always 块里混用 = 和 <= 仿真/综合行为不一致 组合用 =，时序用 <=
11 inout 端口不在顶层 内部 logic 用 inout 非常规 拆成 _i/_o/_oe 三信号
12 信号名与 Verilog 关键字冲突 编译错误 选不同名称

11. 检查清单

编写或修改 RTL 后，逐项确认：

结构检查： - [ ] 文件名 = 模块名，小写 + 下划线 - [ ] 模块头有功能说明注释 - [ ] default_nettype none 开头 / default_nettype wire 结尾 - [ ] 端口有 _i / _o 方向后缀

时序检查： - [ ] 模块输出经寄存器 - [ ] 数据和控制信号在同一 always 块中寄存 - [ ] 高扇出信号已加 max_fanout 或手动复制 - [ ] 跨时钟域信号有同步器 + ASYNC_REG 属性

综合检查： - [ ] 所有 case 有 default - [ ] 组合 always @(*) 中所有输出在进入分支前有默认值 - [ ] BRAM 读使用了 output register - [ ] 乘法器输入/输出有寄存器 - [ ] FSM 使用 fsm_encoding = "one-hot"

约束配套检查： - [ ] SDC 中有时钟定义（与 RTL 端口名匹配） - [ ] 异步时钟域有 set_clock_groups - [ ] IO 有 set_input_delay / set_output_delay
