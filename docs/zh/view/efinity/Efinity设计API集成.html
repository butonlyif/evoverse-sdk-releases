Efinity DesignAPI 集成

Efinity DesignAPI 原生集成

EvoVerse SDK 不定义额外的接口设计文件格式。接口设计以 Efinity 原生文件为准：

文件 角色 是否建议版本管理
<project>.xml Efinity 工程数据库 是
constraints/*.peri.isf Interface Designer Python API 命令，可重建设计 是
<project>.peri.xml Interface Designer 设计数据库 作为生成物管理
ip/<instance>/settings.json Efinity IP Manager 实例参数 是
outflow/<project>.* PT、综合、PNR 和 bitstream 产物 否

编译流程

  1. SDK 选择明确的 Efinity 工程 XML，并以该 XML 所在目录作为工作目录。
  2. SDK 调用 Efinity 原生 efx_run --flow compile，不在主编译前另跑一遍 PT。
  3. Efinity 根据工程 XML 引用的 ISF / interface 配置执行原生 PT。
  4. PT 内部通过 api_service.design.DesignAPI 创建或加载接口设计。
  5. DesignAPI 导入 ISF、完成资源分配和 design check。
  6. Efinity 生成 PT 产物，再继续 Map / PNR / PGM。
  7. 进入 Efinity synthesis、PNR、timing 和 bitstream 流程。

SDK 在运行原生 PT 流程前保存当前 peri.xml 及同工程名的 PT outflow 产物。若 ISF 导入、资源分配、DRC 或生成失败，旧产物会自动恢复，避免工程 停留在半生成状态。

IP 实现

软 IP 继续由 Efinity IPMDesignAPI 创建、配置、校验和生成，并使用原生 settings.json 保存实例参数。需要器件硬资源的 IP，由其 Efinity generator 调用 DesignAPI 修改 peri.xml。SDK 不复制 Efinity 的硬 IP 实现规则。

因此完整职责为：

IPMDesignAPI/settings.json -> IP RTL 与 IP 实例
DesignAPI/*.peri.isf       -> GPIO、PLL、DDR、MIPI、PCIe、JTAG、SoC
Efinity project XML        -> 工程、源文件和 IP 注册
Efinity compile flow       -> synthesis、PNR、timing、bitstream

版本兼容

Block type、property、preset 和 resource 名称与器件及 Efinity 版本相关。 应以当前 Efinity 安装目录的 doc/pdf/efinity-python-api.pdf 为准，不在 SDK 中维护一份可能过期的属性副本。

DesignAPI CLI

SDK 提供只操作原生 peri.xml / ISF 的结构化查询服务：

evoverse design capabilities --peri <project>.peri.xml
evoverse design capabilities --peri <project>.peri.xml --include-resources
evoverse design inspect --peri <project>.peri.xml
evoverse design validate --peri <project>.peri.xml
evoverse design validate --peri <project>.peri.xml --isf constraints/base.peri.isf
evoverse design export-isf --peri <project>.peri.xml --output exported.peri.isf
evoverse design auto-assign --peri <project>.peri.xml
evoverse design auto-assign --peri <project>.peri.xml --apply --output resolved.auto_asg.isf

capabilities、inspect 和 validate 会在临时隔离副本上加载数据库，避免 DesignAPI 自动升级数据库版本时改写用户的 peri.xml。export-isf 的唯一 写入目标是用户明确指定的原生 ISF 文件。

validate --isf 会把 DRC实例映射到原生 ISF 的首次创建行。auto-assign 默认只预览 Efinity auto_assign_resource() 的结果；只有同时提供 --apply 和 --output 才写出独立的原生 ISF，不会合并或覆盖基础 ISF。

evoverse ip add 会在 IPM生成前保存当前 peri.xml，生成后运行 DesignAPI DRC。IPM、结果解析或后置 DRC失败时恢复原数据库，避免硬 IP generator 的 半完成修改进入编译。

历史 peri.xml 可能不兼容当前 Efinity schema。遇到此情况，应使用对应工程 的 *.peri.isf 重新生成数据库，而不是修改 XML schema 或在 SDK 中维护迁移器。

TJ180 实测基线

Efinity 2026.1 下已使用 docs/tutorials/snapshots/stage3-pwm 完成隔离闭环：

  1. 删除复制工程中的旧 peri.xml。
  2. 从 constraints/base.peri.isf 重建接口数据库。
  3. DesignAPI DRC 通过，问题数为 0。
  4. Synthesis PASS。
  5. Interface PASS。
  6. PNR PASS。
  7. PGM/bitstream PASS。

主编译只调用一次 Efinity 原生 efx_run --flow compile，由 Efinity 完成 PT → map → pnr → pgm。SDK 不注入跳过 PT 的环境变量，也不复用预执行 PT 产物绕过原生阶段。
