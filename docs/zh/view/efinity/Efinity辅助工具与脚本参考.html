2. ftdi_program.py —— JTAG/SPI 烧录原生脚本

2.1 实际位置与调用入口

实际路径是 pgm\bin\efx_pgm\ftdi_program.py（不是安装根下的 pgm\ftdi_program.py），主类 FtdiProgram，模块底部 parse_cmdline()（pgm\bin\efx_pgm\ftdi_program.py:3148）+ main()（同文件 :3341）。

官方命令行入口是 pgm\bin\ftdi_pgm.bat：

:: ftdi_pgm.bat:7-8（实读）
set PYTHONPATH=%EFINITY_HOME%/debugger/bin;%EFINITY_HOME%/pgm/bin
"python3.bat" pgm\bin\efx_pgm\ftdi_program.py %*

两个要点（证据 pgm\bin\ftdi_pgm.bat:7-8）：

  1. PYTHONPATH 注入了 debugger\bin（提供 efx_dbg 包）与 pgm\bin（提供 efx_pgm 包）——ftdi_program.py 同时 import 两者（ftdi_program.py:147-171，含 efx_dbg.jcf/jtag/jtag_chain_detector、efx_pgm.jtag2SpiDriver 等）。
  2. bat 内部用相对路径 pgm\bin\efx_pgm\ftdi_program.py 调用，因此必须在 %EFINITY_HOME% 根目录下运行 pgm\bin\ftdi_pgm.bat（或先 cd /d %EFINITY_HOME%）。

底层依赖 pyftdi（MPSSE/JTAG-SPI）与 pyspiflash；docstring（ftdi_program.py:1-116）给出 FTDI C232HM-DDHSL-0 线缆的 ADBUS 引脚映射（SCLK=ADBUS0 … CDONE=ADBUS5）以及驱动安装说明（Linux 用 udev 规则、Windows 用 zadig 替换 FTDI 驱动）。Linux 下还需注意 udev 权限。

默认时钟频率与校验方式在 FtdiProgram.__init__ 中设定（ftdi_program.py:193-219）：

项 默认值 证据
jtag_program_freq 3 MHz（3E6） ftdi_program.py:219 附近（__init__）
spi_direct_program_freq 3 MHz（3E6） 同上
spi_flash_program_freq 6 MHz（6E6） 同上
verify_method onchipx2 ftdi_program.py:219

2.2 八种编程模式全表

-m/--mode 共 8 个合法值（ftdi_program.py:3148 起 parse_cmdline()，choices 列表）。main() 的分发关系（ftdi_program.py:3341-3379）：

mode（默认 passive） main() 分发到的函数 语义 输入文件格式
passive spi_direct_program FPGA 处于未配置状态，SPI flash 总线直连主机，直接烧写 flash .hex
active spi_flash_program FPGA 已配置并运行，经 FPGA 侧桥接访问 SPI flash 烧写 .hex
jtag jtag_program JTAG 直接下载位流到 FPGA（不写 flash） .bit
jtag_chain jtag_program(chain=True) 多器件 JTAG 链，用 -n/--num 选择链上第 N 颗芯片 .bit
erase_flash spi_erase_flash 擦除 SPI flash（配合 --address / --num_bytes） 无输入文件
read_flash spi_read_flash 读回 flash 内容写入 -o/--output_file 无输入文件
jtag_bridge jtag2spi 经 JTAG-Bridge（先向 FPGA 预载 §5 的 flash loader 位流）访问 SPI flash .hex
jtag_bridge_x8 jtag2spi_x8 同 jtag_bridge，8-bit 宽总线变体 .hex

模式-文件兼容性由 check_mode_file_compatibility() 强制（ftdi_program.py:3130-3145）：

  • jtag / jtag_chain 只接受 .bit；
  • passive / active / jtag_bridge / jtag_bridge_x8 只接受 .hex（SPI flash 编程用十六进制格式，由 Efinity GUI 导出）。

jtag_bridge 系列的子操作由 --jtag_bridge_mode 控制，jtag2spi() 内按六种取值分发（ftdi_program.py:1696-1737）：read / erase / write / erase_and_write / all_no_erase / all（all 与 all_no_erase 走完编程后按 --verify_method 校验）。

main() 末尾按成败分别 sys.exit(0) / sys.exit(1)（ftdi_program.py:3341-3379）。脚本/CI 可据此判断烧录结果。

2.5 八种模式调用示例

以下示例均在 %EFINITY_HOME% 根目录执行（原因见 §2.1 要点 2）。设备 URL 先用 --list_usb 查询，示例中以 ftdi:// 泛指：

:: 1. passive：FPGA 未配置，直连 SPI flash 烧 .hex
pgm\bin\ftdi_pgm.bat -m passive -u ftdi:// design.hex

:: 2. active：FPGA 已在运行，经 FPGA 桥接烧 flash
pgm\bin\ftdi_pgm.bat -m active -u ftdi:// design.hex

:: 3. jtag：JTAG 下载 .bit 到 FPGA（附 JCF）
pgm\bin\ftdi_pgm.bat -m jtag -u ftdi:// -x debug.jcf design.bit

:: 4. jtag_chain：多芯片链，选第 2 颗
pgm\bin\ftdi_pgm.bat -m jtag_chain -u ftdi:// -n 2 design.bit

:: 5. erase_flash：整片擦除（可加 --address/--num_bytes 限定区间）
pgm\bin\ftdi_pgm.bat -m erase_flash -u ftdi://

:: 6. read_flash：读回 flash 到文件
pgm\bin\ftdi_pgm.bat -m read_flash -u ftdi:// -o flash_dump.hex

:: 7. jtag_bridge：经 JTAG-Bridge 写 flash（先预载 fli loader，见 §5）
pgm\bin\ftdi_pgm.bat -m jtag_bridge -u ftdi:// --jtag_bridge_mode erase_and_write design.hex

:: 8. jtag_bridge_x8：8-bit 宽 JTAG-Bridge 变体
pgm\bin\ftdi_pgm.bat -m jtag_bridge_x8 -u ftdi:// design.hex

SDK/adapter 侧的自动化：scripts\efx_run.py 的 program flow 直接 import efx_pgm.ftdi_program 并调用 FtdiProgram（scripts\efx_run.py:1718 起的 run_program()），与命令行共享同一套代码路径。

5. flash loader 位流（pgm\fli\）与 device_db IDCODE 对应

5.1 作用与命名规则

pgm\fli\ 下按器件族分三个子目录（trion\ 11 个、topaz\ 14 个、titanium\ 21 个，共 46 个 .bit）。这些是 JTAG-Bridge 烧 flash 时预载进 FPGA 的桥接位流（flash loader）：ftdi_program.py -m jtag_bridge[_x8]（§2.2）先把对应 loader 下载进 FPGA，FPGA 内部再桥接访问 SPI flash。

命名规则：u<IDCODE 小写十六进制>[_t<型号/时序等级>].bit

  • u + IDCODE 去掉 0x 前缀，与 pgm\bin\device_db.xml 中 <idcode value="0x…"> 逐字对应（如 u006C0A79 ↔ 0x006C0A79）。
  • _tXX 后缀：同一 die 覆盖多个型号/时序等级时区分（如 T35/T20 同 die → u00240A79_t35 与 u00240A79_t20）。
  • _tXXqYYY：含封装变体（如 u00210A79_t8q144、u00210A79_t20q144 为 q144 封装变体）。
  • 特例 u00000000_t8/t4：T8/T4 小器件在 device_db 中用全零占位 IDCODE（device_db.xml:41-42，原文注释 "this is obviously invalid"）。

5.2 device_db.xml 结构

pgm\bin\device_db.xml 按 <die name="…"> 组织，每 die 含：<idcode>、<family>、<option_register>（位流选项寄存器布局与同步字）、<scan_chain>（CDONE/NSTATUS/CBUS 等状态位地址）。示例（device_db.xml:125-126）：<die name="T35/T20"> <idcode value="0x00240A79"/> <family value="Trion"/>。全库共 48 个 die 条目（行 16-882）。

5.4 使用时机

只有 -m jtag_bridge / -m jtag_bridge_x8 需要 fli loader（先载 loader、再经桥访问 flash）；-m passive / -m active 直连或经已配置 FPGA 访问 flash，-m jtag / jtag_chain 只下载 SRAM 位流，都不消费 fli。

  2. efx_run.py:33-36 顶部 import efx_run_map/efx_run_sim/efx_run_pnr/efx_run_pgm（同目录 scripts\ 兄弟模块）；

7.2 efinity_init.tcl 加载链

efinity_init.tcl（全文 434 行实读）做三件事：

  1. 加载四个本地 C 扩展库（:15-26，按平台选 bin\*.dll / lib\*.so）：

  1. 定义 help 体系与命令目录：help（:32-94，分 sdc/timing 两类）、print_sdc_commands（:101-148，约 20 条 SDC 命令：create_clock/set_clock_groups/set_false_path/set_input_delay/set_bus_skew 等）、print_timing_commands（:150-183，13 条：read_sdc/report_timing_summary/report_cdc/set_timing_model 等）。
  2. 薄 wrapper 转发 + 集合命令重载：
  3. :199-347 将每个顶层命令一行转发到 C 命名空间：timing::（read_sdc/write_sdc/report_）、sdc_get_cmds::（get_cells/get_ports/all_）、sdc_constr_cmds::（create_clock/set_*）。注释明确"wrapper 必须薄，所有检查在 C 侧完成"（:189-195）。
  4. :349-434 对 lappend/lassign/lsort/lindex/linsert/llength/lrange/lreplace/lreverse/lsearch/lset/foreach 做 rename + interp alias 重载，使其支持 "object group"（集合对象），并提供 foreach_in_collection。这意味着在这些 shell 中遍历时序对象时，标准 Tcl 列表命令已被替换为对象感知版本——自写 STA Tcl 脚本时不要依赖被重载命令的原始语义。

7.4 efx_sta 如何消费这些包

两条消费路径（均实测确认）：

  1. 独立 STA：bin\efx_sta.exe --help（2026-09-25 实测）给出全部用法——--prj <xml> 打开工程；-t/--tclsh [script] "Open the specified project, load the design, then start a Tcl session"（无参数则进交互会话，有参数则执行脚本）。该内嵌 Tcl 解释器启动时即加载 tcl_packages 中的包（efinity_init.tcl 的 4 个 DLL 与命令 wrapper 由此生效）。
  2. 编译流内嵌 STA（sta_tclsh flow）：scripts\efx_run.py:184 的 flow 清单含 sta_tclsh；-t/--tcl_script 指定脚本（:194）；run_pnr(args, run_sta_tclsh=True)（:1273）在 pnr 命令行追加 --sta_tclsh，并经 --sta_tclsh_script <file> 传入用户 Tcl 脚本（:1326-1330）——即 pnr 完成布局布线后直接在结果数据库上打开同一个 Tcl/STA 环境。

扩展点：用户自定义 STA Tcl 脚本可使用 §7.2 全部 timing/SDC 命令与 object-group 遍历设施；写脚本的典型骨架是 efx_run -t my_sta.tcl --prj xxx.xml --flow sta_tclsh（或在 efx_sta -t 会话中交互探索）。SDC 命令语义详见《Efinity工具链参考.md》与《Efinity设计规范.md》。
