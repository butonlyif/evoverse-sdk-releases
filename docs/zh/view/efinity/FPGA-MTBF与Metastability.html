1. Metastability 基础

1.1 触发条件

当 D 触发器的 setup 或 hold 时间被违反时，输出既非 0 也非 1——亚稳态（metastable state）。

"A metastable state occurs when the output of flip-flop is unknown. This occurs when setup or hold times are violated." —— Source: [B4] Max Planck Institute Lesson 11

1.2 物理机制（UBC [B3]）

D 触发器内部是交叉耦合反相器。正常状态下稳定在 0 或 1。若输入变化恰在时钟边沿的亚稳态窗口内，反相器对可能暂时稳定在中间电压，然后指数衰减回到 0 或 1：

V(t) = V_metastable + (V_final − V_metastable) · (1 − e^(−t/τ))

其中 τ = 触发器 RC 时间常数。

1.3 亚稳态传播

亚稳态的解决时间（resolution time）取决于触发器物理参数 + 输出电容 + 噪声。

"When a register's setup or hold time is violated — which can happen when data changes close to a clock edge from a different domain — the output of the register can become undefined for an unpredictable period of time." —— Source: [B10] Embedded Design CDC Part 1

关键事实： - 亚稳态不可避免（仅当 2 个时钟频率比固定且相位固定时可避免——但实际工程不现实） - 亚稳态不可预测（不能保证解决方向——0 还是 1） - 亚稳态概率随时间指数衰减——只要等够久，几乎一定解决

因此：synchronizer 的作用是让亚稳态有时间解决，而不是阻止其发生。

2. MTBF 方程

2.1 经典公式（UBC ELEX 7660 [B3]）

MTBF = e^(T_s / C_2) / (C_1 · f_d · f_c)
变量 含义
T_s Setup slack 时间（从 timing 分析得到）
C_2 触发器时间常数（RC + gain）
C_1 触发器"窗口"常数（捕获 metastability 的窗口大小）
f_d 数据切换频率（toggle rate）
f_c 采样时钟频率

Source: [B3] UBC ELEX 7660 Lec 11（内部研究笔记曾保存摘录，临时笔记不随仓库发布）

2.2 关键公式性质

"Since accurate estimation of MTBF requires knowing the propagation delay between flip-flops and the constants for the specific flip-flops used, MTBF calculations are typically done by timing analysis software. For example, Intel's TimeQuest STA can recognize CDC synchronizers (described below) and generate MTBF estimates." —— Source: [B3] UBC ELEX 7660 Lec 11

Efinity 当前未提供 MTBF 报告工具（截至 2026.1，无 report_mtbf 命令）——需手工计算或参考跨厂商工具（Intel TimeQuest、Xilinx Vivado）。

详见 §6。

3. 变量详解

3.1 T_s（Setup Slack 时间）

定义：从 timing analysis 报告中读取——synchronizer 第 2 级 FF 的 setup slack（从 source 时钟到 destination 时钟）。

典型值： - 100 MHz 系统，源域 50 MHz：T_s ≈ 20 ns（一个目的周期） - 100 MHz 系统，源域 100 MHz：T_s ≈ 10 ns

3.2 C_2（时间常数）

定义：触发器从 metastable voltage 衰减到 valid logic level 的 RC 时间常数。

典型值（Xilinx 7-series 经验）： - C_2 ≈ 10-50 ps（典型 20 ps）

实验测量（UBC [B3] 练习题）：

"Exercise 1: A TimeQuest MTBF report says Under typical conditions, an increase of 100ps in available settling time will increase MTBF values by a factor of 10.8. What is C_2?"

求解：

MTBF ∝ e^(T_s / C_2)
MTBF' / MTBF = 10.8 = e^(100ps / C_2)
ln(10.8) = 100ps / C_2
C_2 = 100ps / ln(10.8) = 100ps / 2.38 ≈ 42 ps

3.3 C_1（窗口常数）

定义：与触发器"亚稳态窗口宽度"成比例——setup/hold 边沿敏感窗口。

典型值（Xilinx 7-series 经验）： - C_1 ≈ 10⁻³ 至 10⁻² (1/s)

3.4 f_d（数据切换频率）

定义：输入 D 端每秒变化次数。

典型值： - 异步控制信号（如中断）：f_d ≈ 1 kHz – 1 MHz - 高速数据流：f_d ≈ 100 MHz – 1 GHz

3.5 f_c（采样时钟频率）

定义：synchronizer 第 2 级 FF 的时钟频率。

4. MTBF vs Slack 的指数关系

4.1 公式性质

MTBF ∝ e^(T_s / C_2)

增加 slack → MTBF 指数增长：

"Since MTBF increases exponentially with slack time (T_s), the most effective way to increase the MTBF is to increase the slack time." —— Source: [B3] UBC ELEX 7660 Lec 11

4.2 数量级示例（典型 C_2 = 20 ps）

Slack T_s T_s / C_2 e^(T_s/C_2) MTBF 改善
100 ps 5 148 1× (基准)
200 ps 10 22,026 148×
500 ps 25 7.2 × 10¹⁰ 4.9 × 10⁸ ×
1 ns 50 5.2 × 10²¹ 3.5 × 10¹⁹ ×

结论：让 synchronizer 多一个目的周期 slack（10 ns），MTBF 可达天文数字。

4.3 另一项关键优化

"The MTBF is also inversely proportional to product of the clock and data input toggle frequencies. Thus another way to increase the MTBF is to minimize the clock frequency and data toggle rates." —— Source: [B3] UBC ELEX 7660 Lec 11

降低 f_d · f_c： - 选择低频时钟作 synchronizer 目的域（高频域放寄存器之前，先经 2-FF sync 到低频域） - 数据源先展宽脉冲（如 1 周期 → 4 周期），减小 f_d

5. MTBF 目标值

5.1 应用分级

应用 目标 MTBF 设计要求
普通消费电子 ≥ 10⁹ 年（1 billion 年） 2-FF synchronizer + async_reg
工业控制 ≥ 10¹² 年 2-FF synchronizer + async_reg + 充足 slack
汽车 AEC-Q100 ≥ 10¹⁵ 年 3-FF synchronizer + 多种冗余
医疗 IEC 62304 ≥ 10¹⁸ 年 3-FF + 完整 fault tree analysis
航天 / 核控制 ≥ 10²⁰ 年 多重冗余 + 自检

Source: Intel TimeQuest MTBF report ([B3] UBC 引用) — "Typical MTBF is Greater than 1 Billion Year" 视为消费级最低要求。

5.2 简单计算示例

假设 100 MHz 系统，2-FF synchronizer： - T_s = 10 ns (一个目的周期 slack) - C_2 = 20 ps - C_1 = 10⁻³ (1/s) - f_d = 1 MHz - f_c = 100 MHz

MTBF = e^(10ns / 20ps) / (10⁻³ · 1MHz · 100MHz)
     = e^500 / (10⁻³ · 10¹⁴)
     = 1.4 × 10²¹⁷ / 10¹¹
     = 1.4 × 10²⁰⁶ 秒
     ≈ 4.4 × 10¹⁹⁸ 年

远超任何合理目标——因此 2-FF synchronizer 通常足够。

6. Efinity MTBF 工具支持

6.1 Efinity 2026.1 现状

Efinity 未提供显式 report_mtbf 命令（截至 2026.1）。MTBF 验证需： 1. 自行计算（使用 §3 公式） 2. 使用跨厂商 STA 工具（Intel TimeQuest / Xilinx Vivado）参考 MTBF 数据 3. 委托第三方形式验证工具（formal.org CDC 模块）

6.2 间接验证

Efinity STA 报告 pt_timing.rpt 中对 CDC 路径会给出 setup slack——若同步器有正 slack（typical > 0.5 ns），可估算 MTBF 远高于消费级要求。

详见 时序分析指南.md §3。

6.3 设计阶段 MTBF 估算脚本（Python）

# mtbf_calc.py — MTBF 估算工具（基于 UBC [B3] 公式）
import math

def mtbf(T_s_ps, C_1, C_2_ps, f_d_Hz, f_c_Hz):
    """Calculate MTBF in years.

    Args:
        T_s_ps: Setup slack in picoseconds
        C_1: Aperture constant (1/s) - device-specific
        C_2_ps: Time constant in picoseconds - device-specific
        f_d_Hz: Data toggle rate (Hz)
        f_c_Hz: Clock frequency (Hz)
    """
    exp_arg = T_s_ps / C_2_ps
    mtbf_sec = math.exp(exp_arg) / (C_1 * f_d_Hz * f_c_Hz)
    SEC_PER_YEAR = 365.25 * 24 * 3600
    return mtbf_sec / SEC_PER_YEAR

# Typical Efinity Titanium FF (estimate from C_2 ≈ 20-50 ps)
# NOTE: Efinity 不公开 FF 常数 — 此处用工业典型值
T_s_ps = 10_000       # 10 ns slack
C_1    = 1e-3         # aperture constant
C_2_ps = 40           # 40 ps time constant
f_d_Hz = 1e6          # 1 MHz data toggle
f_c_Hz = 100e6        # 100 MHz clock

years = mtbf(T_s_ps, C_1, C_2_ps, f_d_Hz, f_c_Hz)
print(f"Estimated MTBF: {years:.2e} years")
# Output: ~10^200+ years (consumer-grade target easily met)

注意：Efinity 不公开 C_1 / C_2 常数（与 Xilinx / Intel 不同）——脚本仅供估算量级，精确值需实际 silicon 测量或参考 Intel TimeQuest 的同等工艺数据。

7. Efinity 2-FF Synchronizer（async_reg）

7.1 async_reg 属性

关键综合属性：标记寄存器为 CDC synchronizer——综合阶段禁止合并 / 优化 / 复制这些寄存器。

"To designate a register as a synchronizer, use the async_reg synthesis attribute. When async_reg is true, synthesis does not perform optimization to reduce, merge, or duplicate these registers." —— Source: C:\Efinity\2026.1\doc\topics\tim-clk-relationships.html ([A3.3])

7.2 完整 RTL 模板

module cdc_sync_2ff #(
    parameter [0:0] INIT = 1'b0
) (
    input  wire dst_clk,
    input  wire dst_rst_n,
    input  wire async_in,
    output wire sync_out
);
    (* async_reg = "true" *)
    reg meta, settled;

    always @(posedge dst_clk or negedge dst_rst_n) begin
        if (!dst_rst_n) begin
            meta    <= INIT;
            settled <= INIT;
        end else begin
            meta    <= async_in;
            settled <= meta;
        end
    end

    assign sync_out = settled;
endmodule

Source: 基于 [A3.4] tim-clk-syncronizers.html 推荐模板

7.3 VHDL 等价

library ieee;
use ieee.std_logic_1164.all;

entity cdc_sync_2ff is
    generic (INIT : std_logic := '0')
    port (
        dst_clk    : in  std_logic;
        dst_rst_n  : in  std_logic;
        async_in   : in  std_logic;
        sync_out   : out std_logic
    );
end entity;

architecture rtl of cdc_sync_2ff is
    attribute async_reg : boolean;
    signal meta, settled : std_logic;
begin
    attribute async_reg of meta, settled : signal is true;

    process(dst_clk, dst_rst_n)
    begin
        if dst_rst_n = '0' then
            meta    <= INIT;
            settled <= INIT;
        elsif rising_edge(dst_clk) then
            meta    <= async_in;
            settled <= meta;
        end if;
    end process;

    sync_out <= settled;
end architecture;

Source: [A1] Efinity Timing Closure User Guide §5 "Metastable Synchronizer Circuit"

8. 3-FF Synchronizer：何时需要

8.1 学术建议（formal.org [B9]）

"The resolution time doubles and the MTBF improves exponentially — typically by many orders of magnitude. For most technologies and clock frequencies, two flip-flops provide MTBF measured in millions or billions of years, which is adequate for functional correctness. High-reliability designs occasionally use three flip-flops for an additional exponential improvement." —— Source: [B9] formal.org Module 7

8.2 何时升级到 3-FF

条件 推荐
普通消费 / 工业（目标 10⁹ 年） 2-FF + async_reg
setup slack < 200 ps 3-FF
目的时钟 ≥ 500 MHz 3-FF（slack 时间短）
航空航天 / 医疗 3-FF + 自检
已知 silicon 亚稳态特性差 3-FF

8.3 Efinity 3-FF 模板

module cdc_sync_3ff #(
    parameter [0:0] INIT = 1'b0
) (
    input  wire dst_clk,
    input  wire dst_rst_n,
    input  wire async_in,
    output wire sync_out
);
    (* async_reg = "true" *)
    reg stage1, stage2, stage3;

    always @(posedge dst_clk or negedge dst_rst_n) begin
        if (!dst_rst_n) begin
            stage1 <= INIT;
            stage2 <= INIT;
            stage3 <= INIT;
        end else begin
            stage1 <= async_in;
            stage2 <= stage1;
            stage3 <= stage2;
        end
    end

    assign sync_out = stage3;
endmodule

9.2 解读

  • Design MTBF = 设计中所有 synchronizer 链 MTBF 的合并值

9.4 Efinity 替代方案

Efinity 不支持 MTBF report。推荐做法： 1. 用 Efinity report_timing 验证 synchronizer setup slack > 0（最好 > 500 ps） 2. 用 §6.3 脚本估算 MTBF 量级 3. 关键路径（医疗 / 航天）用第三方形式验证（formal.org / JasperGold）

10. 设计准则

10.1 最小化 CDC 数量

原则：能避免跨域就避免。

"To avoid CDC problems you should minimize clock domain crossings, use only commonly-accepted synchronization methods and ensure the MTBF calculated by CAD tools are appropriate for the application." —— Source: [B3] UBC ELEX 7660 Lec 11

10.2 使用标准模式

原则：2-FF / Gray code / Handshake / Async FIFO 选一个。

"Use only commonly-accepted synchronization methods." —— Source: [B3] UBC ELEX 7660 Lec 11

详见 FPGA-CDC模式.md §9 模式选型表。

10.3 async_reg 必须

原则：所有 synchronizer FF 必须标 async_reg = "true"。

"When async_reg is true, synthesis does not perform optimization to reduce, merge, or duplicate these registers." —— Source: C:\Efinity\2026.1\doc\topics\tim-clk-relationships.html ([A3.3])

反例（综合器可能错误优化）：

// 错：2 个 synchronizer FF 没有 async_reg
reg sync_ff1, sync_ff2;
always @(posedge dst_clk) sync_ff1 <= async_in;
always @(posedge dst_clk) sync_ff2 <= sync_ff1;
// 综合器可能：合并 → 仅 1 个 FF；或优化掉第二个 → MTBF 失效

10.4 同步器间无组合逻辑

原则：synchronizer 级之间不能有组合逻辑——否则 settling time T_s 不足。

// 错：中间有组合逻辑
always @(posedge dst_clk) sync_ff1 <= async_in;
always @(posedge dst_clk) sync_ff2 <= sync_ff1 & other_signal;  // 错！
// 正确：
always @(posedge dst_clk) sync_ff2 <= sync_ff1;

10.5 复位同步器必须

原则：异步复位撤消前必须经过 2-FF synchronizer。

详见 FPGA-CDC模式.md §8.2 复位同步器模板。

10.6 过短脉冲注意

原则：跨域脉冲宽度必须 ≥ 1 个目的周期（详见 FPGA-CDC模式.md §7 DAC 案例）。
