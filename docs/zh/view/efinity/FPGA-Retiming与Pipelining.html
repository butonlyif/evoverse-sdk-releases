1. 为什么需要 Retiming

FPGA 频率劣势：

"Low clock frequencies are one of the drawbacks of the FPGA technology. According to [1], the clock frequency of FPGA designs increased only by 3.8× between 1999 and 2009. In the same time period, the CPU frequencies increased more than 9× from around 400 MHz to 3.6 GHz. For the 90 nm technology, compared to an ASIC, FPGA designs operate at 3 to 4× lower clock frequency." —— Source: [B6] University of Twente FPGA Pipelining Paper (Asghar et al.)

"Since the invention of the FPGA, the logic density has grown by a factor 10,000, whereas the maximum clock frequency has only increased by 100x." —— Source: [B6] Twente

FPGA vs ASIC 量化对比：

"FPGAs incur 3–4× longer delays, 5–15× greater area usage, and 5–14× higher power consumption than ASICs." —— Source: Kuon & Rose 2007 (转引自 [B5] arXiv 2510.26985)

结论：FPGA 上必须主动做 retiming / pipelining 来逼近 ASIC 性能。

2. Retiming 理论基础（Leiserson）

2.1 经典定义（Leiserson 1983）

"The idea of automatic pipelining was first introduced by Leiserson et al. [8] with an approach called retiming. The retiming is an optimization technique, which attempts to replace the existing registers in a design to achieve certain optimization goals (e.g., reducing the delay of the critical path). This optimization can thus improve the throughput of a system while keeping the initial latency unchanged." —— Source: [B6] Twente (引用 Leiserson 1983)

核心性质： - 不动组合结构——只移动寄存器位置 - 保持 observable behavior——电路功能等价 - 保持 latency 不变（与 pipelining 的关键区别）

2.2 数学描述

retiming label r(v)：每个节点 v 的 retiming 标签 = 移到 v 输入边的寄存器数。

合法 retiming：

r(v) ≥ 0                              （无负延迟）
r(v) − r(u) ≤ w(e) for each edge e    （每条边的 retiming 不超过原始寄存器数）

关键性质（Leiserson）：retiming 后最小周期 Φ* = max over cycles C { (W(C) - w(C)) / |C| } + 1，其中 W(C) = cycle 上最大延迟。

工程含义：retiming 通过平衡各 cycle 的延迟来缩短关键路径。

2.3 简单示例（CSDN [B7]/[C1]）

// 原始设计：3 个加法器串联，所有寄存器在末尾
always @(posedge clk) begin
    temp1 <= a + b;
    temp2 <= temp1 + c;
    result <= temp2 + d;
end
// 关键路径延迟 = (a+b) + (temp1+c) + (temp2+d) → 太长

// Retiming 后：寄存器在每级之间（balance stages）
always @(posedge clk) begin
    temp1 <= a + b;
    temp2 <= temp1 + c;
    result <= temp2 + d;
end
// 综合工具自动重新分布寄存器到组合逻辑间

Source: [C1] CSDN FPGA 优化指南 §"Retiming example"

3. C-Slow Retiming

3.1 概念（Weaver et al., UC Berkeley）

"C-slow retiming is a process of automatically increasing the throughput of a design by enabling fine grained pipelining of problems with feedback loops... each design register is first replaced with c registers before retiming... The effect of c-slow retiming is to enable pipelining of the critical path, even in the presence of feedback loops." —— Source: [B6] Twente (引用 Weaver et al., Iowa State)

3.2 步骤

  1. 每个原始 FF 替换为 c 个 FF（c-slow 化）
  2. 对 c-slow 设计跑 Leiserson retiming
  3. 关键路径可被 c-slow 化打断（即使存在 feedback loop）

3.3 工程含义

  • 吞吐率提升 c 倍（latency 不变）
  • 面积增加 c 倍（FF 数量）
  • 适合场景：流式处理 / DSP / 视频 pipeline

3.4 Efinity 支持

Efinity efx_map --seq_opt 1 + --retiming 2（advanced）隐含 c-slow 类似优化（综合自动决策），但没有显式 c-slow CLI 参数。

详见 Efinity优化设计.md §"重定时"。

4. 集成 Retiming + Placement

4.1 Singh & Brown FPGA 2002（U Toronto）

"Retiming is a synchronous circuit transformation that can optimize the delay of a synchronous circuit by moving registers across combinational circuit elements. The combinational structure remains unchanged and the observable behavior of the circuit is identical to the original." "Our experiments show that the integration of retiming with placement results in 19% better clock periods in comparison to the application of retiming before the place and route steps." —— Source: [B6] Twente (引用 Singh & Brown, FPGA 2002)

关键发现：retiming 与 placement 联合优化比"retiming → placement"串行优化好 19% 的时钟周期。

4.2 Efinity 实现

Efinity 在 efx_pnr（P&R 阶段）集成 retiming，配合综合 --retiming 2（advanced），实现 retiming + placement 联合优化。

详见 Efinity优化设计.md §"P&R 优化"。

5. Pipelining：Latency vs Throughput

5.1 核心权衡

操作 Latency Throughput
未 pipeline L 1/L (Hz)
Pipeline N 级 L (latency 增加 ~N 周期) 1/Tcycle (Hz) — 大幅提升

5.2 流水线示例（8-tap FIR）

// 未 pipeline：组合延迟 = 8 × (mul + add) → 关键路径长
module fir_8tap_comb (
    input  wire clk,
    input  wire [15:0] x_in,
    output reg  [31:0] y_out
);
    reg [15:0] x [7:0];
    wire [31:0] coef [7:0] = '{...};
    always @(posedge clk) x[0] <= x_in;
    always @(posedge clk) x[1] <= x[0];
    // ... 7 delay stages
    always @(posedge clk) y_out <=
        x[0]*coef[0] + x[1]*coef[1] + ... + x[7]*coef[7];
endmodule
// fMAX 受限于 8× mul-add → 几十 MHz

// Pipelined：每级寄存器断开 → fMAX 接近单级 mul-add
module fir_8tap_pipe (
    input  wire clk,
    input  wire [15:0] x_in,
    output reg  [31:0] y_out
);
    reg [15:0] x [7:0];
    reg [31:0] acc [7:0];
    wire [31:0] coef [7:0] = '{...};
    integer i;
    always @(posedge clk) begin
        x[0] <= x_in;
        for (i = 1; i < 8; i = i + 1) x[i] <= x[i-1];
        acc[0] <= x[0] * coef[0];
        for (i = 1; i < 8; i = i + 1) acc[i] <= acc[i-1] + x[i] * coef[i];
        y_out <= acc[7];
    end
endmodule
// fMAX 接近单级 mul-add → 几百 MHz，吞吐率 ×N

5.3 Latency vs Throughput 选择

应用 选择
控制逻辑 / 状态机 不 pipeline（latency 优先）
FIR / FFT / 信号处理 深 pipeline（throughput 优先）
视频处理 中等 pipeline（latency ≤ 1 frame）
处理器流水线 5-20 级 pipeline（如 RISC-V 5 级）

6. Efinity --retiming 参数

6.1 三种模式

值 行为 适用场景
0 禁用 已知 RTL 已手动 pipeline
1 启用 — 在组合逻辑前后移动寄存器，平衡路径延迟 默认值前
2（默认） 高级模式 — 比模式 1 更激进，对 Titanium 推荐 复杂设计、需要最大化 fMAX

Source: C:\Efinity\2026.1\doc\topics\syn-retiming.html ([A3])

6.2 官方说明（verbatim）

"The Efinity software includes an option for retiming. You enable it by setting the --retiming option to 1 in Project Editor > Synthesis tab. When this option is turned on, the software moves registers forward or backward to improve the design's performance." —— Source: C:\Efinity\2026.1\doc\pdf\efinity-synthesis.pdf §4 "Retiming" ([A2])

6.3 限制

只能在已有寄存器间重分布，不能创造新寄存器。适用于流水线不够深的组合逻辑路径。 —— Source: Efinity优化设计.md §1.2（基于 --help 输出）

6.4 CLI / GUI 调用

# CLI: efx_map
efx_map --retiming 2 --seq_opt 1 ...

# GUI: Project Editor → Synthesis tab → Retiming = 2

详见 Efinity工具链参考.md §"efx_map"。

7. Efinity --infer-clk-enable

作用：将门控时钟（gated clock）转换为时钟使能（clock enable）——避免门控时钟带来的 skew/hold 问题。

"Infer Clock Enable Option ... Converts gated clock patterns to clock-enable logic, removing clock tree distortion." —— Source: C:\Efinity\2026.1\doc\topics\syn-options-infer-ce.html ([A3])

好处： - 不生成门控时钟网络（避免 skew） - 保持时序干净的全局时钟 - 自动插入 (* syn_preserve *) 保留寄存器

7.1 示例

// 门控时钟（综合时自动转为 CE）
always @(posedge gated_clk)
    if (enable) reg_data <= reg_data_next;

// 综合后等价于
always @(posedge sys_clk)
    if (enable) reg_data <= reg_data_next;

7.2 CLI 参数

efx_map --infer-clk-enable ...

详见 Efinity工具链参考.md。

8. Efinity --seq_opt

作用：顺序逻辑（sequential logic）综合优化——优化 state machine、寄存器间路径。

值 效果
0 禁用
1（默认） 启用 — 优化时序逻辑综合结果
--seq-opt-sync-only 仅优化同步 set/reset 逻辑

Source: Efinity优化设计.md §1.3

典型效果： - 自动 retiming 同步 set/reset 链路 - 优化状态机编码（one-hot → binary 等） - 平衡 FSM 寄存器到逻辑路径

9. Retiming vs Pipelining：何时用哪个

场景 推荐 理由
已有 RTL 接近 fMAX --retiming 2 自动平衡关键路径
深组合逻辑（≥8 LUT） RTL 加 pipeline stage + --retiming 2 综合 + RTL 双管齐下
Feedback loop 严重 RTL c-slow 改写 + --retiming 2 c-slow 显式断开 loop
Latency 严格不变 仅用 retiming retiming 保持 latency，pipelining 会增加
Latency 可放宽 Pipeline 性能上限更高
DSP-heavy 设计 RTL pipeline + --retiming 2 + --dsp-input-regs-packing 多级优化
状态机 FSM --seq_opt 1 专为 FSM 优化

9.1 决策流程

START
│
├── 现有 RTL 关键路径有几级 LUT？
│   ├── ≤ 3 LUT → 默认即可，无需优化
│   ├── 4-6 LUT → --retiming 2（自动 retime）
│   └── > 6 LUT → RTL 加 pipeline stage + --retiming 2
│
├── 设计有 feedback loop？
│   ├── 否 → retiming 自动有效
│   └── 是 → RTL c-slow 改写（每个 FF 替换为 c 个 FF）
│
├── Latency 受限？
│   ├── 严格 → 仅 retiming（不动 latency）
│   └── 可放宽 → retiming + pipeline
│
└── DSP block 利用率？
    ├── 高 → --dsp-input-regs-packing + RTL pipeline 输入寄存器
    └── 低 → 默认即可

10. 实际 RTL 示例

10.1 加法器链 retiming（CSDN [C1]）

// ===== 原始 =====
module add_chain_orig (
    input  wire        clk,
    input  wire [15:0] a, b, c, d,
    output reg  [15:0] result
);
    reg [15:0] temp1, temp2;
    always @(posedge clk) begin
        temp1  <= a + b;
        temp2  <= temp1 + c;
        result <= temp2 + d;
    end
endmodule
// 关键路径 = (a+b) + (temp1+c) + (temp2+d) = 3 个 adder 串联

// ===== Retiming 后（综合自动）=====
// 综合器在每个加法器间插入 FF：
//   stage1: temp1 <= a + b
//   stage2: temp2 <= temp1 + c
//   stage3: result <= temp2 + d
// 等价结构 + latency 增加 2 周期 + fMAX 接近单加法器

10.2 FIR 滤波器 c-slow 化（Twente [B6]）

// 原始 4-tap FIR（feedback）
module fir_4tap_orig (
    input  wire        clk,
    input  wire [15:0] x,
    output reg  [31:0] y
);
    reg [15:0] d1, d2, d3;
    wire [31:0] coef [3:0] = '{16'h0001, 16'h0002, 16'h0003, 16'h0004};
    always @(posedge clk) begin
        d1 <= x;
        d2 <= d1;
        d3 <= d2;
        y  <= (d3 * coef[3]) + (d2 * coef[2]) + (d1 * coef[1]) + (x * coef[0]);
    end
endmodule

// ===== C-Slow 化（c=2，每 FF → 2 FF）=====
// 吞吐率 ×2（每 2 周期可接收 1 个新样本）
module fir_4tap_cslow2 (
    input  wire        clk,
    input  wire [15:0] x,
    output reg  [31:0] y0, y1
);
    reg [15:0] d1_0, d1_1, d2_0, d2_1, d3_0, d3_1;
    wire [31:0] coef [3:0] = '{16'h0001, 16'h0002, 16'h0003, 16'h0004};
    always @(posedge clk) begin
        // 交错输入：x 隔周期有效
        d1_0 <= x;
        d1_1 <= d1_0;
        d2_0 <= d1_1;
        d2_1 <= d2_0;
        d3_0 <= d2_1;
        d3_1 <= d3_0;

        // 两路并行计算
        y0 <= (d3_0 * coef[3]) + (d2_0 * coef[2]) + (d1_1 * coef[1]) + (d1_0 * coef[0]);
        y1 <= (d3_1 * coef[3]) + (d2_1 * coef[2]) + (d3_0 * coef[1]) + (d2_0 * coef[0]);
    end
endmodule

Source: 基于 [B6] Twente c-slow retiming 模式

附录 A — 关键术语

术语 含义
Retiming 移动寄存器位置，缩短关键路径，保持 latency
Pipelining 在组合逻辑间插入寄存器，提高吞吐率，增加 latency
C-Slow 每 FF 替换为 c 个 FF，使 retiming 能打断 feedback loop
fMAX 最大工作时钟频率
Critical Path 关键路径（slack 最差的路径）
Latency 输入到输出的延迟（周期数）
Throughput 单位时间处理数据量（samples/second）
