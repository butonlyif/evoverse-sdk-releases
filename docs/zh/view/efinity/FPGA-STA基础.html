1. 为什么需要静态时序分析（STA）

STA（Static Timing Analysis）：无需激励向量，遍历设计中所有时序路径并计算最坏情况延迟，是 ASIC 与 FPGA 时序验证的标准做法。

vs DTA（Dynamic Timing Analysis）：

"Dynamic Timing Analysis: Back-annotates the placement-and-routing delays into the gate-level netlist for simulation. Disadvantage: Cannot produce exhaustive test vectors, so some paths may have hidden timing issues. Static Timing Analysis: Uses exhaustive enumeration of all timing paths, computes propagation delays, checks setup and hold. No input vectors needed, exhausts all paths, fast runtime, low memory." —— Source: [B8] CSDN STA Deep Dive

"Two problems with either approach (Dynamic Timing): 1) Analysis was only as good as simulations – a problem was only found if exercised by the sim. 2) Logic simulations were 5-10 times slower." "Static Timing is more comprehensive. Calculate the delay for every possible logical path in the design. The worst case path determines the max freq." —— Source: [B2] UTEP EE5375 (MacDonald)

STA 工具厂商列表（vendor-neutral）： - Xilinx Vivado Timing Engine - Intel Quartus Prime TimeQuest - Synopsys PrimeTime / DC - Efinity 集成 STA（基于 PrimeTime，efx_run.bat --flow compile 自动调用）

Source: [B8] CSDN STA Deep Dive（工具列表部分）

"The introduction of Static Timing Analysis (STA) in the 1980s revolutionized digital design by enabling simulation-free timing verification." —— Source: [B5] arXiv 2510.26985 (Darvishi, 2020)

2. 四条标准时序路径

# 路径类型 中文名 起点 终点 Efinity SDC 约束
1 Reg-Reg 时钟→时钟 寄存器 CLK 寄存器 D create_clock + (multi-cycle/false path 例外)
2 In-Reg 输入→寄存器 Input Port 寄存器 D set_input_delay
3 Reg-Out 寄存器→输出 寄存器 CLK Output Port set_output_delay
4 In-Out 输入→输出（纯组合） Input Port Output Port set_input_delay + set_output_delay (+ set_max_delay)

Source: [B8] CSDN STA Deep Dive（"Four standard timing paths"）；[B2] UTEP EE5375（等价分类："Clock-to-Setup / Clock-to-Pad / Pad-to-Setup / Pad-to-Pad"）

Efinity 工程意义： - 路径 1 + 路径 2 + 路径 3 必须有完整 SDC 才能正确做 STA - 路径 4 经常被遗忘——若不约束，set_max_delay 缺失会导致 P&R 工具采用最宽松默认（与功能频率不匹配）

Source: [B7] CSDN 时序分析（"If you don't add constraints, the tool uses a very permissive default that only guarantees basic connectivity"）

3. 建立时间 Setup Time (Tsu)

定义：在时钟有效边沿（capture edge）到达之前，数据（D 端）必须保持稳定的最小时间。

"The Setup time (t_su) is the time required for the input to be stable before a clock edge." —— Source: [B4] MPI Lesson 11 (Dr. Davide Cieri, Sep 2024)

最小时钟周期方程：

t_clk(min) = t_su + t_h + t_p

其中 t_p = 数据路径延迟（Tco + Tlogic + Tnet）。

Source: [B4] MPI Lesson 11（"Minimum clock period equation"）

Setup 时序方程（数据到达必须早于要求）：

T_dataArrival + T_setupRequirement ≤ T_clockArrival

"Setup time (Tsetup) is the minimum duration that data must be stable before the clock's active edge to ensure correct capture by a flip-flop." —— Source: [B5] arXiv 2510.26985

Setup 违例 = 数据太慢（下一个 capture edge 还没准备好捕获）。

Tsu 量级（FPGA vs ASIC）：

工艺 / 器件 Tsu (ps) Th (ps)
7nm ASIC 45 35
现代 FPGA（Kintex UltraScale+ 等） 180 120

"Experimental results show ASICs achieve superior timing—45ps setup and 35ps hold—while modern FPGAs remain competitive with 180ps setup and 120ps hold times." —— Source: [B5] arXiv 2510.26985

4. 保持时间 Hold Time (Th)

定义：在时钟有效边沿到达之后，数据（D 端）必须保持稳定的最小时间。

"The Hold time (t_h) is the minimum amount of time required for the input to be stable after the clock edge." —— Source: [B4] MPI Lesson 11

Hold 时序要求：数据到达时间必须晚于 Hold 要求时间。

"Hold requirement is the time after the edge that data should remain valid. ... Worst case is a shift register with no logic between flip-flops." —— Source: [B2] UTEP EE5375

Hold 违例 = 数据太快（覆盖了当前 clock edge 正在采样的上一个数据）。

关键工程性质： - Hold 违例与时钟频率无关——慢速时钟不能修复 hold 违例 - Hold 检查必须在最快 PVT corner（fast process / low voltage / high temperature）下进行 - Hold 违例不能通过降频修复——必须加 buffer delay

"Hold times violations are only possible due to the positive clock skew. Sinister problem. Fabricated chip cannot be fixed by slowing down the clock." —— Source: [B2] UTEP EE5375

5. 时钟到输出 Tco

定义：时钟边沿（捕获到数据）到 Q 端稳定输出的时间，主要为 master latch 数据传递到 slave latch 输出的时间。

"Tco refers to the time from clock edge capturing data to stable output Q, mainly the time for data to transfer from master latch to slave latch output." —— Source: [B8] CSDN STA Deep Dive

Tco 计入 Data Arrival Time：

Data Arrival Time = T_clk_launch + Tcko + T_logic + T_net

Efinity 时序报告中 Tco 显示为 model name = ff 的 cell delay，例如：

Data Path
pin name             model name    delay (ns)
============================================
 src_reg|clk-to-q    ff            0.350
 ...

Source: C:\Efinity\2026.1\doc\topics\tim-synth-hi-fanout.html (timing report excerpt)

6. Setup Slack 公式

Slack = Data Required Time − Data Arrival Time
       = (Capture Clock Period − T_setup − T_uncertainty) − (Launch Edge + T_co + T_logic + T_net)

"Calculate the required arrival time (RAT) and the actual arrival time. The actual should be before the required. How much before is your slack." —— Source: [B2] UTEP EE5375

判定： - Slack > 0：满足（正余量） - Slack = 0：临界（任何 PVT 变化都会违例） - Slack < 0：违例（数据到得太晚）

通用 Setup 修复方向（vendor-neutral 5 类）：

  1. 逻辑重构 — 减少逻辑层级 / 平衡层级 / 共享子表达式
  2. Cell Upsizing — 关键路径用更高驱动力 cell
  3. Buffer / Inverter 插入 — 切断长 net，降低 RC 延迟
  4. Retiming / Pipelining — 跨逻辑移动寄存器（详见 FPGA-Retiming与Pipelining.md）
  5. Multi-Cycle Path (MCP) — 仅当数据率实际较慢时（详见 FPGA-时序例外Cookbook.md）

Source: 跨厂商综合 — EcrioniX STA Tutorial + UTEP EE5375 + Intel AN 584 v21.3 §6

7. Hold Slack 公式

Slack = Data Arrival Time − Data Required Time
       = (Launch Edge + T_co_min + T_logic_min + T_net_min) − (Capture Clock + T_hold)

"Calculate the required arrival time (RAT) and the actual arrival time. The actual should be after the required. How much after is your positive slack." —— Source: [B2] UTEP EE5375

判定： - Slack > 0：满足 - Slack < 0：违例（数据太快）

通用 Hold 修复方向：

  1. Buffer / Delay Cell 插入 — 在短路径上加 delay，绝不能使路径更快
  2. 避免直接 FF-to-FF 连接 — 在 FF 之间加组合逻辑提供固有延迟

Source: 跨厂商综合 — UTEP EE5375 + Intel AN 584 v21.3

"Fix Hold violation by inserting delay elements. NEVER speed up the path." —— Source: UTEP EE5375 ([B2]) + Intel AN 584 ([B1])

8. 时钟偏斜 Clock Skew

定义：同一时钟到达不同寄存器的延迟差。

"Skew is the difference in clock arrival time between any two flip-flops." —— Source: [B2] UTEP EE5375

正负偏斜对 Setup/Hold 的影响

偏斜符号 对 Setup 影响 对 Hold 影响
正偏斜（capture 晚于 launch） 有利（延长捕获窗口） 不利（hold 违例风险 ↑）
负偏斜（capture 早于 launch） 不利（压缩捕获窗口） 有利（缓解 hold 风险）

数学示例（UTEP EE5375 [B2]）

正偏斜 — 对 Setup 有利：

Launch = 1ns, Logic = 9ns, Setup = 1ns, Skew = -2ns, Period = 10ns
Setup Slack = +1 ns

正偏斜 — 对 Hold 不利：

Launch = 1ns, Setup = 1ns, Skew = -3ns → Hold Slack = -1 ns (违例)

关键设计含义： - 平衡的时钟树（低 skew）是 setup 和 hold 共同受益的工程目标 - Efinity 通过 beneficial skew（slack borrowing）主动调整时钟相位，把快路径的 slack 借给慢路径

"Beneficial skew (sometimes called 'slack borrowing') is a process in which the software adjusts clocks to better close timing." "This option is only available for Titanium and Topaz FPGAs." —— Source: C:\Efinity\2026.1\doc\topics\tim-beneficial-skew.html ([A3.12])

9. 时钟抖动与不确定度 Jitter / Uncertainty

Jitter = 时钟边沿相对理想位置的时间偏差（短期噪声） Uncertainty = 设计者主观加入的额外时间裕量（覆盖 jitter + margin + OCV）

Efinity SDC 写法

set_clock_uncertainty -to clk -setup 0.06

"How to Set Clock Uncertainty ... set_clock_uncertainty -to clk -setup 0.06" —— Source: C:\Efinity\2026.1\doc\pdf\efinity-timing-closure.pdf §5 "How to Set Clock Uncertainty" ([A1])

set_clock_uncertainty 同时影响 setup 和 hold 检查——典型值： - Setup：周期 100 MHz → 60–100 ps - Hold：5–20 ps（仅为覆盖 on-chip variation）

"The clock insertion delay is the time it takes for a clock signal to travel from the pad of a GPIO configured as a global clock (GCLK) through the global clock network to the destination register. This document calls it the 'base' clock insertion delay." —— Source: AN 042 v1.0 §A4.3 ([A4.3])

详见 FPGA-时钟约束Cookbook.md §6。

10. 逻辑延迟 vs 布线延迟

逻辑延迟 (Tlogic)：组合逻辑（LUT / MUX / 加法器 / DSP）cell delay 总和 布线延迟 (Tnet)：net 上信号传播延迟（RC）

"Propagation delay is the time needed for a signal to travel from a source to a destination component. Sources of Propagation Delay: - Logic Delay: The delay introduced by the combinational logic (e.g., LUTs, multiplexers). - Routing Delay: The delay caused by the interconnects or wiring between logic elements." —— Source: [B4] MPI Lesson 11

"Every time a signal passes through a LUT, flip-flop, or routing switch, there is a small delay called logic delay. The signal traveling on the metal wire connecting these logic elements also produces delay, called routing delay or path delay. These two delays together constitute the total delay from point A to point B." —— Source: [B7] CSDN 时序分析

FPGA 架构含义： - LUT4 架构（Efinity Trion）每个 LUT 仅 4 输入，深组合链（≥3 LUT 无寄存器打断）易触发 setup 违例 - LUT5/6（Xilinx 7-series 6-LUT）面积更大但单级逻辑更强 - 全局时钟网络 Efinity skew 通常 <0.1 ns（详细见 时序分析指南.md §1.3）

Source: 综合 — [B6] Twente FPGA Pipelining Paper + 时序分析指南.md §1.3

11. 恢复 / 去除 Recovery / Removal

Recovery：异步复位撤销（de-assertion）必须在时钟边沿之前若干时间发生，否则不能保证寄存器退出 reset 状态 Removal：异步复位撤销必须在时钟边沿之后若干时间发生

"The rst_n reset assertion moment must be before recovery time; otherwise the register may not be in reset state. The de-assertion of rst_n must be after the removal time (for active-low reset)." —— Source: [B8] CSDN STA Deep Dive

工程含义： - 异步复位必须经过 复位同步器（2-FF）进入时钟域 - 否则跨时钟域 + 异步 reset 路径可能违例 recovery/removal - Efinity 默认对异步复位路径做 STA 检查；建议显式 reset synchronizer + async_reg

详见 Efinity设计规范.md §"复位设计" 与 FPGA-CDC模式.md §"复位信号 CDC"。
