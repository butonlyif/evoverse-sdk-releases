1. set_false_path — 剪断路径

作用：告诉 STA 工具不检查这些路径（无论 setup 还是 hold），通常用于： - 异步时钟域（已用 CDC synchronizer，但 synchronizer 路径仍会被工具检查为 setup 违例——false path 跳过） - 静态配置寄存器（与时钟频率无关） - 调试 / JTAG / 测试路径 - 复位信号（异步复位不参与时序）

1.1 Efinity 完整语法

# 单向：剪断 clk1 → clk2
set_false_path -from clk1 -to clk2

# 双向
set_false_path -from clk1 -to clk2
set_false_path -from clk2 -to clk1

# 剪断到端口
set_false_path -from clk1 -to [get_ports testout]

# 基于 pin 级
set_false_path -from [get_pins {u_fft/clk}] -to [get_pins {u_cpu/data_in[*]}]

Source: C:\Efinity\2026.1\doc\topics\tim-set-false-path.html ([A3.9])

"Provides examples of unidirectional/bidirectional false path constraints." —— Source: C:\Efinity\2026.1\doc\topics\tim-set-false-path.html ([A3.9])

1.2 异步复位完整示例

# 异步复位路径全部 false path
set_false_path -from [get_ports arst_n]

1.3 -through 选项（路径经过特定 pin）

# 剪断经过特定 pin 的所有路径
set_false_path -through [get_pins {u_xbar/sel}]

详见 FPGA-时钟约束Cookbook.md §7。

2. set_clock_groups -exclusive — 互斥时钟

作用：标记一组时钟互斥（同一时刻仅一个 active）。STA 工具完全跳过这些时钟域之间的检查。

Source: C:\Efinity\2026.1\doc\topics\tim-add-clock-set-clock-groups.html ([A3.8])

2.1 多路选择时钟 mux 场景

# 同一时刻仅 clk_a 或 clk_b active（由 sel 寄存器选择）
set_clock_groups -exclusive -group {clk_a clk_b}

# 三选一
set_clock_groups -exclusive -group {clk1 clk2} -group {clk3} -group {clk4}

2.2 决策依据

使用 -exclusive 的前提： - 多路时钟在硬件上互斥（通过 mux 或 clock gate） - 不存在实际同时工作的边界条件 - 若不确定，应使用 -asynchronous（更保守）

详见 FPGA-CDC模式.md §6.1。

3. set_clock_groups -asynchronous — 异步时钟

作用：标记时钟组完全独立（异步时钟域）。STA 工具完全跳过检查——这是 CDC 处理的标准做法。

Source: C:\Efinity\2026.1\doc\topics\tim-unrelated-clk.html ([A3.7])

3.1 典型异步场景

# sys_clk (100 MHz 主系统) vs ddr_ck (400 MHz DDR PHY)
set_clock_groups -asynchronous -group {sys_clk} -group {ddr_ck}

# 多组异步
set_clock_groups -asynchronous \
    -group {sys_clk vid_clk ddr_ck} \
    -group {adc_clk usb_clk}

3.2 注意事项

  • 必须配合 CDC synchronizer（2-FF + async_reg）使用——set_clock_groups 仅告诉工具跳过检查，不消除亚稳态
  • 单 bit 信号用 2-FF，多 bit 数据用 handshake 或 FIFO

详见 FPGA-CDC模式.md §3 完整模板。

4. set_multicycle_path — 多周期路径

作用：告诉 STA 工具某条路径不需要单周期完成，可跨多个时钟周期。

"In a default single-cycle clock relationship, the two clocks are in phase and toggle together. The default setup and hold represent a one clock cycle capture window and is the same as setting a constraint of setup = 1 and hold = 0. The hold is checking one clock cycle before the capture clock edge. When you use the set_multicycle_path constraint, you are adjusting the capture window by shifting it, widening it, or both." —— Source: C:\Efinity\2026.1\doc\topics\tim-multicycle.html ([A3.1])

4.1 默认等价

# 默认 setup = 1, hold = 0 等价于
set_multicycle_path -setup -from a -to b 1
set_multicycle_path -hold  -from a -to b 0

4.2 典型 multicycle 2 场景

# CPU 总线读写：寄存器在 CPU 时钟域，跨 2 周期到外设时钟域
set_multicycle_path -setup -from [get_clocks cpu_clk] -to [get_clocks peri_clk] 2
set_multicycle_path -hold  -from [get_clocks cpu_clk] -to [get_clocks peri_clk] 1

经验规则：setup N → hold N-1（详见 §10.1）。

Source: C:\Efinity\2026.1\doc\pdf\efinity-timing-closure.pdf §5 "set_multicycle_path" ([A1])

4.3 慢时钟域到快时钟域

# 源 50 MHz, 目的 200 MHz → 数据 4 个目的周期才有效
set_multicycle_path -setup -from [get_clocks slow_clk] -to [get_clocks fast_clk] 4
set_multicycle_path -hold  -from [get_clocks slow_clk] -to [get_clocks fast_clk] 3

详见 §10。

5. set_max_delay / set_min_delay — 自定义路径约束

作用：对特定路径（无需识别时钟）施加自定义 max/min 延迟约束。

5.1 何时使用

  • 纯组合逻辑路径（无时钟寄存器）——必须用 set_max_delay 而非 create_clock
  • 跨多个时钟域的特定路径（比 false path 更精确）
  • 模块边界 IO 约束（不关心内部时钟关系）

5.2 完整示例

# 跨时钟域路径施加 10 ns 上限（比单周期约束更紧但仍可满足）
set_max_delay -from [get_pins {u_fft/clk}] -to [get_pins {u_cpu/D_reg[*]/D}] 10.0

# 纯组合路径
set_max_delay -from [get_ports data_in[*]] -to [get_ports data_out[*]] 8.0
set_min_delay -from [get_ports data_in[*]] -to [get_ports data_out[*]] 2.0

"set_max_delay / set_min_delay ... Used for combinational paths or specific inter-clock constraints." —— Source: C:\Efinity\2026.1\doc\topics\constraint_setmaxdelay-setmindelay.html ([A3])

6. 何时用哪个：决策树

START
│
├── 路径是否需要时序检查？
│   ├── 否 → set_false_path
│   └── 是 ↓
│
├── 是否有时钟？
│   ├── 否 → set_max_delay / set_min_delay（纯组合路径）
│   └── 是 ↓
│
├── 路径是否跨多个时钟周期？
│   ├── 是 → set_multicycle_path
│   └── 否 → 默认单周期约束（无需任何例外）
│
└── 多时钟域？
    ├── 互斥时钟 → set_clock_groups -exclusive
    ├── 异步时钟 → set_clock_groups -asynchronous（需 CDC synchronizer）
    └── 同源 / 相位已知 → 默认检查即可

8. 常见陷阱

8.1 过度 false path

陷阱：把所有跨域路径 false path，导致功能 bug。

"If you don't add constraints, the tool uses a very permissive default that only guarantees basic connectivity. The tool may route critical signals on slow channels, or use non-optimized placement, ultimately causing the design to fail to work." —— Source: [B7] CSDN 时序分析

正确做法： - 仅 false path 真正的 false path（异步复位 / 静态配置 / 测试） - 跨域数据路径用 set_clock_groups -asynchronous + CDC synchronizer - 跨域同步路径用 set_multicycle_path

8.2 Multicycle setup N 但 hold = 0（错）

陷阱：忘记同时设 hold，导致 hold 违例。

正确做法： - setup N → hold N-1（同步路径） - setup N → hold 0（shift-only）

详见 §10.1。

8.3 set_false_path 不区分 setup/hold

陷阱：false path 会同时跳过 setup 和 hold 检查——若仅需跳过 setup，需用 set_max_delay 显式约束 hold。

8.4 Clock group 配错

陷阱：用 -exclusive 但实际两时钟可能同时 active（glitch），导致 race condition。

判断： - 同一 PLL 输出不同频率 → 不要 -exclusive - 不同 PLL 输出 → -asynchronous - 多路 mux 选择 → -exclusive（前提是 mux 输出无 glitch）

8.5 Multicycle 路径用错时钟方向

陷阱：set_multicycle_path -from slow -to fast 4 但数据实际方向相反。

修复：用 report_timing -from X -to Y 验证路径方向。

9. Multicycle 移位捕获窗口

9.1 基本概念

Multicycle path 通过调整捕获窗口位置影响 timing 检查：

"When you use the set_multicycle_path constraint, you are adjusting the capture window by shifting it, widening it, or both." —— Source: C:\Efinity\2026.1\doc\topics\tim-multicycle.html ([A3.1])

两类调整： 1. Shifted Capture Window (tim-multicycle-shift.html) — 仅移动窗口位置 2. Shifted and Widened Window (tim-multicycle-shift-widen.html) — 同时移动并扩大窗口

9.2 Shift 公式

setup N → hold N - 1

含义：hold 检查总是从 setup 窗口前一周期开始。

Source: C:\Efinity\2026.1\doc\topics\tim-multicycle-shift.html ([A3])

10. 快慢时钟 multicycle

10.1 完整公式

"Constraints between Fast and Slow Clocks" —— Source: C:\Efinity\2026.1\doc\topics\tim-multicycle-fast-slow.html ([A3])

源时钟 目的时钟 setup N hold 公式 hold 值
慢 快 N (目的周期数) N - 1 N - 1
快 慢 N (源周期数) N - 1 N - 1
同频 同频 N N - 1 N - 1

10.2 典型示例：CPU → 外设

# CPU 200 MHz (5 ns period) → 外设 50 MHz (20 ns period)
# CPU 数据在外设域需 4 个 CPU 周期才能稳定
set_multicycle_path -setup -from [get_clocks cpu_clk] -to [get_clocks peri_clk] 4
set_multicycle_path -hold  -from [get_clocks cpu_clk] -to [get_clocks peri_clk] 3

解读： - Setup N=4：允许 4 个目的周期（peri_clk 4 × 20 ns = 80 ns） - Hold N-1=3：检查数据保持稳定至前 3 个目的周期（之前的数据不要覆盖新数据）

10.3 跨频比 1:2 的复杂场景

# src 100 MHz → dst 50 MHz（2:1 比例）
# 数据在 dst 域需 2 个周期稳定（→ setup N=2）
set_multicycle_path -setup -from [get_clocks src] -to [get_clocks dst] 2
set_multicycle_path -hold  -from [get_clocks src] -to [get_clocks dst] 1

Source: C:\Efinity\2026.1\doc\topics\tim-multicycle-fast-slow.html ([A3])

10.4 验证

report_timing -from [get_clocks cpu_clk] -to [get_clocks peri_clk] -path_type full -max_paths 5
# 确认 captured by 行为符合预期
