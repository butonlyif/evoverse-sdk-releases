图像仿真使用指南

evoverse.simIsp 用户使用手册

适用 SDK 版本: v1.0.0

1. 概述

evoverse.simIsp 是 EVOVERSE SDK 中专用于 ISP（图像信号处理）/ 图像处理 IP 仿真验证 的命令。它编译项目提供的 testbench、RTL 和可选 BFM，捕获 result.hex 后用 Python 后端进行图像质量分析，最终生成包含 PSNR、锐度、白平衡、直方图、Gamma 等指标的分析报告。

当前 v1.0.0 VSIX 提供 Video Sim 启动入口和配套分析能力，但尚未随包提供通用 AXI-Stream BFM。项目如需 BFM，请放入 sim/BFM/ 或 sim/common/。

与 evoverse.sim 的区别

特性 evoverse.sim evoverse.simIsp
适用场景 通用 FPGA 仿真 ISP / 图像处理 IP
配置方式 sim.yaml video_sim.yaml
输入数据 通用激励 图像 / 视频像素流（AXI-Stream）
输出产物 VCD 波形 result.png + JSON 分析报告
分析指标 无 PSNR、锐度、白平衡、直方图、Gamma

两条命令完全独立，零共享代码。

整体数据流

evoverse.simIsp
    ↓
解析 sim/video_sim.yaml
    ↓
scan: RTL (rtl/) + testbench (sim/tb_*.v) + BFM (axis_video_source/sink)
    ↓
iverilog -g2012 编译 → sim_isp.vvp
    ↓
vvp 运行仿真 → result.hex
    ↓
gen_output.py: result.hex → result.png
    ↓
analyze.py: golden.png vs result.png → JSON 报告
    ↓
Webview 展示报告

2. 目录结构

运行 evoverse.simIsp 时，命令会在项目根目录查找 sim/ 目录。完整的目录结构约定如下：

project/
├── rtl/                         # 用户 DUT（RTL 设计文件，自动扫描包含）
│   ├── isp_denoise.v
│   └── color_space.v
└── sim/
    ├── video_sim.yaml           # 【必需】ISP 仿真配置文件
    ├── BFM/                     # 项目自带 BFM（可选）
    │   └── axis_video_*.v
    ├── common/                  # 本地公共 BFM（可选）
    │   └── axis_video_*.v
    ├── tests/                   # testbench 测试用例
    │   └── tb_isp.v
    ├── tb_*.v / tb_*.sv         # testbench 也可直接放在 sim/ 根目录
    ├── testdata/                # 测试数据
    │   ├── stimulus.hex         # 输入激励（axis_video_source 读取）
    │   ├── golden.png           # 参考金标准图像
    │   └── result.hex           # 【仿真产出】axis_video_sink 写入
    └── output/                  # 【自动创建】分析输出
        ├── images/
        │   └── result.png       # 从 result.hex 还原的图像
        └── reports/
            └── sim_isp_<timestamp>.json  # 分析报告

各目录说明

目录 / 文件 必选 说明
sim/video_sim.yaml ✅ 是 配置文件，命令通过检测此文件激活
rtl/ 否 用户 DUT 的 Verilog/SystemVerilog 文件，自动递归扫描
sim/BFM/ 否 用户自定义 BFM；当前版本没有随包提供通用 BFM
sim/common/ 否 用户自定义公共 BFM
sim/tests/ 否 testbench 目录，递归扫描 tb_*.v / tb_*.sv
sim/tb_*.v ✅ 是 至少需要一个 testbench 文件
sim/testdata/ 建议 存放 golden.png、stimulus.hex 等测试数据
sim/output/ 自动 运行时自动创建，存放图像和报告

文件扫描规则

  • BFM 文件：扫描 sim/BFM/ 和 sim/common/。Runner 也保留扫描 bundled/video_sim/sim/common/ 的能力，但当前 v0.9.0 安装包中没有交付通用 BFM 文件。
  • testbench: 扫描 sim/ 根目录的 tb_*.v/tb_*.sv，以及 sim/tests/ 下递归扫描的 testbench 文件
  • RTL 文件: 递归扫描 rtl/ 目录下的所有 .v、.sv、.vh 文件

3. 配置文件 video_sim.yaml

配置文件必须放置在 sim/video_sim.yaml。

完整写法

adapter: video_sim

params:
  width: 1920
  height: 1080
  frames: 1
  pixel_format: RGB888

  golden: sim/testdata/golden.png
  result: sim/testdata/result.hex

metrics:
  - psnr
  - sharpness
  - white_balance
  - histogram
  - gamma

字段说明

顶层

字段 类型 必填 说明
adapter string ✅ 是 固定值 video_sim，用于区分 simIsp 和 sim 命令
params object ✅ 是 仿真参数
metrics string[] 否 要启用的分析指标，默认全部启用

params 参数

字段 类型 默认值 说明
width number 1920 图像宽度（像素）
height number 1080 图像高度（像素）
frames number 1 帧数（单帧图像设为 1）
pixel_format string RGB888 像素格式，见下表
golden string - 参考金标准图像路径（相对项目根目录或绝对路径）
result string - 仿真输出 result.hex 路径（相对项目根目录或绝对路径）

支持的像素格式

格式 位宽 tdata 宽度 通道 说明
RGB888 24 bit 3 字节 3 标准 RGB 8-8-8，当前教程验证格式
BGR888 24 bit 3 字节 3 BGR 字节顺序
RGBA8888 32 bit 4 字节 4 RGBA 字节顺序
BGRA8888 32 bit 4 字节 4 BGRA 字节顺序
RGB565 16 bit 2 字节 3 输入为两个小端字节，转换为 RGB888

result.hex 当前采用一行一个字节的格式。例如 RGB888 的一个红色像素依次写三行 ff、00、00。RAW/YUV 格式尚未完成端到端验证，不作为 v0.9.0 教程承诺。

4. 快速开始

前置条件

  • Python: 3.10+，需安装 Pillow 和 numpy
  • Icarus Verilog: iverilog + vvp，需在 VS Code 中配置 evoverse.iverilogPath
  • EVOVERSE SDK: 已安装扩展

步骤一：创建项目结构

在项目根目录下创建 sim/ 目录和 rtl/ 目录：

mkdir sim                    # PowerShell
mkdir sim\testdata
mkdir sim\tests
mkdir rtl

步骤二：编写 DUT（RTL）

在 rtl/ 目录下放置你的图像处理 IP 的 Verilog/SystemVerilog 代码。DUT 需要符合 AXI-Stream 视频接口规范——接收 axis_video_source 发出的像素流，处理后输出给 axis_video_sink。

步骤三：编写 testbench

在 sim/tests/（或 sim/ 根目录）创建 testbench 文件，命名必须以 tb_ 开头，如 tb_my_isp.v。

testbench 中需要实例化： - axis_video_source — 从 stimulus.hex 读入像素，通过 AXI-Stream 发出 - 你的 DUT - axis_video_sink — 接收 DUT 输出的像素流，写入 result.hex

步骤四：准备测试数据

  1. 按项目 BFM 的约定准备输入激励。SDK 的 result.hex 转换器使用一行一个字节；如果输入和输出共用格式，stimulus.hex 也建议采用同样约定。
  2. 将参考金标准图像 golden.png 放入 sim/testdata/

步骤五：创建配置文件

在 sim/ 目录创建 video_sim.yaml：

adapter: video_sim

params:
  width: 64
  height: 48
  frames: 1
  pixel_format: RGB888

  golden: sim/testdata/golden.png
  result: sim/testdata/result.hex

metrics:
  - psnr
  - sharpness
  - white_balance
  - histogram
  - gamma

步骤六：配置 iverilog 路径

在 VS Code 设置中配置 Icarus Verilog 的安装路径：

{
    "evoverse.iverilogPath": "C:/iverilog/bin"
}

步骤七：运行命令

在 VS Code 中按 Ctrl+Shift+P，输入 evoverse.simIsp 并执行。

命令会自动完成： 1. 解析 video_sim.yaml 2. 扫描并编译所有源文件 3. 运行仿真 4. 生成 result.png 5. 执行图像质量分析 6. 在 Webview 中展示分析报告

所有输出日志会显示在 VS Code 的「输出」面板（选择 "Sim ISP" 频道）。

5. BFM 说明

BFM（Bus Functional Model）是仿真中模拟总线行为的非综合模型。项目可以按以下接口职责提供自己的 BFM；表中的文件当前不是 v0.9.0 VSIX bundled 内容：

axis_video_source — 视频源

从 stimulus.hex 读取像素数据，通过 AXI-Stream 接口逐像素输出。

工作方式： 1. 仿真开始时通过 $readmemh 将 stimulus.hex 全部读入内部数组 2. 按 AXI-Stream ready/valid 握手协议逐像素发送 3. tuser 信号标记每帧首像素（SOF），tlast 信号标记每行末像素（EOL） 4. 支持多帧 replay 模式和冲刷机制（flush，用于有流水线延迟的 IP）

axis_video_sink — 视频接收器

接收 AXI-Stream 像素流并写入 result.hex。

工作方式： 1. 仿真开始时打开 result.hex 文件 2. 每当 tvalid & tready 同时有效，将 tdata 以 8 位十六进制格式写入文件 3. 对 tuser 和 tlast 进行协议合规检查，违规时报错 4. 收满 WIDTH × HEIGHT × FRAMES 个像素后，标记 frame_done 并刷新文件 5. 可配置反压模式（C_READY_MODE / C_READY_RATE），模拟下游吞吐限制

其他 BFM

BFM 功能
reg_config.v 寄存器配置模型，用于向 DUT 发送寄存器读写请求
ddr_model.v DDR 内存行为模型
axi_frame_buffer.v AXI Frame Buffer 模型，用于帧缓存读写

BFM 查找顺序

命令按以下优先级查找 BFM 文件（高到低）： 1. sim/BFM/ — 项目本地 BFM 2. sim/common/ — 项目本地公共 BFM 3. bundled/video_sim/sim/common/ — 预留的扩展 BFM 目录；当前 v0.9.0 包中为空

同名文件以优先级高的为准。

6. 分析指标

6.1 PSNR（峰值信噪比）

衡量输出图像与参考金标准的相似度。值越高，图像失真越小。

PSNR 值 等级 含义
> 40 dB 优秀 几乎无失真，肉眼无法分辨差异
> 30 dB 良好 轻微失真，通常可接受
> 20 dB 一般 明显失真，需要优化
≤ 20 dB 差 严重失真，DUT 可能存在 bug

分析结果包含：总体 PSNR（dB）、逐通道 PSNR（B/G/R）、MSE。

⚠ PSNR 需要提供 golden 参考图和 output 输出图。

6.2 锐度（Sharpness）

衡量图像的清晰度和边缘细节保留程度。通过 Laplacian 方差和 Tenengrad 两个指标综合评定。

Laplacian 方差 等级 含义
≥ 2000 极佳 锐度充足，边缘锐利
≥ 800 优秀 锐度良好，细节完整
≥ 200 良好 锐度中等，基本可接受
≥ 50 一般 偏软，细节有一定损失
< 50 模糊 严重模糊，DUT 可能过度降噪/滤波

分析结果包含：Laplacian 方差、Sobel 梯度均值、Tenengrad 值。

6.3 白平衡（White Balance）

基于灰度世界假说分析图像的色彩平衡。理想情况下 R、G、B 三通道均值应当相等。

分析结果包含： - r_gain / g_gain / b_gain — 各通道增益系数 - bias — 色温倾向： - 偏冷(蓝): R/B 比率 < 0.85，图像偏蓝 - 中性: R/B 比率在 0.85~1.15 之间，色彩平衡 - 偏暖(黄): R/B 比率 > 1.15，图像偏黄 - white_point — 最亮区域的白点 RGB 值

6.4 直方图（Histogram）

统计 RGB 三通道的亮度分布以及输出相对输入的亮度变化。

分析结果包含： - 各通道的均值、标准差、中位数、最小/最大值、P5/P95 百分位 - shift — 整体亮度偏移方向和幅度，例如 "亮度提升 12.3 (均值变化)"

6.5 Gamma

测量 DUT 的 Gamma 曲线与目标值（默认 2.2）的偏差。通过采样 17 级灰度阶梯进行拟合。

偏差 (Δ) 等级 含义
< 0.05 优秀 Gamma 曲线几乎完美匹配目标
< 0.1 良好 轻微偏差，实际使用中几乎不可感知
< 0.3 一般 可感知偏差，建议检查 Gamma 校正逻辑
≥ 0.3 偏差大 严重偏差，Gamma 校正模块可能有问题

分析结果包含：实测 Gamma 值、目标 Gamma 值、偏差、有效采样点数。

⚠ Gamma 分析需要提供 golden 参考图（含丰富灰度级）和 output 输出图。

7. 常见问题

Q: 提示 "iverilog not found"

原因: 未配置 Icarus Verilog 路径，或路径不正确。

解决: 1. 确认已安装 Icarus Verilog（下载地址：http://bleyer.org/icarus/） 2. 在 VS Code 设置中配置 evoverse.iverilogPath： - Windows 示例: C:/iverilog/bin - Linux 示例: /usr/bin 3. 确保路径下包含 iverilog.exe（或 iverilog）和 vvp.exe（或 vvp）

Q: 提示 "No testbench found"

原因: sim/ 目录下没有找到 testbench 文件。

解决: 确保 testbench 文件符合以下之一： - 放在 sim/ 根目录，文件名以 tb_ 开头，扩展名为 .v 或 .sv - 放在 sim/tests/ 目录下，文件名以 tb_ 开头

Q: 提示 "result.hex not found"

原因: 仿真完成后没有生成 result.hex。

可能的情况: 1. testbench 中没有实例化 axis_video_sink，或实例化了但未正确连接 2. DUT 没有正确输出像素流，导致 sink 未收到数据 3. 仿真在写入 result.hex 之前就异常退出了

排查: 检查仿真日志（VS Code 输出面板 → "Sim ISP"），确认是否有 ERROR 日志。检查 testbench 中 axis_video_sink 的例化是否正确。

Q: Python 脚本报错 "No module named 'PIL'" 或 "No module named 'numpy'"

原因: 缺少 Pillow 或 numpy 依赖。

解决:

pip install Pillow numpy

如果使用特定的 Python 环境，可以在 VS Code 设置中配置：

{
    "evoverse.pythonPath": "C:/path/to/python.exe"
}

未配置时，Windows 默认使用 py，Linux/macOS 默认使用 python3。

Q: 分析报告显示 "需要 --output 对比图"

原因: 部分分析项（PSNR、Gamma）需要 golden.png 和 result.png 都存在才能运行。如果仿真没有生成 result.hex 或 result.png，这些分析项会自动跳过。

解决: 确认仿真正常完成并生成了 result.hex，以及 gen_output.py 成功将其转换为 result.png。

Q: 图像尺寸不一致警告

原因: golden.png 和 result.png 的分辨率不匹配。

解决: analyze.py 会自动将 result.png 缩放到 golden.png 的尺寸。如需精确对比，确保 video_sim.yaml 中的 width/height 与 golden.png 一致。

Q: 如何生成 stimulus.hex

当前转换脚本约定一行一个 8 位十六进制字节。RGB888 每个像素连续输出 R、G、B 三行。可以使用 Python 脚本从图像生成：

from PIL import Image

img = Image.open("input.png").convert("RGB")
with open("stimulus.hex", "w") as f:
    for r, g, b in img.getdata():
        f.write(f"{r:02x}\n{g:02x}\n{b:02x}\n")

或者参考 SDK 内置的 products/video-sim/scripts/gen_output.py 中的 hex 解析逻辑。

Q: 可以一次分析多个 DUT 吗

每个项目只能有一个 sim/video_sim.yaml。如果需要测试多个 DUT，可以在 testbench 中实例化不同的 DUT 并通过寄存器配置选择，或者为每个 DUT 创建独立项目目录。

Q: 如何查看详细日志

在 VS Code 中打开「输出」面板（Ctrl+Shift+U），从下拉菜单中选择 "Sim ISP" 频道。所有编译、仿真、分析步骤的日志都会输出到这里。

高级参考用于按需查询；设计记录、发布流程、审计报告和未来规划不属于客户操作入口。
