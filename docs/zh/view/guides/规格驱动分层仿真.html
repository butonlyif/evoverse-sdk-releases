规格驱动的分层仿真与 Vibe Coding

规格驱动的分层仿真与 Vibe Coding

适用版本：EvoVerse SDK v1.0.0

这套流程把设计规格书作为唯一行为权威。即使功能很小，也先建立并冻结规格，再生成 RTL。仿真代码、Oracle、测试向量和模型不从待测 RTL 反推，避免“代码和测试一起错但仍显示通过”。

客户需要分阶段可靠流程时，以 @evoverse 开始规格或 RTL 设计需求，SDK Agent 会先确认工作方式：可靠设计流程或自由开发。普通 Agent 对话保持自由开发，不自动弹出选择。产品实际只有两种工作方式：选择可靠设计流程后必须逐阶段确认；选择自由开发则不进入本流程，直接编辑和 Build 不受影响。

RTL 设计规则验证不是 Coding Style Check。 它检查结构、时钟、复位、CDC、状态机、FIFO、数据完整性及协议契约；动态义务需要仿真证据，incomplete 不是 PASS。

1. 规格分层与合适颗粒

  • ModuleSpec：单个可独立理解和验证的功能单元。它可以包含多个 HDL 文件，不要求“一份 RTL 一个模块规格”。
  • SystemSpec：描述模块组合、子系统边界、系统行为、依赖关系和硬核契约。
  • 验证单元只按功能边界切分为 module、subsystem、system，不把简单 glue logic 机械拆成过小颗粒。

推荐目录：

design/
  modules/<unit>/rtl/              # 多文件 DUT
  modules/<unit>/sim/{tb,models,assertions,vectors}/
  subsystems/<unit>/rtl/
  subsystems/<unit>/sim/{tb,models,assertions,scenarios}/
  system/<unit>/rtl/
  system/<unit>/sim/{tb,models,assertions,scenarios}/
.evoverse/verification/             # 冻结规格、图、请求、证据和决策；不要手工改

2. 可靠设计流程的分阶段顺序

  1. 选择具体板卡/载板，发现相关 Demo、IP、约束和 Efinity 模型；复制到 run-local 隔离区并生成精确字节 baseline-manifest.json。未修改的旧 RTL 可带着已记录的规则债务复用，任何字节变化都会失去豁免；加密代码只作为接口和模型契约黑盒。
  2. 确认仿真等级（用户选择，等级先于规格）：可靠迭代建立后、spec.draft 起草规格之前，必须先确认仿真等级，否则控制面以 SIMULATION_PROFILE_REQUIRED 阻塞起草。AI 从用户需求、材料清单和项目拓扑提取结构化风险事实（单时钟、CDC、FIFO、背压、跨行/跨帧状态、安全相关等）提交 simulation.profile.select 的 riskFacts；控制面按固定风险规则计算推荐等级，AI 不得代填推荐字段。三档预置等级：
等级 适用 默认阻塞义务 默认延期到板测
FPGA_FUNCTIONAL 单时钟、边界清晰、输出易观察的简单功能（计数器、流水灯、秒表、GPIO） 编译展开、复位、1–3 个主路径场景、1 个关键边界、必要时的 1 个集成冒烟 完整回绕、覆盖率配额、长时间回归、按键手感、显示观感、参数微调
FPGA_INTEGRATION 协议、缓存、跨行/跨帧状态、共享资源（FIFO、AXI/流接口、窗口化 ISP、DMA） 功能级全部 + 握手/背压/帧边界、位宽/饱和/截断、FIFO 溢出保护、CDC、集成回归 全输入组合、主观画质穷举
HIGH_ASSURANCE 高速复杂协议、存储控制、不可逆控制、安全相关 冻结规格的全部义务（含恢复场景与覆盖闭合） 无自动延期；主观调优仍可显式延期

用户可以选择接受推荐、更高或更低等级，或用 CUSTOM 显式划分阻塞/延期义务；选择低于推荐最低等级时必须记录 acceptedRisks。等级绑定设计迭代：规格按所选等级的预算编写（场景数量从源头受控），同一迭代内规格修订不改变等级，改变等级需要新的设计迭代。超出等级预算（例如 FPGA_FUNCTIONAL 最多 3 个核心阻塞场景、1 个关键边界、1 个集成冒烟）时控制面要求超出预算重新确认，不得静默裁剪或扩大验证范围。秒表案例：按 FPGA_FUNCTIONAL 只需复位显示、启停保持、一次 00:00.99 → 00:01.00 边界和一次扫描轮转冒烟；完整 59:59.99 回绕、全数字覆盖、1000 次属性激活与窄毛刺注入默认延期。ISP 案例：黑电平偏移等功能级即可，Bayer 插值/窗口滤波/视频流集成按结构事实落入集成级，HDR/3A/安全成像推荐高保障级——按风险分级而不是按应用名硬编码。 3. 从封存物料提取可读事实，再结合客户需求按所选等级的预算创建规格草案并完成自动审查；不能从旧 RTL 反推行为规格，有歧义时生成选项让客户选择，不猜测。 4. 冻结规格，记录语义 digest；未冻结或 digest 过期时禁止生成代码。 5. 只向 Agent 发放 DAG 中 READY 的叶子功能单元，响应只能修改声明的 rtl/ 根。 6. 自动生成并资格审查 testbench、Oracle、断言、向量和模型。编译、接口绑定、正向参考、变异检测、边界/关系、watchdog、事件完整性及模型兼容性任一失败，都记为 TEST_ASSET_FAIL，不能归因给 DUT。 7. Design Assurance 的静态 violation 直接记为 DESIGN_RULE_FAIL；可执行的动态属性编入 Test IR，由仿真证据重新裁决。普通日志中的“PASS”不算证据。 8. 功能仿真与 Design Assurance 同时 PASS 后才解锁依赖它的子系统；子系统 PASS 后才解锁系统。不会一次生成全部层级后再统一补测。仿真通过结果带等级限定（FPGA_FUNCTIONAL_PASS / FPGA_INTEGRATION_PASS / HIGH_ASSURANCE_PASS；接受过延期风险时附 DEFERRED_RISKS_ACCEPTED），延期事项不产生伪 PASS；NATIVE_BUILD_PENDING / BOARD_VALIDATION_REQUIRED 与仿真状态始终分开报告——功能级仿真通过不代表原生构建或硬件通过。 9. 修改模块时自动失效该节点及其下游节点；上游无关节点保持有效。只有 change-promote 能写正式树；外部插件或人工改动会成为 UNVERIFIED_EXTERNAL_CHANGE。 10. 客户确认准备进入 Build 前，读取 BuildEligibility 汇总全部节点、动态义务、注册资产和最终回执。结果不匹配时，可靠流程不建议进入下一阶段；客户仍可明确退出到自由开发，普通 Build 不受影响。

3. 状态含义

状态 含义
PASS 冻结规格、合格资产、完整覆盖和认证证据全部满足
DESIGN_RULE_FAIL Design Assurance 静态或动态属性证据证明违反设计规则
DUT_FAIL 合格测试证据显示 DUT 与规格不一致
TEST_ASSET_FAIL 仿真代码或 Oracle/向量资格审查失败
SIMULATOR_ERROR 仿真器或基础设施失败，不归因 DUT
ORACLE_BLOCKED / MODEL_BLOCKED 需要客户选择 Oracle 或模型方向
TIMEOUT_OR_DEADLOCK 超时归因不唯一，需要选择或补证据
INSUFFICIENT_EVIDENCE 覆盖不足、证据缺失或证据被篡改
WAIVED_PASS 有显式、限定范围且未过期的客户 waiver；不是完整 PASS

使用 ASSUMPTION_MODEL 得到的结果只能表述为“在已批准假设模型下通过”，不能称为无条件系统合规。

4. 客户选择与重新冻结

遇到接口宽度、延迟、寄存器映射、架构边界、硬核模型或 Oracle 方向不明确时，系统给出有限选项、推荐理由、风险、受影响节点和失效范围。客户只能选择已有选项；选择记录是追加式证据。若选择改变规格，受影响规格必须重新审查并冻结后才能继续生成。

仿真与 DUT 不允许静默修改规格、Oracle、测试、阈值、模型或历史证据。自动修复最多三次，每次只允许一个假设和 DUT-only 补丁；失败时字节级回滚。

5. Efinity 硬核

硬核仿真必须先从工程 XML、ISF、peri.xml 和 IP 配置识别实例与配置 digest，再按以下信任等级处理：

  • VENDOR_MODEL：配置匹配且可用的厂商模型。
  • QUALIFIED_BEHAVIOR_MODEL：没有可执行厂商模型时，经契约测试资格审查的行为模型。
  • ASSUMPTION_MODEL：只有明确客户批准才可用，结论必须带限制措辞。

模型缺失、版本或配置不匹配时状态为 MODEL_BLOCKED，不得用空壳或常量模型伪造系统 PASS。Efinity 原生命令和模型事实以 Efinity 通用仿真流程 为准。

6. TB 编写检查清单

来自案例 2026-09-16-led-chaser-t20f256：首轮 3 处 FAIL 全部为 TB 缺陷（假 FAIL），DUT 无缺陷。

  • 复位初值检查必须在同步释放沿（posedge rst_n）采样。 DUT 使用异步复位、 同步释放（3 级同步链）时，复位释放点相对外部 rst_n_i 撤除有 2~3 拍延迟； 按固定拍数检查"复位期间初值未被改动"会与释放沿错位，产生假 FAIL。
  • 覆盖计数器的判定语义必须与覆盖项定义逐字对齐。 例如覆盖项"相邻档切换" 不能实现为"两次周期计数相等"——若各档周期互异，该条件永假，覆盖率不可达。 实现前重读覆盖项定义，逐字核对比较运算。
  • 发现 TB FAIL 时先归因（TB 缺陷 or DUT 缺陷）再修改；FAIL 日志先快照再重跑， 不用裸 > 重定向采集 vvp 输出（见 agent-rules harness 规则）。

7. 使用入口

evoverse verification --help
evoverse verification next --project <project> --json
evoverse verification run --project <project> --input <request.json> --json
evoverse verification integrity-scan --project <project> --json
evoverse verification build-eligibility --project <project> --json

MCP 还提供 verification_change_prepare/validate/promote、verification_integrity_register/scan 和 verification_build_eligibility。IDE 的 System Workspace 显示同一状态和客户决策；命令面板中的 “Request Next Verification-Gated Work Item” 只发放已解锁工作。

工具前提：客户自行安装系统 Python 3.11+；SDK 不自动安装，也不借用 Efinity 的旧 Python。规格、Design Assurance、仿真编排、CLI 和 MCP 使用系统 Python；Efinity Build、DesignAPI、IPM、Debug 则由 Adapter 在选中安装的 setup.bat 环境中调用厂商解释器，两个运行域的 PYTHONHOME、PYTHONPATH 和 PATH 互不继承。

Workbench 会分别显示 System Python、Build、DesignAPI、IPM、Debug 的可用性。运行域探测通过只代表解释器/API 能启动：普通 RTL/Video Sim 可使用 Icarus Verilog；含 Efinity 硬核的厂商模型仿真仍需要匹配的 Efinity 安装和可用 Questa/ModelSim license。仿真通过也不等于原生 Efinity 编译、时序收敛或硬件验证通过。

高级参考用于按需查询；设计记录、发布流程、审计报告和未来规划不属于客户操作入口。
