Trae 安装与首次配置

EvoVerse SDK：Trae 从零安装到全功能使用指南

更新日期：2026-08-15 目标：从一台未安装开发环境的电脑开始，在 Trae（Trae CN / Trae International）中完成 RTL 编辑、规则约束、仿真、Efinity 编译、时序诊断、烧录、MCP Agent 与原生 Chat 集成。

0. 与 VS Code 安装的关系

EvoVerse SDK 使用同一个 VSIX 同时支持 Trae、标准 Visual Studio Code 及其它 VS Code fork。绝大多数安装步骤与 VSCODE-INSTALLATION.md 相同，本文档只列出 Trae 下的差异点和 Trae 独有的安装与初始化行为。

你想知道的事 看这份文档

在标准 VS Code 下安装 SDK VSCODE-INSTALLATION.md
不同宿主之间的全部差异与 Gotchas HOST-DIFFERENCES.md
多宿主打包 / 发布 / 部署 DEPLOYMENT.md

适用对象： - 已选择 Trae 作为日常开发编辑器的客户； - 需要在 Trae Chat 面板中使用 @evoverse 与 MCP 工具的客户； - 需要理解 Trae 专属路径 ~/.trae/ 下哪些文件由 SDK 自动管理的运维人员。

0.1 Agent 与可靠流程入口

  • 需要规格、RTL Design Assurance 和仿真分阶段确认时，以 @evoverse 开始需求，例如：@evoverse 我要在 ws-e1 上实现 MIPI 到 USB，中间用 DDR 缓冲。SDK 会先确认工作方式：可靠设计流程或自由开发。
  • 已有工程开始新的独立设计迭代时，再次以 @evoverse 提出需求；已有规格书则更新，没有则新建。
  • 不带 @evoverse 的普通 Agent 对话保持自由开发，不自动启用可靠流程，也不会向客户工程生成专用规则文件。
  • Build、Timing、Debug 是独立工具入口，不要求先选择可靠流程。

1. 先确认"全功能"的边界

本指南中的全功能包括：

  • EvoVerse Workbench、Catalog、工程创建和健康检查；
  • Verilog/SystemVerilog 编辑、RTL 编码规范和 Agent 工作流；
  • Icarus Verilog 功能仿真与 VCD 波形查看；
  • Efinity 综合、布局布线、bitstream、资源报告和时序报告；
  • Timing Diagnosis、Build AI 和多轮 Conversation Runtime；
  • 通过 USB/JTAG 烧录 Efinix FPGA；
  • Trae Chat 面板中通过 @evoverse 调用 SDK 工具；
  • 可选的 Sapphire/RISC-V 软件编译、烧录和 GDB 调试。

1.1 推荐操作系统

与 VS Code 安装一致，请使用以下之一：

  • Windows 10/11 64 位：客户桌面环境首选；
  • macOS 12 或更高版本：Trae 桌面版官方支持平台；
  • Ubuntu 20.04 或更高版本。

macOS 可以使用 Trae、EvoVerse、MCP、AI 和 Icarus 仿真，但不能作为本文定义的完整 Efinity 编译/烧录工作站。Efinity 当前官方安装要求及 USB 驱动步骤见 Efinity Software Installation User Guide。

1.2 建议电脑配置

项目 最低可启动 客户全功能工作站建议
CPU 64 位双核 8 核或以上
内存 Trae + EvoVerse 约 1 GB；Efinity 设计流约 8 GB 16 GB，较大工程建议 32 GB
磁盘 10 GB 可用空间 30 GB 以上 SSD 可用空间
USB 1 个可用 USB 端口 2 个以上，避免无供电 Hub
网络 离线安装可选 首次下载 Trae、Efinity、插件、模型和工具链时需要

Trae 自身的最低系统要求见 Trae 官方下载页；Efinity 的内存与系统要求以所安装版本的官方文档为准。

2. 硬件准备

与 VS Code 安装完全一致，请阅读 VSCODE-INSTALLATION.md §2 完成硬件清单与连接前检查。至少准备：

  1. EvoVerse/Efinix FPGA 核心板，例如 Catalog 中的 ws-e1；
  2. 与核心板匹配的底板、Carrier 或客户自研板；
  3. 符合板卡规格的电源；不要仅凭接口外形猜测电压和极性；
  4. 可传输数据的 USB 线；只充电线不能用于 JTAG/串口；
  5. 板载 FTDI 调试接口，或兼容的 FT2232H/FT4232H JTAG 模块；
  6. 如需串口日志，准备板载 USB-UART 或独立 3.3 V USB-UART；
  7. 如需传感器、MIPI、显示或网络功能，准备对应 Jacket、线缆和外设。

连接前阅读安装后 Catalog 中的板卡规格：

${EVOVERSE_HOME}/catalog/boards/<board-id>/<board-id>.md
${EVOVERSE_HOME}/catalog/boards/<board-id>/docs/
${EVOVERSE_HOME}/catalog/boards/<board-id>/carriers/

3. 安装基础软件

3.1 安装 Trae

  1. 从 Trae 官方下载页选择平台对应版本：
  2. Trae CN：面向中国大陆用户，默认连接国内模型 Provider；
  3. Trae International：面向海外用户，默认连接海外模型 Provider。
  4. 安装后启动 Trae，按向导完成账号注册与登录。
  5. 验证：
# 打开命令面板执行
Trae: Show Version

或在终端执行：

where trae     # Windows
which trae     # macOS / Linux

3.2 安装 Python 3.11+

EvoVerse CLI 和 MCP Server 使用 Python 标准库，不需要 pip install 其他包。

Windows：

  1. 从 Python 官网安装 64 位 Python 3.11 或更新版本；
  2. 勾选 Add Python to PATH；
  3. 验证：
py -3 --version
python --version

macOS / Linux：

python3 --version

要求输出 3.10 或更高版本。客户使用 VSIX 不需要安装 Node.js 或 npm；它们仅用于从源码构建扩展。

3.3 安装 Efinity

与 VS Code 安装完全一致，请阅读 VSCODE-INSTALLATION.md §3.3 完成 Efinity 安装与许可证配置。完成后记录 Efinity 根目录：

Windows:  C:\Efinity\2026.1
macOS:    /Applications/efinity.app/Contents/Resources/2026.1
Linux:    /opt/efinity/2026.1

EvoVerse 每次运行工具时会使用 Efinity 的 setup 脚本建立子进程环境，因此通常不要求永久修改系统 PATH。

3.4 安装 FPGA USB/JTAG 驱动

与 VS Code 安装一致：

  • Windows：按目标板用户手册和 Efinity 安装指南使用 Zadig/指定驱动。不要盲目替换复合 FTDI 设备的所有接口；先确认板卡文档要求的 interface。
  • macOS：Efinity 官方安装包自带驱动；如未识别按 Efinity 文档执行驱动加载。
  • Linux：断开板卡后执行：
sudo <EFINITY_HOME>/bin/install_usb_driver.sh
sudo udevadm control --reload-rules
sudo udevadm trigger

重新连接板卡。

3.5 安装 Icarus Verilog

完整仿真功能需要 iverilog 和 vvp。

  • macOS：brew install icarus-verilog
  • Linux：
sudo apt update
sudo apt install iverilog

验证：

iverilog -V
vvp -V

3.6 可选：RISC-V 软件工具链

只有使用 Sapphire/RISC-V SoC 时需要，与 VS Code 安装完全一致。详见 VSCODE-INSTALLATION.md §3.6。

4. 安装 EvoVerse SDK VSIX

EvoVerse 在 Trae 与 VS Code 下共用同一个 evoverse-sdk-0.9.0.vsix。

4.1 安装步骤

  1. 在 Trae 中按 Ctrl+Shift+X（macOS: Cmd+Shift+X）打开扩展面板；
  2. 点击右上角 ... → Install from VSIX...；
  3. 选择交付包中的 evoverse-sdk-0.9.0.vsix。

或使用命令行：

# Windows (PowerShell)
trae --install-extension D:\packages\evoverse-sdk-0.9.0.vsix

# macOS / Linux
trae --install-extension ~/packages/evoverse-sdk-0.9.0.vsix

4.2 推荐同时安装的扩展

扩展 用途 是否由 EvoVerse 声明为依赖
VaporView 打开仿真生成的 VCD 波形 是
Cortex-Debug RISC-V/MCU GDB 调试 是
Verilog/SystemVerilog 语言插件 语法高亮、跳转和 lint 否，按客户许可与团队标准选择

Trae 内置 Chat Agent，不需要额外安装 GitHub Copilot 即可在 Chat 面板中使用 @evoverse。如需使用 EvoVerse 内置 Runtime 的 OpenAI-compatible Provider，参见 §7。

5. 首次启动：Trae 专属的 Set Up 行为

EvoVerse 扩展激活时如果检测到 ~/evoverse-sdk 未就绪，会弹窗询问是否 Set Up。在 Trae 下，Set Up 会执行以下额外操作（VS Code 下不会执行）：

5.1 写入 ~/.trae/mcp.json

SDK 会自动将 EvoVerse MCP Server 写入 ~/.trae/mcp.json 的 mcpServers.evoverse 字段：

  • 仅合并，不会覆盖 mcpServers 下的其它条目；
  • 若 ~/.trae/mcp.json 不存在则新建；
  • 若已存在 mcpServers.evoverse，按字节级比较：相等则跳过；不等则备份为 ~/.trae/mcp.json.evoverse.bak 后覆盖。

示例（仅供参考，由 SDK 自动生成）：

{
  "mcpServers": {
    "evoverse": {
      "command": "python",
      "args": ["-m", "mcp_server.server"],
      "env": {}
    }
  }
}

5.2 写入 ~/.trae/user_rules/

SDK 会自动安装两份 Agent Rules：

  • ~/.trae/user_rules/evoverse.md — EvoVerse 通用规则；
  • ~/.trae/user_rules/evoverse-rtl-style.md — RTL 编码风格专项规则。

规则源位于 ~/evoverse-sdk/agent-rules/，SDK 会按字节级比较后写入：

  • 相等 → 跳过（unchanged）；
  • 不等 → 备份为 *.evoverse.bak 后覆盖；
  • 损坏或非预期格式 → 备份并报错，不静默清空。

5.3 "Restart now" 提示

仅在 Trae 下会出现 "Restart Trae now to load MCP" 提示，因为 Trae 的 MCP 由宿主固定目录加载，必须重启 Trae 后 MCP 工具才会出现在 Chat 面板中。

标准 VS Code / 未知宿主不会出现该提示；如在 VS Code 下看到该提示说明宿主识别异常，应先确认 vscode.env.appName 是否以 trae 开头。

5.4 损坏的宿主配置处理

如果 ~/.trae/mcp.json 或 ~/.trae/user_rules/*.md 已损坏，SDK 会：

  1. 备份原文件为 *.evoverse.bak；
  2. 返回错误信息到 UI；
  3. 不静默覆盖（避免客户自定义规则被无意清空）。

7. 使用 OpenAI-compatible Provider（可选）

若不想使用 Trae 内置模型，可在 EvoVerse Conversation Runtime 中配置 OpenAI-compatible Provider：

  1. 执行 EvoVerse: Set OpenAI-compatible API Key，将 API Key 写入 SecretStorage；
  2. 在 evoverse.model.modelId 中填入 Provider 提供的模型 ID；
  3. 重启 Trae 以确保配置生效。

不要把模型 API Key 写入 ~/.trae/mcp.json 的 env 字段；SDK 会拒绝此类配置。

8. 故障排查

8.1 Trae Chat 面板中找不到 @evoverse

按以下顺序排查：

  1. 确认 ~/.trae/mcp.json 中存在 mcpServers.evoverse；
  2. 确认 SDK 提示过 Restart now 且已完成重启；
  3. 打开 Trae → Settings → MCP，确认 evoverse Server 显示为 running；
  4. 在 Chat 面板输入 @，确认下拉列表中出现 evoverse。

8.2 ~/.trae/mcp.json 被破坏

  1. SDK 在写入前会备份为 ~/.trae/mcp.json.evoverse.bak，从备份恢复： bash cp ~/.trae/mcp.json.evoverse.bak ~/.trae/mcp.json
  2. 重新执行 EvoVerse: Set Up。

8.3 ~/.trae/user_rules/*.md 与团队规则冲突

  • EvoVerse 安装的规则源在 ~/evoverse-sdk/agent-rules/，不要直接修改 ~/.trae/user_rules/*.md；
  • 若需在项目中追加规则，改项目级 .github/copilot-instructions.md；
  • 若必须修改用户规则，先备份再改，并在每次 SDK 升级后人工合并。

8.4 宿主识别异常

打开 Trae 命令面板执行：

# 通过 Developer Tools 查看
Developer: Toggle Developer Tools

在 Console 中执行：

JSON.stringify({ appName: require('vscode').env.appName })

应返回 "Trae"、"Trae CN" 或 "Trae - ide" 之一。若返回其它名称，参考 HOST-DIFFERENCES.md §1 确认 detectHostId() 的判定逻辑。

8.5 模型不可用导致构建/报告失败

EvoVerse 的确定性能力（构建、报告、规则诊断、时序分析）在任何宿主下都应能独立工作。如果模型不可用时构建/报告也被阻断，说明 Trae 下的模型 Provider 配置影响了子进程路径，按 VSCODE-INSTALLATION.md §3.3 复查 Efinity setup 脚本调用。
