VS Code 安装差异

EvoVerse SDK：Visual Studio Code 从零安装到全功能使用指南

适用版本：v1.0.0　更新日期：2026-09-30 目标：从一台未安装开发环境的电脑开始，完成 RTL 编辑、规则约束、仿真、Efinity 编译、时序诊断、烧录、MCP Agent、AI 对话以及可选 RISC-V 软件调试。

1. 先确认“全功能”的边界

本指南中的全功能包括：

  • EvoVerse Workbench、Catalog、工程创建和健康检查；
  • Verilog/SystemVerilog 编辑、RTL 编码规范和 Agent 工作流；
  • Icarus Verilog 功能仿真与 VCD 波形查看；
  • Efinity 综合、布局布线、bitstream、资源报告和时序报告；
  • Timing Diagnosis、Build AI 和多轮 Conversation Runtime；
  • 通过 USB/JTAG 烧录 Efinix FPGA；
  • VS Code Chat 通过 EvoVerse MCP 查询 Catalog、创建工程、检查 RTL/SDC；
  • 可选的 Sapphire/RISC-V 软件编译、烧录和 GDB 调试。

1.1 推荐操作系统

要实现上述全部能力，请使用以下之一：

  • Windows 10/11 64 位：客户桌面环境首选；
  • Ubuntu 20.04 或更高版本；
  • RHEL 8.8 或更高版本。

macOS 可以使用 VS Code、EvoVerse、MCP、AI 和 Icarus 仿真，但不能作为本文定义的完整 Efinity 编译/烧录工作站。Efinity 的当前官方安装要求及 USB 驱动步骤见 Efinity Software Installation User Guide。

1.2 建议电脑配置

项目 最低可启动 客户全功能工作站建议
CPU 64 位双核 8 核或以上
内存 VS Code 1 GB；Efinity 设计流约 8 GB 16 GB，较大工程建议 32 GB
磁盘 10 GB 可用空间 30 GB 以上 SSD 可用空间
USB 1 个可用 USB 端口 2 个以上，避免无供电 Hub
网络 离线安装可选 首次下载 VS Code、Efinity、插件、模型和工具链时需要

VS Code 自身的官方最低要求见 VS Code Requirements。Efinity 的内存与系统要求以所安装版本的官方文档为准。

2. 硬件准备

至少准备：

  1. EvoVerse/Efinix FPGA 核心板，例如 Catalog 中的 ws-e1；
  2. 与核心板匹配的底板、Carrier 或客户自研板；
  3. 符合板卡规格的电源；不要仅凭接口外形猜测电压和极性；
  4. 可传输数据的 USB 线；只充电线不能用于 JTAG/串口；
  5. 板载 FTDI 调试接口，或兼容的 FT2232H/FT4232H JTAG 模块；
  6. 如需串口日志，准备板载 USB-UART 或独立 3.3 V USB-UART；
  7. 如需传感器、MIPI、显示或网络功能，准备对应 Jacket、线缆和外设。

连接前阅读安装后 Catalog 中的板卡规格：

${EVOVERSE_HOME}/catalog/boards/<board-id>/<board-id>.md
${EVOVERSE_HOME}/catalog/boards/<board-id>/docs/
${EVOVERSE_HOME}/catalog/boards/<board-id>/carriers/

不要在未知 I/O 电压、JTAG 电平或供电方向的情况下连接自研板。Efinix 官方说明开发板通常使用 FT232H、FT2232H 或 FT4232H；自研板的具体连接仍以板卡原理图为准。

3. 安装基础软件

3.1 安装 Visual Studio Code

  1. 从 VS Code 官方下载页下载 Stable 64 位版本。
  2. Windows 推荐 User Installer；安装时勾选“添加到 PATH”和资源管理器“Open with Code”。
  3. 启动 VS Code，执行：
code --version

如果终端找不到 code，重开终端或重新安装并启用 PATH 选项。

3.2 安装 Python 3.11+

EvoVerse CLI 和 MCP Server 使用 Python 标准库，不需要 pip install 其他包。

Windows：

  1. 从 Python 官网安装 64 位 Python 3.11 或更新版本；
  2. 勾选 Add Python to PATH；
  3. 验证：
py -3 --version
python --version

Linux：

python3 --version

要求输出 3.10 或更高版本。客户使用 VSIX 不需要安装 Node.js 或 npm；它们仅用于从源码构建扩展。

3.3 安装 Efinity

  1. 从 Efinix Support Center 获取与目标器件和许可证匹配的 Efinity 安装包；
  2. 按该版本安装指南完成安装和许可证配置；
  3. Windows 安装 Microsoft Visual C++ 2022 x64 Runtime；部分 IP Manager（例如 Sapphire SoC）还需要 64 位 Java 8 或 11；
  4. Linux 按官方要求安装 GUI 库和 Java，并确保 Java 在 PATH；
  5. 记录 Efinity 根目录，例如：
Windows: C:\Efinity\2026.1
Linux:   /opt/efinity/2026.1

验证根目录中存在：

bin/setup.bat             # Windows
bin/setup.sh              # Linux
bin/efx_run.bat 或 efx_run.py
bin/efinity.exe 或 bin/efinity

EvoVerse 每次运行工具时会使用 Efinity 的 setup 脚本建立子进程环境，因此通常不要求永久修改系统 PATH。

3.4 安装 FPGA USB/JTAG 驱动

Windows：按照目标板用户手册和 Efinity 安装指南使用 Zadig/指定驱动。不要盲目替换一个复合 FTDI 设备的所有接口；先确认板卡文档要求的 interface。

Linux：断开板卡后执行：

sudo <EFINITY_HOME>/bin/install_usb_driver.sh
sudo udevadm control --reload-rules
sudo udevadm trigger

重新连接板卡。Efinity 官方 USB 驱动说明见其安装指南的 “Installing USB Drivers” 章节。

3.5 安装 Icarus Verilog

完整仿真功能需要 iverilog 和 vvp。

Windows 可安装预编译版本；Linux 示例：

sudo apt update
sudo apt install iverilog

验证：

iverilog -V
vvp -V

3.6 可选：RISC-V 软件工具链

只有使用 Sapphire/RISC-V SoC 时需要：

  • xPack GNU RISC-V Embedded GCC；
  • GDB；
  • Efinity 生成的 BSP；
  • VS Code Cortex-Debug 插件；
  • 对应板卡调试器/OpenOCD 配置。

可以执行 EvoVerse: Download & Install RISC-V Toolchain，也可以手动安装后设置 evoverse.riscvToolchainPath。

4. 安装 VS Code 插件

4.1 必装

  1. EvoVerse SDK：安装交付的 evoverse-sdk-0.9.0.vsix。

Chat Agent 不是 EvoVerse VSIX 的强制依赖。推荐使用 VS Code 原生 Chat Agent；若只使用 EvoVerse 内置 Runtime 的 openai-compatible Provider，则不需要安装 GitHub Copilot。

推荐只使用 VS Code 原生 Chat Agent 执行写文件和终端命令，避免多个 Agent 同时自动修改同一工作区。

安装 VSIX：

code --install-extension D:\packages\evoverse-sdk-0.9.0.vsix

也可以使用 Extensions → ... → Install from VSIX...。

4.2 按功能安装

插件 用途 是否由 EvoVerse 声明为依赖
GitHub Copilot VS Code 原生 Chat Agent、VS Code MCP 和 vscode-lm 否，使用原生 Chat Agent 时安装并登录
VaporView 打开仿真生成的 VCD 波形 是
Cortex-Debug RISC-V/MCU GDB 调试 是
Verilog/SystemVerilog 语言插件 语法高亮、跳转和 lint 否，按客户许可与团队标准选择

需要 Agent 对话、MCP 工具调用和项目规则时，使用 VS Code 原生 Chat Agent。未安装 GitHub Copilot 时，EvoVerse 内置 Timing Diagnosis/Build AI 仍可通过 10.3 节的 OpenAI-compatible Provider 工作。

离线环境需要管理员预先准备依赖插件的 VSIX。若 Marketplace 不可访问，EvoVerse 主 VSIX 不一定能替客户下载依赖插件。

5. 初始化 EvoVerse

  1. 重载 VS Code；
  2. 执行 EvoVerse: Set Up (re-run bootstrap)；
  3. 选择 Yes, set up；
  4. 确认 Output → EvoVerse SDK 中出现：
EVOVERSE_HOME ready
Vendored CLI + MCP server
Seeded catalog
CLI works

初始化后主要目录为：

~/evoverse-sdk/                 Catalog、项目、CLI、MCP Server 和共享规则资产
~/evoverse-sdk/cli/             EvoVerse CLI
~/evoverse-sdk/mcp-server/      MCP Server

标准 VS Code 不会创建或写入 ~/.trae。

6. 配置 VS Code Settings

打开 Settings，搜索 evoverse，或在用户 settings.json 中填写：

{
  "evoverse.home": "D:\\EvoVerse",
  "evoverse.pythonPath": "C:\\Users\\<user>\\AppData\\Local\\Programs\\Python\\Python312\\python.exe",
  "evoverse.efinityPath": "C:\\Efinity\\2026.1",
  "evoverse.simulator": "iverilog",
  "evoverse.iverilogPath": "C:\\iverilog\\bin",
  "evoverse.buildMode": "cli",
  "evoverse.build.parallelJobs": 4,
  "evoverse.build.autoOpenReport": true,
  "evoverse.program.defaultMode": "jtag"
}

Linux 示例：

{
  "evoverse.home": "/home/<user>/evoverse-sdk",
  "evoverse.pythonPath": "/usr/bin/python3",
  "evoverse.efinityPath": "/opt/efinity/2026.1",
  "evoverse.simulator": "iverilog",
  "evoverse.iverilogPath": "/usr/bin",
  "evoverse.buildMode": "cli"
}

路径必须换成客户机器上的真实路径。evoverse.iverilogPath 应直接指向包含 iverilog 和 vvp 的目录。

如需使用 QuestaSim：

{
  "evoverse.simulator": "questa",
  "evoverse.questaPath": "C:\\questasim64_2024.1\\win64"
}

evoverse.questaPath 必须直接包含 vlib、vlog 和 vsim。该设置仅影响普通 EvoVerse: Simulate；Video Sim 仍使用其自带的 Icarus 自动流程。

7. 环境变量

7.1 推荐原则

优先使用 evoverse.* Settings；只有 CLI、MCP 或企业部署需要跨进程共享路径时才设置系统环境变量。

变量 是否必须 用途
EVOVERSE_HOME MCP 推荐 Catalog 和工程根目录
EVOVERSE_CLI MCP 推荐 EvoVerse CLI 绝对路径
PYTHONUTF8=1 Windows MCP 推荐 保证中英文 JSON/日志使用 UTF-8
EFINITY_HOME 通常不必永久设置 Efinity 根目录；扩展会从 setting 建立子进程环境
PATH 按需 让终端直接找到 Python、Icarus、Java、RISC-V GCC

Windows PowerShell 当前用户示例：

[Environment]::SetEnvironmentVariable('EVOVERSE_HOME', "$HOME\evoverse-sdk", 'User')
[Environment]::SetEnvironmentVariable('PYTHONUTF8', '1', 'User')

Linux shell 示例：

export EVOVERSE_HOME="$HOME/evoverse-sdk"
export PYTHONUTF8=1

如果写入 shell profile，修改后必须重新打开 VS Code，使 MCP 子进程继承新环境。

8. 在 VS Code 中配置 EvoVerse MCP

8.0 自动注册（推荐）

v0.9.0 起，执行 EvoVerse: Set Up 时扩展会自动把 servers.evoverse 合并进 VS Code 用户级 mcp.json（Windows 为 %APPDATA%\Code\User\mcp.json；写入前自动备份 mcp.json.evoverse.bak，已存在的其它 server 条目保持不变）。重载 VS Code 后执行 MCP: List Servers 确认即可，无需手动编辑 JSON。

自动注册未生效时（例如企业策略锁定配置目录），再按 8.1/8.2 手动合并。

8.1 Windows 用户级配置（手动兜底）

先确认 Python 与文件路径（注意：CLI 与 MCP Server 实际安装在 ~/evoverse-sdk/ 下）：

py -3 --version
Test-Path "$HOME\evoverse-sdk\mcp-server\server.py"
Test-Path "$HOME\evoverse-sdk\cli\evoverse"

在 MCP: Open User Configuration 打开的 mcp.json 中合并：

{
  "servers": {
    "evoverse": {
      "command": "py",
      "args": [
        "-3",
        "C:\\Users\\<user>\\evoverse-sdk\\mcp-server\\server.py"
      ],
      "env": {
        "EVOVERSE_HOME": "C:\\Users\\<user>\\evoverse-sdk",
        "EVOVERSE_CLI": "C:\\Users\\<user>\\evoverse-sdk\\cli\\evoverse",
        "PYTHONUTF8": "1"
      }
    }
  }
}

如果机器没有 py launcher，把 command 换成 python.exe 的绝对路径，并删除 args 中的 -3。

8.2 Linux 用户级配置

{
  "servers": {
    "evoverse": {
      "command": "/usr/bin/python3",
      "args": [
        "/home/<user>/evoverse-sdk/mcp-server/server.py"
      ],
      "env": {
        "EVOVERSE_HOME": "/home/<user>/evoverse-sdk",
        "EVOVERSE_CLI": "/home/<user>/evoverse-sdk/cli/evoverse",
        "PYTHONUTF8": "1"
      }
    }
  }
}

8.3 用户级还是工作区级

  • 用户级：服务器在所有工作区可用，适合固定开发工作站；
  • 工作区级：保存为 <project>/.vscode/mcp.json，适合团队共享，但不能提交客户用户名或绝对路径；
  • Remote/SSH/WSL：MCP 在配置所在环境运行，必须使用远端路径和远端 Python。

首次启动时检查配置并确认 VS Code 的 MCP Trust 对话框。然后执行 MCP: List Servers：

  1. evoverse 状态为 Running；
  2. Tools 中能看到 list_boards、validate_manifest、check_rtl_code_style 等；
  3. 在 Chat Agent 模式中提问：“使用 EvoVerse 工具列出可用板卡”；
  4. MCP 出错时从 MCP: List Servers → evoverse → Show Output 查看日志。

不要把模型 API Key 写入 mcp.json。

8.4 推荐方案：在 VS Code 原生 Chat Agent 中使用 EvoVerse MCP

完成 8.1 或 8.2 的配置后，在 VS Code 中执行 MCP: List Servers，确认 evoverse 已启动且工具列表可见。随后打开原生 Chat，切换到 Agent 模式并允许其使用 EvoVerse MCP 工具。

配置后在 VS Code 原生 Chat Agent 中执行验收提问：

请使用 EvoVerse 的 list_boards 工具列出可用板卡，并说明结果来自工具而不是模型记忆。

如果原生 Chat Agent 能看到 list_boards、validate_manifest 和 check_rtl_code_style，即可对工程进行问答并调用 EvoVerse 工具。首次调用工具或终端命令时仍应由客户确认授权；不要开启不受限制的自动批准。

9. 安装项目规范、RTL 编码规则和工作流

这一步是 VS Code 全功能安装的必做项，不是可选美化。

9.1 建立 EvoVerse 工程

在 Chat 中用自然语言描述新建或接管目标；Agent 通过 Workbench Control 的 project_next envelope 展示当前动作，确认后执行。工程建立时会从以下正式规则资产生成 VS Code 指令：

~/evoverse-sdk/agent-rules/rules.md
~/evoverse-sdk/agent-rules/rules-rtl-style.md

生成 .github/copilot-instructions.md 与 .github/instructions/rtl.instructions.md。前者包含通用工程工作流，后者包含完整 RTL、CDC、复位、Efinity 格式和验证规则。Trae 与 VS Code 的生成内容都来自 SDK 的宿主无关 agent-rules/ 正式源，不依赖 .trae 或已弃用的 CLAUDE.md。VS Code 官方支持 .github/copilot-instructions.md、根目录 AGENTS.md 和 .github/instructions/*.instructions.md，详见 Use custom instructions in VS Code。

9.2 已有工程

从初始化生成的共享规则资产建立 VS Code 指令：

Windows：

New-Item -ItemType Directory -Force ".github\instructions" | Out-Null
Copy-Item "$HOME\evoverse-sdk\agent-rules\rules.md" ".github\copilot-instructions.md"
$header = "---`nname: EvoVerse RTL rules`ndescription: Mandatory RTL, CDC, reset and verification rules`napplyTo: `"**/*.{v,sv,vh,sdc}`"`n---`n`n"
$header + (Get-Content "$HOME\evoverse-sdk\agent-rules\rules-rtl-style.md" -Raw) | Set-Content ".github\instructions\rtl.instructions.md" -Encoding utf8

Linux：

mkdir -p .github/instructions
cp "$HOME/evoverse-sdk/agent-rules/rules.md" .github/copilot-instructions.md
printf '%s\n' '---' 'name: EvoVerse RTL rules' 'description: Mandatory RTL, CDC, reset and verification rules' 'applyTo: "**/*.{v,sv,vh,sdc}"' '---' '' > .github/instructions/rtl.instructions.md
cat "$HOME/evoverse-sdk/agent-rules/rules-rtl-style.md" >> .github/instructions/rtl.instructions.md

生成后的 .github/copilot-instructions.md 来自正式通用规则；不要再建立或维护 CLAUDE.md。其关键审批边界包括：

# EvoVerse project instructions

- Before changing RTL, inspect `evoverse-project.md`, constraints and relevant board/IP manifests.
- Follow the naming, reset, CDC, handshake, synthesis and timing rules in the RTL instruction file.
- Run RTL style checks and simulation before build.
- Do not claim timing closure without a successful Efinity build and timing report.
- Do not program hardware or apply an optimization candidate without explicit user approval.

团队也可以让其他 Agent 读取根目录 AGENTS.md，但不要复制并维护互相矛盾的完整规则；正式源始终是 SDK 仓库的 agent-rules/rules.md 与 agent-rules/rules-rtl-style.md，项目文件由 CLI 生成对应宿主格式。

9.3 验证原生 Chat Agent 的项目规则

VS Code 原生 Chat Agent 使用工程中的 .github/copilot-instructions.md 和 .github/instructions/*.instructions.md。EvoVerse 新建工程会自动生成这些文件；已有工程按 9.2 节创建：

.github/copilot-instructions.md
.github/instructions/rtl.instructions.md

两份文件的正式来源分别是初始化后的：

~/evoverse-sdk/agent-rules/rules.md
~/evoverse-sdk/agent-rules/rules-rtl-style.md

不要从已弃用的 CLAUDE.md 复制规范。打开 VS Code Chat 的 Customizations/Diagnostics，确认通用规则和 RTL 专项规则均已加载。

9.4 建议的 RTL 专项指令

创建 .github/instructions/rtl.instructions.md：

---
name: EvoVerse RTL rules
description: Mandatory RTL, CDC, reset and verification rules
applyTo: "**/*.{v,sv,vh,sdc}"
---

Before proposing or editing RTL:
1. identify clock/reset domains and interface latency;
2. preserve explicit port connections and the project's naming rules;
3. treat CDC and constraints as deterministic verification items;
4. run `EvoVerse: Check This File's RTL Code Style` and the relevant simulation;
5. never treat model output as proof of functional or timing correctness.

在 VS Code Settings 中确认：

{
  "chat.useAgentsMdFile": true,
  "chat.instructionsFilesLocations": {
    ".github/instructions": true
  }
}

在 Chat 中打开 Customizations/Diagnostics，确认 copilot-instructions.md 和 RTL instruction 已加载。自定义指令影响 Chat/Agent，但不保证影响编辑器中的逐字 inline completion，因此最终仍必须运行 EvoVerse 的确定性检查。

10. 配置模型

10.1 两个问答入口的关系

VS Code 原生 Chat Agent 和 EvoVerse 内置 Conversation Runtime 都能进行工程问答，但当前是两套独立会话：

入口 模型配置 EvoVerse 工具来源 是否共享会话历史
VS Code 原生 Chat Agent VS Code Chat 模型选择器 VS Code 中配置的 EvoVerse MCP 否
EvoVerse Timing Diagnosis / Build AI evoverse.model.* 扩展内部上下文与工具链 否

VS Code 原生 Chat Agent 不能直接充当 evoverse.model.provider。如果希望两个入口使用同一宿主模型，在原生 Chat 中选择目标模型，并将 EvoVerse 内置 Runtime 配置为 vscode-lm；也可以让内置 Runtime 单独使用 openai-compatible。凭据应保存在各自的安全存储中，不应通过项目文件共享。

10.2 VS Code 宿主模型

适合已经使用 GitHub Copilot/VS Code Language Model API，且所需模型已出现在 VS Code 模型选择器中的客户。配置步骤：

  1. 安装并登录 GitHub Copilot；
  2. 在 VS Code Chat 中确认目标模型可用，并完成模型服务商要求的授权；
  3. 在用户 Settings 中把 evoverse.model.provider 设为 vscode-lm；
  4. 执行 EvoVerse: Select AI Model，从宿主实际返回的模型中选择；命令会保存准确的 Model ID；
  5. 重载 VS Code 窗口，或等待配置自动刷新。

也可以手工设置：

{
  "evoverse.model.provider": "vscode-lm",
  "evoverse.model.modelId": "<VS Code 暴露的准确 model id>"
}

EvoVerse 不会静默选择模型列表中的第一个模型。若不知道准确 ID，先在宿主模型选择器中确认可用模型，或使用 OpenAI-compatible Provider。

这里的模型清单由 VS Code/Copilot 账号、许可、地区和当前服务决定。只有 VS Code Language Model API 实际暴露的模型才会出现在 vscode-lm 列表中。

10.3 OpenAI-compatible Provider

适合客户自带 OpenAI、DeepSeek、智谱、MiniMax或企业模型网关 API Key。当前实现调用标准 POST <baseUrl>/chat/completions，要求服务支持 OpenAI Chat Completions格式；工具调用和结构化输出还取决于具体模型的兼容程度。

配置步骤：

  1. 从模型服务商取得 API Key、Base URL 和准确的 Model ID；
  2. 在用户 Settings 中填写以下三项；
  3. 执行 EvoVerse: Set OpenAI-compatible API Key，将密钥写入 VS Code SecretStorage；
  4. 执行 Developer: Reload Window；
  5. 第一次问答时核对发送规模提示，选择 Send。
{
  "evoverse.model.provider": "openai-compatible",
  "evoverse.model.modelId": "<endpoint-model-id>",
  "evoverse.model.baseUrl": "https://<provider-host>/v1/",
  "evoverse.model.allowLocalHttp": false
}

执行 EvoVerse: Set OpenAI-compatible API Key 输入密钥。密钥保存于 VS Code SecretStorage，不要放入 settings、MCP、Prompt 或项目仓库。远程请求前 EvoVerse 会显示消息数量和字符规模并要求确认。

本地开发端点只有在地址是 localhost/回环地址且显式打开 evoverse.model.allowLocalHttp 时才能使用 HTTP。

常用服务示例（模型名必须以客户账号实际开放的列表为准）：

服务 evoverse.model.baseUrl evoverse.model.modelId 示例 说明
OpenAI API https://api.openai.com/v1/ 账号实际可用的 OpenAI 模型 ID 使用 OpenAI API Key，不等同于自动复用 Codex订阅
DeepSeek https://api.deepseek.com/v1/ deepseek-chat 使用 DeepSeek API Key
智谱 BigModel https://open.bigmodel.cn/api/paas/v4/ 账号实际可用的 GLM 模型 ID 智谱提供 OpenAI兼容接口；编码套餐可能使用专属端点
MiniMax https://api.minimaxi.com/v1/ 账号实际可用的 MiniMax 模型 ID MiniMax提供 OpenAI兼容接口
企业聚合网关 企业提供的 HTTPS /v1/ 或兼容根地址 网关公布的模型 ID 可由网关转发 Claude等模型，但必须确认 Chat Completions兼容性

当前内置 Runtime 没有原生 Anthropic Messages API Provider。Claude有两种可行路径：在 vscode-lm 中选择 VS Code实际暴露的 Claude模型；或者使用公司/OpenRouter等提供 OpenAI-compatible Chat Completions的网关。不能把 Anthropic原生 Base URL直接填入本节配置。

10.4 验证 Timing Diagnosis 与 Build AI

完成任一 Provider配置后，按以下顺序验证：

  1. 打开一个已经成功构建、包含时序报告的 EvoVerse工程；
  2. 执行 Toolchain: Diagnose Timing Violations；
  3. 在 Timing Diagnose 页面点击 Ask AI，确认出现请求发送确认框，批准后能够流式返回分析；
  4. 在输入框继续追问一次，确认 Conversation Runtime保留本入口的多轮上下文；
  5. 打开 Build Report，点击 询问 AI Agent，确认能够收到带构建摘要的回答；
  6. 检查回答是否引用当前报告中的 WNS/TNS、时钟域或关键路径。模型建议只用于分析，不能替代实际仿真、CDC检查和 Efinity时序报告。

若失败，先检查 Output → EvoVerse SDK，再核对：Provider名称、Model ID、Base URL是否重复包含 chat/completions、API Key权限、账号余额以及企业代理。baseUrl 只填写 API根路径，EvoVerse会自行追加 chat/completions。

11. 首次项目与逐级验收

不要直接跳到烧录。按顺序执行，每一步通过后再继续。

11.1 基础与 Catalog

  1. 打开 EvoVerse Activity Bar；
  2. 确认 Board Catalog 中存在 ws-e1；
  3. 执行 EvoVerse: Show Knowledge Base；
  4. 在 Chat 中描述最小工程目标，确认 project_next envelope 后创建工程；
  5. 确认工程有 evoverse-project.md、.github/copilot-instructions.md 和 .github/instructions/rtl.instructions.md。

11.2 规则与 MCP

  1. 打开一个 RTL 文件；
  2. 执行 Toolchain: Check This File's Code Style；
  3. 在 VS Code Chat 的 Customizations/Diagnostics 中确认规范文件已加载；
  4. 执行 MCP: List Servers，确认 evoverse Running；
  5. 让 Agent 使用 list_boards，结果应来自实际 Catalog，而不是模型记忆。

11.3 仿真

  1. 工程包含 testbench；
  2. 执行 EvoVerse: Simulate；
  3. Output 中 iverilog 和 vvp 返回成功；
  4. 生成 VCD 时用 VaporView 打开并确认时钟、复位和输出行为。

11.4 Efinity 编译与时序

  1. 执行 Toolchain: Project Health Check；
  2. 修复缺失 SDC、器件或源文件问题；
  3. 执行 Toolchain: Build (Full Flow)；
  4. Build Report 中确认资源、I/O/Clock、Timing 和 Critical Paths 可读取；
  5. 执行 Toolchain: Diagnose Timing Violations；
  6. AI 建议只能作为推断，WNS/TNS、CDC、仿真和构建结果才是验证证据。

11.5 烧录

  1. 板卡断电时确认跳帽、电压、JTAG 和启动模式；
  2. 连接电源与 USB 数据线；
  3. 在 Efinity Programmer 中先确认能枚举目标设备；
  4. 回到 VS Code 执行 Toolchain: Program FPGA；
  5. 如果显示 “no FTDI device”，检查数据线、驱动、权限、Hub 和板卡供电。

11.6 可选 RISC-V

  1. 配置 Sapphire SoC IP 并从 Efinity 同步；
  2. 执行 Software: Sync BSP from SoC IP；
  3. 执行 Software: Build App；
  4. 执行 Software: Program FPGA；
  5. 确认 Cortex-Debug、GDB 和调试器路径后执行 Software: Debug App。

12. 故障排查

症状 检查
Set Up 找不到 Python 设置 evoverse.pythonPath 为解释器绝对路径，重载窗口后重跑 Set Up
MCP 启动即退出 检查 command、server.py、EVOVERSE_HOME 和 JSON 转义；打开 MCP Output
MCP 有 server 但没有 tools 重启 server，确认运行的是 VSIX 解出的 server.py，检查 Python stderr
Chat 不遵循 RTL 规则 检查 .github/copilot-instructions.md、RTL instruction、Customizations/Diagnostics 和 applyTo glob
Build 找不到 Efinity 检查 evoverse.efinityPath 指向安装根而不是 bin，确认 setup 脚本存在
IP Manager 启动失败 检查 Java 64 位版本、PATH 和 Efinity 版本要求
仿真找不到可执行文件 检查 evoverse.simulator，并让对应路径直接指向包含 iverilog/vvp 或 vlib/vlog/vsim 的目录
找不到 FPGA/FTDI 检查 USB 数据线、驱动、udev/Zadig、板卡供电和 JTAG 模式
AI 显示 model unavailable 显式设置准确 evoverse.model.modelId，检查授权或端点模型名称
Remote/WSL 中 MCP 路径无效 MCP 在配置所在环境运行；使用远端 Python 与远端文件路径
