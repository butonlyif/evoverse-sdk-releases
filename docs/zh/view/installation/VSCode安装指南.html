VS Code 安装差异

EvoVerse SDK：VS Code 安装指南

适用版本：v1.0.0　更新日期：2026-10-16　宿主：Visual Studio Code Stable

上手链路总览

从拿到发布包到开始第一个设计，主线是 6 步：

flowchart LR
    A[获取发布包] --> B[安装 3 个 VSIX]
    B --> C[重启 VS Code]
    C --> D[首启引导<br>确认工作区]
    D --> E[Welcome 自动打开]
    E --> F[Sync Catalog]
    F --> G[MCP / Workbench 开工]

每步的验证方式见对应章节。VS Code 下的差异在于 Agent 生态：Trae 用内置 Chat 的 @evoverse，VS Code 用原生 Chat Agent + EvoVerse MCP（见 §10）。

1. 前置条件

项目 要求 说明
操作系统 Windows 10/11 64 位（首选）；Ubuntu 20.04+；RHEL 8.8+ macOS 不能作为完整的 Efinity 编译/烧录工作站
Python 64 位 3.11+ CLI 与 MCP Server 只用标准库，无需 pip 装包
Git 在 PATH 中 EvoVerse: Sync Catalog 拉取板卡目录依赖 Git
Efinity 2026.1+ 真实编译、烧录时需要
仿真器 Icarus Verilog RTL 功能仿真；QuestaSim 也可
硬件 FPGA 核心板 + USB 数据线 清单见 §2

电脑配置建议：8 核 CPU、16 GB 内存（较大工程 32 GB）、30 GB 以上 SSD 可用空间、2 个以上 USB 口。

2. 硬件准备

  1. EvoVerse/Efinix FPGA 核心板（例如 Catalog 中的 ws-e1）；
  2. 匹配的底板 / Carrier / 客户自研板；
  3. 符合板卡规格的电源——不要凭接口外形猜测电压和极性；
  4. 可传输数据的 USB 线——只充电线不能用于 JTAG/串口；
  5. 板载 FTDI 调试接口，或 FT2232H/FT4232H JTAG 模块；
  6. 需要串口日志时，备板载 USB-UART 或独立 3.3 V USB-UART；
  7. 传感器 / MIPI / 显示 / 网络外设按需。

不要在未知 I/O 电压、JTAG 电平或供电方向的情况下连接自研板；连接前阅读 Catalog 中的板卡规格：

~/evoverse-sdk/catalog/boards/<board-id>/<board-id>.md
~/evoverse-sdk/catalog/boards/<board-id>/docs/

3. 安装基础软件

3.1 安装 Visual Studio Code

  1. 从 VS Code 官方下载页安装 Stable 64 位版本；
  2. Windows 推荐 User Installer，勾选「添加到 PATH」和资源管理器「Open with Code」。

验证：终端执行 code --version 能返回版本号；找不到 code 时重开终端或重装并启用 PATH。

3.2 安装 Python 3.11+

  1. 从 Python 官网安装 64 位 Python 3.11 或更新版本；
  2. 勾选 Add Python to PATH。

验证：

py -3 --version     # Windows
python3 --version   # Linux

输出必须是 3.11 或更高。版本不足时首启引导会报 SYSTEM_PYTHON_MISSING，Python 相关能力被禁用。客户 VSIX 不需要 Node.js / npm。

3.3 安装 Git

从 Git 官网安装（Windows 默认选项含 Git Credential Manager）。验证：git --version 能返回版本号。

3.4 安装 Efinity 2026.1+

  1. 从 Efinix Support Center 获取与目标器件和许可证匹配的安装包，按官方指南完成安装与许可证配置；
  2. Windows 安装 Microsoft Visual C++ 2022 x64 Runtime；部分 IP Manager（例如 Sapphire SoC）还需要 64 位 Java 8 或 11；
  3. Linux 按官方要求安装 GUI 库和 Java，并确保 Java 在 PATH；
  4. 记录 Efinity 根目录（例如 C:\Efinity\2026.1）。

验证：根目录下存在：

bin/setup.bat             # Windows
bin/setup.sh              # Linux
bin/efx_run.bat 或 efx_run.py
bin/efinity.exe 或 bin/efinity

EvoVerse 每次运行工具时会调用 Efinity 的 setup 脚本建立子进程环境，无需永久修改 PATH。

3.5 安装 FPGA USB/JTAG 驱动

  • Windows：按板卡用户手册与 Efinity 安装指南使用 Zadig/指定驱动；不要盲目替换复合 FTDI 设备的所有接口，先确认板卡文档要求的 interface；
  • Linux：断开板卡后执行 sudo <EFINITY_HOME>/bin/install_usb_driver.sh，重载 udev 规则后重新连接板卡。

3.6 安装 Icarus Verilog

  • Windows：安装预编译版本并加入 PATH；
  • Linux：sudo apt install iverilog。

验证：iverilog -V 与 vvp -V 均能输出版本号。

3.7 可选：RISC-V 软件工具链

仅使用 Sapphire/RISC-V SoC 时需要：xPack GNU RISC-V Embedded GCC、GDB、Efinity 生成的 BSP、Cortex-Debug 插件和板卡调试器配置。可在 VS Code 中执行 EvoVerse: Download & Install RISC-V Toolchain 自动安装，或手动安装后设置 evoverse.riscvToolchainPath。

4. 获取发布包

  1. 拿到客户交付包 EvoVerse-SDK-v1.0.0.tar.gz；
  2. 在包所在目录完整解压（Windows 10 1803+ 自带 tar，不会出现 zip 解压的路径过长报错）：
tar -xzf EvoVerse-SDK-v*.tar.gz

验证：解压目录下能看到 deploy.ps1 / deploy.sh 与 3 个 .vsix。START-HERE.md 和 docs/site/customer-portal.html 是入口文档。

5. 安装 3 个 VSIX

v1.0.0 交付 3 个同版本扩展：

VSIX 作用 是否必装
evoverse-sdk-1.0.0.vsix SDK 核心：Welcome、Catalog、Workbench 外壳、CLI / MCP 必装
evoverse-efinity-adapter-1.0.0.vsix Efinity 编译 / 时序 / 调试 / 烧录 / IP FPGA 开发必装
evoverse-rk3588-adapter-1.0.0.vsix RK3588 软件验证闭环 做 RISC-V 软件时安装

三个 VSIX 版本必须一致；混用不同版本不受支持。

5.1 方式 A：一键部署（推荐）

在解压后的包目录打开 PowerShell：

.\deploy.ps1 -Target vscode

macOS / Linux：

./deploy.sh --target vscode

脚本按依赖顺序安装 Core 与两个 Adapter；可选 Adapter 在包内缺失时跳过并提示。Skill 不复制进 VS Code 宿主目录：8 个 Skill 经 VSIX 的 chatSkills 声明提供给 Copilot Chat（agent 模式按需加载，需已安装 Copilot Chat 扩展）；需要 Skill 内容时，也可让 Agent 直接读取交付包内的 Skills/<skill-name>/SKILL.md 作为指令执行；MCP 控制面工具已由 SDK 写入用户级 mcp.json，不受影响。Video Sim 已内嵌于 Core VSIX，无需单独安装。

5.2 方式 B：命令行 / 扩展面板手动安装

code --install-extension D:\packages\evoverse-sdk-1.0.0.vsix
code --install-extension D:\packages\evoverse-efinity-adapter-1.0.0.vsix
code --install-extension D:\packages\evoverse-rk3588-adapter-1.0.0.vsix

或在扩展面板点右上角 ... → Install from VSIX... 逐个选择。

5.3 推荐同时安装的扩展

扩展 用途 是否由 EvoVerse 声明为依赖
GitHub Copilot VS Code 原生 Chat Agent、VS Code MCP 和 vscode-lm 否，使用原生 Chat Agent 时安装并登录
VaporView 打开仿真生成的 VCD 波形 是
Cortex-Debug RISC-V/MCU GDB 调试 是
Verilog/SystemVerilog 语言插件 语法高亮、跳转和 lint 否，按客户许可与团队标准选择

离线环境需要管理员预先准备依赖插件的 VSIX；Marketplace 不可访问时，EvoVerse 主 VSIX 不会替客户下载依赖插件。

6. 重启 VS Code 并完成首次引导

  1. 重载 VS Code（Developer: Reload Window 或重启），让扩展激活；
  2. 首次激活时弹窗 "Set up EvoVerse SDK?"，选择 Yes, set up。引导会在默认工作区 ~/evoverse-sdk 建立 Catalog、工程与运行时目录（可用 evoverse.home 修改路径），不修改系统文件；
  3. 观察 Output → EvoVerse SDK，引导逐项输出，全部为 ✓ 后出现 === EvoVerse SDK ready ===：
  4. EVOVERSE_HOME ready at …——工作区就绪；
  5. Deployed Efinity knowledge base——知识库部署；
  6. MCP integration: …——把 servers.evoverse 合并进 VS Code 用户级 mcp.json（Windows 为 %APPDATA%\Code\User\mcp.json；已存在的其它 server 条目不变，覆盖前备份为 mcp.json.evoverse.bak）；
  7. CLI works: …——CLI 冒烟测试；
  8. Git 不在 PATH 时会有 ! git not found 警告，装好 Git 后 Sync Catalog 才可用；
  9. Python 缺失或版本不足时报 SYSTEM_PYTHON_MISSING，装好 Python 3.11+ 后重跑引导；
  10. 完成提示出现后选 Restart now 重载窗口。

验证：重启后 Welcome 页自动打开。没有自动打开时，命令面板执行 EvoVerse: Show Welcome（evoverse.welcome）。

弹窗当时选了 Later、或需要重跑引导时，执行 EvoVerse: Set Up (re-run bootstrap)（evoverse.setup）。标准 VS Code 不会创建或写入 ~/.trae；企业策略锁定配置目录导致 MCP 自动注册失败时，按 §10.2 手动合并。

7. 同步 Catalog

首次安装时 Catalog 为空，界面与 MCP 报 CATALOG_NOT_INSTALLED，这是预期状态，不是故障。

  1. 运行 EvoVerse: Sync Catalog（evoverse.syncCatalog）。同步默认拉取官方公开发布仓库（evoverse-catalog-release），无需 GitHub 账号；GitHub 不可达（网络错误）时自动改从 Gitee 国内镜像抓取同一发布，回执记录实际使用的仓库；同步以 treeDigest 校验完整性后事务化切换本地版本；
  2. 运行 EvoVerse: Catalog Status（evoverse.catalogStatus），或终端执行 evoverse catalog status --json，记录 catalogVersion、commit、treeDigest。

如需改用自建镜像或私有仓库，可用 evoverse sync --repository <URL> 或环境变量 EVOVERSE_CATALOG_REPOSITORY 覆盖仓库地址。

验证：Welcome 页 Board Catalog 面板能列出板卡（如 ws-e1）。同步失败不影响已有本地内容，修复网络后重新同步即可。

8. 验证安装

  1. 左侧活动栏能打开 EvoVerse；
  2. Workbench 能显示已安装的 Adapter；
  3. 运行 EvoVerse: Health Check（evoverse.sdkHealthCheck），确认 Python / Efinity / MCP / 仿真器 / CLI / Adapter 各项通过（Welcome 页也有 SDK 体检面板）；
  4. 按 §10 完成 Settings、MCP、项目规则与模型配置。

9. 配置 Settings 与环境变量

9.1 Settings

打开 Settings 搜索 evoverse，或在用户 settings.json 中填写（路径换成客户机器真实路径）：

{
  "evoverse.home": "D:\\EvoVerse",
  "evoverse.pythonPath": "C:\\Users\\<user>\\AppData\\Local\\Programs\\Python\\Python312\\python.exe",
  "evoverse.efinityPath": "C:\\Efinity\\2026.1",
  "evoverse.simulator": "iverilog",
  "evoverse.iverilogPath": "C:\\iverilog\\bin",
  "evoverse.build.parallelJobs": 4,
  "evoverse.build.autoOpenReport": true,
  "evoverse.program.defaultMode": "jtag"
}

Linux 示例：

{
  "evoverse.home": "/home/<user>/evoverse-sdk",
  "evoverse.pythonPath": "/usr/bin/python3",
  "evoverse.efinityPath": "/opt/efinity/2026.1",
  "evoverse.simulator": "iverilog",
  "evoverse.iverilogPath": "/usr/bin"
}

evoverse.iverilogPath 直接指向包含 iverilog 和 vvp 的目录。使用 QuestaSim 时：

{
  "evoverse.simulator": "questa",
  "evoverse.questaPath": "C:\\questasim64_2024.1\\win64"
}

evoverse.questaPath 必须直接包含 vlib、vlog 和 vsim。

9.2 环境变量

优先使用 evoverse.* Settings；只有 CLI、MCP 或企业部署需要跨进程共享路径时才设置系统环境变量。

变量 是否必须 用途
EVOVERSE_HOME MCP 推荐 Catalog 和工程根目录
EVOVERSE_CLI MCP 推荐 EvoVerse CLI 绝对路径
PYTHONUTF8=1 Windows MCP 推荐 保证中英文 JSON/日志使用 UTF-8
EFINITY_HOME 通常不必永久设置 Efinity 根目录；扩展会从 setting 建立子进程环境
PATH 按需 让终端直接找到 Python、Git、Icarus、Java、RISC-V GCC

Windows PowerShell 当前用户示例：

[Environment]::SetEnvironmentVariable('EVOVERSE_HOME', "$HOME\evoverse-sdk", 'User')
[Environment]::SetEnvironmentVariable('PYTHONUTF8', '1', 'User')

写入 shell profile 后必须重开 VS Code，使 MCP 子进程继承新环境。

10. 配置 Agent 工作方式

10.1 两个问答入口

VS Code 原生 Chat Agent 和 EvoVerse 内置 Conversation Runtime 是两套独立会话：

入口 模型配置 EvoVerse 工具来源 是否共享会话历史
VS Code 原生 Chat Agent VS Code Chat 模型选择器 VS Code 中配置的 EvoVerse MCP 否
EvoVerse Timing Diagnosis / Build AI evoverse.model.* 扩展内部上下文与工具链 否

推荐用原生 Chat Agent 执行写文件和终端命令，避免多个 Agent 同时自动修改同一工作区。原生 Chat Agent 不能直接充当 evoverse.model.provider；若要两个入口用同一宿主模型，原生 Chat 选定模型后把内置 Runtime 配成 vscode-lm。

10.2 EvoVerse MCP

§6 的首启引导已自动注册 MCP；本节是验证方法与手动兜底。

验证：重载后执行 MCP: List Servers：

  1. evoverse 状态为 Running；
  2. Tools 中能看到 list_boards、validate_manifest、check_rtl_code_style 等；
  3. 在 Chat Agent 模式提问「使用 EvoVerse 工具列出可用板卡」，结果应来自实际 Catalog 而不是模型记忆；
  4. MCP 出错时从 MCP: List Servers → evoverse → Show Output 查看日志。

手动兜底（自动注册未生效时）：先确认路径——

py -3 --version
Test-Path "$HOME\evoverse-sdk\mcp-server\server.py"
Test-Path "$HOME\evoverse-sdk\cli\evoverse"

在 MCP: Open User Configuration 打开的 mcp.json 中合并：

{
  "servers": {
    "evoverse": {
      "command": "py",
      "args": [
        "-3",
        "C:\\Users\\<user>\\evoverse-sdk\\mcp-server\\server.py"
      ],
      "env": {
        "EVOVERSE_HOME": "C:\\Users\\<user>\\evoverse-sdk",
        "EVOVERSE_CLI": "C:\\Users\\<user>\\evoverse-sdk\\cli\\evoverse",
        "PYTHONUTF8": "1"
      }
    }
  }
}

机器没有 py launcher 时，把 command 换成 python.exe 绝对路径并删掉 args 中的 -3。Linux 示例：

{
  "servers": {
    "evoverse": {
      "command": "/usr/bin/python3",
      "args": [
        "/home/<user>/evoverse-sdk/mcp-server/server.py"
      ],
      "env": {
        "EVOVERSE_HOME": "/home/<user>/evoverse-sdk",
        "EVOVERSE_CLI": "/home/<user>/evoverse-sdk/cli/evoverse",
        "PYTHONUTF8": "1"
      }
    }
  }
}

作用域选择：用户级（所有工作区可用，适合固定工作站）或工作区级（<project>/.vscode/mcp.json，适合团队共享，但不得提交用户名或绝对路径）。Remote/SSH/WSL 下 MCP 在配置所在环境运行，必须用远端路径和远端 Python。不要把模型 API Key 写入 mcp.json。首次调用工具时由客户确认授权，不要开启不受限制的自动批准。

10.3 项目规则与工程指令

在 Chat 中用自然语言描述新建或接管工程；Agent 通过 Workbench Control 的 project_next envelope 展示当前动作，确认后执行。工程建立时会从正式规则资产生成 VS Code 指令：

~/evoverse-sdk/agent-rules/rules.md
~/evoverse-sdk/agent-rules/rules-rtl-style.md

生成 .github/copilot-instructions.md 与 .github/instructions/rtl.instructions.md。VS Code 官方支持这三类文件（copilot-instructions.md、根目录 AGENTS.md、instructions/*.instructions.md），详见 Use custom instructions in VS Code。

已有工程（不经过新建流程）可手动生成：

New-Item -ItemType Directory -Force ".github\instructions" | Out-Null
Copy-Item "$HOME\evoverse-sdk\agent-rules\rules.md" ".github\copilot-instructions.md"
$header = "---`nname: EvoVerse RTL rules`ndescription: Mandatory RTL, CDC, reset and verification rules`napplyTo: `"**/*.{v,sv,vh,sdc}`"`n---`n`n"
$header + (Get-Content "$HOME\evoverse-sdk\agent-rules\rules-rtl-style.md" -Raw) | Set-Content ".github\instructions\rtl.instructions.md" -Encoding utf8

Linux：

mkdir -p .github/instructions
cp "$HOME/evoverse-sdk/agent-rules/rules.md" .github/copilot-instructions.md
printf '%s\n' '---' 'name: EvoVerse RTL rules' 'description: Mandatory RTL, CDC, reset and verification rules' 'applyTo: "**/*.{v,sv,vh,sdc}"' '---' '' > .github/instructions/rtl.instructions.md
cat "$HOME/evoverse-sdk/agent-rules/rules-rtl-style.md" >> .github/instructions/rtl.instructions.md

生成后的关键审批边界包括：改 RTL 前先看 evoverse-project.md、约束与板卡/IP manifest；构建与仿真通过前不宣称时序收敛；未经明确批准不烧板、不应用优化候选。模型输出不能作为功能或时序正确性的证明。

确认 Settings 中：

{
  "chat.useAgentsMdFile": true,
  "chat.instructionsFilesLocations": {
    ".github/instructions": true
  }
}

在 Chat 的 Customizations/Diagnostics 中确认两份指令均已加载。自定义指令影响 Chat/Agent，不保证影响逐字 inline completion；最终仍以 EvoVerse 的确定性检查为准。

10.4 模型配置（Timing Diagnosis / Build AI）

宿主模型（vscode-lm）：安装并登录 GitHub Copilot → VS Code Chat 中确认目标模型可用 → Settings 设 "evoverse.model.provider": "vscode-lm" → 执行 EvoVerse: Select AI Model 从宿主实际返回的列表中选择（会保存准确 Model ID）→ 重载窗口。EvoVerse 不会静默选第一个模型；不知道准确 ID 就先用选择器确认，或改用 OpenAI-compatible。

自带 API Key（openai-compatible）：适用于 OpenAI、DeepSeek、智谱、MiniMax 或企业网关。要求服务支持 OpenAI Chat Completions 格式：

{
  "evoverse.model.provider": "openai-compatible",
  "evoverse.model.modelId": "<endpoint-model-id>",
  "evoverse.model.baseUrl": "https://<provider-host>/v1/",
  "evoverse.model.allowLocalHttp": false
}

配置步骤：

  1. 从服务商取得 API Key、Base URL 和准确 Model ID；
  2. 填上面三项；
  3. 执行 EvoVerse: Set OpenAI-compatible API Key，密钥写入 VS Code SecretStorage；
  4. 执行 Developer: Reload Window；
  5. 第一次问答时核对发送规模提示，选 Send。

baseUrl 只填 API 根路径，EvoVerse 自行追加 chat/completions。密钥不要放进 settings、MCP 或项目仓库。本地端点仅限 localhost/回环地址且显式打开 allowLocalHttp。常用服务：

服务 evoverse.model.baseUrl modelId 示例
OpenAI API https://api.openai.com/v1/ 账号实际可用的 OpenAI 模型 ID
DeepSeek https://api.deepseek.com/v1/ deepseek-chat
智谱 BigModel https://open.bigmodel.cn/api/paas/v4/ 账号实际可用的 GLM 模型 ID
MiniMax https://api.minimaxi.com/v1/ 账号实际可用的 MiniMax 模型 ID
企业聚合网关 企业提供的 HTTPS /v1/ 兼容根地址 网关公布的模型 ID

当前内置 Runtime 没有原生 Anthropic Messages API Provider。要用 Claude：在 vscode-lm 中选 VS Code 实际暴露的 Claude 模型，或走提供 OpenAI-compatible Chat Completions 的网关；不能把 Anthropic 原生 Base URL 填进本节配置。

验证：打开一个已成功构建、含时序报告的工程 → Toolchain: Diagnose Timing Violations → 点 Ask AI 确认流式返回 → 继续追问确认多轮上下文 → Build Report 点 询问 AI Agent 确认收到带构建摘要的回答。回答应引用当前报告的 WNS/TNS、时钟域或关键路径；模型建议只用于分析，不能替代仿真、CDC 检查和 Efinity 时序报告。

11. 开始使用

  1. 自然语言开工：在 VS Code 原生 Chat（Agent 模式）中直接描述需求，无需 @evoverse。Agent 让你选择 free/reliable，并通过 EvoVerse MCP 的 project_next envelope 逐步确认；@evoverse 仅为打开 Project Control 的兼容导航，不会接续原生 Agent、创建 Intent 或替你选择流程。没有原生 Chat Agent 时，可使用 Workbench 的 Project Control 下拉（evoverse.selectDesignFlow）；
  2. Workbench 六个 Tab：Home / Build / Timing / Debug / SW / IP；
  3. 编译：Build Tab 或 Toolchain: Build（evoverse.build）。Build 由 Efinity Adapter 执行 efx_run --flow compile，状态栏显示 Build: Ready / Running / Failed；
  4. 仿真：Toolchain: Simulate（evoverse.sim）；VCD 用 VaporView 打开；
  5. 时序诊断：Toolchain: Diagnose Timing Violations（evoverse.diagnoseTiming）；
  6. 烧板：Toolchain: Program FPGA（evoverse.program）。

日常开发全流程见用户使用手册。

12. 逐级验收

不要直接跳到烧录，按顺序每步通过再继续。

12.1 基础与 Catalog

  1. 打开 EvoVerse Activity Bar，确认 Board Catalog 中存在 ws-e1；
  2. 执行 EvoVerse: Show Knowledge Base 能打开知识库；
  3. 在 Chat 中描述最小工程目标，确认 project_next envelope 后创建工程；
  4. 确认工程有 evoverse-project.md、.github/copilot-instructions.md 和 .github/instructions/rtl.instructions.md。

12.2 规则与 MCP

  1. 打开一个 RTL 文件，执行 Toolchain: Check This File's Code Style；
  2. Chat 的 Customizations/Diagnostics 中确认规范文件已加载；
  3. MCP: List Servers 确认 evoverse Running，list_boards 结果来自实际 Catalog。

12.3 仿真

  1. 工程包含 testbench；
  2. 执行 Toolchain: Simulate，Output 中 iverilog 和 vvp 返回成功；
  3. 生成 VCD 时用 VaporView 打开，确认时钟、复位和输出行为。

12.4 Efinity 编译与时序

  1. 执行 Toolchain: Project Health Check，修复缺失 SDC、器件或源文件问题；
  2. 执行 Toolchain: Build (Full Flow)；
  3. Build Report 中确认资源、I/O/Clock、Timing 和 Critical Paths 可读取；
  4. 执行 Toolchain: Diagnose Timing Violations；AI 建议只作推断，WNS/TNS、CDC、仿真和构建结果才是验证证据。

12.5 烧录

  1. 板卡断电时确认跳帽、电压、JTAG 和启动模式；
  2. 连接电源与 USB 数据线；
  3. 在 Efinity Programmer 中先确认能枚举目标设备；
  4. 回到 VS Code 执行 Toolchain: Program FPGA；
  5. 显示 "no FTDI device" 时检查数据线、驱动、权限、Hub 和板卡供电。

12.6 可选 RISC-V

  1. 配置 Sapphire SoC IP 并从 Efinity 同步；
  2. 执行 Software: Sync BSP from SoC IP；
  3. 执行 Software: Build App…；
  4. 执行 Software: Program FPGA…；
  5. 确认 Cortex-Debug、GDB 和调试器路径后执行 Software: Debug App…。

13. 故障排查

症状 检查
Set Up 报 SYSTEM_PYTHON_MISSING 安装 Python 3.11+，或把 evoverse.pythonPath 指向解释器绝对路径，重载后重跑 Set Up
MCP 启动即退出 检查 command、server.py、EVOVERSE_HOME 和 JSON 转义；打开 MCP Output
MCP 有 server 但没有 tools 重启 server，确认运行的是 VSIX 解出的 server.py，检查 Python stderr
Chat 不遵循 RTL 规则 检查 .github/copilot-instructions.md、RTL instruction、Customizations/Diagnostics 和 applyTo glob
Sync Catalog 失败 确认 Git 在 PATH、网络可达；默认公开仓库无需 GitHub 账号；详见部署指南
Build 找不到 Efinity 检查 evoverse.efinityPath 指向安装根而不是 bin，确认 setup 脚本存在
IP Manager 启动失败 检查 Java 64 位版本、PATH 和 Efinity 版本要求
仿真找不到可执行文件 检查 evoverse.simulator，路径直接指向含 iverilog/vvp 或 vlib/vlog/vsim 的目录
找不到 FPGA/FTDI 检查 USB 数据线、驱动、udev/Zadig、板卡供电和 JTAG 模式
AI 显示 model unavailable 显式设置准确 evoverse.model.modelId，检查授权或端点模型名称
Remote/WSL 中 MCP 路径无效 MCP 在配置所在环境运行；使用远端 Python 与远端文件路径
