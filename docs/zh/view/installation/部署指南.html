客户安装与部署

EvoVerse SDK 客户安装与部署

适用 EvoVerse SDK v1.0.1 · 2026-11-28 适用 SDK 版本: v1.0.1

适用版本：v1.0.1　发布基线：2026-09-30　推荐宿主：Trae

适用对象

拿到客户交付 tar.gz 包，需要安装 EvoVerse SDK、Workbench Adapter 和可选 Video Sim 的最终用户。

你将完成什么

安装交付包中的扩展，运行首次设置，确认 Catalog、工具链和角色文档入口可用。

前置条件

  • Trae；标准 VS Code 也支持，但首次使用优先按 Trae 路线操作。
  • 64 位 Python 3.11+。
  • Git 在 PATH 中（EvoVerse: Sync Catalog 依赖普通 Git 同步）。
  • 需要真实 FPGA 编译、烧录时安装 Efinity 2026.1+。
  • 普通 RTL 仿真需要 Icarus Verilog 或 QuestaSim。

步骤

1. 解压并阅读入口

完整解压客户包后再运行脚本。在客户包所在目录执行：

tar -xzf EvoVerse-SDK-v*.tar.gz

Windows 10 1803+ 自带 tar，走长路径，不会出现 zip 解压的「路径太长」报错（也可用 7-Zip）。解压后打开 START-HERE.md 或 docs/site/customer-portal.html，确认可以看到三条角色路线。

2. 一键部署

在客户包目录运行跨平台 Python 入口（Windows / macOS / Linux 通用，包内自带 evoverse_release 模块，仅需系统 Python 3.11+，安装阶段完全离线）：

# 部署到 Trae CN（推荐宿主）
python deploy.py --host trae

# 或部署到 VS Code
python deploy.py --host vscode
  • --host trae|vscode 必填：显式指定宿主；双宿主并存时报错并列出探测结果，绝不静默二选一。
  • 部署幂等：重复执行结果一致；安装始终带 --force（Trae CN 对同版本号扩展会静默跳过替换）。
  • 安装事务（Skills 备份与回滚）：Skills 部署按「分类 → 备份 → 暂存 → 原子切换 → 提交」执行。只有当本包部署的 Skills 与新版存在差异（你改过或删除过文件）时才创建备份；全新安装与无差异重跑都不产生备份目录。无差异重跑不备份，改过的文件在覆盖前自动备份到 ~/.evoverse/backups/<时间戳>/（保留最近 5 份）。若切换或回滚中途失败（如文件被占用），Skills 目录会完整恢复到部署前状态；极少数情况下回滚也失败时，安装状态标记为 RECOVERY_REQUIRED，并在回执中给出可复制的恢复命令（Windows 为 Move-Item，macOS/Linux 为 mv）——按命令手工恢复后重新部署即可。
  • 装后落盘确认：每次安装命令成功返回后，部署器会检查宿主扩展目录确认 VSIX 实际落盘；IDE 正在运行导致未落盘时，回执 deploy-receipt.json 中出现醒目 warning——完全退出 Trae CN / VS Code 后重跑部署即可（幂等，可安全重复）。
  • 卸载：python deploy.py --host <宿主> --uninstall，按逆依赖序卸载（Adapter 先、SDK 最后），只清理本包部署的 Skills；默认保留你改过的 Skill 目录、备份目录与安装清单（防误删用户工作），确认不需要后用 --purge 一并删除（详见「卸载」一节）。

deploy.py 是客户包唯一的安装入口（旧的 deploy.ps1 / deploy.sh 兼容入口已移除）。

无论走哪个入口，都按依赖顺序安装 3 个 VSIX（Core、Efinity Adapter、RK3588 Adapter）和 Skills（两个 Adapter 为可选组件，包内缺失时跳过并提示）。Skills 装入 Trae 的 Skill 目录（Trae CN 为 ~/.trae-cn/skills），之后在对话中用 /skill-name 斜杠调用；VS Code 目标不复制 Skill 目录，Skill 经 VSIX 的 chatSkills 声明提供给 Copilot Chat（agent 模式按需加载，需已安装 Copilot Chat 扩展），也可让 Agent 直接读取交付包内的 Skills/<skill-name>/SKILL.md。Video Sim 已内嵌于 Core VSIX，无需单独安装。若客户策略禁止脚本安装，可在 Trae 的扩展面板按相同顺序选择 Install from VSIX…。

2.1 退出码与行为变化

Python 交付链相对旧脚本收紧了三处退出语义（其余退出码不变：0 成功，1 阶段失败，2 用法错误）：

场景 旧 deploy.ps1/.sh、release-package.* Python 交付链（deploy.py / release.py）
宿主 CLI 缺失（HOST_CLI_MISSING） 提示后按成功结束 exit 1——未安装即为失败（blocked 语义），不再伪装成功
--version 与版本真值不符 静默覆盖版本号 exit 1（VERSION_OVERRIDE_MISMATCH）——版本真值是唯一事实来源
发布部分成功（GitHub 主仓成功、Gitee 镜像失败） —（无此状态） release.py publish exit 3（PARTIAL_SUCCESS：GitHub 结果保留、镜像落后并给出补齐命令）

2.2 交付矩阵证据边界

本版本按「语言（zh/en）× 操作系统 × 宿主 × 产品 × 动作」对交付矩阵做了逐组合认证，实测边界如下：

组合 build / package install / activate / uninstall
macOS（zh、en） PASS（2026-10-30 发布机实测：3 个 VSIX 构建、ZIP 与 tar.gz 双格式打包、逐件校验通过；SHA256 随包提供） NOT_RUN——需真实 IDE 发布机证据
Windows（zh、en） NOT_RUN——需 Windows 发布机；GitHub Actions 工作流（windows-latest + macos-latest × zh/en）已定义，首次运行尚未发生 NOT_RUN——同左
Linux（vscode 宿主） NOT_RUN——声明级目标（hostsByOs 中 Linux 仅支持 VS Code），暂无 Linux 构建机 NOT_RUN——同左

CI 工作流覆盖发布链单测、双语 build + package + verify 与交付脚本语法检查；install / activate / uninstall 永不在 CI 中执行——写入真实 IDE 的动作一律以发布机证据为准。

3. 首次设置

  1. 在命令面板运行 EvoVerse: Set Up (re-run bootstrap)。
  2. 等待 runtime 和宿主集成完成。首次安装时 Catalog 为空是预期状态，界面与 MCP 会报告 CATALOG_NOT_INSTALLED。
  3. Trae 提示重启时完全重启宿主，使 MCP 配置生效。
  4. 在设置中确认 evoverse.efinityPath 指向实际 Efinity 安装目录。

3.1 同步 Catalog

  1. 运行 EvoVerse: Sync Catalog。同步默认拉取官方公开发布仓库（evoverse-catalog-release），无需 GitHub 账号；GitHub 不可达（网络错误）时自动改从 Gitee 国内镜像抓取同一发布，回执记录实际使用的仓库；完成后写入回执 catalog-sync-receipt.json，记录 catalog_version 与 commit。
  2. 运行 evoverse catalog status --json，记录 state、location 与回执里的 catalog_version、commit。
  3. 网络失败时修复后重试；同步失败不影响本地现有 Catalog（官方条目才被覆盖，本地内容不动）。本地 catalog 目录损坏时，重新运行 EvoVerse: Sync Catalog 重建即可；工作区 .evoverse/catalog.json 指针文件记录受信物料根目录（catalogRoot）。
  4. 如需改用自建镜像或私有仓库，可通过命令 evoverse sync --repository <URL> 或环境变量 EVOVERSE_CATALOG_REPOSITORY 覆盖仓库地址。
  5. 长期离线环境可按《Catalog 物料与获取》的「离线使用」小节直接拷贝完整 catalog 目录。

4. 验证安装

  1. 左侧活动栏能打开 EvoVerse。
  2. Workbench 能显示已安装的 Adapter。
  3. Board Catalog 能列出当前 catalog 板卡。
  4. 命令面板能找到 EvoVerse: 和 Toolchain: 命令。
  5. 运行 EvoVerse: Health Check，确认 Python / Efinity / MCP / 仿真器 / CLI / Adapter 各项体检通过（Welcome 页也有 SDK 体检面板）。
  6. 打开客户门户，按所选角色进入第一个任务。

标准 VS Code 差异

  • 安装同一组 VSIX，不需要专用安装包。
  • 扩展不会写入 Trae 私有的 .trae 配置。
  • MCP 和模型能力按 VS Code 当前公开接口及客户环境配置；确定性仿真、编译和规则诊断不依赖 AI。
  • 详细步骤见 VS Code 安装指南。

成功标志

  • Core 与所需 Adapter 均处于 Enabled 状态。
  • Set Up 有明确完成结果，Output 中没有未处理错误。
  • 能打开客户文档门户、Catalog 和 Workbench。
  • 若尚未连接真实板卡，只能确认安装与入口可用，不能宣称烧录或硬件验证通过。

遇到问题

症状 处理
找不到 Python 安装 Python 3.11+，或设置 evoverse.pythonPath 为真实可执行文件
没有 EvoVerse 图标 在 Extensions 确认 Core 已启用，再查看 EvoVerse Output
Catalog 为空 / CATALOG_NOT_INSTALLED 运行 EvoVerse: Sync Catalog（默认走公开发布仓库，无需 GitHub 账号）
Trae Agent 看不到 MCP 完全退出 Trae 进程后重新打开
Build 找不到 Efinity 检查 evoverse.efinityPath，再运行工具链检测
Efinity 返回编译错误 按错误文本查询 常见编译错误排查
下载中断 / 校验不一致 每个发布资产都带同名 .sha256 校验文件：重新下载完整资产并用 shasum -a 256 <文件> 比对；截断的文件必然校验失败，绝不可安装。客户包内另有 SHA256SUMS 覆盖包内全部成员
已装扩展疑似过期或被改动 部署幂等且始终带 --force：重跑 python deploy.py --host <宿主> 即可整体替换，回执 deploy-receipt.json 可确认
IDE 重启后安装只完成一半 完全退出宿主后重开，再执行同一条部署命令——重复执行收敛到同一安装状态

卸载

# 标准卸载：卸载 3 个 VSIX；未改动的 Skill 目录被删除
python deploy.py --host <宿主> --uninstall

# 连同你改过的 Skill 目录、安装清单一并删除（不可恢复，确认后再用）
python deploy.py --host <宿主> --uninstall --purge

# 只额外删除备份目录（仅删除有效的备份，无效目录不动）
python deploy.py --host <宿主> --uninstall --purge-backups

保留语义（本包只管理 Skills，范围不含扩展设置与客户工程）：

内容 标准卸载 --purge --purge-backups
未改动的 Skill 目录 删除 删除 不变
你改过的 Skill 目录 保留（回执中状态为 kept） 删除 不变
备份目录 ~/.evoverse/backups/ 保留 保留 删除（有效的）
安装清单 ~/.evoverse/install/<宿主>.install-manifest.json 保留 删除 不变
  • --purge / --purge-backups 只能与 --uninstall 同用，否则报用法错误。
  • 找不到安装清单时（例如手工删过 ~/.evoverse/install/）卸载走保守路径：Skill 目录一律保留并在回执中提示，绝不凭猜测删除。
  • 卸载扩展不会自动删除客户工程和 evoverse.home 下的数据；确认不再需要后再手工处理用户数据。
