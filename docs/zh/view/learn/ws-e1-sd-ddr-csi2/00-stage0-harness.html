00 建立 Stage0 物理 Harness

阶段 00 · 建立工程 Harness（Stage0）

目标器件：WS-E1 核心模组 TJ180A484S，C4 timing model。本阶段把一个空目录变成控制面管辖的受管工程，作为后续所有阶段的物理与流程基线——它也是第一轮增量意图（SD 输入）的父基线。

SD card -> DDR frame buffer -> MIPI CSI-2 TX 这条数据链路的每一环，最终都要落到 TJ180A484S 的物理引脚和时钟资源上。所以第一步不是写 RTL，而是声明工程身份：板卡、载板、夹克、器件与速度等级。这一步在控制面里对应 project.initialize 动作。

准备环境

先装 IDE，再开工程。三步：

  1. 安装三个 VSIX：evoverse-sdk、evoverse-efinity-adapter、evoverse-rk3588-adapter（版本一致，当前为 1.0.0），装完重启 IDE。
  2. 首次启动会弹出 "Set up EvoVerse SDK?"，确认 SDK 工作区（默认 ~/evoverse-sdk）；确认后 Welcome 页自动打开。
  3. 在 Welcome 页点一次 Sync Catalog 同步板卡目录，然后按宿主开始：Trae：在聊天里输入 @evoverse；VS Code：在原生 Chat 的 Agent 模式直接描述目标，无需 @evoverse，并确认 EvoVerse MCP 为 Running。Workbench 的 Project Control 下拉（evoverse.selectDesignFlow）只负责图形导航。
flowchart LR
    A["安装三个 VSIX<br>SDK + Efinity/RK3588 Adapter"] --> B["重启 IDE<br>确认工作区 ~/evoverse-sdk"]
    B --> C["Welcome 页<br>Sync Catalog"]
    C --> D["Trae: @evoverse<br/>VS Code: 原生 Agent"]

注意：~/evoverse-sdk 是 SDK 工作区，不是本教程的工程根。下一步打开的是一个空目录，Stage0 在那里建工程。

你对 Trae 说什么

打开一个空目录作为工程根，在 Trae Chat 里说：

用 @evoverse 在当前空目录建一个 EvoVerse 工程（VS Code 原生 Agent 中去掉开头的 @evoverse）。板卡选 ws-e1 / ws-e1-base，
我的硬件是一块 WS-E1 核心模组（TJ180A484S）插在 ws-e1-base 底板上，
目标是做一条 SD card -> DDR frame buffer -> MIPI CSI-2 TX 的显示链路。
动手之前，先把要写入的工程身份（板卡、载板、器件、速度等级）讲给我听；
我确认后再初始化，并把初始化回执解释给我。

Trae 会帮你做什么

  1. project_status 确认当前目录还不是受管工程（没有 revision、没有 Baseline）。
  2. project_next 读取服务端 envelope，确认 recommendedAction.actionId 是 project.initialize，并核对 expectedRevision。
  3. 向你复述将写入的工程身份：board（ws-e1）、carrier（ws-e1-base）、jacket、器件 TJ180A484S、timing model C4。
  4. 你确认后提交 project_execute（actionId 为 project.initialize），拿到初始化回执与新 revision。
  5. 重新读取 project_next，向你展示新 revision、Baseline 区已建立和下一推荐动作；不按本地清单自行推进。

你需要确认什么

  • 板卡 / 载板 / 夹克组合是否就是你手上的硬件：WS-E1 模组（TJ180A484S）插在 ws-e1-base 底板上。
  • 器件与速度等级：Titanium Ti60、C4。速度等级写错会在后续编译时序模型上整体偏离。
  • 工程根目录确实是空目录或只含你自己的笔记；不要把别的工程文件混进来。

如果不顺利

现象 怎么处理
重启后没有弹出 "Set up EvoVerse SDK?" 在命令面板执行 evoverse.setup 手动触发；仍无反应就检查三个 VSIX 是否都装上并已启用。
Welcome 页没有自动打开 在命令面板执行 evoverse.welcome 打开；目录没同步过时先别急着对话。
Sync Catalog 失败或很慢 多为网络原因，重试一次即可；完成后用 evoverse catalog status --json 确认目录版本。不要跳过同步硬选板卡。
提示"工程目录非空"拒绝初始化 换一个空目录，或把已有文件挪走——控制面不接管来历不明的文件。
初始化半天没动静 问一句"初始化到哪一步了"；不要重发提示词，重复初始化只会制造对账负担。

通过条件

  • project_status 返回的 revision 非零，工程身份（board / carrier / jacket / device / timing model）与你的硬件一致。
  • project_next 不再以"project is not initialized"阻塞后续动作。
  • 你能说出工程根在哪里、Baseline 区是什么状态。
  • 你能说出第一轮增量（SD 输入）的父基线就是本阶段建立的初始基线：阶段 03 的 intent.create 会把它快照进 baseBaselineFiles。
  • 后续所有阶段（包括最终 efx_run --flow compile）都将发生在这个受管工程内，而不是散落的临时目录里。

完成后进入 阶段 01：物料分析。
