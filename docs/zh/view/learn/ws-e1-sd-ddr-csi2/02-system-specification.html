02 冻结规格

阶段 02 · 冻结规格（差量规格与等级决策）

物料账本把自研空白区拆成了三轮增量（SD 输入、DDR 缓冲、CSI-2 输出），合起来覆盖整条 SD card -> DDR frame buffer -> MIPI CSI-2 TX 显示链路。本阶段讲清两件事的机制：仿真等级怎么选、差量规格怎么冻结，并以第一轮增量（SD 输入）为例完整走一遍——spec.draft → spec.approve。规格未批准之前，控制面不会允许任何候选交付；后两轮增量会在阶段 03 各自重复等级与规格决策。

规格是可靠设计流程的合同：后续 candidate.deliver 的候选会按它的摘要校验，verification.simulate 的证据会绑定到它的版本。差量规格的对照物是父基线——第一轮的父基线是 Stage0 初始基线，后两轮的父基线是上一轮的晋级结果。写得不完整，后面每一步都会被阻塞回来。

第一轮增量的完整决策链如下：

flowchart TD
    A["提取本轮风险事实<br>SD 握手 / 写端口背压 / CDC"] --> B["simulation.profile.select<br>提交 riskFacts"]
    B --> C["服务端按固定风险规则<br>给出推荐等级"]
    C --> D{"用户选择等级"}
    D -->|低于推荐| E["填写 acceptedRisks"]
    E --> F["spec.draft<br>按所选等级预算起草差量规格"]
    D -->|推荐及以上| F
    F --> G["spec.approve<br>冻结规格并生成摘要指纹"]

你对 Trae 说什么

开始第一轮设计：在我的 WS-E1 板子（TJ180A484S）上做 SD 卡读入并写入 DDR 帧缓冲。
先告诉我这一轮需要什么仿真等级：
它涉及 SD 协议握手和帧缓冲写端口的背压，把推荐等级和会延后验证的事项讲给我听，
等级我来定。定完之后按物料清单起草这一轮的规格，只覆盖 SD 写入路径；
遇到行为有分歧的地方（比如 SD 卡初始化超时怎么处理）给我几个选项让我拍板，
别替我决定。确认后冻结。

Trae 会帮你做什么

  1. project_status 确认规格区为空或存在草稿，project_next 确认 simulation.profile.select 与 spec.draft 可用。
  2. 等级先于规格：从本轮增量提取风险事实（SD 协议握手、写端口背压、CDC），提交 simulation.profile.select 的 riskFacts；控制面按固定风险规则给出推荐。对 SD 输入增量，推荐通常是 FPGA_INTEGRATION：协议握手、背压与数据不丢失是阻塞义务，主观画质和长时间全量回归可以延期。用户选择等级后（低于推荐最低等级需要填写 acceptedRisks），规格按所选等级的预算编写——场景数量、Oracle 与覆盖项从源头受控，超出预算时控制面会要求重新确认。
  3. 按物料账本起草差量规格：SystemSpec 增量、本轮自研模块的 ModuleSpec、MaterialContract（引用账本材料）、接口契约、场景与 Oracle、验收 Property 与覆盖项；与父基线复用部分的边界逐条写清。
  4. 遇到行为歧义（如 SD 卡初始化超时策略），生成结构化 DecisionRequest：2-3 个互斥选项 + 推荐理由，交给你选择。
  5. 你选定后提交 project_execute（spec.draft），再以 spec.approve 冻结。
  6. 重新 project_status，展示规格摘要与摘要指纹（digest）——本轮候选与证据都挂在这个指纹下。

你需要确认什么

  • 仿真等级由你本人选择：AI 只按固定风险规则推荐并解释预计阻塞验证与延期事项；recommendedProfile 等字段由服务端计算，Agent 不得代填，也不存在"AI 自动选择等级"。选择低于推荐最低等级时，必须写下你接受的具体风险（acceptedRisks）。等级绑定在各自的设计迭代上，三轮增量各自决策，互不继承。
  • 不得选择、复制或快照 sd-ddr-csi2 工程目录作为规格来源；规格必须出自你的物料账本与你的决策。允许选择其他 Demo 材料作为物料，但它们的结论只能进 MaterialContract，不能直接变成你的设计。
  • 每个决策项都由你本人拍板：控制面不接受从自然语言推断出的"默认批准"。
  • 验收场景可执行：每一个验收 Property 都能在阶段 03 的仿真里跑出 pass/fail，而不是一句"看起来对了"。规格中的场景要标注验证角色（reset / main-flow / critical-boundary / integration-smoke / protocol / cdc / fifo / numeric-boundary 等），仿真按等级选阻塞范围。
  • 差量规格对照父基线：哪些文件复用、哪些新增、哪些修改，逐条可辨认——这是后面 candidate.promote 合并的依据。
  • 时钟方案符合 Efinity 约束：PLL 在 ISF 中创建、无分频时钟驱动逻辑、异步域有同步器——这些会写进规格的物理约束节。

如果不顺利

现象 怎么处理
推荐等级比预想高 可以选低一档，但要把 acceptedRisks 逐条读过再确认——你签收的是"延后验证什么"。
规格草稿被打回要求补充 这是控制面的正常保护：写得含糊的规格会在候选交付和仿真时反复阻塞你，现在补最便宜。
决策选项都不合意 让 Trae 补齐每个选项的差异说明和后果再重新起草；也可以直接描述你的策略，请它生成新选项。
卡在等级决策不动 问"还缺哪些风险事实"；推荐来自服务端固定规则，事实齐了自然会给。

通过条件

  • simulation.profile.select 的用户选择已在控制面状态里可见（selectedBy: user），spec.draft 不再被 SIMULATION_PROFILE_REQUIRED 阻塞。
  • spec.approve 回执在控制面状态里可见，第一轮（SD 输入）差量规格从 draft 进入 approved。
  • 规格摘要指纹已生成，project_next 的候选动作不再被"an approved specification exists"阻塞。
  • 你能指认：本轮模块清单、每个模块的接口契约、验收场景与 Oracle 的位置、所选仿真等级与延期清单、相对父基线的新增/修改清单。
  • 后续 efx_run --flow compile 的 SDC/ISF 约束需求已在规格物理节中有对应条款。

完成后进入 阶段 03：生成 RTL 并交付候选。
