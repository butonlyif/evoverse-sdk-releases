03 生成 IP 与受控 RTL

阶段 03 · 按模块生成与独立仿真

适用 EvoVerse SDK v1.0.1 · 2026-11-28

规格冻结后，三个模块切片各自生成候选、做 Design Assurance 规划、跑对应等级的仿真，然后各自收敛。它们可以并行推进，也可以先后推进；关键是每个模块只对自己的 ModuleSpec 与接口契约负责，失败只回退该模块，不牵连另外两个。整条 SD card -> DDR frame buffer -> MIPI CSI-2 TX 链路的证据仍挂在同一份规格摘要下，最终仍需通过 TJ180A484S 上的原生 efx_run --flow compile。

模块生成的边界如下——所有动作都由 Agent 在“生成与收敛”阶段完成，你不需要逐个模块下达控制面动作：

flowchart TD
    A["sd_host<br>候选 + 仿真"] --> D{"契约通过？"}
    B["frame_buffer_writer<br>候选 + 仿真"] --> E{"契约通过？"}
    C["csi2_tx<br>候选 + 仿真"] --> F{"契约通过？"}
    D -->|否| A
    E -->|否| B
    F -->|否| C
    D -->|是| G["芯片内 composition"]
    E -->|是| G
    F -->|是| G
    G --> H["整链集成检查"]

失败的候选不能原地补丁：候选一旦交付就冻结，修复必须重新生成候选并重新仿真。这样你获得的不是“某次本地改动后看起来能跑”，而是一条可复现、可审计的证据链。

你对 Trae 说什么

开始按模块生成。先用我批准的规格并行推进 sd_host、frame_buffer_writer、csi2_tx：
每个模块独立生成候选、做 Design Assurance、按规格里的仿真等级跑验收场景。
哪个模块失败就只修哪个模块、只重新仿真哪个模块，不要把三个模块绑在一起重来。
三个模块都通过自己的接口契约后，再做芯片内 composition 和整链集成检查。
每一步告诉我用了哪个仿真等级、哪些场景 pass、哪些 fail；失败时把根因指到规格或候选，而不是只说“再试一次”。

Trae 会帮你做什么

  1. 从冻结规格的摘要指纹下展开三个模块任务：各自的候选生成、Design Assurance 规划、仿真注册与证据交付。
  2. 每个模块只读自己的 ModuleSpec 与接口契约；模块之间不共享内部实现细节。
  3. 按阶段 02 所选等级执行验收场景；每个场景 pass/fail 都写进证据，incomplete 不会被当作 PASS。
  4. 失败时定位到规格歧义、候选实现或测试环境，并只重跑该模块的候选与仿真。
  5. 三个模块的契约证据齐备后，执行芯片内 composition 与整链集成检查，把顶层连接、时钟域、复位和只读 IP wrapper 一起验一遍。

你需要确认什么

  • 仿真等级已由你在阶段 02 选定；本阶段不再为每个模块重复选择。若某模块的失败证明当前等级不足，回到规格决策处理，不要在 RTL 里“顺手加个仿真”。
  • 失败恢复：候选冻结 + 重新生成 + 重新仿真。任何“直接改已交付候选”的做法都会破坏证据绑定。
  • 规格升级：例如把 DDR 缓冲深度从 2 行改为 4 行，只有 frame_buffer_writer 的规格与仿真证据失效；sd_host 与 csi2_tx 的契约没变，证据继续有效；composition 整链证据需要重跑。正确做法是只重跑受影响节点，而不是整条链路重来。
  • 三个模块都达到契约后，composition 只负责连接与集成检查，不替任何模块补功能。

如果不顺利

现象 怎么处理
某一模块反复 FAIL 先区分是规格歧义、候选实现问题还是测试环境；连续失败两次就停止盲目重试，回到规格或问根因。
三个模块一起重跑 说明证据被错误耦合；要求按模块隔离，只重跑失败模块。
仿真 PASS 但覆盖率或场景明显缺失 指出缺哪个验收场景或覆盖项；规格里的 Oracle 才是判据。
composition 后整链失败，而三个模块单独都过 回到接口契约与顶层连接检查；不要用“在顶层打个补丁”掩盖契约问题。
规格升级后全部证据被清空 这是过度失效；按“只重跑受影响节点”的原则纠正，保留无关模块的既有证据。

通过条件

  • 三个模块各自的候选、Design Assurance 结论与仿真证据可见，且都挂在规格摘要指纹下。
  • 每个模块都能指出“接口契约是什么、验收场景有哪些、用什么仿真等级、结果如何”。
  • 失败恢复遵循“候选冻结、重新生成、重新仿真”，没有对已交付候选打补丁。
  • 规格升级演练（如改缓冲深度）只让受影响模块与 composition 证据失效，无关模块证据保留。
  • 芯片内 composition 后的整链集成检查有明确结论；没有硬件时，整链证据停在可执行的边界，不会写成 HARDWARE_VERIFIED。
