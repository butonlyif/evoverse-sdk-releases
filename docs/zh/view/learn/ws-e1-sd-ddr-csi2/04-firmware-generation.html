04 Sapphire 固件

阶段 04 · Sapphire 固件

SoC 里的 RISC-V 要跑起来，得先有固件。本阶段在 Sapphire 裸机环境生成软件工程与 BSP，把软件候选送进同一个控制面，并明确硬件/软件契约的交接边界。

SD card -> DDR frame buffer -> MIPI CSI-2 TX 链路跑在 TJ180A484S 上，固件负责 SD 卡初始化、FAT 读取与帧缓冲灌注的调度。它编译在 Sapphire SoC 上，但它的证据和 RTL 一样进控制面：编译成功只是 SW_BUILT，不等于功能正确。

固件的证据边界如下图——SW_BUILT 之后的每一步都换一种证据，不能互相顶替：

flowchart TD
    A["三轮增量全部<br>candidate.promote 晋级"] --> B["soc/ 建裸机工程<br>启动代码 / 链接脚本 / BSP"]
    B --> C["构建软件<br>保存完整日志"]
    C --> D{"产物可校验？"}
    D -->|是| E["SW_BUILT<br>ELF / BSP 摘要登记"]
    D -->|否| C
    E --> F["candidate.deliver<br>hardware-software-contract"]
    F --> G["板上功能验证留待阶段 06<br>此前状态为 INTEGRATION_PENDING_HARDWARE"]

你对 Trae 说什么

为本工程的 Sapphire SoC 生成软件分区：在 soc/ 下创建裸机应用，
按规格实现 SD 初始化与帧缓冲灌注的主循环，用 new_software 建立软件工程，
硬件配置变更后用 regenerate_bsp 重新生成 BSP。
软件候选完成后同样用 candidate.deliver 提交，标注 hardware-software-contract；
host 级可测的每个强制性需求都要给出 host 或 board 测试方法。

Trae 会帮你做什么

  1. project_status 确认三轮增量已全部 candidate.promote 晋级（软件依赖晋级后的基线），读取 hardware-software contract。
  2. 在 soc/ 下建立裸机软件工程：启动代码、链接脚本、BSP 头文件与寄存器图（来自 CSI-2 晋级基线对应规格的寄存器节，不是任何中间轮次的草稿）。
  3. 硬件配置（时钟、地址映射）变更后执行 BSP 重新生成，保证 BSP 与 bitstream 同源。
  4. 构建软件并保存完整日志；只把实际生成且可校验的 ELF/BSP 产物标记为 SW_BUILT。
  5. 软件候选以 candidate.deliver 提交（origin 标注 software 分区），控制面记录它与硬件候选的契约绑定。
  6. 明确报告边界：板上功能验证要等阶段 06 的 hardware.validate 回执；在那之前不会把任何"应该能跑"写成 PASS。

你需要确认什么

  • 硬件 bitstream、BSP 和软件必须来自同一工程配置；不要混用其他版本的 BSP。
  • 每个强制性软件需求都有可执行的测试方法：host 级单测或 board 级场景，二选一，不允许"人工看一下"。
  • 所有权交接清晰：硬件侧提供寄存器图与中断契约（OWN_P1），软件侧消费它；任何一侧变更都要重新走候选交付。
  • 没有硬件时，本阶段止步于 SW_BUILT，板上验证在控制面状态里保持 INTEGRATION_PENDING_HARDWARE。

通过条件

  • 软件候选回执在控制面状态里可见，ELF 与 BSP 摘要已登记。
  • 硬件/软件契约（寄存器图、地址映射、中断）双方引用同一版本。
  • 构建日志完整保存，SW_BUILT 与功能验证两类状态没有被混写。
  • 固件与 RTL 候选一起构成后续 efx_run --flow compile 与板上验证的完整输入。

完成后进入 阶段 05：SDK 集成。
