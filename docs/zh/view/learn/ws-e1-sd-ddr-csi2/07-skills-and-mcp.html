07 Skills 与 MCP

阶段 07 · Skill 与 MCP 工具速查

七个阶段走完，回头看清这条路径用到的全部接口：11 个公开 MCP 工具、25 个控制面动作、6 个内置 Skill。你在 TJ180A484S 上完成 SD card -> DDR frame buffer -> MIPI CSI-2 TX 的每一步，都对应这张表里的一行和一条证据。

你对 Trae 说什么

带我做一次交付前回顾：按初始化、物料、规格、候选与仿真、固件、集成、
编译与硬件七个阶段，讲清楚每一步做了什么、留下了什么证据、
哪些边界还没验证。用客户能听懂的话讲，不要只报工具名。

Trae 会帮你做什么

  1. 用 project_status 汇总当前 revision 下的全部事实：Baseline、意图、候选、证据区。
  2. 把每个阶段的动作回执与证据文件一一对应，标出 incomplete 或未执行的环节。
  3. 按下文速查表解释"你看到的阶段 ↔ 底层接口"的关系，不重新生成任何代码。
  4. 给出下一步选项：继续优化、开新意图、或带着证据链进入阶段 08 的目录整理。

你需要确认什么

  • 每个阶段的结论都有回执或文件支撑，"没做过"和"没验证"没有被写成"通过"。
  • 你能说清 11 个公开 MCP 工具各自回答什么问题：控制面 3 个管状态、下一步、执行；evoverse_health 管健康；其余 7 个 rk3588_* 管 RK3588 环境与工程构建。
  • 普通 Agent 对话可以解释和整理，但不能替代 candidate.deliver 与 verification.simulate 的回执。

如果不顺利

现象 怎么处理
回顾漏了某个阶段 对着 Workbench 控制面的状态分区（Baseline / 意图 / 候选 / 证据）逐区核对补齐，不要凭记忆放行。
解释全是术语听不懂 追问"这一步对板子最终显示图像意味着什么"，让它换成人话再讲一遍。
Trae 想跳过回顾直接整理目录 不建议。回顾能提前暴露缺证据的环节，到阶段 08 才发现就要回滚复编译。

通过条件

  • 你能不看文档说出工程从物料到 efx_run --flow compile 编译证据的完整路径。
  • 你能指出每个动作回执在 project_status 输出里的位置。
  • 你能判断当前工程停在哪个阶段、下一步允许动作是什么（project_next 的答案，不是猜测）。

速查：公开 MCP 工具（11 个）

工具 回答的问题
project_status 工程现在是什么状态？（revision、Baseline、意图、候选、证据）
project_next 现在允许做什么？（动作列表 + 每个动作的 inputSchema 与 blockedReasons）
project_execute 执行选定动作（actionId + expectedRevision + inputs）
evoverse_health SDK 与工具链是否健康可用
rk3588_environment_status RK3588 环境只读体检：工具链、BSP 各装到哪一步
rk3588_environment_prepare 准备 RK3588 环境，返回 inspectionToken 供后续检查
rk3588_environment_deploy 部署 RK3588 工具链 / BSP（acceptedLicenses 授权）
rk3588_project_generate 受控生成 RK3588 工程（产出 PROFILE_READY）
rk3588_project_preflight 构建前只读资格化检查
rk3588_project_build 四阶段构建：uboot → kernel → rootfs → package
rk3588_project_status 读取 .evoverse/output/build-report.json 构建报告

其余能力（JTAG 观测、DesignAPI / IP 管理、工程合同检查等）由扩展的 provider 工具面提供，通过 Skill 与自然语言调用，不在模型可见的公开 MCP 面中。

速查：控制面动作（25 个）

分组 动作 语义 对应阶段
项目 project.initialize 声明工程身份（板卡 / 载板 / 夹克 / 器件） 00
意图 intent.create 声明一次有目标、有作用域的增量意图（父基线快照进 baseBaselineFiles） 03
意图 intent.rebase 父基线变化后把意图挂到新基线上（REBASE_REQUIRED 时使用） 按需
意图 intent.abandon 放弃当前意图（SUPERSEDED 终态） 按需
意图 intent.purge 清除已终结意图的记录（墓碑） 按需
规格 spec.draft 起草差量规格 02
规格 spec.approve 批准并冻结规格 02
等级 simulation.profile.select 两阶段等级决策：服务端按 riskFacts 推荐，用户选择；低于推荐记 acceptedRisks 02 / 03
资产 asset.observe 观察工作树与材料 01
资产 asset.adopt 把复用资产显式连到意图作用域 01 / 03
契约 contract.qualify 用户批准确定性渲染的 CONTRACT.md，模块契约资格化（CONTRACT_QUALIFIED） 按需
候选 candidate.deliver 冻结候选并执行 Design Assurance，基线保持不变 03 / 04
候选 candidate.repair 修复未通过的模块候选（按 moduleId 与契约 digest 重新交付） 按需
候选 candidate.promote 仿真 PASS 且资格满足后，把候选与父基线合并安装为新基线 03
验证 verification.simulate 记录仿真证据（iverilog / questa），独立取证 03 / 04
构建 build.native 记录 efx_run --flow compile 构建证据 06
硬件 hardware.program 记录烧录证据（器件身份显式 + 操作者确认） 06
硬件 hardware.validate 按 scenarios 逐条记录板上验证证据 06
集成 integration.process candidate.promote 之后关闭系统集成（mainline 合入收尾） 按需
恢复 recovery.open 非终态无可用动作时建立持久恢复记录（inputPreview 原样提交） 按需
恢复 recovery.quarantine 恢复期间的幂等安全出口：保留可信基线与失败证据，隔离故障范围 按需
诊断 diagnostic.options.propose 提出诊断选项 按需
诊断 diagnostic.choice.select 从诊断选项中选定一条 按需
诊断 diagnostic.finding.record 记录诊断发现 按需
诊断 diagnostic.repair.record 记录修复结果 按需

速查：内置 Skill（6 个）

Skill 何时用
/efinity-knowledge Efinity 工具链、ISF、SDC、优化问题查证
/efinity-project 创建 Efinity 工程或调整器件、源文件、约束、IP、构建设置
/evoverse-design-spec 起草可执行设计规格包与决策选项
/evoverse-rtl 按已批准规格生成候选 RTL 与测试平台
/evoverse-board-create 从原理图 / BOM / 器件资料重建板卡材料
/evoverse-project-review 里程碑 / 完成后的项目复盘

以上斜杠 Skill 在 Trae 中可用——SDK 已把它们装入 Trae 的 Skill 目录。VS Code 中这些 Skill 经 VSIX 的 chatSkills 声明提供给 Copilot Chat（agent 模式按需加载，需已安装 Copilot Chat 扩展）；也可让 Agent 读取交付包内 Skills/<skill-name>/SKILL.md（如 Skills/efinity-knowledge/SKILL.md）并按其执行。MCP 工具在两种宿主下都由 SDK 写入用户级 MCP 配置，不受影响。
