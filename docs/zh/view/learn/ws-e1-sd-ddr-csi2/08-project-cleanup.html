08 整理工程并交付

阶段 08 · 目录整理与交付

显示链路验证完成后，不要让临时草稿、候选文件和报告散落在工程根目录。本章让 Trae 先生成整理预览，由你逐条确认后再执行，最后用一次 efx_run --flow compile 复编译证明工程仍可交付。

整理的目标是让下一位工程师容易找到文件，不是重写一个已经能用的工程。冻结的规格包（design-package/）、三轮增量晋级形成的基线（含各轮 candidate.promote 回执）、已交付候选与全部证据回执都是受保护文件——它们是这条 TJ180A484S 上 SD card -> DDR frame buffer -> MIPI CSI-2 TX 链路的证据链，不参与整理。

整理的执行顺序如下图，预览先行、确认驱动、复编译收尾：

flowchart TD
    A["生成整理预览<br>reports/project-cleanup-preview.md"] --> B["你逐条确认<br>不确定项标为需要决定"]
    B --> C["只执行确认条目<br>同步修正引用路径"]
    C --> D{"工程 XML 与<br>脚本路径仍有效？"}
    D -->|是| E["build.native 复编译<br>efx_run --flow compile"]
    D -->|否| F["停在问题处<br>回滚未确认动作"]
    E --> G["报告：已整理 / 受保护 /<br>引用更新 / 复编译结果"]

你对 Trae 说什么

请检查当前 WS-E1 工程，先生成一份"工程目录整理预览"，不要移动、重命名或删除任何文件。
按 design-package/、rtl/、sim/、constraints/、software/、reports/、scripts/ 和 IP/ 的归属列出：
保留位置、建议移动的位置、引用它的工程文件或脚本、以及移动后需要更新的路径。

只允许整理本工程自己生成的 RTL、仿真、软件、报告和辅助脚本。
不得移动、重命名、删除或重新生成第三方 IP、Efinity 生成物、冻结规格包、材料账本、
已晋级基线文件与 candidate.promote 回执、工程 XML、约束和已登记的源文件。
把不确定的文件标为"需要我决定"，等我确认预览后再执行。

我确认后，只执行我确认的条目；完成后检查工程 XML、源文件清单和脚本路径是否仍然有效，
再用 build.native 记录一次 efx_run --flow compile 复编译结果。
分别报告：实际整理的文件、保留不动的受保护文件、更新过的引用、复编译结果。
不要从 sd-ddr-csi2 或其他参考工程补充文件。

Trae 会帮你做什么

  1. 读取工程合同、材料账本、candidate.deliver 与 candidate.promote 回执和 Efinity 工程文件，建立"文件归属与引用"清单。
  2. 预览阶段只产出报告（如 reports/project-cleanup-preview.md），不修改任何工程文件。
  3. 你确认后才整理允许变动的文件，并同步修正已确认的相对路径。
  4. 整理完成后用 build.native 记录一次原生 efx_run --flow compile：路径失效或编译失败会停在问题处，不会复制参考工程文件来掩盖问题。
  5. 每一步都尊重工程合同：工程 XML 不手动编辑，引用修正走同步能力。

你需要确认什么

  • 每一个建议移动的文件都是本工程自己生成或维护的，且清单列出了引用位置。
  • IP/ 下第三方 IP、Efinity 生成物、design-package/ 冻结规格包、工程 XML、约束和基线文件都在受保护列表内。
  • "删除"只针对你明确批准的临时文件；判定不了的保持原样，列为需要决定项。
  • 整理后工程 XML 仍引用正确的 RTL、约束、IP 和软件输入，复编译报告来自本次目录状态。

自然语言触发红线

本章只能动本工程自己生成的 RTL / 仿真 / 软件 / 报告 / 辅助脚本。下列说法会让 Agent 越过受保护列表，破坏工程契约：

不要这样说 为什么危险 请改写为
"把临时目录清理一下" 没区分"临时文件"与"受保护文件"——冻结规格包、IP 生成物、工程 XML 都可能被当成"临时" "先在预览中标出哪些是本工程临时文件，未列出的保持原样"
"这个文件已经不用了，删掉" "不用"是主观判断，Agent 容易把基线文件当临时文件 "提供回执或路径证据说明它是临时的，再删"
"把候选区文件归档到 reports/" 候选与基线由控制面管辖：candidate.deliver 冻结、candidate.promote 晋级，回执已记录摘要，手工归档会污染 reports "候选区文件交付后保持原样，无需归档"
"重命名一下工程 XML 让目录更整洁" 工程 XML 是受保护文件，重命名会让 Adapter 找不到工程 "不重命名、不删除工程 XML；只在确认报告中说明现状"

通过条件

  • reports/project-cleanup-preview.md 记录了预览、你的确认范围、实际变更和未处理项。
  • 目录能清楚区分 design-package/、rtl/、sim/、constraints/、software/、reports/ 与辅助脚本，第三方 IP 与 Efinity 生成物未被误动。
  • 复编译 efx_run --flow compile 成功，且报告来自整理后的目录状态；失败则保留报告并回滚未确认动作，而不是声称工程仍可交付。
  • 最终交付说明能指出：物料、冻结规格、三轮晋级形成的基线、编译与硬件证据各在什么目录。

至此，这条从空目录到板上显示的路径全部走完。回看 阶段 07 的速查表，或回到 教程总览 开始下一个意图。
