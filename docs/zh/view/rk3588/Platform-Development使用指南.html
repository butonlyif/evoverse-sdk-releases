RK3588 Platform Development 使用指南

RK3588 Platform Development 使用指南

适用 EvoVerse SDK v1.0.1 · 2026-11-26

v1.0.1 VSIX 已提供下述选板卡入口；第 4 节保留手动部署路径。

适用版本：EvoVerse SDK v1.0.1 当前发布边界：软件资格可在无板卡时完成；烧录、启动、板端运行和 NPU 性能必须使用真实板卡验证。

1. 客户获得什么

客户使用签名的 Platform Development Release，不需要取得或克隆 Platform 开发仓库。一个 Release 用同一份 platform-development-release.json（包含描述符、资格状态和 Ed25519 签名）绑定：

  • 可刷写固件 update.img；
  • 从同一 rootfs 派生的 sysroot；
  • Windows + Docker 使用的 App Builder；
  • AI 项目按需使用的 Model Builder；
  • 源码合规包（含 SBOM、许可证及对应源码）；
  • 软件、启动和硬件资格状态。

工程中的 .evoverse/platform-lock.json 固定平台版本和描述符摘要。再次打开工程时复用该锁；不同版本不会静默覆盖。

2. Workbench 在线路径

  1. 安装 SDK、RK3588 Adapter，并同步 Catalog。
  2. 创建或打开与 Catalog 板卡/载板身份匹配的工程。
  3. 在 RK3588 Workbench 的 Board 页点击 选择 Catalog 板卡并本地准备，会跳转到 Software → Platform Development。在那里选择 Catalog 板卡、载板和修订版，再点击 本地准备平台。SDK 根据 Catalog 的公开地址获取签名描述符，核对摘要、签名和目标身份，并写入工程锁；不需要手工下载描述符。
  4. 默认准备 sysroot + App Builder；AI 工程勾选 AI Model Builder 后一起下载。固件可单独预下载，但不能记为已烧录。
  5. 选择 构建应用。转换模型前填写 ONNX 路径、固定输入张量、归一化、精度与准确度参数，并配置获授权的 RKNN 厂商材料目录。转换模型 依次调用 Platform Model Builder 的 model.prepare 与 model.convert，主机核对准备输出摘要；旧 AI Pipeline 的 Run Pipeline 仍是独立入口。

在 Windows 主机上，已校验的 sysroot.tar 保持在 SDK 内容寻址缓存；Builder 在 Linux 容器内解包到 /sysroot 后交叉编译，不要求 Windows 解开 Linux 符号链接。 6. 有板卡后按对应板卡的烧录说明操作，验证板卡身份后再执行 部署并运行。 7. 使用 查看证据 区分软件、烧录、启动、板端执行和 NPU 性能状态。

当前 WS-E2 + RK3588J EVM 修订版 1 的候选包位于 Platform Release：update.img 是固件，sysroot.tar 和 app-builder.tar 是 App SDK 物料，model-builder.tar 是 AI 构建物料；文件名不含板卡名，目标身份由签名描述符绑定。

下载采用内容寻址缓存并复验大小和 SHA-256。缓存命中不等于板卡已烧录或已启动。

3. 没有板卡时

没有板卡是受支持状态。客户仍可完成：

  • Platform Release 解析和工程锁定；
  • AArch64 应用交叉编译；
  • ELF 架构、loader、动态依赖和 RPATH 检查；
  • ONNX 检查、量化、RKNN 转换和 host simulator 对照；
  • Application Package 组装与静态验证。

完成后状态应为 WAITING_FOR_BOARD。以下事实必须保持 NOT_RUN / NO_BOARD：板卡发现、烧录、启动、目标部署、目标执行、NPU 执行和硬件性能。

4. 手动和离线路径

在线渠道、企业镜像和离线介质必须携带同一份签名 manifest 和相同资产摘要。

  1. 从已批准渠道取得完整 Release 目录；不要只复制 update.img。
  2. 离线传输签名的 platform-development-release.json、所需资产和 source-compliance.tar（内含 SBOM、许可证及对应源码材料）。
  3. 在联网主机或发布方提供的校验工具上验证签名；在目标 Windows 主机复验每个文件的 SHA-256 和大小。
  4. 将已验证资产导入 SDK 内容寻址缓存，或把描述符放入工程 .evoverse/platform-descriptor.json 后执行 准备平台。不得修改描述符以改写本地路径。
  5. Docker 不可用时，板卡到货后可选择 SSH 板载原生编译；板卡上的 Developer Runtime 身份必须与工程锁一致。

手动烧录必须使用 Release 随附的烧录说明和该板卡对应的工具。烧录前再次核对 module、carrier、board revision、固件摘要和资格状态。UNQUALIFIED_NO_BOOT 只允许下载和工程准备，不代表客户可以把它当成已验证量产镜像。

5. AI 模型路径

Model Builder 负责 ONNX 检查、量化、ONNX→RKNN 转换和 host simulator；App Builder 负责编译调用 RKNN Runtime/MPP/RGA 的 AArch64 应用。两者由同一 Platform manifest 绑定 Toolkit、Runtime、driver ABI 和目标 NPU。

host simulator 通过不等于真实 NPU 通过。最终精度、性能、内存、温度和稳定性必须在真实 RK3588 上记录独立证据。

6. 常见阻断

  • PLATFORM_DESCRIPTOR_UNREADABLE：描述符缺失、不是合法 JSON 或无法读取。
  • PLATFORM_UPGRADE_CONFIRMATION_REQUIRED：工程已有不同平台锁；先审查升级，不要删除锁来绕过。
  • PLATFORM_MATERIALS_MISSING：缓存资产不完整；重新执行准备平台或重新导入离线资产。
  • WAITING_FOR_BOARD：软件阶段已完成，等待真实板卡，不是失败。
  • UNQUALIFIED_NO_BOOT：固件尚无真实启动资格，不得声明烧录/启动 PASS。

7. 客户不需要的内容

客户不需要 Platform 私有仓库、内部 CI/CD、构建凭证、未发布 BSP 分支或实验室自动化。Kernel、U-Boot、Buildroot 等开源义务通过与 Release 摘要绑定的 source-compliance 资产履行。

高级参考用于按需查询；设计记录、发布流程、审计报告和未来规划不属于客户操作入口。
