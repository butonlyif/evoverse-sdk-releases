1.3.1 Bridge 物理接口概览

接口 用途 RK3588 资源 备注
PCIe Gen3 x4 高速数据通道 PCIe3x4 PHY, MSI/MSI-X 中断 BAR 空间由 FPGA 决定；RK3588 作为 Root Complex
GE Ethernet (RGMII) 网络/控制面 GMAC 控制器, MDIO PHY 可能在 FPGA 内部实现，需 MDIO 配置
MIPI CSI / DSI 视频流 VICAP / VOP CSI 4-lane 输入, DSI 4-lane 输出
GPIO 低速控制信号 任意空闲 GPIO Bank FPGA 复位、中断、模式选择、状态指示

1.3.2 PCIe 接口细化

RK3588 内置 PCIe Gen3 x4 控制器，通常作为 Root Complex (RC)，FPGA 作为 Endpoint (EP)：

  • Lane 配置: PCIe Gen3 x4，理论带宽 ~4 GB/s（每 lane ~1 GB/s）
  • BAR 空间: FPGA EP 暴露 BAR0~BAR5，典型分配：
  • BAR0: 32-bit 不可预取内存，用于控制寄存器（如 1 MB）
  • BAR2: 64-bit 可预取内存，用于 DMA 缓冲区（如 256 MB）
  • 中断: 使用 MSI/MSI-X，无需额外 GPIO 中断线
  • MSI: FPGA 最多可分配 32 个 MSI 向量
  • MSI-X: 支持每向量独立地址，适合多队列场景
  • 地址映射: FPGA 寄存器通过 PCIe BAR 映射到 RK3588 内存空间
  • 内核驱动: 使用标准 pci_driver 框架按 PCI vendor/device/subsystem ID 匹配；PCIe EP 是可枚举设备，不以 DT compatible 作为常规绑定方式

Device Tree 中 PCIe 节点引用:

&pcie3x4 {
    status = "okay";
    // FPGA Endpoint 配置
};

1.3.3 GE Ethernet (RGMII) 细化

使用 RK3588 的 GMAC 控制器，通过 RGMII 接口连接 FPGA 内部实现的以太网 PHY：

  • 接口: RGMII (Reduced Gigabit Media Independent Interface)
  • TXC/TX_CTL/TXD[3:0]: 发送通路
  • RXC/RX_CTL/RXD[3:0]: 接收通路
  • MDC/MDIO: PHY 管理接口，用于配置 FPGA 内部 PHY 寄存器
  • PHY 地址: FPGA 内部 PHY 通过 MDIO 分配地址（通常 0~31）
  • 时钟方案:
  • RK3588 提供 TXC 时钟（125 MHz DDR）
  • RXC 由 FPGA PHY 恢复并提供给 RK3588
  • MAC 地址:
  • 推荐从 RK3588 OTP/eFuse 读取唯一 MAC
  • 若无 OTP 烧录，可在 Device Tree 中通过 local-mac-address 固定
  • 内核驱动: 使用标准 stmmac (Synopsys GMAC) 驱动，通过 MDIO 发现并配置 PHY

Device Tree 中 GMAC 节点配置:

&gmac0 {
    phy-mode = "rgmii-rxid";
    // FPGA 内部 PHY, MDIO 地址通常为 0
    fixed-link {
        speed = <1000>;
        full-duplex;
    };
};

1.3.4 MIPI 接口细化

RK3588 提供多组 MIPI 接口，用于 FPGA 视频流传输：

MIPI CSI (Camera Serial Interface) — FPGA → RK3588 视频输入： - 用途: FPGA 作为视频源，将处理后的图像流通过 CSI 发送给 RK3588 - 控制器: RK3588 VICAP (Video Input Capture) - Lane 配置: 4-lane，每 lane 最高 2.5 Gbps - 数据格式: RAW8/RAW10/RAW12, YUV422, RGB888 等 - 虚拟通道: 支持 4 个虚拟通道，可多路复用 - 驱动框架: V4L2 (video4linux2)，用户态通过 /dev/videoX 访问

MIPI DSI (Display Serial Interface) — RK3588 → FPGA 显示输出： - 用途: RK3588 将显示内容通过 DSI 发送给 FPGA 做进一步处理或转发 - 控制器: RK3588 VOP (Video Output Processor)，内部 DSI 控制器 - Lane 配置: 4-lane，每 lane 最高 2.5 Gbps - 分辨率: 最高支持 4K@60Hz（取决于 FPGA 接收能力） - 驱动框架: DRM (Direct Rendering Manager)，通过 /dev/dri/cardX 访问

Device Tree 中 MIPI 节点配置:

&csi2_dphy0_hw {
    status = "okay";
};

&csi2_dphy0 {
    status = "okay";
    ports {
        port@0 {
            // 连接 FPGA CSI-TX
        };
    };
};

&dsi0 {
    status = "okay";
    // FPGA 作为 DSI 面板
};

1.3.5 GPIO 接口细化

FPGA 与 RK3588 之间的低速控制信号，通过 GPIO 实现：

信号名 方向 用途 推荐 GPIO
FPGA_RESET RK→FPGA FPGA 复位控制（低有效） 任意 GPIO，开漏输出
FPGA_IRQ FPGA→RK FPGA 到 RK3588 的中断请求 支持中断的 GPIO（带 IRQ 功能）
FPGA_DONE FPGA→RK FPGA 配置完成指示 任意 GPIO 输入
FPGA_INIT FPGA→RK FPGA 初始化状态 任意 GPIO 输入
FPGA_MODE[1:0] RK→FPGA FPGA 启动模式选择 任意 GPIO 输出
FPGA_STATUS FPGA→RK FPGA 运行状态指示 任意 GPIO 输入
SYS_PWR_EN RK→FPGA 系统电源使能 任意 GPIO 输出

GPIO 使用注意事项: - 确认 GPIO 引脚未被系统外设（UART、I2C、SPI 等）占用 - 中断引脚必须使用支持 interrupt-parent 的 GPIO 控制器 - 开漏输出引脚（FPGA_RESET）需外接上拉电阻 - 高速信号不建议走 GPIO，应使用专用接口（PCIe/MIPI）

Device Tree 中 GPIO 的 pinctrl 配置:

&pinctrl {
    fpga-bridge {
        fpga_bridge_pins: fpga-bridge-pins {
            rockchip,pins =
                <0 RK_PA0 RK_FUNC_GPIO &pcfg_pull_none>,   // FPGA_RESET
                <0 RK_PA1 RK_FUNC_GPIO &pcfg_pull_up>,     // FPGA_IRQ
                <0 RK_PA2 RK_FUNC_GPIO &pcfg_pull_none>;   // FPGA_DONE
        };
    };
};

2.4 parseReport 实现

// rk3588Adapter.ts

parseReport(rawOutput: string[]): BuildReport {
  const report: BuildReport = {
    success: true,
    stages: [],
    errors: [],
    warnings: [],
    artifacts: [],
    timing: {},
  };

  for (const line of rawOutput) {
    // U-Boot 编译阶段
    if (this.isUBootStage(line)) {
      report.stages.push(this.parseUBootStage(line));
    }

    // Kernel 编译阶段
    if (this.isKernelStage(line)) {
      report.stages.push(this.parseKernelStage(line));
    }

    // Buildroot 编译阶段
    if (this.isBuildrootStage(line)) {
      report.stages.push(this.parseBuildrootStage(line));
    }

    // 错误解析
    if (this.isError(line)) {
      report.errors.push(this.parseError(line));
      report.success = false;
    }

    // 警告解析
    if (this.isWarning(line)) {
      report.warnings.push(this.parseWarning(line));
    }

    // 产物路径
    if (this.isArtifact(line)) {
      report.artifacts.push(this.parseArtifact(line));
    }
  }

  return report;
}

// ── Buildroot 特定解析 ──

parseBuildrootStage(line: string): BuildStage {
  // Buildroot 输出格式: ">>> toolchain 1.0 Building...
  const match = line.match(/>>>\s+(\S+)\s+Building/);
  if (match) {
    return {
      name: match[1],
      status: 'building',
      startTime: this.parseTimestamp(line),
    };
  }

  // 成功标记: ">>> toolchain 1.0 Done"
  const doneMatch = line.match(/>>>\s+(\S+)\s+Done/);
  if (doneMatch) {
    return {
      name: doneMatch[1],
      status: 'success',
      duration: this.parseDuration(line),
    };
  }

  // 进度: "[  25%]" 或 "[100%]"
  const progressMatch = line.match(/\[(\d+)%\]$/);
  if (progressMatch) {
    return {
      name: 'progress',
      status: 'building',
      progress: parseInt(progressMatch[1]),
    };
  }

  return { name: 'unknown', status: 'unknown' };
}

// ── 错误解析 (Buildroot 格式) ──

parseBuildrootError(line: string): BuildError {
  const patterns = [
    // Makefile 错误
    {
      pattern: /make\[(\d+)\]: \*\*\* (.*)/,
      parse: (m: RegExpMatchArray): BuildError => ({
        level: 'error',
        message: m[2],
        location: { file: 'Makefile', line: 0 },
        suggestion: '检查依赖或配置错误',
      }),
    },
    // 配置错误
    {
      pattern: /Configuration file .* is not valid/,
      parse: (): BuildError => ({
        level: 'error',
        message: 'Buildroot 配置文件无效',
        suggestion: '运行 make clean && make defconfig 重置配置',
      }),
    },
    // 依赖缺失
    {
      pattern: / Missing: (.*)/,
      parse: (m: RegExpMatchArray): BuildError => ({
        level: 'error',
        message: `缺少依赖: ${m[1]}`,
        suggestion: '安装缺失的开发工具',
      }),
    },
    // 编译错误
    {
      pattern: /error: (.*)/,
      parse: (m: RegExpMatchArray): BuildError => ({
        level: 'error',
        message: m[1],
        suggestion: '检查源码或交叉编译工具链',
      }),
    },
  ];

  for (const { pattern, parse } of patterns) {
    const match = line.match(pattern);
    if (match) {
      return parse(match);
    }
  }

  return { level: 'error', message: line };
}

// rk3588Build.ts

export async function buildUBoot(config: UBootConfig): Promise<BuildStage> {
  const startTime = Date.now();

  // 1. 准备源码
  await this.prepareUBootSource(config);

  // 2. 配置
  const configureResult = await this.runCommand(`
    cd ${config.sourceDir}/u-boot
    make CROSS_COMPILE=aarch64-linux-gnu- ${config.defconfig}
  `);

  if (!configureResult.success) {
    throw new BuildError('U-Boot 配置失败', configureResult.stderr);
  }

  // 3. 编译
  const buildResult = await this.runCommand(`
    cd ${config.sourceDir}/u-boot
    make CROSS_COMPILE=aarch64-linux-gnu- -j${config.jobs}
  `, {
    env: {
      ...process.env,
      // Rockchip 特定环境变量
      RK_IDBLOADER: '1',          // 生成 idbloader.img
      RK_CHIP: 'RK3588',
    },
    timeout: config.timeout || 600000, // 10分钟
  });

  if (!buildResult.success) {
    throw new BuildError('U-Boot 编译失败', buildResult.stderr);
  }

  // 4. 生成 idbloader.img
  const idbloaderPath = await this.runCommand(`
    cd ${config.sourceDir}/u-boot
    ./tools/mkimage -n rk3588 -T rksd -d ./u-boot-tpl.bin:./u-boot-spl.bin idbloader.img
  `);

  return {
    name: 'u-boot',
    status: 'success',
    duration: Date.now() - startTime,
    artifacts: {
      'idbloader.img': `${config.sourceDir}/u-boot/idbloader.img`,
      'u-boot.bin': `${config.sourceDir}/u-boot/u-boot.bin`,
    },
  };
}

// deviceTreeGenerator.ts

export interface DTBGenerator {
  generateBaseDTS(project: ProjectModel): string;
  generateBoardDTS(project: ProjectModel): string;
  generateOverlay(bridgeSpec: BridgeSpec): string;
  compileDTS(dtsPath: string): string;
  mergeOverlays(baseDtb: string, overlays: string[]): string;
}

export function generateDeviceTree(
  project: ProjectModel,
  bridgeSpec?: BridgeSpec
): DeviceTreeFiles {
  const generator = new RK3588DTBGenerator();

  // 1. 生成基础 DTS
  const baseDts = generator.generateBaseDTS(project);

  // 2. 生成板级 DTS
  const boardDts = generator.generateBoardDTS(project);

  // 3. 生成 Bridge Spec Overlay (如果存在 FPGA 互联)
  let overlayDts = '';
  if (bridgeSpec) {
    overlayDts = generator.generateOverlay(bridgeSpec);
  }

  // 4. 编译为 DTB
  const baseDtb = generator.compileDTS(baseDts);
  const boardDtb = generator.compileDTS(boardDts);

  // 5. 合并 overlays
  const mergedDtb = overlayDts
    ? generator.mergeOverlays(boardDtb, [overlayDts])
    : boardDtb;

  return {
    baseDts,
    boardDts,
    overlayDts,
    baseDtb,
    boardDtb,
    mergedDtb,
  };
}

  generateOverlay(bridgeSpec: BridgeSpec): string {
    const dts = [
      '// Bridge Spec Overlay - Auto-generated',
      '// FPGA ↔ SoC Interface Definition',
      '',
      '/ {',
      '  fragment@fpga-bridge {',
      '    target = <&amba>;',
      '    __overlay__ {',
      '',
    ];

    // 地址映射
    for (const addrMap of bridgeSpec.addressMaps) {
      dts.push('      // 地址映射');
      dts.push(`      fpga@${addrMap.fpgaBase.toString(16)} {`);
      dts.push('        compatible = "rockchip,fpga-bridge";');
      dts.push(`        reg = <0x0 ${addrMap.fpgaBase.toString(16)} ${addrMap.size}>;`);
      dts.push('        #address-cells = <0x1>;');
      dts.push('        #size-cells = <0x1>;');
      dts.push('');
      dts.push('        // FPGA 内部寄存器');
      for (const reg of addrMap.registers) {
        dts.push(`        reg@${reg.offset.toString(16)} {`);
        dts.push(`          reg = <${reg.offset} ${reg.size}>;`);
        dts.push(`          // ${reg.name}: ${reg.description}`);
        dts.push('        };');
      }
      dts.push('      };');
      dts.push('    };');
    }

    // 中断路由
    if (bridgeSpec.interrupts.length > 0) {
      dts.push('');
      dts.push('    __overlay__ {');
      dts.push('      // 中断路由');
      for (const irq of bridgeSpec.interrupts) {
        dts.push(`      fpga-irq@${irq.gicNumber} {`);
        dts.push(`        compatible = "rockchip,fpga-irq";`);
        dts.push(`        interrupts = <GIC_SPI ${irq.gicNumber} IRQ_TYPE_LEVEL_HIGH>;`);
        dts.push(`        // Source: ${irq.source}`);
        dts.push('      };');
      }
      dts.push('    };');
    }

    dts.push('  };');
    dts.push('};');

    return dts.join('\n');
  }

  compileDTS(dtsPath: string): string {
    const dtbPath = dtsPath.replace('.dts', '.dtb');
    this.runCommand(`dtc -I dts -O dtb -o ${dtbPath} ${dtsPath}`);
    return dtbPath;
  }

  mergeOverlays(baseDtb: string, overlays: string[]): string {
    let current = baseDtb;
    for (const overlay of overlays) {
      const overlayDtb = overlay.replace('.dtsh', '.dtbo');
      this.runCommand(`dtc -I dts -O dtb -o ${overlayDtb} ${overlay}`);
      current = this.runCommand(
        `fdtapply ${current} ${overlayDtb}`
      );
    }
    return current;
  }
}

export class RK3588ResourceAllocator {
  // 预定义的体系结构资源
  private static readonly ARCH_RESERVED = {
    // GPIO 组预留
    gpio0: { used: ['PA0-PA7'], reserved: ['PB0-PB7'] },
    gpio1: { used: ['PA0-PA7'], reserved: [] },
    gpio2: { used: [], reserved: ['PC0-PC7'] },  // 用于 Camera

    // 中断预留 (GIC SPI)
    reservedIrqs: [32, 33, 34, 35],  // 系统中断

    // 时钟预留
    reservedClks: ['pll_npu', 'clk_npu'],
  };

  allocateGPIOA(project: ProjectModel): GPIOAllocation[] {
    const allocations: GPIOAllocation[] = [];

    for (const pin of project.hardware.gpioPins) {
      // 检查是否与架构预留冲突
      const isReserved = RK3588ResourceAllocator.ARCH_RESERVED.gpio0.reserved
        .some(r => r === pin.pin);

      if (isReserved) {
        throw new Error(`GPIO pin ${pin.pin} is reserved by architecture`);
      }

      allocations.push({
        pin: pin.pin,
        function: pin.function,
        direction: pin.direction,
        pull: pin.pull || 'none',
      });
    }

    return allocations;
  }

  allocateInterrupts(project: ProjectModel): InterruptAllocation[] {
    const allocations: InterruptAllocation[] = [];

    // 分配起始 IRQ 号 (从 64 开始，预留前 64 个)
    let nextIrq = 64;

    for (const irq of project.hardware.interrupts) {
      allocations.push({
        source: irq.source,
        gicNumber: nextIrq,
        type: irq.type,  // 'level' | 'edge'
        polarity: irq.polarity || 'high',  // 'high' | 'rising' 等
      });
      nextIrq++;
    }

    return allocations;
  }

  allocateClocks(project: ProjectModel): ClockAllocation[] {
    const allocations: ClockAllocation[] = [];

    // 固定时钟分配
    const fixedClocks = [
      { name: 'clk_uart2', freq: 24000000, source: 'xin24m' },
      { name: 'clk_gmac0', freq: 125000000, source: 'gmac_clkin' },
      { name: 'clk_sdmmc', freq: 200000000, source: 'cpll' },
    ];

    for (const clk of fixedClocks) {
      allocations.push(clk);
    }

    // 动态时钟分配
    for (const dynamicClk of project.hardware.clocks) {
      allocations.push({
        name: dynamicClk.name,
        freq: dynamicClk.frequency,
        source: dynamicClk.source,
      });
    }

    return allocations;
  }
}

export interface FlashConfig {

export class RK3588Flash {
  private rkTool: string;
  private device: string;

  constructor(config: { rkToolPath: string; device?: string }) {
    this.rkTool = config.rkToolPath;
    this.device = config.device || '/dev/ttyUSB0';
  }

  async flash(firmware: FirmwareBinary): Promise<FlashResult> {
    const result: FlashResult = {
      success: false,
      partitions: [],
      error: undefined,
    };

    try {
      // 1. 检测 Maskrom 模式
      await this.detectMaskrom();

      // 2. 下载 MiniLoader
      await this.downloadLoader();

      // 3. 写入分区表
      await this.writeParameter(firmware.parameter);

      // 4. 下载固件
      for (const partition of firmware.partitions) {
        await this.downloadPartition(partition);
        result.partitions.push({
          name: partition.name,
          offset: partition.offset,
          size: partition.size,
          path: partition.file,
          checksum: await this.calculateChecksum(partition.file),
        });
      }

      // 5. 校验并重启
      await this.verifyAndReboot();

      result.success = true;
    } catch (error) {
      result.success = false;
      result.error = error.message;
    }

    return result;
  }

  // ── Maskrom 模式检测 ──

  async detectMaskrom(): Promise<void> {
    const result = await this.runCommand(`
      ${this.rkTool} list
    `);

    if (!result.stdout.includes('Maskrom')) {
      throw new Error(
        '设备未进入 Maskrom 模式。请：\n' +
        '1. 断电\n' +
        '2. 按住 MASKROM 按键\n' +
        '3. 上电\n' +
        '4. 释放按键'
      );
    }
  }

  // ── LOADER 下载 ──

  async downloadLoader(): Promise<void> {
    console.log('Downloading MiniLoader...');

    const result = await this.runCommand(`
      ${this.rkTool} dnl ${this.loaderPath}
    `, { timeout: 60000 });

    if (!result.success) {
      throw new Error(`Loader 下载失败: ${result.stderr}`);
    }

    // 等待设备进入 loader 模式
    await this.waitForLoaderMode();
  }

  // ── 分区表写入 ──

  async writeParameter(parameter: string): Promise<void> {
    console.log('Writing parameter...');

    const result = await this.runCommand(`
      cd ${this.firmwareDir}
      ${this.rkTool} down ${parameter}
    `);

    if (!result.success) {
      throw new Error(`Parameter 写入失败: ${result.stderr}`);
    }
  }

  // ── 分区写入 ──

  async downloadPartition(partition: PartitionInfo): Promise<void> {
    console.log(`Downloading ${partition.name}...`);

    const result = await this.runCommand(`
      ${this.rkTool} up ${partition.name} ${partition.file}
    `, { timeout: partition.size / 1024 / 10 }); // 约 10MB/s

    if (!result.success) {
      throw new Error(`分区 ${partition.name} 写入失败: ${result.stderr}`);
    }
  }

  // ── 校验与重启 ──

  async verifyAndReboot(): Promise<void> {
    console.log('Verifying and rebooting...');

    const result = await this.runCommand(`
      ${this.rkTool} verif
    `);

    if (!result.success) {
      throw new Error(`校验失败: ${result.stderr}`);
    }

    // 重启设备
    await this.runCommand(`${this.rkTool} reboot`);
  }

  // ── 工具函数 ──

  private async waitForLoaderMode(timeout = 30000): Promise<void> {
    const start = Date.now();
    while (Date.now() - start < timeout) {
      const result = await this.runCommand(`${this.rkTool} list`);
      if (result.stdout.includes('Loader')) {
        return;
      }
      await this.sleep(500);
    }
    throw new Error('等待 Loader 模式超时');
  }

  private async calculateChecksum(file: string): Promise<string> {
    const result = await this.runCommand(`md5sum ${file}`);
    return result.stdout.split(' ')[0];
  }
}

export interface SerialConfig {
  port: string;           // '/dev/ttyUSB0' 或 'COM3'
  baudRate: number;       // 1500000 (RK3588 默认)
  dataBits: 8;
  stopBits: 1;
  parity: 'none';
}

export class SerialDebugger {
  private port: SerialPort;
  private reader: ReadableStreamDefaultReader;
  private logBuffer: SerialLog[] = [];

  async connect(config: SerialConfig): Promise<void> {
    this.port = new SerialPort({
      path: config.port,
      baudRate: config.baudRate,
      dataBits: config.dataBits,
      stopBits: config.stopBits,
      parity: config.parity,
    });

    this.reader = this.port.read(ttyBuffer).getReader();
  }

  async readLogs(duration = 5000): Promise<SerialLog[]> {
    const logs: SerialLog[] = [];
    const startTime = Date.now();

    while (Date.now() - startTime < duration) {
      const { value, done } = await this.reader.read();

      if (done) break;

      const line = new TextDecoder().decode(value);
      logs.push({
        timestamp: Date.now(),
        content: line,
        level: this.parseLogLevel(line),
      });

      this.logBuffer.push(logs[logs.length - 1]);
    }

    return logs;
  }

  parseLogLevel(line: string): 'info' | 'warn' | 'error' | 'debug' {
    if (line.includes('[    0.000000]') || line.includes('Starting kernel')) {
      return 'info';
    }
    if (line.includes('WARNING') || line.includes('warn')) {
      return 'warn';
    }
    if (line.includes('ERROR') || line.includes('BUG') || line.includes('Panic')) {
      return 'error';
    }
    return 'debug';
  }

  // 持续监听并实时返回
  async *streamLogs(): AsyncGenerator<SerialLog> {
    while (true) {
      const { value, done } = await this.reader.read();
      if (done) break;

      const line = new TextDecoder().decode(value);
      const log: SerialLog = {
        timestamp: Date.now(),
        content: line,
        level: this.parseLogLevel(line),
      };

      this.logBuffer.push(log);
      yield log;
    }
  }
}

    return output.split('\n').filter(line => line.trim());
  }

  async getKernelPanic(): Promise<KernelPanicInfo | null> {
    const dmesg = await this.getDmesg();

    // 查找 kernel panic 信息
    const panicLines: string[] = [];
    let inPanic = false;

    for (const line of dmesg) {
      if (line.includes('Kernel panic')) {
        inPanic = true;
      }
      if (inPanic) {
        panicLines.push(line);
        if (line.includes('---[ end trace')) {
          break;
        }
      }
    }

    if (panicLines.length === 0) {
      return null;
    }

    return {
      fullLog: panicLines.join('\n'),
      timestamp: this.extractTimestamp(panicLines[0]),
      reason: this.extractPanicReason(panicLines),
      callTrace: this.extractCallTrace(panicLines),
    };
  }

  private extractPanicReason(lines: string[]): string {
    for (const line of lines) {
      if (line.includes('not syncing')) {
        const match = line.match(/not syncing: (.+)$/);
        return match ? match[1] : 'Unknown';
      }
    }
    return 'Unknown';
  }

  private extractCallTrace(lines: string[]): string[] {
    const trace: string[] = [];
    let inTrace = false;

    for (const line of lines) {
      if (line.includes('Call trace:') || line.includes('Stack:')) {
        inTrace = true;
        continue;
      }
      if (inTrace && line.match(/^\s*0x[0-9a-f]+/)) {
        trace.push(line.trim());
      }
      if (inTrace && line.match(/^\s*--- end trace/)) {
        break;
      }
    }

    return trace;
  }
}

export interface PanicAnalysis {

export class RK3588PanicAnalyzer implements KernelPanicAnalyzer {
  // Panic 类型识别模式
  private readonly PANIC_PATTERNS = [
    {
      type: 'oom' as PanicType,

      severity: 'critical',

      ],
    },
    {

      ],

      ],
    },

    for (const pattern of this.PANIC_PATTERNS) {

      type: 'unknown',
      severity: 'high',

      affectedComponent: 'unknown',

      }

    return callTrace.map(addr => ({
      address: addr,
      // 可以进一步使用 addr2line 解析符号
      symbol: this.resolveSymbol(addr),
    }));
  }

  private resolveSymbol(addr: string): string {
    // 调用 arm-none-eabi-addr2line 或 aarch64-linux-gnu-addr2line
    // return runCommand(`aarch64-linux-gnu-addr2line -e vmlinux ${addr}`);
    return addr;
  }
}

9. Adapter 契约补强

9.1 Profile 驱动，而不是 RK3588 硬编码

RK3588Adapter 必须消费不可变的 BspProfile：板卡/载板 revision、BSP manifest、构建入口、组件提交、容器 digest、工具链、defconfig、基础 DTS、loader、分区布局、产物规则及已验证能力。Adapter 不猜测 defconfig、DT label、GPIO 或烧录偏移；缺失时在 preflight 阶段失败。

interface BspProfile {
  schemaVersion: '1';
  id: string;
  boardRevision: string;
  bsp: { manifest: string; commit: string; family: 'rockchip-linux' | 'vendor-fork' };
  environment: { containerDigest: string; toolchainTriple: string; toolchainSha256: string };
  commands: { configure: CommandSpec; build: Record<BuildStageName, CommandSpec> };
  boot: { loaderSha256: string; partitionLayoutSha256: string };
  deviceTree: { baseDtb: string; permittedOverlays: string[] };
  capabilities: Record<string, 'verified' | 'experimental' | 'unsupported'>;
}

命令必须以参数数组执行，不通过 shell 拼接用户输入；设置 cwd、环境变量 allowlist、超时和取消信号，并将 stdout/stderr 原样保存。构建输出写入独立目录，禁止修改 SDK 源树中用户未声明的文件。

9.2 接口应从同步伪代码升级为异步、可取消契约

建议把通用 VendorAdapter 的 build() 拆成 preflight/plan/execute/collect，把 program() 与 debug() 作为可选 capability，而不是让 FPGA 时序接口强迫 SoC 返回伪数据。

interface AdapterCapabilities { build: true; package: boolean; flash: boolean; debug: boolean; timing: boolean }
interface VendorAdapterV2 {
  readonly id: string;
  readonly capabilities: AdapterCapabilities;
  preflight(ctx: OperationContext): Promise<Diagnostic[]>;
  plan(project: ProjectModel, ctx: OperationContext): Promise<BuildPlan>;
  execute(plan: BuildPlan, ctx: OperationContext): AsyncIterable<BuildEvent>;
  collect(runId: string, ctx: OperationContext): Promise<BuildReport>;
  flash?(request: FlashRequest, ctx: OperationContext): AsyncIterable<FlashEvent>;
}

OperationContext 至少包含 workspace、AbortSignal、日志脱敏器、执行策略和批准令牌。BuildReport 记录 stage DAG、命令摘要、退出码、耗时、峰值资源、诊断、产物 SHA-256、配置/源码身份与日志位置；success 必须由必需 stage 全部成功且产物校验通过推导，不能只看最后一个进程退出码。

9.3 Device Tree 生成的安全边界

Adapter 默认不从零生成板级 DTS，而是：选择 profile 的已验证 base DTS → 生成最小 overlay/受控 patch → dtc 编译 → schema/语义校验 → 与基础 DT 合并验证 → 输出 diff。PCIe RC 的 DT 负责控制器、PHY、时钟/复位和板级 PERST#；FPGA Endpoint 由 PCI 总线枚举，驱动按 PCI ID 绑定。所有示例中的节点 label、clock ID、reset ID、GPIO 与 ranges 都是板卡/BSP 相关占位符，未经目标 BSP 校验不得发布。

Bridge Spec 必须同时产出：FPGA 寄存器头文件、Linux UAPI/驱动描述、设备树补丁（仅适用项）、协议版本与 ABI 哈希。地址、宽度、对齐、endianness、缓存一致性、DMA mask/IOMMU、IRQ 语义、复位时序和错误恢复均为必填或显式 not-applicable；禁止重复维护多份手写寄存器表。

9.4 Flash 的事务与权限模型

Flash 是高风险独立 capability。流程为 discover → identify → snapshot layout → validate images → dry-run plan → explicit approval → write → verify → reboot/health-check。请求必须携带稳定设备标识、期望 SoC/模式、profile ID 和镜像哈希；多设备或身份不一致即拒绝。禁止把串口设备路径当作 rkdeveloptool 的设备选择器，也禁止默认擦除和硬编码 LBA。全盘镜像、bootloader、GPT 与用户数据分区采用不同风险级别。

9.6 明确纠正的设计假设

  • RGMII 的延时只能由 MAC、PCB 或 PHY 中的明确一处/组合承担；phy-mode 必须与硬件一致。fixed-link 与“通过 MDIO 配置内部 PHY”是两种不同模型，不应同时描述为默认方案。
  • MAC 地址来源是板级策略（OTP/NVMEM、bootloader 注入、生产配置），不能笼统假定 RK3588 OTP 一定已有可用唯一地址。
  • Combo PHY、PCIe/SATA/USB3 复用、MIPI DPHY 共享和 GPIO 可用性均取决于封装、原理图和 BSP；附录中的“无冲突”只能作为待验证候选，不能作为设计承诺。
  • update.img、trust.img、uboot.img、FIT/Android boot image 等产物由 BSP 打包方案决定；Adapter 通过 profile 描述产物图，不固定某一种命名。

9.7 测试策略

单元测试覆盖 profile schema、命令转义、日志解析、DT/Bridge 生成与诊断去重；契约测试用 fake toolchain 验证事件序列、取消、超时和失败传播；集成测试对锁定 BSP 做 clean/incremental build；HIL 测试用独占锁管理板卡，采集串口并验证冷启动、烧录恢复与 Bridge 压力。发布兼容矩阵的最小键为 adapter + profile + BSP commit + board revision + boot media。

以下列出 Bridge 四种物理接口占用的 RK3588 主要引脚组及其潜在的冲突风险：

A.1 PCIe Gen3 x4 引脚占用

引脚组 引脚 功能 冲突风险
PCIE30X4_TX[3:0] TX0_P/N ~ TX3_P/N PCIe 发送 独占，无复用
PCIE30X4_RX[3:0] RX0_P/N ~ RX3_P/N PCIe 接收 独占，无复用
PCIE30X4_REFCLK REFCLK_P/N PCIe 参考时钟 与 PCIe30X2 共享 PHY
PCIE30X4_PERSTn PERSTn PCIe 复位 可复用为 GPIO
PCIE30X4_WAKEn WAKEn PCIe 唤醒 可复用为 GPIO
PCIE30X4_CLKREQn CLKREQn 时钟请求 可复用为 GPIO

冲突检查: - ⚠️ PCIe30x4 与 PCIe30x2 共享同一 PHY，不能同时使用 - ⚠️ PCIe30x4 与 SATA 部分引脚共享，若使用 SATA 需检查

A.2 GE Ethernet (RGMII) 引脚占用

引脚组 引脚 功能 冲突风险
GMAC0_TXCLK TXCLK 发送时钟 (125MHz) 独占
GMAC0_TXD[3:0] TXD0~TXD3 发送数据 独占
GMAC0_TXCTL TXCTL 发送控制 独占
GMAC0_RXCLK RXCLK 接收时钟 独占
GMAC0_RXD[3:0] RXD0~RXD3 接收数据 独占
GMAC0_RXCTL RXCTL 接收控制 独占
GMAC0_MDC MDC MDIO 时钟 与 GMAC1 独立
GMAC0_MDIO MDIO MDIO 数据 与 GMAC1 独立

冲突检查: - ⚠️ RGMII 占用约 14 个专用引脚，不与普通 GPIO 冲突 - ⚠️ GMAC0 与 GMAC1 引脚独立，可同时使用 - ✅ RGMII 信号为高速信号，PCB 布局需做等长和阻抗匹配

A.3 MIPI CSI/DSI 引脚占用

MIPI CSI (输入):

引脚组 引脚 功能 冲突风险
CSI_DPHY0_CLK CLK_P/N CSI 时钟 独占
CSI_DPHY0_D[3:0] D0_P/N ~ D3_P/N CSI 数据 独占

冲突检查: - ⚠️ CSI DPHY0 与 CSI DPHY1 独立，可同时使用（各有独立 DPHY） - ⚠️ CSI 使用 DPHY，不能与 DSI 共用同一 DPHY

MIPI DSI (输出):

引脚组 引脚 功能 冲突风险
DSI_DPHY0_CLK CLK_P/N DSI 时钟 独占
DSI_DPHY0_D[3:0] D0_P/N ~ D3_P/N DSI 数据 独占

冲突检查: - ⚠️ DSI0 与 DSI1 独立，可同时使用（各有独立 DPHY） - ⚠️ DSI DPHY0 与 LVDS 可能共享 IO 资源，需检查具体封装

A.4 GPIO 引脚占用（与 Bridge 相关）

GPIO Bank 总引脚数 预留情况 可用性
GPIO0 32 (PA0~PD7) PMU 相关，部分被系统占用 ⚠️ 谨慎使用，PA0~PA7 通常可用
GPIO1 32 (PA0~PD7) 部分被 UART2/I2C 占用 ✅ 大部分可用
GPIO2 32 (PA0~PD7) 可能被 Camera/SPI 占用 ✅ 需检查具体电路
GPIO3 32 (PA0~PD7) 部分被 SDMMC/I2S 占用 ✅ 可用，需检查
GPIO4 32 (PA0~PD7) 部分被 GMAC1/PCIe 占用 ⚠️ 若使用 GMAC1 则受限

建议 GPIO 分配策略: 1. 优先使用 GPIO1 或 GPIO3 中空闲的引脚 2. 避免使用已被内核驱动占用的 GPIO（如 sdmmc_det, wifi_reg_on 等） 3. 中断信号（FPGA_IRQ）使用 GPIO0（支持独立的 IRQ 功能） 4. 检查当前板卡 BSP Device Tree 中的 pinctrl 配置，确认空闲引脚

A.5 综合冲突检查矩阵

接口组合 冲突可能性 说明
PCIe x4 + GMAC0 ⚠️ 待板级验证 核对封装、原理图、电源域、时钟和 pinctrl
PCIe x4 + MIPI CSI ⚠️ 待板级验证 核对 Combo PHY/DPHY 资源与实际走线
PCIe x4 + MIPI DSI ⚠️ 待板级验证 核对 Combo PHY/DPHY 资源与实际走线
GMAC0 + MIPI CSI ⚠️ 待板级验证 核对复用、电源域和板级连接
GMAC0 + MIPI DSI ⚠️ 待板级验证 核对复用、电源域和板级连接
MIPI CSI + MIPI DSI ⚠️ 待板级验证 不能仅凭控制器名称推断 DPHY 独立性
PCIe30x4 + 其他 HSIO ⚠️ 高风险 以目标封装的 TRM、原理图和 BSP PHY 配置为准
GMAC0 + GMAC1 ⚠️ 待板级验证 控制器存在不代表目标板均已引出且供电可用
所有四种接口同时使用 ⚠️ 未证明 需完成资源分配表、SI/PI 评审及逐接口 HIL 验证
