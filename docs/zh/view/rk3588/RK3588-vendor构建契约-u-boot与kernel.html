RK3588 vendor 构建契约：u-boot 与 kernel

RK3588 vendor u-boot / kernel 构建契约（2026-11-11 实测）

适用 EvoVerse SDK v1.0.1 · 2026-11-28

出处：ws-e2 公开源 BSP 重建实测（kernel develop-6.1@77168c8d5、u-boot next-dev@1c535d65、 rkbin@3e288fe8、buildroot 2026.08.1，交叉工具链 aarch64-linux-gnu-gcc 13.3.0）。 本文记录 vendor 树的构建契约——这些行为不在任何 --help 里，逐条试错代价高，Adapter build flow 与现场工程都应按本文执行。对应复盘清单 C10/C11/C12（project-review/2026-11-10-ws-e2-rk3588-env-migration）。

1. 宿主依赖（C9 事实边界）

rk3588-ai 环境的 platform-builder 镜像（Ubuntu 24.04 基线，137 包）只有交叉编译器 aarch64-linux-gnu-gcc 13.3.0，没有 host 构建工具。完成 vendor kernel/u-boot 构建需要：

用途 host 依赖
kernel/u-boot 通用 make、gcc（host 编译 scripts/tools）、bc、bison、flex、pkg-config、rsync、libssl-dev
kernel dtb device-tree-compiler（dtc）
u-boot FIT dtc + swig（若启用)
idbloader 打包 u-boot 树自带 tools/mkimage（无需 apt 版）
boot.img（Android bootimg） mkbootimg（Ubuntu 包 mkbootimg）

容器配方若只装交叉编译器，平台构建会以连环 host-tool 缺失失败——镜像要求清单进 manifest， verify 阶段应校验「镜像内可独立完成 vendor kernel defconfig 构建」（C9 修复方向）。

2. vendor kernel 构建契约

入口：rockchip_linux_defconfig + rk3588.config fragment 合并（fragment 在 arch/arm64/configs/rk3588.config，由 kconfig merge 完成）。

  1. merge_config.sh 必须在 O= 目录内调用（C12）： merge_config.sh 把合并结果写到 $KCONFIG_CONFIG（默认 .config，即当前工作目录）。 在源树根调用会把 kernel/.config 写进源树 → 随后任何 make O= 触发 outputmakefile "The source tree is not clean" 检查失败。正确做法： bash make O=$O rockchip_linux_defconfig cd "$O" && "$K/scripts/kconfig/merge_config.sh" -m .config "$K/arch/arm64/configs/rk3588.config" make olddefconfig && make -j"$(nproc)" Image dtbs
  2. O= 与 in-tree 污染互相阻断：任何一次失败/中断后先 make mrproper（源树）并删除 O= 目录， 恢复干净基线再定位真因；不要在脏树上换通道反复试。
  3. kernel 默认不开 -Werror，对 gcc 13/14 告警宽容（vendor 6.1.172 在 gcc 13.3 实测干净通过）。

3. vendor u-boot 构建契约

入口：rk3588_defconfig（变体用 rk3588-*.config fragment）。实测约束：

  1. vendor 树自带 -Werror，与 gcc 13.3 不兼容（C10）：
  2. common/edid.c：-Wmaybe-uninitialized（gcc 13 新分析）
  3. common/command.c：-Wenum-int-mismatch（gcc 13 新增告警类） 通过方式：make KCFLAGS="-Wno-error"（告警保留可见、不致命）。构建收据必须记录该放宽。
  4. FIT 组装读硬编码文件（C11）：arch/arm/mach-rockchip/make_fit_atf.sh → decode_bl31.py 读源树根的 ./bl31.elf 与 ./tee.bin——make 变量 BL31= 不进脚本。 构建前必须按 vendor 惯例拷入： bash cp rkbin/bin/rk35/rk3588_bl31_v1.56.elf u-boot/bl31.elf cp rkbin/bin/rk35/rk3588_bl32_v1.23.bin u-boot/tee.bin
  5. idbloader.img 没有 make 规则（C11）：vendor fork 把打包留给 SDK 层。TPL+SPL 均为 树内源码构建（rk3588 in-tree TPL 含 sdram 驱动，非 rkbin ddr blob 路线亦可），打包命令： bash ./tools/mkimage -n rk3588 -T rksd -d tpl/u-boot-tpl.bin idbloader.img cat spl/u-boot-spl.bin >> idbloader.img idbloader 写 eMMC 扇区 0x40（64）；u-boot.itb（make u-boot.itb 产出）写 uboot 分区。 vendor 备选路线：ROCKCHIP_TPL 指向 rkbin ddr blob（rk3588_ddr_lp4_2112MHz_lp5_2400MHz_v1.24.bin）。
  6. O= 支持但被 in-tree 残留阻断（C12）：prepare3 检查同 kernel；失败后 make distclean。
  7. boot 流程是 Android bootimg：rk3588_defconfig 含 CONFIG_ANDROID_BOOTLOADER + CONFIG_CMD_BOOT_ANDROID（无 extlinux bootmethod）——boot 分区内容必须是 mkbootimg 产物， dtb 走 --second。注意 CONFIG_ANDROID_AVB=y：未配 vbmeta 的裸 boot.img 是否被 AVB 拒收 属板级 bring-up 待验证项（ws-e2 硬件 NOT_RUN）。

4. 工具链 × BSP 兼容门（C10 修复方向）

环境身份（容器 digest / toolchain sha）与 BSP 身份（commit）目前互不校验——「绑定成功 ≠ 可构建」。 本节契约应编码进 Adapter preflight： - u-boot：检测 vendor 树 -Werror 与工具链告警类组合，或统一预置 KCFLAGS=-Wno-error 并记入收据； - kernel：gcc 13/14 实测可用，无需放宽； - 升级 vendor commit 或工具链大版本时，本表需重新实测。

5. ws-e2 工作样例

完整可执行样例见 catalog 交付物 boards/ws-e2/carriers/rk3588j-evm/bsp/（bundle + manifest + board-ws-e2 BR2_EXTERNAL 树，buildroot LINUX_OVERRIDE_SRCDIR 方式消费 pinned kernel）。 2026-11-11 冒烟证据：kernel Image 6.1.172 + 77 dtbs；idbloader.img/u-boot.itb sha256 见该目录 manifest。
