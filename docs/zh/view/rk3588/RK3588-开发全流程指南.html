RK3588 开发全流程指南

RK3588 开发全流程指南

版本：v1.0.0　更新日期：2026-09-25
当前基线：WS-E2 / RK3588J / BSP b8f5dda5 / 工具链 2026.09

本文说明 EvoVerse 当前真实可用的环境部署、工程生成和最小系统构建链路。第一次操作请直接阅读《WS-E2 RK3588J 最小系统自然语言教程》。

1. 四个状态不能混用

flowchart LR
  A[安装三个 VSIX] --> B[同步 Catalog]
  B --> C[双离线包部署]
  C --> D[环境 READY]
  D --> E[生成并绑定工程]
  E --> F[PROFILE_READY]
  F --> G[Preflight + 四阶段构建]
  G --> H[工程 BUILD_READY]
  H --> I[烧录与硬件验证 NOT_RUN]
  • 环境 READY：Docker、固定工具链、WS-E2 BSP、回执和逐文件身份通过检查。
  • 工程 PROFILE_READY：工程骨架已生成，但绑定或 preflight 尚未完全闭合。
  • 工程 BUILD_READY：同一 Build Identity 下 U-Boot、kernel/DTB、rootfs、package 全部成功。
  • 硬件 NOT_RUN：尚未完成烧录、启动、DDR/eMMC 和板级接口验证。

环境部署不会查找或改写任意客户工程，环境 READY 也不等于工程 BUILD_READY。

2. 交付组成

三个 VSIX

VSIX 职责
evoverse-sdk-1.0.0.vsix SDK Shell、Catalog、自然语言工具和系统编排
evoverse-efinity-adapter-1.0.0.vsix WS-E2 FPGA 侧 Efinity 能力
evoverse-rk3588-adapter-1.0.0.vsix RK3588 环境体检、工程预检、构建和证据展示

双离线包

大型 BSP 不进入 Git 或客户安装包。客户向 EvoVerse 获取：

文件 字节数 SHA-256
rk3588-toolchain-2026.09.evopkg 256,584,627 d05eaff178a72f6764e75f52418ee3e642a74cb15ca182c93a03cdc005fc28f2
ws-e2-rk3588-bsp-b8f5dda5.evopkg 344,225,733 b3107d7bfeabc1fc29bf013bbc980d3d6b883d7ce4e5ef97881b42d2fc43f118

Catalog 还锁定内部 manifest、最低 Adapter 版本、板卡绑定和许可策略。部署硬门槛为 8,300,000,000 字节，建议至少保留 9 GiB。

3. 环境建立

  1. 安装三个 VSIX 和 Docker Desktop，切换到 Linux containers。
  2. 同步私有 Catalog。
  3. 执行 Adapter 环境体检。
  4. 将双离线包放入 <EVOVERSE_HOME>/downloads/rk3588/，或逐个选择。
  5. Adapter 校验外层大小/SHA、内部 manifest、逐文件 checksum 后签发一次性 inspection token。
  6. 用户明确接受许可，再执行一键部署。
  7. Adapter 重建 BSP Git 树、导入 Docker image、运行 BSP qualification、写入逐文件回执并再次体检。

默认位置：BSP 在 <EVOVERSE_HOME>/bsp/ws-e2/b8f5dda5/，工具链材料在 <EVOVERSE_HOME>/toolchains/rk3588/2026.09/，回执在 <EVOVERSE_HOME>/receipts/rk3588/。

部署具备事务语义：取消或失败时回滚本次目录、回执和新导入的镜像；部署前已有镜像不删除。半套安装只有在完整文件闭包、BSP qualification 或 Docker image 身份重新通过后才复用。

4. WS-E2 最小系统推荐

整理后的 WS-E2 材料确认核心板包含 RK3588J、PMIC、电源时序、LPDDR4X、eMMC 和 24 MHz 基准时钟；载板提供最小启动所需的串口与 USB OTG 路径。当前推荐：

  • Rockchip Linux 6.1 系列 BSP；
  • eMMC 启动，UART2 输出首个启动日志；
  • Buildroot minimal rootfs；
  • 先闭合 SoC 最小启动，再加入 FPGA↔RK3588 接口。

这是工程推荐，不是实板结论。DDR 参数、loader、分区表和 DTS 必须来自当前 Catalog/BSP 身份，不能按“同为 RK3588”跨板复用。

5. 自然语言生成工程

用户只需在自然语言中选择 WS-E2、rk3588j-evm、目标 rk3588 和工程目录。Agent 调用 SDK 的板卡工程生成链路，不让用户手写 Profile 或 DTS。

生成物包括：

  • evoverse-rk3588-profile.json：板卡、BSP、容器、工具链、loader、分区和四阶段命令；
  • .evoverse/board/*.dts / *.dtsi：受生成 manifest 管理的板级候选；
  • .evoverse/rk3588-generation-manifest.json：生成输入和文件所有权；
  • applications/：客户代码区，再生成时保留；
  • output/：构建报告、回执、日志和固件。

材料不完整时保持 PROFILE_READY 并返回 BSP_BINDING_REQUIRED，不得把模板状态冒充为可构建。

6. Preflight 与四阶段构建

flowchart TD
  P[Preflight] -->|身份一致| U[U-Boot]
  P -->|不一致| X[阻塞并说明修复动作]
  U --> K[Kernel + DTB]
  K --> R[Buildroot rootfs]
  R --> F[Firmware package]
  F --> E[Receipts + Build Identity]
  E --> B[BUILD_READY]

Preflight 重新检查 BSP Git 状态、固定 commit、submodule、loader/分区 SHA、容器 digest、工具链和 DTS manifest。tracked 文件发生变化时返回 BSP_SOURCE_DIRTY 或 BSP_QUALIFICATION_STALE，不会继承历史 PASS。

阶段 主要产物
U-Boot uboot.img
Kernel Image、rk3588j-evoverse.dtb
Rootfs rootfs.ext2
Package ws-e2-rk3588j-minimal-firmware.tar.gz

成功判定同时要求退出码、当次必要产物、产物 SHA-256 和六字段 Build Identity 一致。真实工具错误不能因旧产物存在而降级为成功。

7. 证据与边界

所有构建证据归属于工程目录下的 .evoverse/output/：

  • .evoverse/output/build-report.json：整体 success、readiness 和 diagnostics，是最终状态的唯一权威；
  • .evoverse/output/build-manifest.json：阶段命令、退出码和产物摘要；
  • .evoverse/output/logs/：原生命令输出；
  • 固件压缩包：软件构建产物，不代表已经烧录或启动。

聊天回复中的阶段状态只是上述证据的摘要；两者冲突时以 build-report.json 为准。

WS-E2 历史基线曾完成真实四阶段构建并达到 BUILD_READY，但它不替代客户当前工程的 preflight 和新构建。

8. FPGA + RK3588 后续扩展

最小系统完成后可创建 system 目标，绑定 FPGA 证据、RK3588 BUILD_READY 证据和同一接口契约。板间连接器不作为独立设计真值；系统消费最终器件/管脚映射以及 PCIe、MIPI、RGMII 或 GPIO 接口契约。

9. 常见阻塞

状态 正确处理
PACKAGE_REQUIRED 获取声明版本的两个离线包
PACKAGE_DIGEST_MISMATCH 更换原包，不修改 Catalog 或回执
USER_ACTION_REQUIRED 处理 Docker、空间或冲突目录后重检
BSP_BINDING_REQUIRED 用当前已部署材料重新生成/绑定工程
BSP_SOURCE_DIRTY 备份并恢复声明版本，不绕过 qualification
PROFILE_READY 继续补齐绑定并运行 preflight
BUILD_READY 进入烧录方案确认，硬件仍为 NOT_RUN
