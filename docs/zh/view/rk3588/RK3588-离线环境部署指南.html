RK3588 离线环境部署指南

RK3588 离线环境部署指南

本文适用于 WS-E2 的 RK3588J 开发环境。SDK 不从公网或网盘自动下载大型 BSP；请先向 EvoVerse 获取两个经过锁定的离线包，再由 RK3588 Adapter 完成校验、部署和资格检查。

需要获取的两个文件

文件 下载大小 安装后用途 SHA-256
rk3588-toolchain-2026.09.evopkg 256,584,627 字节（约 244.7 MiB） Ubuntu 22.04 / AArch64 GNU 交叉编译 Docker 镜像 d05eaff178a72f6764e75f52418ee3e642a74cb15ca182c93a03cdc005fc28f2
ws-e2-rk3588-bsp-b8f5dda5.evopkg 344,225,733 字节（约 328.3 MiB） 固定提交的 kernel、U-Boot、rkbin、Buildroot 和 WS-E2 输入 b3107d7bfeabc1fc29bf013bbc980d3d6b883d7ce4e5ef97881b42d2fc43f118

BSP 重建后的预计占用约 4.03 GiB；工具链镜像展开约 685 MiB。Catalog 的部署硬门槛为 8,300,000,000 字节，考虑日志与后续构建，建议目标磁盘至少保留 9 GiB。

部署前准备

  1. 安装并启动 Docker Desktop，切换到 Linux containers。
  2. 确认 SDK 已同步最新私有 Catalog。
  3. 确认目标磁盘有足够空间。
  4. 不要解压、改名或重新压缩 .evopkg。

默认 EVOVERSE_HOME 是 %USERPROFILE%\evoverse-sdk。如果在 SDK 设置中改过它，下面所有路径都以实际配置为准。

推荐操作：放入固定目录后一键部署

  1. 在 RK3588 Workbench 的 Overview 中点击“打开离线包目录”。
  2. 把两个 .evopkg 都复制到：

text <EVOVERSE_HOME>\downloads\rk3588\

  1. 点击“检查环境”。只有两个包的文件名、大小、外层 SHA-256、内部 manifest 和逐文件 checksum 全部通过后，界面才会提供本次检查绑定的部署令牌。
  2. 阅读许可提示并勾选许可确认。
  3. 点击“一键部署”，不要在部署过程中关闭 IDE 或 Docker Desktop。
  4. 等待 Overview 显示 READY，再进入 Build。

如需中止，使用当前运行的取消操作；Adapter 会通过同一运行 ID 取消解包/部署，并回滚本次新建的安装目录、回执和 Docker 镜像，不删除部署前已经存在的镜像。

也可以点击“选择离线包”分别选择两个文件。选择文件不会立刻安装；必须两个包都通过同一次受控检查后，才能部署。

Adapter 实际做了什么

flowchart LR
  A[两个离线包] --> B[大小与外层 SHA-256]
  B --> C[manifest 与逐文件 checksum]
  C --> D[暂存目录解包]
  D --> E[Docker load 并核对 image ID]
  D --> F[Git bundle 重建 BSP]
  F --> G[root/submodule/loader/分区表/工具链资格校验]
  E --> H[原子安装与回执]
  G --> H
  H --> I[Environment READY]
  I --> J[工程 preflight / build]
  J --> K[硬件验证仍为 NOT_RUN]

BSP 包中不直接保存 .git 目录，而是保存受控 Git bundle。部署时会重建一个真实 Git 仓库，恢复固定 root commit 和四个 submodule，再调用 SDK 原有 BSP 资格门禁。资格失败时不会把暂存结果冒充正式安装。

安装结果

内容 默认位置
BSP <EVOVERSE_HOME>\bsp\ws-e2\b8f5dda5\
工具链归档 <EVOVERSE_HOME>\toolchains\rk3588\2026.09\
安装回执 <EVOVERSE_HOME>\receipts\rk3588\
临时部署区 <EVOVERSE_HOME>\staging\rk3588\

请不要手工编辑安装回执。已安装目录与回执不匹配时，健康检查会报告 REPAIRABLE 或 USER_ACTION_REQUIRED，不会静默覆盖未知内容。

状态含义

  • PACKAGE_REQUIRED：缺少一个或两个离线包。
  • REPAIRABLE：包已找到且环境可以通过受控部署修复。
  • USER_ACTION_REQUIRED：需要用户处理 Docker、磁盘空间、包损坏或现有目录冲突。
  • READY：环境身份和安装回执通过；这不等于工程已经编译。
  • BUILD_READY：当前工程已通过自己的 preflight，可开始受控构建。
  • NOT_RUN：尚未完成烧录或板级硬件验证。

常见问题

报 PACKAGE_DIGEST_MISMATCH

文件不是 Catalog 声明的原包，或复制过程损坏。删除该副本，重新向 EvoVerse 获取；不要修改 Catalog JSON 或校验回执。

Docker CLI 存在但 daemon 不可用

启动 Docker Desktop，等待引擎就绪，并确认当前为 Linux containers，然后重新点击“检查环境”。

现有安装目录不匹配

工具不会覆盖来源不明的目录。先备份该目录及回执，再由工程负责人确认是恢复旧版本还是移走冲突目录，之后重新部署。

可以只拿 BSP、不拿工具链吗

不可以。WS-E2 的可复现环境同时绑定 BSP 与工具链镜像；缺少任一包都不会生成部署令牌。

READY 后是否可以直接烧录

不可以。仍需生成/确认工程 Profile，执行 preflight 和 Build，并完成固件、烧录方式及板级验证。环境健康只解决“开发材料和工具是否为声明版本”。

一键部署不会查找或改写任意客户工程的 Profile。环境达到 READY 后，用户仍需明确选择目标工程，再由工程生成/绑定链路写入 BSP、容器、loader 和分区身份；只有该工程自己的 preflight 通过，才会得到 BUILD_READY。

高级参考用于按需查询；设计记录、发布流程、审计报告和未来规划不属于客户操作入口。
