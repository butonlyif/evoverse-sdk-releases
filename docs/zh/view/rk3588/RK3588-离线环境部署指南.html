RK3588 离线环境部署指南

RK3588 离线环境部署指南

适用 EvoVerse SDK v1.0.1 · 2026-11-26

本文适用于 WS-E2 的 RK3588J 开发环境。环境安装由独立交付的 Linux Environment Manager（evoverse-env）执行，RK3588 Adapter 是唯一本地客户端；SDK 不代理 Manager 命令，VSIX 也不内置 Manager 或大型 BSP。

交付物

交付物 用途
Ubuntu 24.04 x86_64 的 evoverse-env .deb 安装、验证和运行 RK3588 环境
经验签的 release assets 目录 包含环境索引、manifest、material lock 和许可策略
rk3588-toolchain-2026.09.evopkg 固定的 AArch64 交叉编译工具链物料
ws-e2-rk3588-bsp-b8f5dda5.evopkg 固定的 kernel、U-Boot、rkbin、Buildroot 和 WS-E2 输入

两个 .evopkg 的发布身份以 release assets 中的签名索引和 material lock 为准，不要解压、改名或重新压缩。部署硬门槛为 8,300,000,000 字节，建议至少保留 9 GiB。

主机和连接前提

  1. 在 Ubuntu 24.04 x86_64 主机安装 Manager .deb，准备可用的 Docker Engine。
  2. 执行 evoverse-env handshake --json，确认输出包含 environment-manager/v1。
  3. 默认安装到 /usr/bin/evoverse-env 或 /usr/local/bin/evoverse-env 时，Adapter 会自动发现。其他位置在 RK3588 Adapter 设置 evoverse.rk3588.environmentManagerPath 中填写绝对路径。
  4. Adapter 只校验合同主版本和必需能力，Manager 与 Adapter 可各自升级；已选中的二进制在会话内不会静默切换。

Windows IDE 本身不是 Manager 的安装主机。当前没有 SDK Proxy、HTTP Hub 或隐式 WSL 转发；如果 IDE 在 Windows 上运行，必须显式提供 Adapter 能直接启动的本地 Manager launcher，否则应在 Ubuntu 主机上运行 IDE/Adapter。

安装流程

Workbench 会使用同一条 Adapter → evoverse-env 直连通道完成下列步骤：

  1. catalog list 读取已验签的 release assets；
  2. plan create 为明确的 <id>@<version> 生成确定性计划，其 planDigest 绑定材料、版本和磁盘影响；
  3. Workbench 展示计划和许可，用户确认后 Adapter 签发并立即消费单次 token；
  4. Manager 以原计划和显式许可集执行 install，不会静默重新规划；
  5. verify 重新验证安装身份，只有提交回执和 quick verify 都通过才返回环境 READY。

Manager 拥有事务、许可、安装回执和环境身份；Adapter 只拥有 UI 确认、调用会话和标准化结果。取消或失败不得伪造 READY。

诊断

状态 处理
MANAGER_NOT_FOUND 安装 .deb 或配置 evoverse.rk3588.environmentManagerPath
RK_MANAGER_INCOMPATIBLE 根据缺失合同/能力升级 Manager；不要放宽安全校验
RK_MANAGER_UNREACHABLE 检查可执行权限、主机和 handshake --json 输出
LICENSE_NOT_ACCEPTED 重新审阅当前计划的许可集并确认
MATERIAL_DIGEST_MISMATCH 替换为发布锁定的原始物料，不修改索引或回执
INSUFFICIENT_SPACE 清理磁盘后重新生成计划

环境 READY 只证明安装和环境身份。工程编译、烧录、启动和板上验证是独立阶段；未执行时必须保持 NOT_RUN。
