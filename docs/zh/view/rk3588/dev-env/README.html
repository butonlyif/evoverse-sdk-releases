RK3588 最小可交叉编译环境（Windows + WSL2）

为 vibe coding 而设的 RK3588 AArch64 交叉编译最小基线。不含 SDK 全量构建/烧录链路； 那部分必须等目标板卡 + BSP 锁定后再上（见 RK3588-开发环境调研报告.md 8.x）。

1. 使用方法

# 进入 WSL Ubuntu
wsl -d Ubuntu-22.04

# 加载本目录的环境脚本
source /mnt/d/work/trae_projects/RK3588/.scratch/rk3588-dev-env.sh

# 跨编 + 冒烟测试
cd /mnt/d/work/trae_projects/RK3588/.scratch
aarch64-linux-gnu-gcc -O2 -Wall -static hello.c -o hello
qemu-aarch64-static ./hello    # 应输出 hello from aarch64 (uid=...)

# DTS 编译/反编译
dtc -I dts -O dtb -o probe.dtb probe.dts

2. 已安装清单

组件 版本 用途
Ubuntu 22.04.5 LTS WSL2 distro Linux 编译环境
gcc-aarch64-linux-gnu / g++-aarch64-linux-gnu Ubuntu 11.4.0 AArch64 交叉编译器
libc6-dev-arm64-cross 2.35 cross3 跨编 C 库 + sysroot
device-tree-compiler (dtc) 1.6.1 DTS ↔ DTB
qemu-user-static 6.2.0 本机跑 AArch64 ELF 冒烟测试
python3 / python3-venv 3.10.12 RKNN / 通用脚本
numpy / onnx 1.26.4 / 1.22.0 在 venv /root/rknn-venv 内

3. 已验证（端到端）

  • ✅ aarch64-linux-gnu-gcc -static hello.c 产出 ELF 64-bit LSB ARM aarch64
  • ✅ qemu-aarch64-static ./hello 在 host 上跑通
  • ✅ dtc DTS↔DTB 双向编译
  • ✅ 跨编译 sysroot 通过 /usr/aarch64-linux-gnu/lib/pkgconfig 可被 host pkg-config 检索

4. 未完成项 / 待目标板 + BSP 决定后再做

  1. RKNN Toolkit2 wheel 安装 —— 必须等板卡/BSP + NPU 驱动版本确定后再装，避免 numpy/librknn 版本冲突
  2. rkdeveloptool —— 烧录工具链；需要 USB 设备透传方案（WSL2 不默认直通）
  3. BSP 全量容器化 —— 调研报告 3.3.2 的 rk3588-dev Docker 镜像；只在锁定板卡后才有意义
  4. build-manifest.json 契约 —— 调研报告 8.2；首块板卡选定后再生成
  5. 板级 DTS overlay —— 调研报告 5.x；需要 vendor DTS 才能制定 overlay
  6. kernel module cross build —— 需要把目标 kernel headers 从 vendor BSP 拉来作为 sysroot，不应当前 venv

5. 已知小坑

  • aarch64-linux-gnu-pkg-config 不在 Ubuntu 仓库；用 PKG_CONFIG_LIBDIR=/usr/aarch64-linux-gnu/lib/pkgconfig + host pkg-config
  • WSL2 当前默认 distro 仍是 docker-desktop；切换：wsl -s Ubuntu-22.04
  • WSL2 不默认直通 USB Maskrom 设备，烧录前要在 Windows 主机上验证设备可达性或准备 usbipd
