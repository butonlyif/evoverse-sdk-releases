工作树资产与 RTL 基线

工作树资产与 RTL 基线（Asset Observe / Adopt）

版本：v1.0.0 · 状态：已实现 · 范围：控制面 asset.observe / asset.adopt 动作

1. 背景与动机

可靠设计流程需要明确回答一个问题：哪些文件是既有基线（只读），哪些文件是本次增量（可交付）？

  • 控制面把工程内所有已登记文件按字节哈希作为只读基线。Agent 直接改写基线文件不是一次合法的状态变更。
  • Catalog 物料（Jacket / Demo / IP）经 catalog sync 落地后属于外部只读材料，永远不进入可写范围；可靠流程通过规格的 MaterialContract 引用它们。
  • 已有工程中"自由代码"（未经控制面登记的本地改动）要进入可靠流程，必须先经过资产观察与采纳，不能静默混入候选。

2. 机制

2.1 asset.observe — 观察工作树

记录工作树观察证据（WORKTREE_OBSERVED），不改变任何状态：

{
  "actionId": "asset.observe",
  "inputs": { "scanRoot": "rtl/" }
}
  • scanRoot：由服务执行扫描（observation scan），返回观察到的资产清单。
  • assets：也可以直接提交一份显式资产列表。
  • 前置条件：工程已初始化（project.initialize）。

2.2 asset.adopt — 把自由代码纳入受管候选

在活动 Intent 下，把观察到的 WORKING 资产冻结为候选（CANDIDATE_FROZEN）：

{
  "actionId": "asset.adopt",
  "intentId": "INTENT-001",
  "inputs": { "assets": ["rtl/frame_writer.sv", "rtl/pack.sv"] }
}

前置条件（服务强制，不可绕过）：

  1. 工程已初始化，Intent 存在且处于活动状态。
  2. 被采纳资产状态为 WORKING。
  3. 采纳范围不得与任何活动候选范围重叠（_scope_conflict 拒绝）。
  4. 采纳必须覆盖 Intent 的完整声明范围——不允许一半走采纳、一半走新生成。

2.3 采纳之后的正常流程

采纳冻结候选后，按标准链路继续：

spec.approve → candidate.deliver（files/filesRoot，含 Design Assurance）
→ verification.simulate（iverilog / questa）→ build.native → hardware.*

3. 与历史 bootstrap 方案的关系

v0.9.0 设计稿曾规划独立的 rtl_baseline_register MCP 工具 + rtl_task_* 状态摘要 + sync hook。v1.0.0 控制面收敛后，该方案整体退役：

旧概念 v1.0.0 对应物
rtl_baseline_register 扫描登记 asset.observe（扫描即观察证据）
stateDigest / expectedStateDigest revision（每次动作后递增，读改写由 expectedRevision 保护）
writableCandidatePaths 隔离 candidate.deliver 的 files 清单 + 只读基线拒绝
sync_catalog 后自动登记 不需要——catalog 物料始终是只读材料，经 MaterialContract 引用
安装脚本首跑 bootstrap 不需要——首次 project.initialize 即建立基线

4. 边界

  • 采纳不产生 Design Assurance 或仿真证据；只有 candidate.deliver / verification.simulate 产生。
  • 编译依赖（IP 输出、综合产物）不会因为被观察而变成可写文件。
  • 观察结果只是证据快照；工作树在观察之后又发生直接改动时，需要重新观察再采纳。
  • 初始基线尚未形成时，第一个设计作为无 feature worktree 的 INITIAL_DESIGN 系统集成 Intent 在主线执行；完成前不允许创建第二个 Intent。形成基线后，feature Intent 由 SDK 放入独立 Git worktree，最多同时 4 个。
  • Feature 本地验证只到 READY_FOR_INTEGRATION。主线系统集成 Intent 的 FIFO 可中止合并、组合规格、系统仿真与文档确认属于控制面执行生命周期，不替代 asset.observe / asset.adopt 的资产证据语义。
