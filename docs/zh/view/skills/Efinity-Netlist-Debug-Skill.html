Skill：自然语言网表调试

自然语言网表调试

efinity-netlist-debug Skill 用于在 Trae 对话中调试一个已编译的 Efinity 工程：描述你想观察什么行为（信号、总线、状态机、握手、计数器），Skill 从编译后网表发现候选信号并呈现给你。对话在发现后停止——确认选点、生成调试配置与调试编译都在 Workbench Debug 页完成。这条流程不修改 RTL——不写 (* mark_debug *) 属性，选中的是综合后的真实标量信号，不会被综合改名或优化掉。

调用方式因宿主而异：Trae 中 SDK 已把本 Skill 装入宿主 Skill 目录，可直接用 /efinity-netlist-debug 调用；VS Code 中 Skill 经 VSIX 的 chatSkills 声明提供给 Copilot Chat（agent 模式按需加载，需已安装 Copilot Chat 扩展），等效做法是让 Agent 直接读取交付包内的 Skills/efinity-netlist-debug/SKILL.md 并按其执行（MCP 调试工具已由 SDK 写入 mcp.json）。

用法示例

/efinity-netlist-debug
我想观察 counter 计到 0xA5 时 rdata 的变化。

完成契约分两段：对话只跑 SELECT → INTENT → DISCOVER，呈现 Adapter 的排序候选后即停止；CONFIRM → PROFILE → BUILD → HAND OFF 由 Workbench 接管——你在 Workbench Debug 页确认结构化选点，可信 host 铸造一次性的 APPLY 与 BUILD 确认，对话无法铸造或伪造任何确认。每个阶段单独汇报：发现、配置、编译、烧录、采集。

对话阶段（Skill 执行）

  1. SELECT：指定工程 XML（绝对路径）。工作区有多个 XML 时先问你选哪个，绝不按顺序、时间戳或文件名默认。
  2. INTENT：efinity_debug_intent_create 登记观察目标，Adapter 返回带 revision 的权威意图；改目标用 efinity_debug_intent_revise（按当前 expected_revision），随时可用 efinity_debug_intent_read 读取真实状态——不凭记忆信任上一次的响应。
  3. DISCOVER：efinity_debug_signals_discover 通过 Efinity 原生 STA 流程（efx_run --flow sta_tclsh）查询编译数据库，返回排序后的候选（精确 net: 标识、位宽、时钟状态、匹配原因）。候选只来自 Adapter，Skill 不添加自己的名字。呈现候选后对话即停止，引导你打开 Workbench Debug 页。对话绝不调用 efinity_debug_selection_preview、efinity_debug_selection_apply 或 efinity_debug_build——预览、应用与编译都在 Workbench 铸造的一次性确认之后，无确认的无头调用会被按设计拒绝。

Workbench 阶段（说明，不代跑）

  1. CONFIRM：你在 Workbench 从候选构造结构化选点（标量 ID 原样使用、探针类型、采样时钟/深度、userTap——只接受 USER1/USER2 闭合枚举，不是布尔值）。「全部采集」类请求会先展示探针数/位宽/深度总量并要求明确确认。efinity_debug_selection_preview 返回结构化预览（精确探针、解析后的 USER TAP、apply 将改动的 XML 摘要）与一次性回执，Workbench host 按该身份铸造 APPLY 确认。
  2. PROFILE：efinity_debug_selection_apply 在已铸造确认下消费一次性回执（重放失败关闭）；成功后意图到达 PROFILE_READY，配置文件与调试核由 Adapter 发布到工程的 work_dbg/，无人手写配置文件或 Tcl。
  3. BUILD：efinity_debug_build 在独立铸造的 BUILD 确认下执行带调试核的统一编译——已确认的 Apply 永不授权 Build。编译验收会把编译产物中的 jtag_user 与确认的 USER1/USER2 对账：任何 TAP 漂移都以 DEBUG_BUILD_REJECTED 失败关闭；阶段失败返回日志路径（DEBUG_BUILD_FAILED），不盲目重试。成功后意图到达 READY_TO_PROGRAM（含位流摘要）。
  4. HAND OFF：烧录、扫描设备、触发配置与采集在 Workbench Debug 页按同一权威状态进行；Skill 会主动提出打开它。

与 mark_debug 流程的关系

两条流程互补：已知要观察的源码信号、想保留属性标记时用 mark_debug 七步流程（见《Efinity 片上调试指南》§3）；想直接描述行为、由编译后网表选点时用本 Skill。两者不要混用——本流程既不读取也不生成 mark_debug 标记。

停止条件与纪律

  • BASELINE_BUILD_REQUIRED：没有当前编译数据库。普通 Build 是你的授权动作，Skill 不隐式代跑，会先询问。
  • STALE_DISCOVERY：源码或数据库在上次发现后漂移。重新发现即可；目标措辞要改就先 revise。过期的选点绝不复用。
  • UNRESOLVED_CLOCK_DOMAIN / AMBIGUOUS_BUS：选点跨时钟域或总线无法安全成组。收窄目标后重试，绝不默认取第一个时钟。
  • REVISION_CONFLICT：另一个界面（Workbench）与对话共享同一意图。用 efinity_debug_intent_read 重新读取并对账。
  • 源码变更使候选、回执与已铸造的确认失效——这是系统在正常工作，不是错误。

验收边界

本对话是唯一的自然语言输入；位流不是硬件证据。到达 READY_TO_PROGRAM 只说明调试核已编进位流（含摘要）；烧录、设备扫描与触发采集是独立的用户操作，未实际执行时一律报告 NOT_RUN，不由编译 PASS 推断。
