EvoVerse Design Spec Skill

EvoVerse Design Spec Skill

evoverse-design-spec 用于把一个 FPGA 或 FPGA 加软件的自然语言意图，转化为可评审、可实施、可追溯的设计包。它的产物是规格和实施计划，不是 RTL，也不会创建 Efinity 工程、约束、固件或编译产物。

何时使用

  • 从空目录开始一个新系统，先确定板卡、IP、接口、时钟、软件边界和验收标准。
  • 需要从 Catalog、Efinity 或其他允许使用的 Demo/IP 材料中提取事实，但不能把参考工程当作新工程的复制基线。
  • 需要让客户确认 RISC-V、硬 IP 模型、寄存器接口、外部接口或验证 Oracle 等影响架构的选择。

不适合用它做一次小的自由 RTL 修改；这类工作可直接编辑，或在需要受控证据时使用 /evoverse-rtl。

在 Trae 中调用

在目标工程的空目录打开 Trae 对话，先输入 Skill，再给出完整目标和材料范围。例如：

/evoverse-design-spec
为 WS-E1 的 TJ180A484S 新建一个工程：从 SD 卡读取图像，写入 DDR 帧缓存，再由 MIPI CSI-2 TX 输出到外部桥接器。
只从 Catalog、Efinity IP 和允许使用的其他 Demo 中发现物料；不得复制 sd-ddr-csi2 工程。请生成 design-package，列出每个物料的证据、复用分类、待确认决策和分阶段实施计划。

Skill 会先澄清会改变架构或验收的少数问题。对可由当前材料确认的内容，它应当使用 MCP 查询，而不是凭名称或经验猜测。

产物与证据

规格分两种上下文，但系统始终只有一份有效规格：

  • 第一次设计是主线上的 INITIAL_DESIGN 系统集成 intent。它不创建工作树，负责完整设计包、首次生成、系统仿真和第一版系统基线。
  • 已有基线后，每个 feature intent 在自己的工作树中只维护绑定当前 revision/digest 的 ChangeSet 和局部验证定义。本地验证通过时状态是 READY_FOR_INTEGRATION，不能直接更新系统基线。
  • SDK 随后在主线启动无工作树的系统集成 intent，将有效规格与一个 ChangeSet 合成为不可变的候选系统规格。系统仿真和文档确认全部通过后，候选规格才替换有效规格。

Skill 在当前工程创建 design-package/。一个可冻结的设计包至少包含：

design-package/
  materials/<material-id>/...
  material-manifest.json
  evidence-snapshot.json
  design-context.json
  decisions.md
  specification.md
  implementation-plan.md
  traceability-matrix.md
  generation-manifest.json

materials/ 是选中物料的逐字节副本。material-manifest.json 同时记录原始位置、时间、SHA-256、用途和分类：

  • REUSE_UNCHANGED：可以不改字节复用。
  • ADAPT_REQUIRED：可作为起点，但改动必须写入实施计划的具体任务，并给出验证方式。
  • REFERENCE_ONLY：只用于接口、配置或行为事实，不能直接带入工程。
  • REJECTED：不允许用于本次设计，并记录原因。

evidence-snapshot.json 中的每一条事实必须附来源 ID。已经证实的结论标为 CONFIRMED；设计推断标为 PROPOSED；需要客户做选择的内容标为 DECISION_REQUIRED。后者未清零前，设计包不能冻结。

与 MCP 的协作

Skill 通过当前 EvoVerse MCP 发现事实和保存受控设计信息。常见动作包括读取 Catalog 与知识库、检查工程/板卡/IP 能力、建立或读取规格、以及核对后续验证状态。Agent 应在对话中展示关键 MCP 返回的来源、摘要和未决决策，而不是只给出最终文档。

物料发现遵循可信物料源层级：① 已安装 Catalog（catalog_status 返回的 location 下的 catalog/，唯一可信物料库）；② 工具链自带代码与示例（$EFINITY_HOME/examples/、SDK docs/efinity/ 知识库）；③ 本工作区现有代码（只读）；④ 网络开源代码（不可信，仅用于发现，引用前必须经仿真确认并记录来源）。禁止全盘搜索定位物料或引用开发树副本。

对 Efinity 相关结论，先查询运行时工具链知识和当前 IP/工程能力；静态示例或旧工程只可作为带来源的材料。客户确认后，Skill 运行 scripts/validate_design_package.py design-package 校验结构、摘要和物料适配任务，并本地预报服务端 spec.draft 会拒绝的 GENERATION_NOT_READY 发现（决策状态、数值策略、协议角色、连接方向等），避免密封后才被服务端退回。此检查不等于 RTL 仿真、Efinity 编译、时序收敛或硬件验证。

可靠工作流中，spec.draft 以 packagePath 提交密封的可执行 2.0 规格包目录：服务端密封并记录 specPackageDigest 作为可靠身份，specification.md 由密封脚本确定性生成、仅供人工评审；Markdown 文件不能作为 packagePath 提交。

冻结后的下一步

客户确认设计包中所有 DECISION_REQUIRED 项后，冻结的 generation-manifest.json 绑定物料账本、证据快照和设计上下文的摘要。之后使用 /evoverse-rtl 把实施计划中的一个叶子任务生成到受控候选目录。它可以读取 materials/，但绝不能修改材料副本或回写参考基线。Feature intent 完成后等待系统集成；最终规格和复盘由系统集成 intent 一并确认，避免分支状态与主线交付状态不一致。

冻结前还必须在验证规格的 assurance 段声明 rtl-baseline@1、选定规则包、每个显式协议契约，以及带规则 ID、原因、到期时间和精确文件/模块/接口范围的例外。视频契约使用 evoverse.video@1，必须明确 module、imageWidth、bitsPerPixel、parallelism 和 lineBufferDepth；任何缺失或歧义均为 DECISION_REQUIRED，不得从端口名称推断。

停止条件

当外部接口、寄存器图、时钟策略、CDC、硬 IP 行为、Oracle、安全要求或 RISC-V 使用方式不明确时，Skill 必须停下并要求客户决定。它不能为了继续生成而虚构事实、替客户选择，或把参考设计的实现细节当成已批准规格。

高级参考用于按需查询；设计记录、发布流程、审计报告和未来规划不属于客户操作入口。
