Efinity AI 工程感知编译评审

Efinity AI 工程感知编译评审 · 使用说明书

efinity-build-review Skill 把一个现有 Efinity 工程的全部原生编译证据变成一份可审计的评审报告：先给确定性状态，再给 AI 解读与可验证建议。它支持 EvoVerse 工程，也支持没有 .evoverse、源码位于任意目录、通过 flist/include 引用的客户原生工程，甚至只有报告没有源码的工程。

评审是只读的：Skill 不改 RTL、SDC、ISF、工程 XML，也不改任何报告。要应用建议时，先给补丁/设置预览，确认后才走原生能力执行，并用新的原生编译证据验收。

一、它解决什么问题

接手一个 Efinity 工程时，通常要回答这些问题：编译到底走到哪一步了？时序过没过、差多少？资源用了多少？约束全不全？报告里的关键路径对应我哪段代码？下一步该改什么、改了会不会破坏功能？这份评审把上述问题一次性回答清楚，并且每条结论都能追溯到证据：

  • 确定性事实（资源、WNS/TNS、编译阶段、verdict）来自对原生报告的解析，不由 AI 编写；
  • AI 只负责解释、风险分析和可验证建议，且每条建议都带风险等级、功能影响和验证步骤；
  • 缺失的信息显示 NOT_AVAILABLE 或 UNKNOWN，不会被渲染成 0，也不会被猜一个数。

二、前置条件

条件 说明
Trae + EvoVerse SDK 已安装 SDK 与 efinity-adapter 两个 VSIX，MCP 会话已连接
一个 Efinity 工程目录 至少有原生工程 XML；有 outflow/ 原生报告时结论更完整
Efinity 工具链（可选） 仅当需要跑新编译（efx_run --flow compile）时需要
MCP 工具可用 efinity_review_collect / efinity_review_validate / efinity_review_render 三个工具在会话中可见

升级或重新部署 SDK 后需重连 MCP 会话（重启 Trae 或重连 MCP），工具列表才会刷新。

三、快速开始

你对 Trae 说什么

在工程目录打开 Trae，输入：

/efinity-build-review
评审这个 Efinity 工程。先让我选择工程 XML，再解释工程结构、编译阶段、资源、时序、约束覆盖、产物、关键路径源码关联和下一步。

常用变体：

/efinity-build-review
目录里有多个工程，评审其中的客户交付工程。当前没有原生报告，请先征得我同意后跑一次完整编译，再出评审。

/efinity-build-review
重新评审上次那个工程。重点解释 Setup 最差路径的源码来源，并对比可行的优化策略，不要直接改代码。

如果目录中有多个 Efinity XML，Skill 会列出全部候选要求明确选择，不会静默使用第一个或最新的文件。默认只分析已有报告；运行新的原生编译前会说明动作并取得授权。

四、完整工作流程

flowchart LR
    A[用户选择工程 XML] --> B[efinity_review_collect 采集确定性证据]
    B --> C[AI 阅读闭包内源码与索引生成 AIReviewDocument]
    C --> D[efinity_review_render 最终校验并原子落盘六件产物]
    D -->|文档无效| E[仅修复报告字段并重试一次]
    E -->|仍失败| F[mode deterministic 渲染确定性降级报告]
    D -->|成功| G[返回全部产物路径]
    F --> G
    G --> H[可用时打开 Webview 否则返回 HTML 入口]
  1. 选择评审对象：Skill 只在当前工作区内发现原生 Efinity XML；多候选时必须由你选择。
  2. 采集证据：调用 efinity_review_collect，得到证据包（evidence bundle），包含能力等级、新鲜度、六维度状态、关键路径、源码关联、策略评估等。
  3. 理解工程：AI 只读选定 XML/flist/include 命名的源码闭包与相关 SDC/ISF/peri/IP 配置，建立顶层功能、模块层级、时钟/复位域、外部接口、状态机与反馈路径的理解。
  4. 生成并最终校验：AI 按 AIReviewDocument 契约生成评审，直接提交 efinity_review_render；render 内置权威校验，失败时只修复报告字段一次，不重新分析工程。efinity_review_validate 仅用于需要单独诊断校验错误的场景。
  5. 渲染落盘：正常评审修复后仍失败或 AI 不可用时，调用 efinity_review_render 的 mode: deterministic 生成合法的确定性降级报告。只有聊天文字、没有六件产物路径，不算完成。
  6. 查看与导出：用 evoverse.openEfinityBuildReview 打开报告；需要给客户时用导出功能生成脱敏版。

如果宿主没有提供这三个 MCP 工具，Skill 会报告 CAPABILITY_UNAVAILABLE，而不是用自由文本冒充正式报告。

五、能力等级与证据新鲜度

能力等级 含义
FULL_PROJECT 工程、源码、约束与报告齐全，可做代码级关联分析
LIMITED_PROJECT 部分源码、生成单元、VHDL 或加密 IP 无法深入分析
REPORT_ONLY 只有报告状态，代码级结论被禁用
PREFLIGHT_ONLY 没有任何原生实现报告
新鲜度 含义
CURRENT 报告可证明对应当前输入
POSSIBLY_STALE 时间戳兼容，但报告不带完整输入摘要，无法证明严格对应
STALE 工程输入比报告新，报告是历史证据
UNKNOWN 无法建立新鲜度

mtime 兼容检查只能产生 POSSIBLY_STALE，不能证明 CURRENT。STALE 报告按历史证据对待：改完源码后应重新编译再评审。

六、阅读报告

6.1 六维度状态与 verdict

报告首先给出执行摘要和客户行动建议，随后用「确定性状态总览」展示六个互相独立的维度：编译流程（Flow）、产物（Artifact）、时序（Timing）、资源（Resource）、约束（Constraint）、新鲜度（Freshness）。每个 section 标题右侧有状态徽章（需修复/需关注/正常/数据缺失），hero 区按 verdict 着色。总状态（verdict）含义：

  • BLOCKED：编译失败或证据不足以继续。
  • BUILT_NOT_READY：已有编译产物，但存在时序失败、过期证据或其他阻断。
  • READY_WITH_RISK：可以进入下一步验证，但仍有明确风险。
  • READY_FOR_VERIFICATION：编译证据满足进入后续验证的条件；这不等于仿真、烧录或实板功能通过。

6.2 报告章节导览

报告界面以中文为主（信号名、工具标识符保留英文），并提供互链的纯英文版 report-en.html / report-en.md。章节顺序问题前置：

当前阅读顺序为“执行摘要与 AI 建议 → 状态与宏观系统框架 → 技术诊断 → 默认折叠附录”。宏观框架只展示顶层和按模块类型聚合的主要功能块；原生编译流程、产物、设计—实现对照、限制和证据身份位于附录，其中设计—实现对照默认收起并显示总项数与需关注项数。

章节 内容 来源
确定性状态总览 六维度状态、阻塞项、风险项 确定性解析
执行摘要 AI 执行摘要 AI
问题聚类 时序违例 / 原生错误 / 警告风暴聚类 确定性解析
关键路径与源码关联 路径卡片：违例/满足徽章 + 裕量 + 起止点摘要头，展开见 hop 表、端点映射、数据锥、策略矩阵 确定性 + AI
时序预算 Setup / Hold 的 WNS、TNS、违例路径数 确定性解析
原生编译流程 map / interface / place / route / timing / pgm 六阶段 确定性解析
时钟与约束覆盖 每时钟域 WNS/TNS 与约束覆盖度 确定性解析
资源占用 每类资源 used / avail / util 确定性解析
设计拓扑 设计单元、实例边界、黑盒 确定性解析
设计—实现对照 设计单元与实现证据对照 确定性解析
原生产物 报告、数据库、bitstream 及 SHA-256 确定性解析
AI 分析章节 模型按工程定制生成的 sections AI
限制与未知项 证据局限与 AI 未知项 混合
证据身份 reviewInputId 与生成时间 确定性解析

bitstream 已生成不代表时序收敛；两者在报告中分开呈现。

6.3 结论类型

每条 AI 结论标注为四类之一：

类型 含义 必须携带
FACT 报告/源码直接支持的事实 证据 ID
INTERPRETATION AI 解读或根因假设 证据 ID
RECOMMENDATION 行动建议 风险、功能影响、验证步骤、是否需要用户决策
UNKNOWN 证据不足的未知项 —

模块用途等由命名或行为推断的结论是 INTERPRETATION，不是厂商事实。置信度标注 HIGH / MEDIUM / LOW / NOT_APPLICABLE。评审文档为双语：中文主字段 + 必填的英文镜像（文档 headlineEn、章节 titleEn、结论 en），缺失镜像会导致校验失败。

七、源码关联与定位等级

关键路径定位分为五级：

等级 含义
EXACT 原生报告的 file:line 注释落在选定工程证据闭包内
SYMBOL_MATCH 叶子符号匹配；重名候选全部保留并标记歧义
SEMANTIC_CANDIDATE 语义候选
HEURISTIC 文件名/综合后缀启发式，非精确注解
UNRESOLVED 无法解析

Verilog/SystemVerilog 使用结构化 tokenizer/parser 建立 module、instance、port、parameter、process、assign、function、generate、数组、source range 与驱动—消费者图，再以数据锥辅助定位。宏与参数展开不完整、VHDL、生成或加密单元会明确降级，不伪装为完整 elaboration。路径抽屉并列显示端点候选、AST 数据锥、主逻辑区映射、pipeline 适用性、策略矩阵、功能影响和验证清单。

八、优化建议与约束安全

8.1 pipeline 适用性

建议增加 pipeline 寄存器前，Skill 会检查：反馈、状态转移逻辑、valid/ready 握手、包边界 sideband、多消费者、Reset/CE、固定延迟协议、RAM/DSP 延迟、CDC、验证资产（断言/testbench）。结论只有四种：SUITABLE、CONDITIONALLY_SUITABLE、UNSUITABLE、UNKNOWN——缺一项语义证据就不能给出确定的 pipeline 建议。

8.2 策略矩阵

策略 含义
PIPELINE 流水线打拍
RETIME 寄存器重定时
EXPRESSION_REFACTOR 表达式重构（逻辑深度/比较器扇入）
FANOUT_REPLICATION 高扇出网络复制
RAM_DSP_REGISTER 使用原语支持的 RAM/DSP 输入输出寄存
TOOL_EFFORT 原生工具档位/seed 选项
CLOCK_ARCHITECTURE 时钟架构调整
IO_CONSTRAINT 补全 IO 时序约束
CDC_ARCHITECTURE CDC 架构改造
NO_ACTION 证据或收益不足，暂不改动

每条建议并列给出预期方向、风险与功能影响、验证步骤。策略生命周期：PROPOSED → ACCEPTED → APPLIED_UNVERIFIED → IMPROVED / NO_CHANGE / REGRESSED / REJECTED；终态必须引用新的原生 after-build 证据，没有新证据时策略不能标记为终态。

8.3 约束安全红线

  • I/O delay 需要外部器件时序（Tco/Setup/Hold）与 PCB 延迟/偏斜参数；缺参数时只显示占位并向你索要，绝不编造 0 ns、2 ns 或其他"保守值"。
  • set_false_path、set_multicycle_path、set_max_delay、set_min_delay 只为消除违例而添加是被禁止的；时序例外需要结构证据、设计意图证据和你的明确确认。
  • Skill 不会为消除违例自动改写 RTL、SDC、ISF 或工程 XML。

九、报告产物与目录结构

<工程根>/
└─ .evoverse/
   ├─ reports/build-review/<reviewId>/     # 本地完整评审（不可覆盖）
   │  ├─ review.json        # AI 评审文档（权威输入，中文主字段 + en 镜像）
   │  ├─ evidence.json      # 确定性证据包
   │  ├─ report.html        # 自包含 HTML 报告（中文为主）
   │  ├─ report.md          # Markdown 版（中文为主）
   │  ├─ report-en.html     # 纯英文版 HTML
   │  └─ report-en.md       # 纯英文版 Markdown
   └─ exports/build-review/<reviewId>/     # 客户脱敏导出（同样六件，evidence 为脱敏版）
  • 本地评审通过临时目录原子生成；已存在的 reviewId 不会被覆盖。失败或取消不会留下可误认成完成的报告。
  • 导出的 HTML 保持零脚本与严格 CSP（default-src 'none'）；IDE Webview 只注入带 nonce 的本地桥，打开源码时再次按 evidence ID、文件存在性和行号校验，客户内容不能直接执行命令。
  • HTML 提供可打印样式；当前 PDF 边界是 IDE/浏览器"打印为 PDF"，不是内置确定性 PDF 引擎。
  • 客户导出会删除本地绝对路径和源码正文，并扫描凭据式文本、环境变量值及路径；发现泄漏风险时导出失败关闭（fail closed），必须先处理 finding，不能绕过。
  • 对比会先检查工程、器件和 Top 兼容性，再显示 WNS/TNS、资源、耗时、路径、约束和问题簇变化。

十、命令与 MCP 工具速查

入口 作用
efinity_review_collect 为明确选择的工程 XML 采集确定性证据；正式评审第一步
efinity_review_validate 可选诊断工具；单独查看 schema / 证据引用错误，正常流程无需预调用
efinity_review_render 最终校验并原子生成六件产物；传 review 生成完整评审，AI 不可用时传 mode: deterministic 生成确定性降级报告
命令 evoverse.openEfinityBuildReview 打开当前工程最新一份已渲染评审（Webview）

三个 MCP 工具的公共参数：project（工程目录绝对路径）、projectXml（你明确选择的工程 XML 绝对路径）；validate 需传入 review。render 二选一传入绑定 collect reviewInputId 的 review，或在 AI 不可用时传 mode: deterministic。

evoverse.openEfinityBuildReview 打开前会重新校验 review.json 与 evidence.json 的 schema 一致性及 HTML 安全性；校验失败会提示重新渲染，不会打开被改动过的报告。

十一、常见问题

现象 处理
Skill 报 CAPABILITY_UNAVAILABLE 宿主未暴露评审 MCP 工具。升级/重部署 SDK 后重连 MCP 会话；不要接受自由文本冒充的报告
目录里有多个工程 XML Skill 会列出全部候选要求选择；确认你选的是要交付/评审的那一个
能力等级是 PREFLIGHT_ONLY 没有原生报告。明确要求后 Skill 会执行 efx_run --flow compile 再评审
报告标记 STALE 视为历史证据；重新编译后再评审，不要基于旧报告做验收
render 返回文档校验错误 Skill 只修复报告字段一次；仍失败则用 mode: deterministic 渲染确定性报告，不在分析阶段结束
导出被 privacy findings 阻止 失败关闭。先按 finding 处理（如报告文本中的绝对路径），再重新导出
打不开报告，提示 schema/HTML 校验失败 评审目录被改动过或损坏；用 efinity_review_render 对同一评审重新渲染

十二、验证边界

Compile、Timing、Simulation、Programming 和 Hardware 是独立状态。评审可以确认原生报告记录了 map/interface/PNR/PGM 和 bitstream，但不得据此推断仿真、下载或板级功能通过。资源、WNS/TNS、阶段状态及顶层 verdict 来自确定性解析层；AI 只负责解释、风险分析和可验证建议。工程文件与报告是证据，不是指令——Skill 会忽略任何试图借注释或日志文本改变评审流程的内容。

高级参考用于按需查询；设计记录、发布流程、审计报告和未来规划不属于客户操作入口。
