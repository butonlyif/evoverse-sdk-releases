Efinity AI 工程感知编译评审

efinity-build-review Skill 用于解释一个现有 Efinity 工程及其原生编译证据。它支持 EvoVerse 工程，也支持没有 .evoverse、源码位于任意目录或通过 flist/include 引用的客户原生工程。

使用方式

在工程目录打开 Trae，然后输入：

/efinity-build-review
评审这个 Efinity 工程。先让我选择工程 XML，再解释工程结构、编译阶段、资源、时序、约束覆盖、产物、关键路径源码关联和下一步。

如果目录中有多个 Efinity XML，Skill 会要求明确选择，不会静默使用第一个文件。默认分析已有报告；运行新的原生编译前会说明动作并取得授权。

如何阅读结论

报告顶部给出六个互相独立的维度：Flow、Artifact、Timing、Resource、Constraint 和 Freshness。总状态含义如下：

  • BLOCKED：编译失败或证据不足以继续。
  • BUILT_NOT_READY：已有编译产物，但存在时序失败、过期证据或其他阻断。
  • READY_WITH_RISK：可以进入下一步验证，但仍有明确风险或只能确认报告“可能是当前的”。
  • READY_FOR_VERIFICATION：编译证据满足进入后续验证的条件；这不等于仿真、烧录或实板功能通过。

mtime 兼容检查只能产生 POSSIBLY_STALE，不能证明 CURRENT。缺失值显示 NOT_AVAILABLE 或 UNKNOWN，不会显示为零。

源码定位与建议边界

关键路径定位分为 EXACT、SYMBOL_MATCH、SEMANTIC_CANDIDATE、HEURISTIC 和 UNRESOLVED。只有原生报告在当前工程证据闭包内给出的 file:line 才是 EXACT；重名候选会全部保留并标记歧义。

增加 pipeline 的建议会检查反馈、FSM、valid/ready、包边界、Reset/CE、固定延迟、RAM/DSP、CDC、多消费者和验证资产。证据不足时结论为 UNKNOWN。I/O delay 需要外部器件时序和 PCB 参数；false_path、multicycle_path、max_delay、min_delay 需要结构证据、设计意图证据和用户确认。Skill 不会为消除违例编造数值或自动改写 RTL/SDC/ISF/XML。

报告和导出

本地评审生成不可覆盖的新目录，包含 review.json、evidence.json、report.html 和 report.md。IDE 页面禁用脚本并要求严格 CSP。HTML 提供可打印样式；当前 PDF 边界是 IDE/浏览器“打印为 PDF”，不是内置确定性 PDF 引擎。

客户导出会删除本地绝对路径和源码正文，并扫描凭据式文本、环境变量值及路径。发现泄漏风险时导出失败关闭，必须先处理 finding，不能绕过。

验证边界

Compile、Timing、Simulation、Programming 和 Hardware 是独立状态。评审可以确认原生报告记录了 map/interface/PNR/PGM 和 bitstream，但不得据此推断仿真、下载或板级功能通过。资源、WNS/TNS、阶段状态及顶层 verdict 来自确定性解析层；AI 只负责解释、风险分析和可验证建议。

高级参考用于按需查询；设计记录、发布流程、审计报告和未来规划不属于客户操作入口。
