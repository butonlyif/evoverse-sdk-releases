Skill：自然语言配置 Efinity 工程

自然语言配置 Efinity 工程

efinity-project Skill 用于在 Trae 对话中创建或修改 Efinity 工程。它逐步确认器件、RTL、时钟、引脚、IP、编译选项和 Debugger 设置，解释每个选择的影响，然后调用 Efinity 自带的工程 API、DesignAPI、IP Manager 和统一编译流程。

新建工程

在目标目录打开 Trae 后输入：

/efinity-project
为 Ti60F225 新建一个 Efinity 工程，顶层模块是 top。先问我时钟、复位和板卡引脚，再生成工程并用本机 Efinity 完整编译验证。

Skill 优先选择器件匹配且已有编译证据的 Efinity 官方示例或 Catalog 基线，再通过 efx_py 修改原生 XML。若只能使用 Configuration.New()，生成的 XML 仍是候选，不能在完整编译前称为可用工程。新的接口设计在首次引导编译后，还会再编译一次验证 ISF 可以重复执行。

修改现有工程

/efinity-project
检查这个工作区中的 Efinity 工程。把综合目标解释给我，再按速度优先调整设置；先预览修改，应用后重新完整编译。

如果有多个工程 XML，Skill 会先要求选择目标。旧版本工程会先说明迁移风险并保留可恢复副本。缺少原理图、引脚或 Bank 电压资料时，它会保留待决项，不套用其他开发板的数据。

参数解释与知识来源

Skill 同时查阅 SDK 的 docs/efinity/ 和当前 Efinity 安装自带的 doc/topics/、doc/pdf/、组件文档、schema、工具帮助与 API docstring。合法参数和器件差异以当前安装版本为准；仓库知识库用于解释已经实测的陷阱。它不复制一套 Efinity 参数数据库，也不创建编译包装工具。

Debugger

片上调试遵循 Efinity 原生顺序：标记至少一个有效信号，保持自动实例化关闭并先编译生成 debug profile，确认其中确有调试核或选中探针，再预览并应用 Debugger 设置，最后重新编译把调试核加入位流。仅有文件但没有探针的空 profile 会被拒绝。LA/VIO、采样深度与资源开销会在选择前解释。

验收边界

只有当前 XML、RTL、约束和 IP 输入实际完成 efx_run --flow compile 的 map、PT、PNR、PGM 全流程，Skill 才报告“工程已编译通过”。失败、工具不可用或资料不足时明确报告“未验证通过”和当前阻塞。时序收敛、仿真、烧录与实板功能是独立结果，不由编译 PASS 推断。
