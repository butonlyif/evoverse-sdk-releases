Skill：从原理图创建板卡

evoverse-board-create · 用户指南

面向客户 · EvoVerse SDK v1.0.0 · 2026-10-24

这个 Skill 把板卡资料整理成 SDK 可验证的机器契约，并自动生成人可读说明书。 适用于独立 FPGA 单板、纯 SoC 单板（RK3588 为首个实现）、FPGA 核心板+底板， 以及 FPGA+RK3588 异构系统；多个 SoC 目标各生成独立目录互不覆盖。

需要准备

  • 对应硬件版本的原理图、BOM 和受控设计资料；
  • FPGA 与 RK3588 的精确器件/封装身份；
  • Efinity 当前安装版本自带的器件数据和文档；
  • 主要芯片厂商的官方 datasheet、reference manual 或产品页；
  • 板卡形式、版本、电源、时钟、复位、启动介质等关键选择。

不确定项会保留为 UNVERIFIED，来源冲突会保留为 CONFLICT，不会用推测值 补齐。分销商或社区页面只能帮助发现型号，不能确认电气或功能事实。

输出结构

每个物料根包含 board.yaml、hardware.yaml、sources.yaml，并按 FPGA 与 RK3588 分开保存功能 pinout。核心板和底板各自保存机器事实，选择底板后才生成 组合说明书。功能映射直接连接到最终器件，不包含冗余的板间连接器位置。 每个 SoC 目标在 platforms/<target-id>/ 下生成三份最小物料：规范化的小型 platform.yaml、由已确认原理图事实推导的 <board-id>.dts 初始骨架，以及 Adapter 词汇的 profile.template.json（未绑定字段保持空白/未解决，绝不伪造）； 当平台输入中带有确认的本地 BSP/环境绑定事实时，同目录额外生成可执行的 evoverse-rk3588-profile.json（沿用现有 Profile 模式，原值渲染）。

docs/generated/ 自动产生；其中面向客户阅读的综合说明书固定为 docs/generated/board-manual.md：

  1. 板卡概览；
  2. 硬件参考；
  3. 器件行为（按键有效电平、数码管共阴/共阳等，由原理图拓扑推导）；
  4. 接口说明；
  5. 电源与时钟；
  6. 开发指南；
  7. Bring-up 指南；
  8. 来源索引；
  9. 带 Mermaid 框图的综合板卡说明书。

客户自己的 docs/datasheet.md 永远不会被创建、覆盖或整理；demos/、 ips/ 与非 Stage0 jackets 也不会被修改。

器件行为推导

Skill 不只罗列器件，还会从原理图拓扑（上拉/下拉、驱动三极管、公共端接法） 推导按键、拨码开关、LED、数码管、蜂鸣器、继电器等用户可交互/可见输出器件 的电气行为，写入 hardware.yaml 的 device_behaviors 容器：例如按键按下 在 FPGA 引脚上读到 low 还是 high、数码管是共阳（common_anode）还是 共阴（common_cathode）。没有原理图依据时保持 UNVERIFIED，绝不猜值。 这些事实在 board-manual.md 的 "Device behaviors" 一节呈现，后续 RTL 与 约束设计可直接参考。

FPGA 与 RK3588

FPGA 校验区分“封装球存在”和“该球允许承担指定 GPIO/硬核功能”。它检查 bank/VCCIO、PLL 参考时钟、配置/JTAG、差分对、MIPI lane、DDR、PCIe/QSE/ SerDes 等器件约束。Efinity probe 的 package/bank 输出不能单独证明硬核合法。

RK3588 走直接资源流：先确认目标身份，再按「板卡/模组厂商官方 BSP → 芯片 厂商官方 SDK → 厂商明确支持的上游项目」顺序搜索一手开发资源；社区仓库、 镜像、论坛帖、分销商页面只作发现线索，除非用户显式接受否则不能成为选定的 BSP 或环境。定制板没有板卡厂商 BSP 时，以芯片厂商官方 SDK 为基础，从原理图 事实推导本板 DTS；同 SoC 其他板卡的 BSP 不能互换。选定资源只记录可复现信息 （官方归属、URL/仓库、发布 ref、支持的主机构建环境、许可证/访问说明、观察 日期）到 sources.yaml，未下载核验的字节不编造哈希。

大型 BSP 压缩包、工具链、容器镜像、固件包或任何需要接受许可的资源，下载前 必须先向用户展示确切的来源、版本/ref、已知大小、目标位置与许可/访问要求， 确认后才下载；Skill 不嵌入凭据、不代用户接受许可。确认后使用现有 Git/HTTP/ 归档/包管理/容器工具在用户批准的位置取得资源，重新运行生成更新同一 platforms/<target-id>/ 目标文件，用真实 BSP 根、ref、环境、loader、分区与 阶段补全 evoverse-rk3588-profile.json，然后调用现有 RK3588 Adapter preflight。下载成功本身不是 BUILD_READY——该结论只由 Adapter 在绑定完成且 preflight 通过后报告。

缺失必备原理图事实、权威 BSP/环境来源、访问权限或用户确认时，状态为 INCOMPLETE：部分物料仍然生成并激活，可进入 Catalog 被发现，后续补齐事实后 重新生成同一目标目录即可完成——INCOMPLETE 不是 Catalog 拒收。只有畸形契约、 路径逃逸或破坏性写冲突才会让生成操作失败退出。

运行

cd Skills\evoverse-board-create
python -m pinout_tool.cli material-generate `
  --root <板卡或核心板物料目录> `
  --carrier <所选底板目录> `
  --fpga-authority <精确FPGA器件权威数据.json> `
  --rk3588-authority <精确RK3588权威数据.json>

命令按结构、来源、器件管脚、组合、目标产物、文档的顺序执行。任何错误都不会 替换上一版有效自动产物。

验证范围

生成 Stage0 只证明输入文件已经形成，不证明 Efinity 编译、烧录或实板运行。 未运行原生编译时状态为 NATIVE_BUILD_NOT_RUN。RK3588 的原生构建、镜像打包、 烧录、启动和实板验证是彼此独立的证据边界，生成文件一律不宣称其中任何一项； RK3588 Adapter 也会自动发现 platforms/<target-id>/ 下生成的模板与可执行 Profile（可执行 Profile 优先），未绑定模板只呈现 PROFILE_READY 与缺失绑定 清单，不会转为完整 Profile。

高级参考用于按需查询；设计记录、发布流程、审计报告和未来规划不属于客户操作入口。
