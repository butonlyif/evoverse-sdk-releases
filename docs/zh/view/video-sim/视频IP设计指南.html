视频 IP 设计指南

EvoVerse VIP/IP 设计指南 与 Assurance 契约 v1.1

文档版本：v1.1 更新日期：2026-09-01

0. 文档关系

  • 客户视频 IP 设计的唯一权威规范源
  • 与冻结规格的 Assurance 契约同步（见 §0.5）
  • 不替代 Efinity 工具链参考、IPM 库使用指南

0.5 SDK Assurance 契约声明

本指南定义视频 IP 的设计要求；项目的冻结规格将每个实例的明确取值写入 assurance.contracts，并使用 evoverse.video@1 验证候选 RTL。

RTL 可以由设计者或 Agent 自由编写，但不得由模块名或端口名推断其视频意图。 缺少 module、imageWidth、bitsPerPixel、parallelism 或 lineBufferDepth 时，规格必须 标为 DECISION_REQUIRED，不能进入冻结或受控 Assurance。

SDK 实施点：

  1. 规则实现：sdk/design-assurance/evoverse_assurance/protocols/video.py
  2. 规格实现：冻结的 ModuleSpec/SystemSpec assurance.contracts
  3. 执行入口：evoverse assurance 或 MCP assurance_check
  4. 工程 harness：evoverse new-project 把本指南复制至 <project>/docs/VIP-IP-DESIGN-GUIDE.md，并落项目级 instruction（applyTo: **/*.{v,sv}）；工程内修改 video_* 代码必须遵循。单一来源：本文件（docs/video-sim/视频IP设计指南.md）；bundle（build-vsix.ps1 vendor）与工程内的 VIP-IP-DESIGN-GUIDE.md 均由本文件生成，勿直接编辑。

同步原则：本指南、规格模板和 evoverse.video@1 规则变动必须一并评审。任何一方变动必须在 DAYLOG/ 留痕。

1. 适用范围与术语

  • VIP：Video IP，泛指 AXI-Stream 视频处理核
  • 通用寄存器接口（cfg_*）
  • AXI-Stream 流接口（s_axis_/m_axis_）
  • BRAM 行缓冲（line buffer）
  • 同步复位（aresetn，低有效）

2. 公共规格定义（契约正文）

2.1 系统参数

参数 默认值 说明
MAX_WIDTH 3840 最大像素宽度
MAX_HEIGHT 2160 最大像素高度
DATA_WIDTH 24 默认像素位宽（RGB888）
PARALLEL 1 每时钟像素数
CLK_FREQ_MHZ 125 工作时钟频率

2.2 时钟架构

  • 单时钟 aclk + 低有效同步复位 aresetn
  • 复位同步释放（rst_sync_r 两级触发器链）
  • 多时钟域需在 §4 中显式标注 CDC

2.3 AXI-Stream 视频接口标准（契约）

信号集（与 Xilinx AXI-Stream Video 兼容）： | 信号 | 方向 | 位宽 | 说明 | |---|---|---|---| | aclk | in | 1 | 时钟 | | aresetn | in | 1 | 异步低有效复位 | | s_axis_tvalid | in | 1 | 发送方数据有效 | | s_axis_tready | out | 1 | 接收方就绪 | | s_axis_tdata | in | DATA_WIDTH | 像素数据 | | s_axis_tuser | in | 1 | SOF 帧起始 | | s_axis_tlast | in | 1 | EOL 行结束 | | m_axis_* | out | 同上 | 镜像输出集 |

约定： - SOF（tuser=1）只在每帧第一像素置位 1 拍 - EOL（tlast=1）只在每行最后一像素置位 1 拍 - 帧/行计数器由 IP 内部维护，外部不暴露

2.4 寄存器接口标准（契约）

信号集： | 信号 | 方向 | 位宽 | 说明 | |---|---|---|---| | cfg_clk | in | 1 | 寄存器接口时钟（与 aclk 异步时需 CDC） | | cfg_addr | in | 8 | 字节地址 | | cfg_wdata | in | 32 | 写入数据 | | cfg_wen | in | 1 | 写使能 | | cfg_ren | in | 1 | 读使能 | | cfg_rdata | out | 32 | 读出数据 | | cfg_rdy | out | 1 | 就绪 |

寄存器映射模板： - 0x00 IP_VERSION（RO） - 0x04 IP_CTRL（RW）：[0] enable，[1] bypass - 0x08 IP_STATUS（RO）：[0] running，[1] error - 0x0C IP_RESET（WO）：写 1 软复位 - 0x10 IMG_WIDTH（RW，16 bit） - 0x14 IMG_HEIGHT（RW，16 bit） - 0x18 IMG_FORMAT（RW，3 bit：0=RAW8/1=RAW10/2=RAW12/3=RGB888/4=YUV422） - 0x1C-0x3C IP_PARAM_*（RW，算法参数，由具体 IP 定义）

2.5 IP 核基本结构（契约：顶层模板）

module <ip_name> #(
    parameter C_DATA_WIDTH = 24,
    parameter C_MAX_WIDTH  = 3840,
    parameter C_MAX_HEIGHT = 2160
) (
    // 系统接口（顺序固定）
    input  wire        aclk,
    input  wire        aresetn,

    // 寄存器接口
    input  wire        cfg_clk,
    input  wire [7:0]  cfg_addr,
    input  wire [31:0] cfg_wdata,
    input  wire        cfg_wen,
    input  wire        cfg_ren,
    output wire [31:0] cfg_rdata,
    output wire        cfg_rdy,

    // AXI-Stream 输入
    input  wire        s_axis_tvalid,
    output wire        s_axis_tready,
    input  wire [C_DATA_WIDTH-1:0] s_axis_tdata,
    input  wire        s_axis_tuser,
    input  wire        s_axis_tlast,

    // AXI-Stream 输出
    output wire        m_axis_tvalid,
    input  wire        m_axis_tready,
    output wire [C_DATA_WIDTH-1:0] m_axis_tdata,
    output wire        m_axis_tuser,
    output wire        m_axis_tlast
);

端口顺序契约：①系统（aclk/aresetn）→ ②寄存器（cfg_）→ ③输入流（s_axis_）→ ④输出流（m_axis_*）。任何重排视为实现缺陷。

2.6 BRAM 行缓冲契约

资源估算公式（用于 §4 综合资源预算）：

单行数据量（bits）= IMG_WIDTH × BPP × PARALLEL
所需 BRAM 块数 = ceil(单行数据量 / 10240) × 行数

TJ180 限制：单 IP ≤ 16 块 BRAM；行缓冲深度 ≤ 4 行。

2.7 性能指标契约

指标 要求
最高分辨率 3840×2160
最高帧率 60 fps @ 1080p
流水线深度 ≤ 16 级
端到端延迟 ≤ 1 行（带 BYPASS 旁路）

3. RTL 编码与命名规范

3.1 命名约定

元素 规范 示例
模块名 小写蛇形 video_register_slice
参数 大写蛇形，C_ 前缀 C_DATA_WIDTH
寄存器地址 大写蛇形，REG_ 前缀 REG_IP_CTRL
端口 小写蛇形，方向后缀 s_axis_tvalid, cfg_wdata
内部信号 小写蛇形 pixel_cnt

3.2 编码风格（与 SDK 通用模板一致）

  • timescale 1ns / 1ps
  • default_nettype none（文件尾恢复 wire）
  • 同步复位 aresetn，低有效
  • 复位同步释放（两级触发器）
  • 端口后缀：_i（输入）、_o（输出）、_io（双向）
  • 中文行内注释

3.3 仿真测试要求

  • 每个 IP 必须含 _tb.v 自检 testbench
  • 必须覆盖：基本功能、边界（最小/最大分辨率）、连续帧、复位恢复

3.4 综合约束模板

create_clock -name aclk -period 8.0 [get_ports aclk]
set_input_delay -clock aclk -max 2.0 [all_inputs]
set_output_delay -clock aclk -max 2.0 [all_outputs]
set_false_path -from [get_ports {aresetn}]
set_false_path -from [get_ports {cfg_clk}]   # 异步寄存器时钟

4. 多时钟域与 CDC

4.1 单时钟 IP（默认）

  • 所有信号在 aclk 域
  • 寄存器接口 cfg_clk = aclk（同步寄存器接口）

4.2 异步寄存器接口

  • cfg_clk 与 aclk 异步时需两级同步器
  • 必须在 RTL 注释中标注 CDC
  • 校验器检查 // CDC: 注释存在

5. Assurance 契约（SDK 实施点）

5.1 冻结规格必须声明

assurance:
  rulePacks: [rtl-baseline@1, evoverse.video@1]
  contracts:
    - id: camera_pipe
      protocol: evoverse.video
      module: video_pipe
      imageWidth: 1920
      bitsPerPixel: 24
      parallelism: 1
      lineBufferDepth: 2

5.2 规则覆盖范围

  1. §2.3 信号集完备（s_axis_ / m_axis_ 各 6 个）
  2. §2.4 寄存器信号集完备（cfg_* 7 个）
  3. §2.5 端口顺序（系统→寄存器→输入流→输出流）
  4. §2.6 BRAM 行缓冲预算

5.3 执行方式

受控 RTL 任务从冻结规格读取契约并保存候选绑定回执。自由开发可直接运行 evoverse assurance 检查已明确声明的请求；缺少动态证据时结果为 incomplete， 不是 PASS。

6. 不在本指南范围

  • ISP 算法本身（去马赛克/AWB/降噪等）：由客户在模板之上实现
  • regmap.h C 头文件生成：v1.1 再纳入
  • 跨语言绑定：v1.1 再纳入
